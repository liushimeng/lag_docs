## 1. 为什么需要这一层

《总体设计》回答「一个人如何在城市里过完一生」；《规则与经济系统》回答「钱、表、市如何运转」；
`已实现/11-城市扩张` 回答「央行、财政、产业链、金融市场、公共服务、监管、选举这些子系统已落地多少」。
但一座真实城市之所以是「城市」，还在于以下三组尚未被系统设计文档覆盖的骨架：

1. **空间骨架**——土地如何分区、路网如何组织、16 个城区凭什么在那个位置、地价由什么决定（→ 01、03、09）。
2. **运行骨架**——水电气热、垃圾、通信这些看不见的公用事业如何像血液一样循环；城市如何应对火灾、内涝、疫情、挤兑（→ 02、08）。
3. **人治骨架**——城市是居民建起来、也是居民管起来的：规划局、公安局、法院、街道办、城管如何分工；
   居民如何通过选举、信访、舆论、社区参与反过来塑造城市（→ 04、05、07）。
4. **生命骨架**——城市里每一个「人」都是 `LsmAgentGame-City-Human`。他们如何一天 24 小时安排时间、
   如何生老病死、如何成家立业、如何产生情绪与决策（→ 06，本目录的核心）。

> 一句话：**已实现层让城市「转得动」，本层让城市「活得像一座真城」。**

## 3. 三条贯穿原则

### 3.1 城市是居民建的，也是居民管的
本层拒绝「城是凭空生成的布景」。每一块地的用途、每一条路的走向、每一座新城区的开辟、
每一次旧区改造，在叙事上都由居民需求、企业投资、政府规划三者博弈产生（机制上由
04 治理、05 建设、06 居民行为三方交互涌现）。城市不是舞台，是居民的作品。

### 3.2 空间、时间、钱三者必须闭合
- **空间闭合**：一个居民住哪个区、上班哪个区、孩子上学哪个区，必须有一条通勤链（03），
  并影响其时间（06）与精力消耗。
- **时间闭合**：所有公共服务（02/04/08）的响应、所有设施的运行时间，都落在居民的 24 小时
  与每月 1 tick 的时间轴上（《规则》月度节拍）。
- **钱闭合**：基础设施收费、政府税收、居民住房支出，全部汇入既有 Ledger 双式记账
  （`已实现/02-架构`），不新增游离于三表之外的钱。

### 3.3 高保真，但不做物理模拟
与 `已实现/12-CityHuman重构 §7` 一致：本层做**语义级**的系统设计（容量、概率、影响因子、
状态机），不做连续物理引擎、不做逐帧碰撞、不做十万级实时路径寻路。所有"真实感"通过
确定性规则表 + 居民 Agent 的感知/决策文本体现。

## 5. 落地优先级建议（供后续迭代参考，非本期实现承诺）

| 优先级 | 系统 | 理由 |
|--------|------|------|
| P1 | 06 City-Human 全生命周期 | 城市的"人"是定位核心；现有感知工具已就位，补行为闭环 |
| P1 | 01 空间格局 + 03 交通 | 让 see/move/通勤链有空间语义，居民感知落地 |
| P2 | 09 住房深化 + 04 治理 | 与已有房地产、财政、选举系统衔接，边际成本低 |
| P2 | 02 基础设施 | 作为"环境因子"接入 Ambiance 与公共服务质量 |
| P3 | 07 社会生态 + 08 应急 | 丰富事件与舆情，提升城市"活感" |
| P3 | 05 建设演进 | 长周期涌现，需要稳定的城市运行后再接入 |

> 本层文档为设计蓝图，**不承诺本期全部落地**；任何一项进入实现时，须在 `已实现/` 新增对应实施档案。
