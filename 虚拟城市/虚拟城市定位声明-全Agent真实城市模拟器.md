## 1. 定位声明

「虚拟城市」**不是一款游戏**。它是一个**由人类 Agent（居民 Agent）组成的真实城市模拟器**：

1. **全 Agent 城市运行**：城市中的居民由大模型驱动的 Agent 扮演。每位居民 Agent 依据一张全息人生档案
   （75,115 张人物卡，Schema v1.1，65 字段：行业 / 收入 / 资产 / 负债 / 健康 / 情感 / 人格 / 家庭 /
   出生 / 人生经历 / 行为特征 / 风险偏好等）获得身份、记忆与行为倾向。
2. **真实人类生活**：居民在城市中持续生活——就业与晋升、消费与储蓄、投资与创业、借贷与信用、
   婚姻与家庭、购房与养老、社交与博弈，一切决策由居民 Agent 自主做出并留下可追溯的轨迹。
3. **城市级涌现**：市场周期、资产价格、利率通胀、社会信用、公共财政与治理，不由剧本预设，
   而由全体居民行为与制度规则**交互涌现**。
4. **真实中国经济底座**：个税七级累进、五险一金、居民收支与社保、LPR/CPI 区间、八类投资品风险收益
   等参数全部锚定真实数据（见《虚拟城市真实世界经济与财商理论底座》与年度数据锚点文档），
   使模拟尽可能高保真地复现真实中国的经济与社会运行。
5. **没有胜负**：不存在胜利条件与竞技排名。模拟以人生的时间推进为轴，终了时做多维人生结局评定
   （财务自由度 / 人生满意度 / 社会贡献），如同真实人生没有标准答案。

**一句话定位**：虚拟城市是一个全 Agent 模拟城市运行、人类真实生活的系统——用真实数据与制度规则，
让十万级居民 Agent 在其中过完真实的一生。

## 6. 预测运行与场景推演

> 本节确立虚拟城市的**科研级用法**：它不只是一座会自己运行的城市，更是一台**可干预、可复现、
> 可观测的预测机器**——研究者向运行中的城市注入一个外部条件，观察十万级居民 Agent 的连锁反应，
> 得到「如果这样，城市会怎样」的量化预测。完整规格见
> [《虚拟城市场景推演与预测运行设计》](虚拟城市场景推演与预测运行设计.md)。

### 6.1 多场景模拟范式

一次场景推演由四个环节首尾相接：

```
条件注入（Scenario Injection） → 城市状态演化（N 个模拟月）
      → 指标观测（宏观 / 中观 / 微观） → 结果预测（预测报告）
```

| 环节 | 输入 | 系统动作 | 输出 |
|---|---|---|---|
| **条件注入** | 场景类型 `kind` + 强度 `L1–L5` + 目标 / 持续月数 | 改写对应子系统状态（价格、财政、资产、舆情、物理损毁） | 场景事件 + 首批直接冲击 |
| **状态演化** | 注入后的世界状态 | 居民 Agent 依档案与记忆重新决策，市场 / 劳动 / 银行 / 财政逐月清算 | 逐月状态轨迹（可回放） |
| **指标观测** | 状态轨迹 | 采样宏观（CPI/失业/财政/信用）、中观（行业/城区）、微观（家庭收支）指标 | 指标时间序列 + 与基线之差 |
| **结果预测** | 指标差 + 传导链 | 归因（哪条链路贡献最大）+ 外推（后续 3–12 月） | 预测报告：影响面 / 恢复期 / 风险点 / 置信区间 |

**核心不变量**：同一基线快照 + 同一场景 + 同一随机种子 ⇒ **同一结果**（可复现）；
不同场景可在同一基线上并行比较（反事实对照）。

### 6.2 能力范围

| 场景群 | 具体能力 | 主要被观测指标 |
|---|---|---|
| **市场与经济** | 商品价格冲击对居民消费选择的影响（替代效应 / 收入效应 / 囤积）、政策冲击（税率 / 利率 / 补贴 / 限购）、市场崩盘（杠杆强平链、流动性枯竭） | 消费篮子结构、CPI、失业率、企业生灭、财政收支、信用利差 |
| **社会与舆情** | 调研问卷反馈推演（给定问卷设计，预测各阶层回答分布）、选举舆情模拟（议题设置 / 媒体偏向 / 从众效应 → 得票率） | 满意度分项、议题关注度、候选人支持率、社会信任指数 |
| **自然灾害** | 地震（震级 / 震中 / 建筑损毁率）、海啸（淹没带 / 基础设施瘫痪）、极端灾难事件（复合灾害、长期重建） | 直接经济损失、伤亡与迁移、重建支出、保险赔付、恢复期 |
| **未知灾难** | 陨石撞击（撞击当量 / 破坏半径 / 尘霾气候效应）、外星人入侵（不可预期冲击、信心崩塌、制度应急） | 城市功能瘫痪度、信心指数、财政极限、人口净流出、长期产出缺口 |

> **未知灾难的意义**：它不追求「预测得准」，而是做**压力测试**——在模型已知边界之外注入
> 不可标定的冲击，观察系统在极端不确定性下的自适应、崩溃与恢复能力，输出「韧性画像」。

### 6.3 与内生事件的关系

- **内生事件**：由城市内部机制自然产生（市场周期、企业生灭、舆情扩散、行为偏差），无外部操作者。
- **注入场景**：由条件触发者从外部施加，带有明确的 `kind / magnitude / target / duration` 元数据，
  全程留痕；注入后**仍走同一套传导机制**，不写死结果。
- 二者可叠加：注入场景与内生周期共振（如衰退期注入价格冲击）时，预测报告须标注「共振放大」。

## 7. 人类角色

> 虚拟城市**不设人类座位**。城市里的每一个居民都是 Agent；人类的身份只有两种：
> **观察者**与**条件触发者**。房间列表不再提供「加入」，全 Agent 房间一律拒绝人类入座。

### 7.1 两种角色

| 角色 | 权限 | 入口 | 限制 |
|---|---|---|---|
| **观察者（Observer）** | 只读观战：查看 `game.state`、地图、事件流、居民档案、指标看板；不占座位、不影响模拟 | 房间列表「👁 观察」或路由 `/virtual-city/spectate/:roomId` | 不可发送任何输入帧（后端一律 `30011`） |
| **条件触发者（Condition Trigger / 场景操作员）** | 在观察权限之上，向运行中的模拟注入场景条件（市场 / 舆情 / 灾害 / 未知灾难），观看连锁反应与推演结果 | 对局页「场景推演台」面板（观察者可见可操作） | 任意登录用户可用（与调研同权限口径）；月度注入次数受限；全部注入入审计流水 |

### 7.2 硬约束

1. **无人类座位**：`virtual_city` 恒为全 Agent 房间，人类 `join` 一律拒绝（`35036`），
   创建时不得以 `full_agent:false` 旁路绕过。
2. **条件触发者不是玩家**：注入条件 ≠ 操纵角色。人类不能指定某个居民如何反应，只能改变世界条件，
   由居民 Agent 自主响应——这是模拟保真度的底线。
3. **可审计**：每次注入记录 `actor / kind / magnitude / target / applied_month / note`，
   并与模拟事件流一一对应，供事后复盘与论文级引用。
4. **可回放**：注入记录 + 随机种子 + 基线快照 = 完整复现路径。
