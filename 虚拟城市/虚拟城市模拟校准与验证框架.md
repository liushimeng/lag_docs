# 虚拟城市 · 模拟校准与验证框架

> **文档定位**：本文档定义虚拟城市作为**科研级城市模拟器**的**校准目标、验证指标、回归不变量、
> 数据采集规范与数值回填流程**。它回答一个工程问题：**我们凭什么相信这座城市模拟得对、跑得稳、
> 可复现？** 所有「示意值」走向「校准值」都必须经由本文档规定的流程。

> **与既有文档的分工（不重复）**：
> - 本文档**不定义规则**。规则数值的设计值以《虚拟城市规则与经济系统》（下称《规则手册》）为准；

> - **版本**：v2.2（2026-10-22，批次 72 增补 §9.4：蒙特卡洛门禁 / 写盘 / R-E1·E2 / 运行历史）
> - **计价货币**：人民币（元）
> - **定位依据**：《虚拟城市定位声明-全Agent真实城市模拟器》v3.0 §6。
>
> **v2.0 重写说明**：删除全部游戏化度量（胜率、通关率、卡池抽到率作为「体验指标」、单周期墙钟时长、

## 1. 校准总纲：为什么模拟器需要校准与验证

### 1.1 两类校准

| 类型 | 含义 | 保证什么 | 现状 |
|---|---|---|---|
| **文献校准（静态）** | 参数锚定真实数据：统计局收支、LPR/CPI 区间、七级累进个税、五险一金费率、八类投资品风险收益 | 数值「不像假的」 | 已在《规则手册》与《真实世界经济与财商理论底座》完成 |
| **运行校准（动态）** | 全 Agent 真实决策下的涌现结果是否落在真实城市区间，且系统内部自洽 | 模拟「跑起来是真的、稳的、可复现的」 | **本文档负责** |

《知识库审计与去重报告_20260912》将「无任何运行实测记录」列为 G3 缺口；文献校准只能证明参数来源，
不能证明**十万级 Agent 交互后**宏观指标仍然收敛、账目仍然守恒、同一随机种子仍然给出同一结果。

### 1.2 核心原则

| 原则 | 说明 |
|---|---|
| **先验证机制闭合，再调参数** | α 阶段只问「守恒与结算对不对」，不问「数字漂不漂亮」；数值问题留到 β。 |
| **一切结论可复算** | 每条校准结论必须能追溯到一次带种子的运行记录，或蒙特卡洛的一次可复现抽样；禁止「我觉得」。 |
| **守恒优先于拟合** | 会计恒等式、劳动力恒等式、财政预算恒等式任一破裂，无论宏观指标多接近真实值，一律判失败。 |
| **反事实成对比较** | 参数改动必须用「同基线 + 同种子 + 只改一个参数」的成对运行判定，杜绝跨运行的口径漂移。 |
| **场景可复现** | 同一基线快照 + 同一场景 + 同一种子 ⇒ 指标轨迹逐月一致（允许浮点末位容差），否则预测报告不可引用。 |

## 2. 校准目标与九维验证指标

### 2.1 总目标

一次标准模拟周期为 **480 模拟月（20→60 岁人生轴，1 步 = 1 模拟月，见《规则手册》§1.2）**，
覆盖 2–6 个基准居民变体或全量居民池。周期结束时，以下三条必须同时成立：

- 至少 **60% 的居民**形成 ≥2 类资产的资产配置（不是「全员单一资产」的退化均衡）；
- **无单一投资品收益率长期跑赢其他品类 1.5 倍以上**（防模型内单一套利路径碾压）；
- 模拟内货币扩张倍数（D2）落在 **3.0–5.5 倍**区间。

### 2.2 九维验证指标

| # | 维度 | 指标定义 | 校准目标 / 阈值 | 测量方式 |
|---|------|---------|----------------|---------|
| D1 | **推进吞吐** | 每模拟月的服务端墙钟耗时（含 LLM 决策与结算） | 中位数 ≤ 设计预算；软渲染/离线批处理另计 | 运行日志 `step_ms` |
| D2 | **货币扩张倍数** | 周期末全体居民总资产 ÷ 周期初全体现金（名义扩张） | **3.0–5.5 倍 / 480 模拟月**；>7 倍触红线 | 期末聚合 |
| D3 | **阶层与结局分布** | 财务自由 / 小康 / 温饱 / 破产 四类结局占比 | 自由+小康 ≥45%，破产 15–30% | 期末分类 |
| D4 | **事件载体触发频偏** | 每类事件载体（原卡池）实际触发频次 vs 设计频次 | 偏差 ≤ ±25% | 事件流统计 |
| D5 | **破产率** | 触发《规则手册》§12 破产清算的居民占比 | **15–30%**；≥40% 触红线 | 破产事件记录 |
| D6 | **投资品收益率分布** | 8 类投资品的模拟年化收益率 | 任一品类持续 >30% 或 <3% 触红线 | 逐资产结算 |
| D7 | **居民主观福祉** | 模拟内问卷（满意度 / 压力 / 公平感 / 向上流动预期）分项均分 | 均分 ≥3.8（5 分制）；不可与客观指标严重背离 | 模拟内调研 |
| **D8** | **会计与流量守恒** | 资产 = 负债 + 净值；部门资金流量加总 = 0；税收集总额 = 入库额 | **误差 0**（分币级） | 每次月结自动校验 |
| **D9** | **确定性与可复现** | 同基线 + 同参数 + 同种子运行两次，状态哈希与指标序列是否一致 | 逐月状态哈希一致（浮点容差 ≤1e-9） | 双跑对拍 |

> **D8/D9 是模拟器区别于游戏的核心指标**：游戏可以「差不多」，模拟器不可以——
> 一次账目对不平或一次不可复现，就足以让该批结论全部作废。

### 2.3 为什么是这九维

- **D1** 决定可研究性：一次预测运行若跑不完，场景对比就无从谈起。
- **D2** 衡量货币与信用创造是否失控：过高=名义繁荣失真，过低=流动性死锁。
- **D3** 验证社会流动性结构不是退化分布（90% 破产或 90% 自由都说明模型失效）。
- **D4** 保证事件供给结构符合设计，既无「死事件」也无「霸屏事件」扭曲因果归因。
- **D5/D6** 是经济系统的两只手：D5 管尾部风险强度，D6 管单一资产是否成神。
- **D7** 校准主观层，避免「客观正确但人不像人」。
- **D8/D9** 是科学底线：守恒与可复现。

## 3. 三阶段校准运行：机制 → 参数 → 规模

### 3.1 阶段总览

| 阶段 | 代号 | 核心问题 | 样本量 | 运行画像 | 通过标准（Go/No-Go） |
|------|------|---------|--------|----------|---------------------|
| **α 机制闭合** | α | 结算算得对吗？守恒吗？流程会卡死吗？ | **≥15 次模拟运行** | 内部校准组 + 小型居民池 | ①单周期可完整推进至终局；②D8 守恒零错账；③无「必须临时改规则才能继续」的断点 |
| **β 参数校准** | β | 宏观指标落在真实区间吗？分布合理吗？ | **≥60 次模拟运行** | 分层抽样：入门 / 进阶 / 高净值各 1/3 | ①D2 落 3.0–5.5；②D5 破产率 15–30%；③D6 无品类持续 >30%；④D9 双跑一致 |
| **γ 规模与压力** | γ | 万级 Agent 扛得住吗？场景注入并发稳吗？ | **≥300 次运行**（含批量场景推演） | 全量居民池 + 多场景并行 | ①失败率 <1%；②D1 吞吐达标；③批量推演可复现；④注入审计链完整 |

### 3.2 α 阶段（机制闭合）细则

- **样本量下限 15 次**：须覆盖 2/3/4/5/6 个基准居民变体的不同组合，因为参与规模直接改变
  《交易经营》§2 交易窗口的撮合深度。
- **关键动作**：每次运行指定 1 名「流程观察员」，记录 S1–S7 七阶段（《规则手册》§1.1）的
  **实际耗时**与**异常点**；月结后逐项核对 D8。
- **No-Go 情形**：任一运行出现「必须发明一条新规则才能继续」，或出现会计恒等式不平，则不进入 β。

### 3.3 β 阶段（参数校准）细则

- **样本量下限 60 次**：按抽样统计惯例，60 次足以使单类投资品收益率分布的均值标准误 <2 个百分点
  （见 §6.2 统计功效估算）。
- **分层要求**：入门（18–25）/ 进阶（26–40）/ 高净值（40+）各 ≥20 次，避免「只被年轻人校准过」
  导致参数偏向激进型居民。
- **双盲埋点**：β 起全部数据由引擎自动埋点（见 §4），不依赖人工事后回忆。
- **成对切换**：同一周内对同一批运行轮换「旧参数 vs 新参数」（隐藏版本号），用 §6.3 的成对比较
  判断改动是否真的改善了 D3/D5/D6，同时用 D9 校验可复现性未被破坏。

### 3.4 γ 阶段（规模与压力）细则

- **样本量 300 次运行**：其中 ≥30% 为小规模居民池（评估冷启动偏差），≥20% 为极端场景推演
  （自然灾害 / 未知灾难，验证《场景推演》的注入链路）。
- **压测重点**：①月结与拍卖撮合在高并发下的延迟与错算；②事件载体组合（职业 18 类 × 投资品 8 类 ×
  市场周期 4 阶段）是否出现 D4 的「死事件 / 霸屏事件」；③场景注入后重跑同种子是否逐月一致（D9）。

## 5. 回归不变量与红线清单

> **红线 = 触发即冻结当前参数版本、必须回炉重校的硬指标。** 下表阈值为初始设计建议值，
> 经 α 阶段实测后在 §7 回填为正式值。不变量（R-I）无条件成立，经济阈值（R-E）为区间判定。

### 5.1 守恒与结算不变量（无条件）

| 规则 | 不变量 | 触发后的动作 |
|------|--------|-------------|
| **R-I1** | 每笔交易后 `资产 = 负债 + 净值`，分币级零误差 | 立即中止该次运行，定位结算函数，修复前禁止进入下一阶段 |
| **R-I2** | 每次月结后部门资金流量加总 = 0（工资/税/社保/利息/分红闭环） | 同上；常见根因是漏记某类转移支付或税收入库 |
| **R-I3** | 财政侧 `收入 − 支出 = 结余`，结余入账不得凭空生成或消失 | 同上；检查重建支出与场景注入的直接损失是否重复计账 |
| **R-I4** | 劳动力侧 `就业 + 失业 = 劳动年龄人口`，迁移进出须守恒 | 同上；检查场景灾害伤亡/迁移是否同步扣减 |
| **R-I5** | 同一 `seed` 双跑逐月状态哈希一致（浮点容差 ≤1e-9） | 判定不可复现缺陷；禁止在 LLM 决策路径引入无种子随机 |
| **R-I6** | 场景注入必须完整留痕并可回放（注入记录 + 种子 + 基线快照） | 缺任一要素的预测报告不得引用 |

### 5.2 经济阈值红线

| 规则 | 阈值 | 触发后的动作 |
|------|------|-------------|
| R-E1 | **某投资品模拟年化收益率持续 >30%**（连续 10 次运行均值） | 该品过强，**削弱**：下调其景气期收益率一档或提高入手门槛 |
| R-E2 | 某投资品模拟年化收益率 <3%（连续 10 次运行） | 该品是「死资产」，**增强**：增加其非货币效用（人脉 / 认知补偿）或降低入手价 |
| R-E3 | **货币扩张 D2 >7 倍** | 信用创造失控：发薪/分红总和 > 系统回收（税/支出/损失），调高税率或生活成本增速 |
| R-E4 | 货币扩张 D2 <2 倍 | 流动性死锁：降低优质资产入手门槛或缩短衰退期 |
| R-E5 | **破产率 D5 >40%** | 初始资源/容错过低，**上调初始现金或延长新手保护期**（v2.58 P2-09 已有前 3 个月禁复杂衍生品） |
| R-E6 | 破产率 <8% | 破产线形同虚设，尾部风险失真 → 收紧信用评分 / 缩短宽限期 |

### 5.3 分布与响应红线

| 规则 | 阈值 | 触发后的动作 |
|------|------|-------------|
| R-B1 | 初始位次（第一个行动的居民）良好结局占比 > 其他位次均值 +15pp | 顺序偏差过大，给后手补偿性初始资源或把起点设为中性 |
| R-B2 | 某职业画像（P01–P18）良好结局占比偏离全体均值 ±20pp | 该职业收入/风险画像失衡，回填《规则手册》§10 |
| R-B3 | 拍卖参与率中位数 <30% | 拍卖机制没人用（《交易经营》§4），改为强制触发或降低参与成本 |
| R-B4 | 某类事件载体触发频偏 > ±50% | 死事件（<50% 设计频次）或霸屏事件（>150%），调整权重 / 增删条目 |
| R-B5 | 偏差事件触发后居民「事后仍认为自己是对的」比例 >60% | 偏差机制未生效或复盘话术未击中，调整《行为金融》§5 话术 |
| R-B6 | 场景注入的直接冲击 3 个月内衰减 >90%（应持续更久的场景） | 传导链断开，检查对应子系统是否真正接收了注入参数 |

### 5.4 阈值使用示例（决策树）

若 D5 破产率 = 45%（>40% 红线 R-E5）

## 6. 数值校准方法：蒙特卡洛 / 敏感度 / A-B 对照

### 6.1 蒙特卡洛参数扫描

用于在**不消耗线上算力**的前提下粗筛参数。Agent 引擎天然可跑批量模拟。

| 参数 | 取值 | 说明 |
|------|------|------|
| 单次配置样本 | **1,000 次运行 / 配置** | 对齐 v2.58 P1-09「1000 次蒙特卡洛复盘」 |
| 居民决策原型 | 5 种（《总体设计》§10.2 保守/激进/社交/学习/谨慎）按真实人群比例投放 | 30%/17%/17%/22%/14%（对齐《行为金融》v1.3 画像分布） |
| 随机种子 | 固定种子集 + 每配置重复 10 个种子 | 保证可复现并可估计种子方差 |
| 输出 | D1–D6 六维指标的分布（中位数/P25/P75） | 输入《规则手册》§7.4 周期参数扫描 |
| 用途 | **在 β 之前**筛掉明显失衡的参数配置，线上运行只校验通过的 2–3 个候选 | |

### 6.2 敏感度分析

一次只动一个参数（同基线 + 同种子配对），观察 D3/D5/D6 的响应，找出「杠杆点」。

| 被调参数 | 扫描范围 | 观察指标 | 预期敏感度方向 |
|---------|---------|---------|---------------|
| 股票景气期收益率（现 +10%，见《总体设计》§8.3） | 5% / 10% / 15% / 20% | D6 股票收益率、D3 分布 | 越敏则股票越易成神 |
| 初始现金 | ±20% | D5 破产率 | 直接对应 R-E5 |
| 衰退期持续月数（现 2–4 年） | 1/2/4/6 年 | D2 扩张倍数、D6 | 越长则积累段越苦 |
| 个税起征档距（现 7 级累进） | 档距 ±20% | D7 公平感、高净值结局占比 | 高净值线敏感 |
| 偏差事件触发阈值（如连赢 3 次） | 2/3/4/5 次 | 偏差触发次数、NEG-3 占比 | 阈值越低触发越密 |
| 场景强度映射系数（L1–L5 → 冲击幅度） | ±30% | 场景响应的单调性与饱和度 | 用于校准《场景推演》的强度分级 |

**方法**：每个参数取 4 档 × 1000 次 = 4000 次运行，画「参数—指标」曲线；曲线最陡的参数即
「杠杆参数」，校准运行时人工重点盯防。

### 6.3 成对对照（A/B）设计

用于确认参数改动方向：

| 要素 | 规定 |
|------|------|
| 分组 | 同一种子集配对执行「旧参数 vs 新参数」，交叉设计抵消种子偏差 |
| 最小样本 | 每组 **≥20 次运行**（使破产率差的统计检验功效 ≥0.8，α=0.05） |
| 主指标 | 先看 D5 破产率与 D6 收益率差；D7 主观分作护栏（不得因调参把主观福祉打下来） |
| 显著性判定 | 两比例用卡方检验；收益率均值用 t 检验；p<0.05 才认定改动有效 |
| 护栏 | 任一组出现 R-I* 不变量破裂或 D2 越界，立即中止该组 |

## 8. 数据治理与复盘流程

### 8.1 一次运行一闭环（结束后 24 小时内）

1. 运行级 + 居民级采集表由引擎自动生成（埋点缺失视为运行无效）。
2. 观察员对照 §4.4 给每位居民打结局成因分类。
3. 若触碰任一 §5 红线或不变量，自动生成「校准警报工单」，48 小时内召开设计评审。

### 8.2 阶段汇报（每 20 次运行一次）

- 出一张**仪表盘**：D1–D9 当前均值 vs 目标区间 + 最近 5 条红线事件 + 不变量通过率。
- 决策：Go（进下一阶段）/ Iterate（回炉调参）/ Hold（数据不足，继续跑）。

### 8.3 防数据自欺

- **避免幸存者偏差**：未跑完的运行（中途失败/超时）也必须记录，不能只统计成功的运行。
- **避免观察者效应**：居民 Agent 不得感知「自己正在被校准」，校准侧只读埋点，不向 Agent 注入提示。
- **数值不可回改**：一经回填《规则手册》，旧值只入变更日志，不在文档正文覆盖。
- **报告可追溯**：所有对外引用的指标必须标注 `run_id + seed`，无法追溯的数字不得进入结论。
