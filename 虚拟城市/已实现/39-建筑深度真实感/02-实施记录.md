## 4. 与方案的偏差（含**方案自身被推翻**的部分）

| # | 方案原定 | 实际落地 | 理由 |
|---|---|---|---|
| **D1** | B1.3 用 `map.offset` 做逐区打散 | 改**打在几何 UV**（`districtFacadeUvOffset`，整数周期） | 贴图经 `textureCache` 按 url 共享，同族 3 区是**同一个 `THREE.Texture` 实例**，写 `.offset` 是全局副作用、会被最后挂载者覆盖；`clone()` 在 three r169 下按 Texture 对象分配 `__webglTexture`（`source` 只共享解码）⇒ 32 区各克隆 = 显存翻倍。几何 UV 天然逐区独立，且 `map` 与 `emissiveMap` 共用同一套 UV ⇒ 遮罩与窗格**天然对齐** |
| **D2** | C2 给定具体楼高公式 | 改「对称 + clamp」：`clamp(round(nominal + span·0.25·(2fn−1)), minF, maxF)` | 方案式无 clamp，finance 满繁荣度算出 24 层（72 m），**越出 `DISTRICT_FLOORS` 明写的 8–20 层**；且方案式按旧 factor 区间 [0.6,1.0] 归一，新区间是 [0.55,1.0] |
| **D3** | C1 只加 `u(0.3)` 净距判定 | `SLOTS_PER_SIDE` **4 → 3**（中心距 1.8→2.7 u） | **方案自身算错了**：槽位中心距 1.8 u 而楼宽 1.5–1.9 u + jitter ±0.15 ⇒ **同街墙相邻楼必然重叠**。`MIN_GAP` 从 0.03 逐档放宽到 0，楼数恒 180（0.03/0.02/0.01/0 各跑一次），证明瓶颈是槽位间距而非 margin 口径。保住 `w∈[1.5,1.9]` 合同（`w>1.4` 的 `hasBillboard/useSaw` 一致性 = 材质签名归并 = draw call 控制） |
| **D4** | C1 不应导致楼数跌破下限 | 9 个区 < 4（基线本就 8 个） | **未静默放宽任何 margin**。基线交叉验证：`{suburb, riverside, logistics_port, hightech_park, industrial_park, central_park, cultural_creative, airport_town}`；本批次重合 7 个、增 `transport_hub`(5→3)/`software_park`(4→3)/`old_city_culture`(4→3)。成因是 keep-out（水域/主路/一环），非 C1 |
| **D5** | A3 只给塔冠顶加压顶 | tower 与 **slab 都加** | 真实城市所有平屋顶女儿墙顶都有压顶收头；只改一处 = 两种平屋面收头不一致，一眼看出「只改了一处」。**shed 不加**（锯齿顶的檐口收边是**檐沟**不是女儿墙，加压顶反而不符合厂房做法） |
| **D6** | A3 判据对 `roofs` 用「四边像素差 < 2/255」 | 改**按族两指标**：① 逐点相等（`facade_tiles`）② 统计无缝 P99 比 ≤1.10（`roofs`） | 判据 ① 测「首末列**逐点相等**」，比可平铺**更严** —— 碎石/斑块这类逐像素随机场在 x=0 与 x=W−1 是**两次独立采样**，逐点差必然 >2/255，**与是否可平铺无关**。首跑即 33/144 全族翻红 = 假警报。`facade_tiles` 行为逐位不变 |
| **D7** | A1 交付后 `ROOF_TILE` 立即升 1024 | 前端 agent 一度**拒绝**改登记值 | 判据正确：改登记时磁盘仍是 512² 占位图，会与磁盘不符。**art39 重出后**才改 —— 顺序对了 |
| **D8** | 阶段 A/B 由一个 frontend agent 做完 | 拆两个（阶段 A+B / 阶段 C） | `building_shapes.tsx` 两者都改，并行会撞写集；串行由我控制 |

## 6. 流程教训（新增）

1. **seam 判据必须按贴图类分**——「首末像素逐点相等」对低频开间纹样是对的，对逐像素随机场**在构造上恒失败**。造一个永远红的门禁 = 没有门禁。判据选错比资产坏更危险，因为它会诱导人放宽阈值。
2. **法线图的无缝性来自二阶导，不是高度场**——本批次 5 张法线超阈时，高度场实测完全无缝（① 0.07/255、② 1.00），泄漏 100% 来自 Sobel 对满铺碎石（15.6 mm 粒径）的二阶放大。修法是**对高度场做环面感知的预平滑**（σ≈1.25 px）再取梯度，而非调阈值。
3. **共享 `THREE.Texture` 上的 `.offset` 是全局副作用**——`textureCache` 按 url 共享贴图，同族多个城区拿到的是**同一个实例**；想「逐区差异化」必须打在**几何 UV** 或付出显存翻倍（`clone()` 按 Texture 对象分配 GPU 存储）。
4. **headless 后台页的 rAF 被节流到 ~1fps**——`renderer.render` 包装后若不泵帧，`H.camera` 恒 null，机位 patch 抛 `Cannot read properties of null (reading 'clone')`。对策：cam patch 后立刻泵 3 帧，并在 apply 失败时泵帧重试。
5. **时刻冻结会被 `game.state` 帧覆盖**——`setCityClockAnchor(..., ratio=0)` 冻结后实测 **1 秒内** 0.915 → 0.765 被回写。单次注入 + 快拍不够，须用 `setInterval` **持续重锚**直到截图完成。
6. **CDP 合成截图拍的是整页**，3D 视口只占左侧约 2/3，且 y>880 被底部 UI 遮挡 ⇒ 街景贴脸机位要**把目标点压到 y≈0.4**（楼底）才看得见首层。
7. **「楼层数」这类中间量必须抽成导出函数**——`buildingTopY` 与 hover 提示的楼层数原本各写一份 `Math.round(minF + (maxF-minF)*prosperity)`，改楼高公式时必然漂移。抽 `buildingFloorsOf()` 后 `buildingTopY` 缩为一行，§130 在数据侧的等价形态被消除。
