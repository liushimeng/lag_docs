## 1. 为什么是建筑

建筑是虚拟城市**占屏面积最大**的物体：默认俯瞰机位下建筑剪影 + 立面 + 屋顶合计覆盖
画面 60% 以上。审计在建筑这一类物体上找到 **30 条缺口**，其中 **9 条「大影响」**，
且多数为「资产占位 / 接线缺失」而非「需要新架构」——投入产出比最高。

同时，建筑审计暴露的三条事实构成本批次的核心论点：

| 事实 | 证据 | 为什么致命 |
|---|---|---|
| **16 张屋顶贴图是纯色占位块 + 4 字母水印** | `roofs/finance.png` 512² 像素里只有 **245 种颜色**（实测）；`industrial_park` **101 种**。生成器 `generate_virtual_city_city_assets.py::placeholder_roof()` 只画一块 `PLACEHOLDER_COLORS` 底色 + `f"{district_id[:2]}RF"` 文字 | 屋顶是俯瞰视角下的**主表面**。一块带 "fiRF" 水印的纯色板铺满全城屋顶，是任何玩家一眼能识破的「未完成」信号 |
| **夜间屋顶连水印一起发暖光** | `building_shapes.tsx:254-271` `topMatProps`：`emissiveMap: tex` = 屋顶 albedo 自发光 | 夜景里全城屋顶是发光的 "fiRF" 文字块 |
| **建筑立面不接收阴影** | `DistrictBuildings.tsx:281` 墙 mesh 只有 `castShadow` 无 `receiveShadow`；`:284` 点缀 mesh 显式 `receiveShadow={false}` | 楼与楼之间没有遮蔽、楼自身没有自遮挡、晨昏没有长影 ⇒ 整城建筑的立体感缺失（几何明明是对的） |

## 3. 阶段 A · 屋顶

> 判据：俯瞰/斜俯视截图里，**看不到任何纯色块与文字水印**；屋顶有可辨认的屋面材料质感。

### A1 · 16 张屋面贴图程序化重出（art-designer）

**现状**：`roofs/<stem>.png` 16 张 512²，全部来自 `placeholder_roof()`（纯色 + "xxRF" 字样），
法线/粗糙度 `pbr/roofs/<stem>_{n,r}.png` 同样是占位（法线 = 纯紫全平）。

**修法**：新建 `python-generate-image-tool/generate_virtual_city_roof_assets.py`，
**纯 Pillow + numpy 程序化生成、零网络、固定 seed 可复现**（范式对齐批次 38 的
`generate_virtual_city_water_assets.py`，复用同目录 `road_texture_utils` 的
`periodic_noise` / `fbm` / `sobel_normal` / `save_rgb`）。

**关键约束**——**不是 16 张互不相干的图，而是 6 个屋面材料族**（真实城市屋顶就那么几种）：

| 族 | 基色 | 表面特征 | 成员 stem |
|---|---|---|---|
| `bitumen_gravel` 深灰卷材+碎石 | 深灰 | 搭接缝格 + 均匀碎石颗粒 + 2 个雨水口 | finance / tech / commerce / medical_city / riverside / hightech_park / cultural_creative |
| `light_concrete` 浅灰混凝土屋面 | 浅灰 | 伸缩缝分格（6 m 格）+ 细麻面 | residential / oldtown / edu_district / transport_hub / suburb |
| `standing_seam` 锌板压型金属 | 锌白 | 竖向立缝凸棱（0.6 m 间距）+ 横向搭接 | industry / industrial_park / logistics_port / air_logistics |
| `colored_metal` 彩涂钢板 | 蓝/绿/红 | 立缝 + 轻微色差条带（每条泛光不同） | sports_new_city / highspeed_rail_town / university_town |
| `green_roof` 种植屋面 | 土绿 | 植被斑块（低频）+ 砾石步道网格 | central_park / wetland_park |
| `pv_array` 光伏屋面 | 深蓝黑 | **光伏板阵列**：等距板列 + 板间缝隙 + 组件边框 + 检修通道 | tech / hightech_park（与 bitumen 叠：板列压在深灰底上） |

> 族内 16 个 stem 由**同一族函数 + 每 stem 独立 seed 变体**产出 ⇒ 观感成族但无重复感。

**分辨率与周期**（进 `texScale.ts` 登记表 + `audit_texture_fit.py` 判据 A1/A2/A5）：

```
roofs/<stem>.png            1024×1024   周期 10 m × 10 m  ⇒ 102.4 px/m ✅ 入 60–120 带
pbr/roofs/<stem>_n.png       512×512    同周期（比例 1:1，不变式成立）
pbr/roofs/<stem>_r.png       512×512    同周期
```

不变式 `tileMetersU/tileMetersV === texW/texH` = `10/10 === 1024/1024` ✅。
`ROOF_TILE` 常量由 `512/10 m` 改为 `1024/10 m`（只改像素数、不改物理周期 ⇒
纹素密度从 51.2 提到 102.4 px/m，B21 闭环）。

**体量纪律**（批次 37 返工 R1 的教训）：**出图后先实测单张字节**，若 16 张合计 > 24 MB
则法线/粗糙度降档 512²→256²（仍满足比例不变式），并在实施记录里写明实测值。
预估：程序化屋面噪声中等，1024² 单张约 1.0–1.8 MB，16 张约 16–29 MB。

**无缝硬判**：四边像素差 < 2/255（判据 A3），由生成器末尾自检并打印，不吞。
`pbr/roofs/*` 加入 `A3_FAIL_TILES` 硬判集（原为 advisory）。

### A2 · 顶面材质去自发光

`building_shapes.tsx::topMatProps` 删除 `emissive` / `emissiveMap` / `emissiveIntensity`
三项 —— 屋顶在任何时刻都不该自发亮。连带效果：B2（夜间隔夜发光的 "fiRF" 水印）闭环。

### A3 · 女儿墙 / 压顶 / 屋顶设备补齐

| 位置 | 现状 | 修法 |
|---|---|---|
| 塔身顶（退台面） | 无护栏，`podiumRailAccent(w,d,pH)` 误用 podium 尺寸 ⇒ 栏杆与裙楼女儿墙穿插（B30） | 改传塔身尺寸 `w*0.8/d*0.8` 且 y 移到 `pH+bodyH` |
| 塔冠顶 | 裸 BoxGeometry，无女儿墙/压顶 | 加 `parapetAccent(w*0.55, d*0.55, pH+bodyH+cH)` + 压顶线脚 |
| 塔冠顶设备 | 仅 2 件小圆柱孤立中央 | 加设备平台（格栅板）+ 检修马道 + 天线（按 stem 分高度） |
| slab/house/shed 顶 | slab 有；house/shed 坡屋顶无需 | 保持 |

女儿墙高度沿用 `u(0.9)` = 0.9 m（真实规范 0.9~1.2 m，合规），压顶为女儿墙顶加宽
`t + u(0.06)` 的薄挑檐。

### A4 · 屋顶杂物锚点归位

`StreetPropsLayer.tsx:334,343,357` 的 `roofY = buildingHeight((minF+maxF)/2)*0.9` 与
真实楼顶无关联（审计实测：finance 繁荣度 0 时悬空 14 m）。改为调用
`cityScale.buildingTopY(districtId, prosperity, factor)`（渲染与碰撞体同源，批次 32 已立此约定），
并把**该栋楼自身的 `factor`** 传进去（需在布局结果里带出 `spec.factor`，B13 闭环）。

### A5 · 坡屋顶改走独立瓦面贴图

现状：`case 'prism'` 里 `eff = ctx.roofMap ? ctx.roofPbr : synth` —— 坡屋顶优先吃**平屋顶**
贴图，于是红瓦色屋顶被贴上深灰卷材纹理。修法：`prism` 一律走
`ctx.tilePbr` / `ctx.metalPbr`（synth 瓦面/金属面），`roofMap` 只服务 `top` 面。

> 注：synth 瓦面是程序化 PBR 材质（`useSynthPBR`），本批次不为其新增贴图资产 ——
> 避免 A 阶段同时引入「平屋面新贴图」与「新瓦面贴图」两套未验收资产。

### A6 · 米制字面量收口

`building_shapes.tsx:827`（檐口 `0.05`）、`:921`（挑檐 `0.04`）、`:859`（坡顶 `+0.12`）
三处世界单位裸值改走 `u()`，与批次 30「禁止把世界单位当米用」纪律对齐。

## 4. 阶段 B · 立面

> 判据：夜景截图中**只有窗发光、墙面不发光**；斜阳下墙面出现楼间阴影；
> 逐栋放大后楼层线与窗格行对齐。

### B1 · 独立亮窗遮罩（`emissiveMap` 换源 + 逐区 UV offset）

**现状**：`emissiveMap: tex`（= albedo）。整个墙面含窗间墙、贴图里画好的空调外机、
晾衣绳一起发光；同材质族全城共用一张图 ⇒ 亮窗分布完全一致；`prosperity=0` 时基准为 0
⇒ 夜全黑（B3/B4/B5）。

**修法**：

1. **art 侧**：`generate_virtual_city_facade_tiles.py` 增开 `_lit` 产物
   —— `facade_tiles/<family>_lit.png`（512×1024，与 `_base/_mid` 同周期 6 m × 12 m），
   语义为「窗玻璃亮灯遮罩」：玻璃区域按确定性随机取 0 / 暖黄 / 暖白三档，
   **墙面/窗间墙/装饰件一律纯黑**。法线/粗糙度不需要（自发光不吃 PBR）。
2. **前端侧**：`sideMatProps` 的 `emissiveMap` 由 albedo 改指 `_lit`；
   `emissive` 颜色由 `EMISSIVE_WINDOW` 改为随档位读取（遮罩自身带色即可，省一套 uniform）。
3. **逐区打散**：材质 UV 共享 ⇒ 用 `map.offset` 的**逐区确定性偏移**让同一张遮罩
   在不同城区落在不同窗格上（周期 6 m × 12 m，偏移取该区 seed 的 6 个相位组合）。
   这是**零额外资产**拿到「每区亮窗不同」的关键手法。
4. **入住率下限**：`emissive = max(0.06, min(0.35, prosperity*0.35))` ——
   繁荣度 0 的萧条城区仍有零星灯光（真实城市夜间从不全黑），B5 闭环。

### B2 · 立面接收阴影

`DistrictBuildings.tsx:281` 墙 mesh 补 `receiveShadow`；`:284` 点缀 mesh 由
`receiveShadow={false}` 改 `true`（点缀件已 `castShadow` 自投影，收阴影后楼角/雨棚
会正确压暗）。**一行级改动，立体感提升最显著的一条**（审计标注影响「大」）。

> 风险：阴影贴图 4 帧一更（批次 28 性能约定），立面收阴影后可能出现轻微滞后。
> 实测为准，若肉眼可见拖影再议分「静态/动态两套阴影贴图」。

### B3 · 楼高对齐层高（消除楼层线错位）

**现状**：`floors = minF + (maxF-minF)*prosperity`（浮点）→ 楼高非 3 m 整数倍；
立面贴图 12 m = 4 层，楼层水平线从 `y=0` 起 ⇒ 永久错位、顶部一行窗被腰斩。

**修法**（`cityScale.ts::buildingTopY` 内，**渲染与碰撞体同源改**，不新增第二公式）：

```ts
const floorsRaw = minF + (maxF - minF) * prosperity;
const floors = Math.max(minF, Math.round(floorsRaw));   // 取整 ⇒ 楼高 = 3 m 整数倍
return buildingHeight(floors) * (0.85 + factor * 0.15);
```

⚠ **但** `0.85 + factor*0.15` 仍是非整数缩放，会重新引入错位。故 B3 与 C2 合并实施：
C2 把该系数改为**对齐 3 m 的层数增量**（见下），一次性保证
`buildingTopY ≡ FLOOR_HEIGHT_M × 整数层数`。

### B4 · 三张内容错误的立面贴图修正（art-designer）

| 文件 | 缺陷 | 修法 |
|---|---|---|
| `facade_tiles/office_panel_mid.png` | 贴图**顶部画了一根屋面天线**，随 12 m 周期每 4 层重复一次 ⇒ 办公楼每 4 层墙上长一根天线 | 生成器去掉天线；天线只作为几何放楼顶（A3） |
| `facade_tiles/oldtown_tile_mid.png` | 贴图**顶部是一条坡屋顶檐口**，每 12 m 重复 ⇒ 每 4 层墙面上出现假屋檐 | 同上，檐口只作为几何 |
| `facade_tiles/cbd_glass_{base,mid}.png` | `base` 无首层商业（与「裙楼商业基座」语义矛盾）；一个 3 m「层」带内画 4 排玻璃 ⇒ 实际窗距 0.75 m，层高语义失效 | 改为「每层 1 排窗」；`base` 的底层 3 m 带改为落地玻璃幕墙 + 雨篷阴影 |

同时把 `facade_tiles/*_lit.png` 纳入 `pbr/` 之外的新目录约定（不与 PBR 三件套混放）。

## 5. 阶段 C · 体量

> 判据：全城无楼体互相穿插；同区天际线有明确高低差；每栋首层商业朝街、背街面无门。

### C1 · 楼-楼间距判定

`building_layout.ts::slotBuildable` 增加**楼-楼 AABB 不重叠**判定：新增一个
`rectsOverlap` 纯函数，按已接受的候选集逐个判（楼数 8~14，O(n²) 完全可接受）。
最小净距取 `u(0.3)` = 3 m（真实防火间距远大于此，但楼群贴街墙排布，3 m 净距
足以消除可见穿模且不至于把楼数砍到不足）。

- 与既有 keep-out 一致：判定不通过**丢弃该槽位、不递补**（批次 38 口径），
  楼数下限 `< 4` 时走既有的 `KEEP_OUT_MARGIN_RELAXED` 兜底 + `console.warn`。
- **验收**：`buildingsFor` 全 32 区跑通，楼数不跌破 `MIN_BUILDINGS`；
  场景审计确认 0 对楼体重叠。

### C2 · 楼高分布改幂律

现状 `0.85 + factor*0.15`（factor∈[0.6,1.0]）⇒ 同区 11 栋楼高差 **≤6%**，天际线齐平。

修法：`factor` 改由**幂律采样**产生（`factor = 0.55 + 0.45 * rnd()^2.2`，
多数楼偏低、少数楼拔高），并把缩放系数改为**层数增量**口径：

```ts
// cityScale.ts
const floorsBase = Math.max(minF, Math.round(minF + (maxF - minF) * prosperity));
const floors = Math.max(minF, Math.round(floorsBase + (maxF - minF) * 0.35 * (factor - 0.6) / 0.4));
return buildingHeight(floors);
```

⇒ `buildingTopY` **恒为 3 m 整数倍**（B3 由此自动闭环），
且同区楼高按 factor 拉开到 `minF+0` ~ `minF+0.35*(maxF-minF)` 的跨度 ——
finance（8~20 层）最高与最低相差 4 层 ≈ 12 m，肉眼可见的天际线。

> ⚠ **`factor` 语义变更须同步**：`buildingTopY` 是渲染与 `freeViewColliders` 碰撞体的
> 单一事实来源（CLAUDE.md §130），改它必须两侧同时生效 —— 因为只改了这一个函数，
> 两侧自然同源，**无需额外接线**。但布局侧 `buildingsFor` 产出的 `factor` 分布要同步改
> （否则 0.55~1.0 反而使低factor 楼更矮，跨度方向反了）。

### C3 · `base`/`mid` 按临街面重分配

现状 `sideA`(±X) 恒拿 `facadeBase`（含首层商业），`sideB`(±Z) 恒拿 `facadeMid`；
但街墙布局里南北边楼（`faceX=true`）的**临街面是 ±Z**，东西边楼的临街面是 **±X**
⇒ 一半的楼「首层商业朝街区内部、背街面无门」。

修法：`BuildingSpec` 增加 `streetAxis: 'x' | 'z'`（布局层已知：南北边 → `'z'`，
东西边 → `'x'`），透传到 `buildBuildingParts`，由它决定哪个材质索引挂
`'A'` 面（±X）还是 `'B'` 面（±Z）。**不新增材质、不改 draw call 签名结构**。

### C4 · 底层构件归位 + 高度自适应

| 项 | 修法 |
|---|---|
| 门 / 门框 / 雨棚 / 底商雨棚 + 灯带 | 全部按 `streetAxis` 挂到**同一个临街面**（现状门在 +Z、底商在 −Z，永不同面） |
| 高度自适应 | 门高 `min(u(2.4), 0.62 * bodyH)`、雨棚 y `min(u(2.6), 0.75 * bodyH)` —— 郊区 2.8 m 楼不再长出穿屋顶的门（B11） |
| 塔楼裙楼 | `podiumRailAccent` 尺寸口径随 C3 同步 |

### C5 · 建筑基座 / 勒脚

建筑 box 底面 y=0、区底板 y=0.010 ⇒ 基座被埋 10 cm，无勒脚。
加一圈 `u(0.35)` 高、`u(0.08)` 出挑的基座带（沿四边），贴地过渡到建筑本体。

## 7. 明确不做

| 项 | 理由 |
|---|---|
| 人物 / 车辆 / 交通 / 地面铺装的任何改动 | 本批次主题是「建筑」这一种物体；四路审计给出的 G-1~G-31 与地面 G1~G12 全部转入后续批次候选池 |

| 立面贴图 32 张全量重画 | 本批次只修 3 张**内容错误**的（天线/假檐口/窗距），其余保持 |
| 引入 CSM / 阴影贴图分块 | 属渲染管线批次 |
