## 3. R1 · 速度倍率档（Shift 切换 ×1…×16）

### 3.1 语义变更

| | 旧（批次 32） | 新（批次 34） |
|---|---|---|
| 档位表 | `[0.25, 1, 4]` | `[1, 2, 4, 8, 16]` |
| `Shift` | **按住**临时 ×4 | **按一次**切到下一档，回绕 |
| `[` / `]` | 步进夹取 [0,2] | 步进**回绕**（X16→X1 / X1→X16） |
| HUD | 显示档位值，**不含 Shift** | `速度 ×N` 与真实移速**恒等** |
| 存储 key | `engine3d.freeView` | `engine3d.freeView.v2`（旧下标语义不兼容，整体作废） |

基础移速不变：fly 20 m/s、orbit pan 10 m/s（`VirtualCityCityMap.tsx:186/188`）。
⇒ 全域 20 ~ 320 m/s，与旧上限（4×4×20=320）**跨度零回归**。

### 3.2 为什么换 key 而不是迁移

旧下标 `1` = ×1，新下标 `1` = ×2。迁移映射会误伤「新用户刚选 ×2」的场景，
而旧值丢失的代价只是重选一次视角模式 + 速度档。**换 key 优于错误映射。**

### 3.3 速度自适应 FOV 的归一化修正

`computeFov()` 旧式 `fast = vel / (base * tier * 4)` 是拿当前档移速当分母
⇒ 多档位下恒 ≈1，增益失效。改为固定分母 `base × MAX_TIER`（= base×16），
X1 几乎不涨、X16 顶满 `fovSpeedGain`，五档之间才有梯度。

## 4. R2 · 路灯夜间发亮（3D 渲染支持）

**方案：伪光三件套**（辉光 + 光锥 + 地面光池）+ emissive 提亮。
**不做真实 `PointLight`** —— 261 盏点光会击穿前向渲染光照预算且不可投影；
additive 伪光是批次 30 窗灯/车灯已验证的等效做法。

| 层 | 实现 | 成本 | 昼 | 夜 |
|---|---|---|---|---|
| ① 灯头 emissive | 已有 `meshStandardMaterial.emissive` | 0 | 0.12 | **3.4**（旧 2.2） |
| ② 灯头辉光 | **新增** `THREE.Points` + radial 贴图，additive，永远朝向相机 | **1 DC** | 0 | 0.85 |
| ③ 光锥 | **新增** 开口圆台 `Instances`，自灯头向下张开，纵向渐隐贴图，additive | **1 DC** | 0 | 0.16 |
| ④ 地面光池 | 已有 radial 面片 additive | 1 DC | 0 | **0.72**（旧 0.55），⌀ **10 m**（旧 8 m） |

辉光用 `THREE.Points` 而非 billboard 面片：**1 个 draw call 合批全部灯头**，
且 Points 天然朝向相机，无需逐帧更新 quaternion。
昼夜驱动沿用 `cityTimeStore.getDayNight().dayFactor01` + 指数平滑（时间常数 ~0.5 s），
四层共用同一 `k = min(1, delta*2)`，避免层次间相位错开。

光锥若在验收截图中显脏（穿模/抢戏/糊），**降级为仅保留 ①②④**，并在实施记录登记。

## 6. R6 · 人流分布（非线性公式 + 布点 + 换班）

### 6.1 户外/户内非线性公式

记房间 `resident_count = N`，**同时在街上可见人数** `V(N)`：

```
V(N) = min( CAP_q , N , ceil( N0 · (N / N0)^γ ) )

N0 = 100          // 「人少就都上街」的拐点
γ  = 0.45         // 次线性指数（0<γ<1 ⇒ 越多人、人均上街概率越低）
CAP_high = 110    // 高画质档全城行人上限（沿用批次 28，见下方「为什么不上调」）
CAP_low  = 60     // 低画质档（批次 28 A4 口径）
```

**验证关键点**：

| N | `ceil(100·(N/100)^0.45)` | `V(N)` | 户内 `N−V` | 说明 |
|---|---|---|---|---|
| 10 | 36 | **10** | 0 | 全部上街 ✓（用户 R6 原文） |
| 50 | 73 | **50** | 0 | 全部上街 ✓ |
| 100 | 100 | **100** | 0 | 全部上街 ✓（拐点） |
| 400 | 187 | **110** | 290 | 触顶画质上限 |
| 1 000 | 376 | **110** | 890 | 触顶 |
| 10 000 | 1 259 | **110** | 9 890 | 触顶 |
| 100 000 | 3 981 | **110** | 99 890 | 触顶 |

次线性体现在 **N 从 100 → 1000（×10）时理论户外人数只 ×3.76**，
且最终被画质上限截断；`N ≤ 100` 时恒 `V(N)=N`，严格满足「人少就都在外面」。

`γ = 0.45` 取值依据：真实城市「上街人口 / 常住人口」随城市规模近似幂律衰减
（大城市的通勤/居家比例更高）；0.45 让 100→1000 之间仍能观察到「街上变挤」，
又不至于在 400 人房就把画质上限打满。**可调参数**，实施记录须给出截图对照。

> ⚠️ **为什么 CAP 不上调到 160**：行人**不实例化**（每人一个 GLB clone +
> AnimationMixer，批次 28 §1.1 A5），抬到 160 约多 100 DC，而默认视角 DC 已经
> 超预算（实测 ~2230 / 目标 1500）。110 仍严格满足用户 R6（N ≤ 100 全上街）。
> 若后续行人改实例化（需 `SkeletonUtils.clone` 蒙皮专项），再回来抬 CAP。

### 6.2 初始化位置（确定性，禁 `Math.random`）

居民 `district`（0..31）是**权威归属**（锚定时由人物卡 `HomeDistrict` 映射，
或合成时按 `domainCum`/`districtCum` 分布抽样）。布点规则：

1. 对每个「上街」居民 i，用 `seed = hash(roomSeed, churnTick, i)` 派生确定性 PRNG；
2. 在其 `district` 底板上采样一点：**60% 落在人行道带**（沿该区道路网线段法向偏移
   1.2~2.4 m），**40% 落在公共场所**（广场/公园/滨河等该区 `publicSpots`）；
3. 拒绝采样：落在建筑 footprint 内、落在水面/绿化隔离带内（最多 6 次重试）；
4. `path` 折线 2–3 段、总长 **1.5~3.5 世界单位**（= 15~35 m，与 `pathForDistrict`
   半径 1.5~3.5 的三点折线有效弦长同量级），端点折返；折线每点钳回城区底板内。

`V(N) >` 该区可容纳人数时，按城区 `population` 权重二次分配到邻近城区。

### 6.3 换班（「也可以出来活动」）

户内居民**不渲染**，但每 `CHURN_PERIOD`（默认 1 个城市月 ≈ 墙钟 60 s ÷ time_ratio）
推进一次 `churnTick`：

- 从户内池按确定性 PRNG 抽 `⌈0.10 · V⌉` 人「上街」；
- 从街上池抽等量人「回屋」（选停留时间最长的优先）；
- 新上街者的 `path` 起点在其 `district` 重新采样，**入场方向朝向道路**。

⇒ 用户观感：街上人群会换面孔，偶见新人从楼里走出来 —— 对应「隐藏起来，也可以出来活动」。
换班**不改变 `V(N)`**，只换身份，保证 DC 与 mixer 数恒定。

### 6.4 后端 crowd manifest（跨层契约）

`city.Snapshot` 增 `Crowd *CrowdSnapshot`（omitempty，未建城房间不下发）：

```go
// CrowdEntry — 名上街居民的外观投影（批次 34）。
type CrowdEntry struct {
    Index    int    `json:"index"`     // backdrop.residents 下标（可回溯）
    CardID   string `json:"card_id"`   // 人物卡编号（可点开 ResidentProfileDrawer）
    Name     string `json:"name"`      // 化名
    Archetype string `json:"archetype"` // char_business|char_casual|...（§5.1 表）
    Gender   string `json:"gender"`    // m|f|u
    Age      int    `json:"age"`
    Domain   int    `json:"domain"`    // 0..25 L1 行业域
    District int    `json:"district"`  // 0..31
    Wealth   int    `json:"wealth"`    // 0..3
    Health   string `json:"health"`    // A|B|C
    Indoor   bool   `json:"indoor"`    // true = 在建筑内（不渲染，换班候选）
}

type CrowdSnapshot struct {
    Outdoor int          `json:"outdoor"`   // V(N)
    Indoor  int          `json:"indoor"`    // N − V(N)
    Churn   int          `json:"churn"`     // 换班代数（前端据此重算 path）
    Entries []CrowdEntry `json:"entries"`   // ≤ CAP_q 条；indoor=true 的条目仅占
                                            // 少量名额作为「换班候选」，不渲染
}
```

- **产出方**：`city.Backdrop.CrowdSnapshot(cap int, churn int)`（锁内纯函数视图，
  与 `Snapshot()` 同源同锁）；archetype / wealth 判定在 Go 侧一次算完（可单测）。
- **下发**：`view.go::BuildClientState` 的 `city` 块，随 `game.state` 广播
  （与 `ambiance`/`driver` 同级）。频率 = 月结 + 换班代数变化时，**不逐帧**。
- **容量**：`entries` 上限 = `CAP_q + 16`（16 条为户内换班候选），
  单条 ≈ 120 B ⇒ 整包 ≤ 22 KB，远低于既有 `bot_contexts` 包体。
- **隐私**：全量可见（与 `Snapshot` 同口径），不含现金/负债等敏感数值
  （只给外观相关派生量）。

## 8. 渲染 / UI 设计

- **路灯夜景**：暖色温 `#ffd98a`（与既有地面光斑 `#ffe4aa` 同族），
  辉光半径 ≈ 灯头 3 倍、光锥顶径 = 灯头长、底径 ≈ 6 m、高 = 灯高。

  不引入 `opacity: 0.4` 禁用态（§26.2 反模式 5）。

## 9. 不做清单（防范围蔓延）

1. **不做真实 `PointLight`**（261 盏点光击穿光照预算）—— 用 additive 伪光。
2. **不做 Bloom / 后处理**（需 `@react-three/postprocessing` 新依赖，批次 18 已否决）。
3. **不做蒙皮骨骼**（批次 29 L8：需 `SkeletonUtils.clone`，另立专项）。
4. **不做室内几何**（只做「户内 = 不渲染」语义，不开楼层/入户/室内漫游）。
5. **不改经济模型 / Agent 决策语义 / LLM 节流**（本批次纯视觉 + 人流）。
6. **不做 `road_props.glb` 重生**（路灯维持程序化实例化单源，见 §2.4）。
7. **不引入发光窗贴图**（批次 16 已技术否决）。
8. **不做 `python-generate-image-tool` 贴图**（辉光/渐变用 `CanvasTexture` 即可，
   AI 生成贴图在发光类上批次 16 已证窗口错位）；该工具保留给后续立面/广告牌需求。
9. **不改 `PEDESTRIAN_DENSITY` 之外的街具布点**（报刊亭/自行车/电话亭等不动）。
10. **不做居民个体级 LLM 驱动的视觉联动**（如「Agent 说想去公园，人就走到公园」）——
    属后续批次，本批次只做确定性人流。

    > move 位置同步 + 动作/发言实时冒泡）已在批次 35 实现，见
    > [`../35-Agent工具收敛与居民实体化/01-方案设计.md`](../35-Agent工具收敛与居民实体化/01-方案设计.md) §4/§5。
