## 1. 问题诊断（代码实证）

### 1.1 事件处理没有「全程留痕」

现状（`world_event.go` / `room_world_event.go` / `scenario.go`）：

| 留痕 | 现状 | 缺口 |
|------|------|------|
| 世界事件 | `World.WorldEventLog`（环 50，含 `Injected` 标志） | 只记「事件 → 是否注入」，**不记决策依据**（哪个闸门放行/拦截） |
| 场景注入 | `World.ScenarioApplied`（环 20） | 只记「注入参数 + 效果」，**不记触发来源 / 决策 / 前后状态哈希** |
| 预测运行 | `PredictionState`（基线 + 轨迹） | 只服务「预测报告」，**不是通用事件留痕** |
| MC 采集 | `World.MCEvents`（环） | 纯校准用，不含决策 |

**根因**：`applyScenarioToWorld`（`scenario.go:453`）是唯一的注入入口，但它的
调用链上**没有任何结构化的 4 阶段记录**。需求书 §五要求「触发、决策、执行、结果
四阶段日志，支持回放」——现状只有「执行」和「结果」的碎片。

### 1.2 没有存档/读档/回滚

现状：`World` 是纯内存态，**没有任何持久化**。

- `room_city.go:10-12` 明确写着「wealth 房间级选项仅存内存 pendingOpts，重启不恢复」
- `World` 无 JSON round-trip 测试，无 snapshot 机制
- `applyScenarioToWorld` 虽然「先校验后改写」（校验失败零改动），但**没有 panic 兜底**
  —— 一旦引擎内部 panic，城市状态可能损坏

**实证**：`json.Marshal(r.World)` 实测 46 KB，round-trip 后除 `Rand`（未导出字段）
与 `startAge`（未导出）外全部字段保持 —— **JSON 快照可行**（见本批实施记录）。

### 1.3 关键指标看板缺 3 项

需求书 §五要求「人口、经济、满意度、事件队列积压」。现状（`view.go` + 前端
`CityOverviewPanel.tsx`）：

| 指标 | 后端 | 前端看板 |
|------|------|---------|
| 人口 | `World.Players` 非空座位数 / `ResidentCount` | ❌ 未在「实时看板」展示（只在 `CityStatsPanel` 的城区人口条形里） |
| 经济 | `Society.TotalWealth` / `Labor.RevenueCNY` | ✅ 有（总财富/中位财富） |
| 满意度 | `Election.SentimentBias` / `100-gini*100` | ❌ 未展示（只有选举投票明细里的 per-vote satisfaction） |
| 事件队列积压 | `WorldEventLog` 未注入条数 + `Scenarios` 活动数 | ❌ 未展示 |

### 1.4 Agent 总线丢消息无痕迹

`citybus/bus.go:311-328`：`Post` 队列满（cap 64）⇒ **直接丢弃 + zap warn**，
调用方拿到 `nil`（无错误）。需求书 §二.5 要求「消息持久化与重试机制，避免单点
故障导致的事件丢失」——现状是**静默丢弃**。

## 2. 目标与非目标

**本批做四件事**：

1. **事件生命周期留痕**：4 阶段（触发/决策/执行/结果）结构化日志，环形缓冲，
   支持按 trace_id **回放**（恢复快照 → 重放注入 → 校验状态哈希）。
2. **存档/读档与灾难恢复**：World JSON 快照（存盘 + 内存），异常自动回滚，
   启动时灾难恢复。
3. **关键指标看板**：`game.state.key_metrics` 下发人口/经济/满意度/事件队列积压，
   前端「实时看板」新增关键指标区。
4. **消息持久化与重试**：citybus 增加 outbox（投递留痕）+ `Send` 失败重试。

**非目标**（本批刻意不做）：

- **不做跨进程分布式消息队列** —— outbox 是进程内环形缓冲 + 落盘 JSONL，
  不是 Kafka/RabbitMQ；「持久化」= 投递记录可查 + 进程重启后可读。
- **不做 World 全量字段的双跑对拍** —— 快照恢复后不保证与恢复前**逐位相同**
  （`Rand` 内部状态不可序列化），只保证**语义等价**（见 §3.2.4 恢复口径）。
- **不做自动回滚的「事务语义」** —— 回滚只覆盖 `applyScenarioToWorld` 的 panic
  兜底 + 手动回档，不做跨月结的事务。
- **不改 `applyScenarioToWorld` 的既有签名** —— 新增 `applyScenarioToWorldTraced`
  包装，既有调用方零改动（零回归）。

### 3.1 事件生命周期留痕（4 阶段 + 回放）

#### 3.1.1 数据结构（`game/virtual_city/event_lifecycle.go`，新文件）

```go
// EventPhase 事件生命周期阶段(需求书 §五「触发、决策、执行、结果」)。
const (
    EventPhaseTrigger   = "trigger"
    EventPhaseDecision  = "decision"
    EventPhaseExecution = "execution"
    EventPhaseResult    = "result"
)

// TriggerSource 触发来源(留痕归属)。
const (
    TriggerSourceAgentTool     = "agent_tool"     // City-System inject_scenario
    TriggerSourceRealWorldRule = "realworld_rule" // 批次80 规则派生
    TriggerSourceAutoInject    = "auto_inject"    // 月结自动注入
    TriggerSourceManual        = "manual"         // HTTP 直发
    TriggerSourceReplay        = "replay"         // 回放重放
    TriggerSourceSystem        = "system"         // 系统内部
)

// GateDecision 单个决策闸门的结果。
type GateDecision struct {
    Gate   string `json:"gate"`             // idempotency | magnitude_limit | active_limit | monthly_count | kind_dedup | unknown_kind | params
    Passed bool   `json:"passed"`
    Detail string `json:"detail,omitempty"` // 拦截原因(未通过时)
}

// EventLifecycleTrace 单条事件生命周期留痕(4 阶段)。
//
// 纪律:恒为值语义(环形缓冲存值);Effects 为副本;SnapshotID 关联 §3.2 快照。
type EventLifecycleTrace struct {
    TraceID      string `json:"trace_id"`
    EventKey     string `json:"event_key,omitempty"` // 关联世界事件指纹(可空)
    ScenarioKind string `json:"scenario_kind,omitempty"`
    TriggeredAt  int64  `json:"triggered_at"` // unix 毫秒

    // ① 触发
    TriggerSource string `json:"trigger_source"` // TriggerSource*
    TriggerDetail string `json:"trigger_detail"` // 触发依据(规则 id / 工具名 / 用户备注)

    // ② 决策
    DecisionGates   []GateDecision `json:"decision_gates"`
    DecisionOutcome string         `json:"decision_outcome"` // pass | reject

    // ③ 执行
    ExecutionMagnitude int              `json:"execution_magnitude"`
    ExecutionDuration  int              `json:"execution_duration"`
    ExecutionTarget    string           `json:"execution_target"`
    ExecutionEffects   []ScenarioEffect `json:"execution_effects"`

    // ④ 结果
    ResultOutcome   string `json:"result_outcome"` // success | failed | rolled_back
    ResultErrCode   int    `json:"result_err_code"`
    ResultErrMsg    string `json:"result_err_msg,omitempty"`
    StateHashBefore string `json:"state_hash_before"`
    StateHashAfter  string `json:"state_hash_after"`

    // 回放关联:注入前快照 id(§3.2;空 = 无快照,不可回放)。
    SnapshotID string `json:"snapshot_id,omitempty"`
}
```

#### 3.1.3 注入 hook（`scenario.go`）

**不改 `applyScenarioToWorld` 签名**，新增包装：

```go
// applyScenarioToWorldTraced 是带留痕的注入入口(批次86)。
// trace 为 nil 时行为与 applyScenarioToWorld 逐字一致(零回归)。
// trace 非 nil 时:① 拍 StateHashBefore + 存快照(§3.2);② 逐闸门记录决策;
// ③ 记录执行参数;④ 记录结果 + StateHashAfter;⑤ panic ⇒ 恢复快照 + 标记 rolled_back。
func applyScenarioToWorldTraced(w *World, kind string, magnitude, durationMonths int,
    target, note string, at int64, seed int64, trace *EventLifecycleTrace) (
    *ScenarioAppliedRecord, []ScenarioEffect, *ScenarioActive, *errcode.Error)

// applyScenarioToWorld 保持原签名,内部委托 traced(nil)。
func applyScenarioToWorld(w *World, kind string, magnitude, durationMonths int,
    target, note string, at int64, seed int64) (
    *ScenarioAppliedRecord, []ScenarioEffect, *ScenarioActive, *errcode.Error) {
    return applyScenarioToWorldTraced(w, kind, magnitude, durationMonths, target, note, at, seed, nil)
}
```

**决策闸门记录**：把 `applyScenarioToWorldTraced` 内既有的校验顺序显式映射为
`GateDecision`：

| 校验 | gate 名 | 通过条件 |
|------|---------|---------|
| 未知 kind | `unknown_kind` | `scenarioDefFor` 命中 |
| 强度越界 | `magnitude_limit` | 1..5 |
| 持续月数越界 | `params` | 1..24 |
| 活动场景上限 | `active_limit` | `< scenarioMaxActive` |
| target 非法 | `params` | `scenarioValidateTarget` 通过 |

> 注：批次80 的「幂等 / 每月条数 / 强度上限 / 同 kind 去重」四闸门在
> `refreshWorldEventsLocked`（房间层）评估，**不在** `applyScenarioToWorld` 内。
> 这四闸门的留痕在 §3.1.4 的房间层 hook 补齐。

**panic 兜底（自动回滚）**：

```go
if trace != nil {
    snapID, snapErr := saveSnapshotInternal(w, SnapshotReasonAutoRollback)
    trace.SnapshotID = snapID
    defer func() {
        if rec := recover(); rec != nil {
            if snapErr == nil && snapID != "" {
                _ = restoreSnapshotInternal(w, snapID) // 尽力恢复
                trace.ResultOutcome = "rolled_back"
            }
            panic(rec) // 恢复后原样上抛(不吞)
        }
    }()
}
```

### 3.2 存档/读档与灾难恢复 + 自动回滚

#### 3.2.1 存盘格式（`game/virtual_city/save_load.go`，新文件）

```go
// SnapshotReason 快照用途(留痕)。
const (
    SnapshotReasonManual       = "manual"        // 用户/Agent 手动存档
    SnapshotReasonAutoRollback = "auto_rollback" // 注入前自动留档(回滚用)
    SnapshotReasonRecovery     = "recovery"      // 灾难恢复点
    SnapshotReasonReplay       = "replay"        // 回放基线
)

// WorldSnapshot 世界快照(存盘格式;JSON)。
type WorldSnapshot struct {
    SchemaVersion int             `json:"schema_version"` // 1
    RoomID        string          `json:"room_id"`
    SnapshotID    string          `json:"snapshot_id"` // "snap-<unixnano>-<rand6>"
    CreatedAt     int64           `json:"created_at"`  // unix 毫秒
    Month         int             `json:"month"`
    StateHash     string          `json:"state_hash"`
    Reason        string          `json:"reason"`
    WorldJSON     json.RawMessage `json:"world_json"` // World 全量 JSON
}

// SnapshotMeta 快照元信息(列表用;不含 WorldJSON)。
type SnapshotMeta struct {
    SnapshotID string `json:"snapshot_id"`
    CreatedAt  int64  `json:"created_at"`
    Month      int    `json:"month"`
    StateHash  string `json:"state_hash"`
    Reason     string `json:"reason"`
    SizeBytes  int    `json:"size_bytes"`
}
```

**目录约定**（照抄 `calibration_runs.go` 模式）：

```
./virtual_city_saves/<roomID>/
    ├── recovery.json          # 灾难恢复点(最近一次成功月结后自动写)
    └── <snapshot_id>.json     # 手动/自动快照(每个文件一个)
```

**写盘纪律**（照抄 `calibration_runs.go`）：
- 原子写：先写 `<name>.tmp` 再 `os.Rename`
- 失败返回 error，**绝不 panic、绝不阻断对局**
- 目录 `os.MkdirAll(0755)`，文件 `0644`
- 包级 `SnapshotStore`（`mu` + `dir`），`SetSnapshotDir` 供测试注入

**World JSON round-trip**（`save_load.go` 内）：

```go
func marshalWorld(w *World) ([]byte, error) { return json.Marshal(w) }

// unmarshalWorld 恢复 World:JSON → World,然后修复不可序列化字段:
//   - Rand:用 World.Seed 重新播种(rand.New(rand.NewSource(seed))
//     —— 内部状态不可序列化,语义等价(同 seed 同序列);
//   - startAge:恢复为 MasterStartAge(未导出字段,JSON 丢失);
//   - nil 子系统:按需惰性初始化(照抄 NewWorld 的构造口径)。
func unmarshalWorld(data []byte) (*World, error)
```

> ⚠ **恢复口径**：`Rand` 的内部状态无法序列化 ⇒ 恢复后**随机序列不与恢复前
> 逐位相同**。但 `World.Seed` 被保存 ⇒ 重新播种后**同 seed 的派生逻辑**（建城、
> 发卡等）仍一致。这是「语义等价」而非「逐位等价」，需求书 §五的「避免城市
> 状态损坏」达成（状态不丢、不坏），但**不承诺跨恢复的确定性续跑**。

#### 3.2.4 灾难恢复

- **恢复点写入**：`trySettle` 月结成功后，异步（goroutine + 超时）写
  `recovery.json`（`SnapshotReasonRecovery`）。写盘失败只 zap warn，不阻断月结。
- **启动恢复**：`Start` 时检查 `recovery.json`：
  - 存在 ⇒ 自动恢复到 `r.World`，记 zap info（`recovered_from` / `month`）；
  - 不存在 ⇒ 正常开局（零回归）。
- **手动恢复**：`RestoreSnapshot("recovery")` 或 HTTP 端点。

> **恢复点容量**：`recovery.json` 恒为 1 份（覆盖写），不轮转 —— 最近的成功月结
> 就是最好的恢复点。

#### 3.2.5 自动回滚

- **注入前**：`applyScenarioToWorldTraced` 存快照（`SnapshotReasonAutoRollback`）
- **panic 时**：`recover` + 恢复 + 标记 `rolled_back` + 原样上抛
- **手动回滚**：`RollbackLastScenario` 找最近一条 `ResultOutcome=success` 的
  trace，用其 `SnapshotID` 恢复

> **保留策略**：`auto_rollback` 快照保留最近 **3** 份（超出删最旧），避免磁盘膨胀。

### 3.4 消息持久化与重试（citybus）

#### 3.4.1 outbox（`agent/citybus/outbox.go`，新文件）

```go
// OutboxRecord 单条消息投递留痕。
type OutboxRecord struct {
    Seq      int64  `json:"seq"`       // 单调递增
    At       int64  `json:"at"`        // unix 毫秒
    RoomID   string `json:"room_id,omitempty"`
    From     string `json:"from"`
    To       string `json:"to"`
    Type     string `json:"type"`
    Delivery string `json:"delivery"` // sent | posted | dropped | failed
    ErrMsg   string `json:"err_msg,omitempty"`
    Retries  int    `json:"retries"`
}

// Outbox 环形缓冲(cap 200;线程安全)。
type Outbox struct { ... }
func (o *Outbox) Record(rec OutboxRecord)
func (o *Outbox) Snapshot(limit int) []OutboxRecord
```

**接线**：
- `Send` 成功 ⇒ `Record(delivery="sent")`
- `Send` 失败 ⇒ 重试（§3.4.2）⇒ 最终 `Record(delivery="failed")`
- `Post` 入队 ⇒ `Record(delivery="posted")`；队列满 ⇒ `Record(delivery="dropped")`
- `postLoop` handler 失败 ⇒ `Record(delivery="failed")`

#### 3.4.2 重试

```go
// SendWithRetry 同步请求-响应(带重试;批次86 §3.4.2)。
// 重试策略:最多 3 次,间隔 50ms / 150ms(指数退避);仅对「目标未注册」之外的
// 错误重试(未注册是确定性失败,重试无意义)。
func (h *Hub) SendWithRetry(ctx context.Context, roomID, from, to, typ string, payload any) (any, error)
```

- `Send` 保持原语义（单次），`SendWithRetry` 供对可靠性敏感的调用方使用
- 重试记录写 outbox（`retries` 字段）

#### 3.4.3 落盘（可选，默认关）

`Outbox` 内存环 + JSONL 落盘（`./virtual_city_saves/outbox.jsonl`），由
`citybus.SetOutboxPersistence(true)` 开启。**默认关**（零回归），需要时配置开启。
