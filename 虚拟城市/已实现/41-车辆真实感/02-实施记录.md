### 2.3 阶段 C · 车流行动规律（frontend-dev）

| 项 | 落地 |
|---|---|
| C1 密度 | connector 去 20 上限（36 全量）；arterial 每方向 1→2；**low 档保底每方向 1（8 辆，替代旧 0）**；变体池 connector 无公交（9 m 窄路）；涂装 hash 轮转（sedan i%3===0→silver / truck i%3===1→white）；速度 ×(0.92+0.16·hash01) + phase fract(i·0.37+0.21·hash01)。**high 69 / low 8** |
| C2 信号耦合 | `vehiclesForNetwork` 内从 arterial 段动态推导交点（Z 跑 × X 跑两两求交，atan2 升序 —— 与 `roadNetwork.arterialIntersections` 同点集合同排序）；相位 = 灯面朝 −x 者携 phase(idx) 服务沿 X 跑的路（**几何实证**，与 trafficSignalsForCity 注释命名相反以几何为准）；`Vehicle.tsx` useFrame 按 `signalLitColor(phase, clock.elapsedTime)`（**import 复用零重复实现**）红/黄 → v=√(2·0.8·d) 运动学减速 + 停稳保持，绿 → 巡航起步 |

## 6. 流程教训（新增）

1. **建模 SubAgent 在本环境不可用**（连续两个批次实证）——方案文档含完整规格时主 Agent 直接代行更快（15 分钟/件 vs 35+ 分钟零产出）。frontend-dev SubAgent 两轮均高质量交付（含模拟抓真 bug），**代码类 SubAgent 可用、建模类不可用**。
2. **横跨件的宽度轴**：路牌屏 / 挡泥板 / 贯穿灯条这类「横跨车宽」的部件，其「长边」落在 Blender Y（车宽）——写尺寸前先算包围盒预算（本批次两处笔误均为把轿车尺度或单侧件尺度带入公交/卡车）。
3. **AABB 合同是建模期最有效的自查**：render_preview 的包围盒打印行每轮必看，超宽/超高当场定位（本批次 3 次笔误均由该行捕获，未流入下一环节）。
4. **站体 GLB 与站内摆件会互相重复**：civic 建筑 GLB 里烘焙的「院内小物件」（假车/杂物）在前端用 `<Vehicle>`/组件接管同类摆件时必须同步删掉，否则 GLB 模式下双渲染或永不显示。
5. **方案伪码的量纲要标注**：C2 的 v(t/s) 与 vAllow(u/s) 直接比较在实现期被迫重推导；方案写伪码时应显式写单位域。
