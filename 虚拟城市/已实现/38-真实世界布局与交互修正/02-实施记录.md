## 2. 关键修复详记

### 2.1 布局互知层 `cityObstacles.ts`（新增 280 行）

本批次的核心不是逐个打补丁，而是把「五套布局互不查询」改成**一个共享几何事实源**：

- 运河/港池常量（`CANAL_Z=17` / `CANAL_HALF_X=48` / 河宽 3u / 港池矩形）从 `VirtualCityCityMap.tsx` **迁入**本模块作唯一事实来源；`WaterLayer` 改为 import 消费。
- `roadNetwork.ts::pointSegDist` **去私有化导出**，全模块复用一份（禁止复制第二份）。
- API：`buildRoadCorridors` / `inWater` / `onRoadCorridor` / `onFirstRing` / `isBuildable` / `segIntersectsWater`（Liang-Barsky 精确求交）/ `segCrossesCanal`。
- `FIRST_RING_CORRIDOR.halfWidth = FIRST_RING_WIDTH/2 + SIDEWALK_W = 0.95u`（含人行道）。
- 未注入路廊时惰性自建，杜绝「空廊道 = 全放行」。
- `cityScale.ts` 新增 `ROAD_WIDTH_MAIN/SIDE`（叶子模块），消除 tsx↔ts 循环 import 的 TDZ 风险。

### 2.2 建筑退让（R2）


- **路廊只取 main 级**（arterial / edgeLink）+ 一环 + 水域。connector 走街区庭院，纳入「中心 + 外接圆」判定会误杀实测 14/32 区、整轮 130 栋。

### 2.3 道路贴图 P0（R5 / R6）

```diff
- const merged = { ...rest, ...mp };        // mp.map 覆盖 base.map ❗
+ const merged = { ...mp, ...overrides };    // base 显式键优先，pbr 补缺
```

- **根因**：`withPBR` 让 `mp.map`（`asphalt_main` 纯沥青）覆盖 `base.map`（`road_main` 含烘焙标线）⇒ **`road_main` / `road_side` 从不上屏**，路面只剩纯沥青，与地面同色 ⇒ 用户看到的「道路没有显示出来」。
- **契约**：语义反转为「**pbr 提供缺省，base 可覆盖**」；且 base 的 `undefined` 值不算覆盖（保住 `{ map: tex ?? undefined }` 惯用法的 pbr 回落）。
- **回归确认**：`grep withPBR(` 共 **12 处调用点**逐一核对 —— 仅 `Road.tsx` 同时给 `base.map` 与 `mp.map`（即本次要修的那处），其余 11 处 base.map 为空或与 pbr 同 URL，**零行为变更**；另补 4 项逻辑级单测。
- UV 周期：`roadRepeatY = round(len/roadWidth)` 取整拉伸已删，改为几何 UV 按物理长度连续烘焙、贴图 `repeat` 恒 `[1,1]`（同时消除纹理缓存键分裂）。

## 6. 流程教训（新增，供后续批次复用）

1. **`verify_glb_aabb` 的「主轴 = Y」判据对横向线性构件是误报** —— 驳岸挡墙、桥栏杆段的长度本就在 X。与其改判据，不如加 `DOMINANT_AXIS_EXEMPT` 窄豁免并写明理由。
2. **长串 JS 注入的语法错误会伪装成「场景为空」** —— `evaljs` 返回 `{"__error__": "SyntaxError…"}`，而审计代码只判 `res.get("error")`（JS 内部返回的 `error`），于是走进「mesh=0 ⇒ 全判失败」的死路。**注入前先 `node --check`**；本轮就栽在 `catch(e){}}` 多闭一层花括号。改为「独立 .js 文件 + Python 读文件」最省事。
3. **重复观战会让 canvas 整个不挂** —— `spectate` 返回 `code 30001` 时即使 `canvas:false`、场景全空，根因是上轮页面还占着观战位，**不是代码回归**。稳妥做法是每轮新建房（建房 body 须嵌 `virtual_city: {time_ratio: N}`，顶层 `time_ratio` 会被 `DisallowUnknownFields` 拒 400）。
4. **AABB 中心的「AABB 偏严」要分物件类型判断** —— 细长杆件（信号杆 / 路灯杆）落在路口是合理的，只按几何判会误报；而树冠顶球的中心 xz **就是树干位置**，判为真实违例。同一个「AABB 中心落带内」的信号，对两类物件含义相反，必须靠尺寸签名拆开看。
5. **`?debug=1` 是调试面的门控** —— `__objectInfoStore` / `__cityTimeStore` 都只在带该参数时挂载，漏带会静默失败（`no __objectInfoStore`），比缺功能更难查。
