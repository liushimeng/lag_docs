## 1. 现状调研结论（2026-09-30 全量代码精读）

### 1.1 一句话总纲

> **路网（`roadNetwork` / `FirstRingRoad`）、建筑（`building_layout`）、街具（`StreetPropsLayer`）、水系（`WaterLayer`）、桥（`CanalBridgeSpots`）五套布局各自为政、互不查询。**
> 唯一的历史交汇点（CBD 放射径向 + 桥位通式）还停留在 **2026-09-28 删除 spoke 之前**的口径。
> 用户看到的「一环路穿楼 / 树长在河上 / 桥是歪的 / 道路看不见」全部是这一解耦结构在不同层的投影。

### 1.2 五层布局的锚点口径（现状）

| 层 | 文件 | 锚点 | 是否查询其它层 |
|---|---|---|---|
| 路网线段 | `roadNetwork.ts::buildRoadNetwork` | 区心 k 近邻 / 硬编码方格 / 径向延长 | 仅 CBD 半径 5.0 禁入 |
| 一环路 | `FirstRingRoad.tsx` | 固定圆 `r=20`，32 段折线，y=0.022 | **否** |
| CBD 环 | `RingRoad.tsx` | 固定圆 `r=5.6`，16 段，y=0.017 | **否** |
| 建筑 | `building_layout.ts::buildingsFor` | 8×8 底板 4 边 × 4 槽，槽心距区心 2.85 | **否** |
| 行道树 | `StreetPropsLayer.tsx::roadTreesForNetwork` | 路中心线 **单侧交替** ±1.35u | **否** |
| 路灯 / 垃圾桶 / 人行道 | `Road.tsx::lampsForRoad` / `roadsideBinsForNetwork` / `RoadMarkings.tsx` | 路中心线 + 常量侧偏 | **否** |
| 水系 | `VirtualCityCityMap.tsx::WaterLayer` | 固定矩形 `z=17`，`\|x\|≤48`，宽 3u | **否** |
| 运河桥 | `CanalBridge.tsx::CanalBridgeSpots` | **已删除的 spoke 径向**与 z=17 的交点 | **否（且口径已废弃）** |

### 1.3 标高分层现状（`cityScale.ts`）

| 面 | Y | 含义 |
|---|---|---|
| 路面 | `ROAD_SURFACE_Y = 0.015` | 普通路段 |
| connector | `+0.002` | 防 z-fighting |
| arterial | `+0.004` | 防 z-fighting |
| 一环路 | `+0.007` → **0.022** | 最高层 |
| 区底板 | `DISTRICT_SURFACE_Y = 0.02` | 32 区底板 |
| 人行道 | `SIDEWALK_Y = 0.027` | |
| **水面** | **0.028** | 运河 / 港池 |
| 桥面顶 | 0.035 | `CanalBridge.tsx` |

> ⚠️ **由此产生的两条「不可见 / 沉没」事实**：
> 1. 路面 y=0.015 **低于** 区底板 y=0.02 ⇒ 穿越街区底板的路段被底板盖住（批次 31 设计原意「穿板段走板下」，但副作用是**街区内部道路整体不可见**）。
> 2. 路面 y ≤ 0.022 **低于** 水面 y=0.028 ⇒ 所有过河路段都是「潜水路」，一环路过河处（x=±10.54）整段沉入水中。

## 2. 根因分析（逐条对应 R1–R7）

### R1 信息卡文字无法选中复制

- **现状**：`objectInfo/ObjectInfoOverlay.tsx` 的 `DetailCard` 走 drei `<Html>`，CSS
  （`styles/virtualCity-objectinfo.css`）**没有** `user-select: none`；但同样没有 `user-select: text`，
  且卡片根节点未阻止事件外溢 —— 按下拖选时手势可能被画布侧的
  `FreeViewControls`（`gl.domElement` 上的 `pointerdown` + `setPointerCapture`）或 R3F 事件系统截走。
- **结论**：属**未建档议题**（知识库 `user-select` / 复制 关键词零命中，见批次 38 调研）。
  不能只靠「碰巧能选」，必须**显式契约化**：显式 `user-select: text` + 事件隔离 + 一键复制。

### R2 一环路穿透建筑物

三重叠加，全部是「层与层零互知」：

1. **一环是固定圆，城区底板/街墙楼是固定网格，二者不避让。** 一环带域 r∈[19.3, 20.7]：
   - `suburb` 区心 (−14, 14) → r = **19.80**，正压在环带中心线上；其街墙楼
     （槽心距区心 2.85、进深 ≤1.6 ⇒ 外缘 ±3.65）例：南排楼 (−16.7, 11.15) 的 r=20.08 —— **一环路从楼中间穿过**。
   - `riverside` (14, 10) 东北角、`logistics_port` (−22, −4) 东南角、`hightech_park` / `cultural_creative` 角部均被环带切到。
2. **建筑只看 8×8 底板，路只看线段。** `buildingsFor` 的「退线」是相对底板边（假定路沿板边走），
   而路根本不沿板边走。
3. **同一病灶在 arterial 上同样存在**（文档容忍）：`x=−18` 贯穿线切入 suburb 西排楼约 4 m
   （`roadNetwork.ts:8` 自述「与 32 区底板重叠 ≤1 块/条」）。**用户主诉的「一环路穿楼」是这条机制性缺陷最显眼的一次爆发。**

### R3 行道树长在运河上 + 河流显示过简

1. **布点全是「中心线 + 常量侧偏」，全系统没有任何水体掩膜。**
   - `arterial x=±18` 贯穿 z∈[−48,48]，必然横穿河道 z∈[15.5,18.5]；
     `roadTreesForNetwork` 沿整段无裁剪布树 ⇒ **每条纵贯 arterial 约 3 棵树正立在水里**（侧偏只改 x 不改 z）。
   - `edgeLink` / `connector` 过河段同样布树、布路灯、铺人行道。
   - 区内树（`propsForDistrict`，半径 3.3±0.6）在 `suburb`(−14,14) 北向也能伸进河道。
2. **河流显示过简**：水面 = 两层滚动法线 plane（`props/WaterPlane.tsx`）+ 两岸草皮收边 + 岸雾；
   **无驳岸挡墙、无亲水台阶、无河床深度感、无芦苇/石块、无护栏连续体**；
   且**没有 river/canal/bridge 专用 .glb 或贴图**（全仓检索零命中），水贴图 `ground/water_tile.png`
   纹素密度 ≈51 px/m 也偏低。

### R4 行道树应位于道路 2 侧

- **现状**（`StreetPropsLayer.tsx:544-552`）：`side = i % 2 === 0 ? 1 : -1` —— 是
  **单侧交替**（这棵树在左、下棵在右），不是真实世界的**双侧平行行列**。
- 侧偏 `sideOffset = ROAD_WIDTH_MAIN/2 + 0.35 + 0.3 = 1.35u`（路缘外、人行道外缘）本身合理。

### R5 道路没显示出来 + 不知可点选

三个独立子因：

1. **贴图接线缺陷导致「道路看起来就是一块平地」** —— 见 R6 缺陷 A：`road_main/road_side` 的
   **烘焙标线永远不上屏**，路面只剩纯沥青色，与地面/底板色接近 ⇒ 视觉上「道路没有显示出来」。
2. **标高被盖住** —— 路面 y=0.015 < 区底板 y=0.02（街区内部道路被底板盖）；
   过河段 < 水面 0.028（过河道路被水盖）。
3. **可发现性缺失** —— 选中链路其实**已经接好**（`Road.tsx:112` `useObjectInfoProps('road.surface')`、
   `FirstRingRoad.tsx:115` `road.first-ring`、`RingRoad.tsx:129` `road.ring`、`CanalBridge.tsx:50` `road.bridge`），
   但 UI **没有任何提示**告诉用户「左键点击物体可查看详情」。

### R6 道路贴图显示有问题

| 级 | 缺陷 | 位置 | 后果 |
|---|---|---|---|
| **P0** | `withPBR` 的 `mp.map` **覆盖** `base.map` | `engine3d/textureCache.ts:224`；`Road.tsx:142-150` | `road_main/road_side`（带中心黄虚线 + 白边线的烘焙标线）**从不上屏**，只剩 `asphalt_main` 纯沥青。`road_main.png` 成「加载了但没接线」的死资产 |
| **P1** | streets 未入 `texScale.ts` 登记表 | `texScale.ts`；`3d_script/audit_texture_fit.py` `TILE_TARGETS` 只有 facade/roof | 无「纹素密度恒定」不变式保护；asphalt **36.6 px/m**、sidewalk **204.8 px/m**，远出审计带 60–120 但不报 |
| **P1** | `roadRepeatY = round(len/roadWidth)` 取整 | `Road.tsx:122-129` | 单周期长度 ≠ `roadWidth` ⇒ 纵向拉伸/压缩；每段 repeat 不同 ⇒ 纹理缓存键分裂、同一 PNG 多份 GPU 纹理 |
| **P2** | 生成器已删不可复现 | `procedural_pbr_maps.py` / `procedural_city_textures.py` 于 2026-09-23 清理删除 | `pbr/{synth,facades,roofs,districts,ground}` 无法重生成（本批次只补街道/水系，不复活旧脚本） |

### R7 运河桥是歪的 + 未衔接道路

1. **桥位来自已删除的 spoke 网，与现行路网完全脱钩。**
   `xAt = c.x * (CANAL_Z / c.z)` 是「原点→区心」径向与 z=17 的交点（spoke 时代的过河点）。
   现行路网的真实过河点是 arterial (±18, 17)、若干 connector/edgeLink 交点 ——
   **交集几乎为空：路过的没桥，桥立着的没路。**
2. **朝向沿径向，与东西向河道天然斜交。** `rotation = atan2(-c.x, -c.z)` 让桥长轴指向原点；
   河道是直线 z=17，只有正南正北的径向才垂直河道。最歪一例 `old_city_culture`
   桥位 (−34, 17) 桥轴与河道法线夹角 **≈63°** —— 桥面斜切水面。
3. **桥长固定 4.6u（按垂直跨设计：水宽 3 + 两岸各 0.8），斜交时法向投影不足 ⇒ 桥头够不到两岸。**
4. **筛选 `c.z <= CANAL_Z` 直接跳过南岸城区** ⇒ 南岸道路过河永远没桥。
5. **没有任何几何上与路段对齐/拼接的代码** —— `CanalBridgeSpots()` 不接收 `RoadNetwork` 参数就是证据。

## 3. 方案总纲

### 3.1 设计原则

> **把「五套布局互不查询」改成「一个共享几何事实源 + 各层消费」。**
> 不引入新的重型系统，只加一个**纯函数**的布局互知模块，并让建筑 / 街具 / 桥
> 三条链路在布点时查询它。

### 3.2 分层修复表

| 层 | 方案 | 归属 |
|---|---|---|
| **L0 几何事实源** | 新建 `cityObstacles.ts`：道路廊道 + 水域矩形的统一 keep-out 查询 | frontend |

## 4. 契约设计（实现必须照此落地）

### 4.1 L0 `cityObstacles.ts` —— 布局互知唯一入口

```ts
// ClientWeb/src/components/virtualCity/cityObstacles.ts
// 纯函数、无副作用、无随机。所有布点方（建筑/街具/桥）共用。

/** 道路廊道（世界 xz 平面线段 + 半宽）。 */
export interface RoadCorridor {
  from: [number, number];
  to: [number, number];
  /** 路幅半宽（含人行道），单位 u。 */
  halfWidth: number;
}

/** 水域（轴对齐矩形）。 */
export interface WaterBody {
  minX: number; maxX: number;
  minZ: number; maxZ: number;
}

/** 一环带域（环形廊道）—— 一环路是圆，不能用线段表达。 */
export interface RingCorridor {
  radius: number;
  halfWidth: number;
}

/** 由 RoadNetwork + 一环/CBD 环常量生成全部道路廊道。 */
export function buildRoadCorridors(net: RoadNetwork): RoadCorridor[];

/** 运河 + 港池（常量来自 WaterLayer，本模块为唯一持有处，WaterLayer 改为消费）。 */
export const CANAL_WATER: WaterBody;      // z∈[15.5,18.5], |x|≤48
export const PORT_POOL_WATER: WaterBody;  // 物流港港池

/** 点到线段距离（从 roadNetwork.ts 导出，去私有化）。 */
export function pointSegDist(px,pz,a,b): number;

/** 点是否落入任一水域（含 margin 外扩，默认 0）。 */
export function inWater(x: number, z: number, margin?: number): boolean;

/** 点是否落入任一路廊（含 margin 外扩）。 */
export function onRoadCorridor(x: number, z: number, margin?: number): boolean;

/** 点是否落入一环带域 |dist(point,0) - radius| < halfWidth + margin。 */
export function onFirstRing(x: number, z: number, margin?: number): boolean;

/** 综合判定：该点可否放置「地面实体」（建筑 / 树 / 灯 / 桶）。 */
export function isBuildable(x: number, z: number, margin?: number): boolean;
// = !inWater && !onRoadCorridor && !onFirstRing
```

**硬约束**：
1. `roadNetwork.ts` 的 `pointSegDist` **改为导出**（去私有化），并在 `cityObstacles` 复用，禁止复制第二份。
2. `WaterLayer` 的运河常量（`CANAL_Z` / `CANAL_HALF_X` / 河宽 3）**迁到 `cityObstacles.ts`**
   作为唯一事实来源；`VirtualCityCityMap.tsx` 改为 import 消费。
   - 迁移后 `civic/CanalExtras.tsx` 写死的「避开跨河桥 x=±6.2」**作废**，改查桥位表。
3. **确定性**：无随机、无时间依赖，同输入必同输出（批次 31 的 `roadNetwork` 同规约）。

### 4.2 L1 建筑退让路廊（R2）

`building_layout.ts::buildingsFor` 在产出每个 `BuildingSpec` 后追加一次校验：

```ts
// 伪代码 —— 放在现有 jitter 之后、push 之前
const margin = 0.25;                       // 退让余量 2.5 m
if (!isBuildable(spec.x, spec.z, margin + Math.max(spec.w, spec.d) * 0.5)) {
  continue;                                // 丢弃该槽位楼，不递补（保持确定性与楼层高度可预测）
}
```

- **判定口径**：楼体包围盒外接圆半径 `max(w,d)*0.5` 作为 margin，中心点判 `isBuildable`。
  （轴对齐盒 vs 路廊线段的精确相交更准，但中心+外接圆已足够拦住用户主诉的穿楼，且零新增几何代码。）
- **不递补**：被丢弃的槽位空着（留出真实世界里「路口/环路旁的空地」），避免递补引发连锁重排。
- **兜底**：若某区 `buildingsFor` 产出 `< 4` 栋（keep-out 误伤过狠），放宽 margin 至 0.1 重算一轮，
  仍不足则保留原结果并在 dev 控制台告警（`§4 代码约束` 不允许静默降级）。
- **同时生效于一环、CBD 环、arterial、connector、edgeLink 全部路廊** ⇒ 一并解决
  「arterial x=−18 切 suburb 西排楼 4 m」这条历史遗留。

### 4.3 L2 街具：水域 keep-out + 行道树双侧行列（R3/R4）

**（a）水域 keep-out —— 所有地面布点器统一加一行判定**

| 布点器 | 文件 | 补丁 |
|---|---|---|
| `roadTreesForNetwork` | `StreetPropsLayer.tsx:524` | 候选点 `if (inWater(x,z,0.3)) continue` |
| `lampsForRoad` | `Road.tsx:72` | 同上 |
| `roadsideBinsForNetwork` | `StreetPropsLayer.tsx:667` | 同上 |
| `busStopsForNetwork` | `StreetPropsLayer.tsx:714` | 同上 |
| `propsForDistrict`（区内树） | `StreetPropsLayer.tsx:280` | 同上 |
| `RoadMarkings`（人行道/斑马线/停止线） | `RoadMarkings.tsx` | **过河段整段跳过**（按段与水域矩形相交判定），只保留桥面自身的标线 |

**（b）行道树改双侧平行行列（R4）**

```ts
// 现状（单侧交替，错）
const side = i % 2 === 0 ? 1 : -1;
// 目标（双侧行列，与真实街道一致）
for (const side of [1, -1]) {
  const x = fx + dx * t + nx * sideOffset * side;
  const z = fz + dz * t + nz * sideOffset * side;
  if (inWater(x, z, 0.3)) continue;

```

- 株距仍走 `spacing('streetTree') = 9 m`，**两侧同相位**（同 t 处左右各一棵），与真实行道树一致。
- `TREE_TOTAL_CAP = 1800` 不变；双侧化后总数翻倍，需在 cap 内截断（按段顺序、确定性）。
- 与路灯错相位的既有约定保留（`t = i/(count+1) + 0.25`）。

### 4.4 L3 运河桥改由真实过河路段驱动（R7）

`CanalBridge.tsx::CanalBridgeSpots(net: RoadNetwork)` —— **签名加 `net` 参数**（现签名无参即根因证据）。

```ts
export interface CanalBridgeSpot {
  x: number; z: number;
  /** 桥面朝向：必须垂直河道。运河 z=17 东西走向 ⇒ 桥轴南北向，rotation ≈ 0 或 π。 */
  rotation: number;
  /** 桥面长度（u）：按路段与河道夹角派生，见下。 */
  length: number;
  /** 桥宽（u）：取过河路段的路幅宽（main 1.4 / side 0.9）。 */
  width: number;
  /** 收尾衔接的路段 key（用于 objectInfo 与视觉接顺）。 */
  roadKey: string;
}

export function canalBridgeSpots(net: RoadNetwork): CanalBridgeSpot[] {
  const spots: CanalBridgeSpot[] = [];
  for (const s of net.segments) {
    const hit = segIntersectCanal(s);       // 与 z=17 直线求交，t∈(0,1)
    if (!hit) continue;
    if (inWater(hit.x, hit.z) === false) continue;   // 只在河道内建桥
    const angleToNormal = ...;              // 路段方向与河道法线（+Z）夹角
    // 桥长：水宽 3u / cos(夹角) + 两岸引桥各 0.9u，且不得短于 4.2u
    const length = Math.max(3 / Math.cos(angleToNormal) + 1.8, 4.2);
    spots.push({
      x: hit.x, z: CANAL_Z,
      rotation: 0,                          // 垂直河道：桥轴沿 +Z
      length,
      width: s.kind === 'main' ? ROAD_WIDTH_MAIN : ROAD_WIDTH_SIDE,
      roadKey: s.key,
    });
  }
  return dedupeByDistance(spots, 2.0);      // 距离 <2u 的过河点合并
}
```

**硬约束**：
1. **桥轴必须垂直河道** —— 运河是东西向直线 z=17，故 `rotation` 恒为 0（或 π，仅影响端柱朝向）。
   **禁止**再用 `atan2(-c.x, -c.z)` 的径向口径。
2. **桥头衔接道路** —— 桥两端落在 `z = 17 ± length/2`，须保证该处仍有对应路段（过河段本身）；
   桥面 y_top 保持 0.035（高于水 0.028），并**把过河路段的可见部分从水面下抬出**
   （见 §4.6 标高修复）。
3. **南岸不再被跳过** —— 删掉 `if (c.z <= CANAL_Z) continue` 这条筛选；改为对**全部**路段求交。
4. **`civic/CanalExtras.tsx` 的「避桥 x=±6.2」写死值作废**，改按 `canalBridgeSpots()` 返回值避让。
5. 桥数变化是预期结果（桥位从「8 座径向孤桥」变成「N 座真实过河桥」）。
