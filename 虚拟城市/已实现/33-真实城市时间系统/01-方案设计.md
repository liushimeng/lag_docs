# 虚拟城市 · 批次 33 — 真实城市时间系统（世界前 20 大城市 + 日出日落）

> 2026-09-29 §批次33。前置：批次 25（城市时钟）、批次 27（时间比例与昼夜季节天气）、批次 30（昼夜收口）。
> 数据来源：`00-数据来源-世界前20大城市经纬度与逐月日出日落.md`（用户整理，本批次唯一事实来源）。

## 1. 需求

1. 创建虚拟城市房间时新增「城市」选项：可选**世界前 20 大城市**之一，或**随机**（建房时从 20 城中确定性抽取一座）。
2. 房间开局时城市时钟**从服务器当前时间开始**（不再固定纪元 2025-01-01），随后按建房选择的**时间比例**（1分钟比1小时 / 1分钟比2小时 …）推进；显示与逻辑全部对齐。
3. 日出日落按所选城市的**逐月数据表**（数据文档）实现：主界面显示该城市名称（替换"虚拟城市"标题）、经纬度/国家信息与当日日出日落时间；**3D 昼夜循环的太阳升落时刻**也按该城市当月的日出日落驱动（不再是全球固定 6:00/18:00）。
4. 未选城市（默认）的房间行为与批次 27/30 **逐分不差**（零回归红线）。

## 2. 后端设计（ServerGo/game/virtual_city）

### 2.1 城市静态表 `city_geo.go`（新建）

```go
type CityGeo struct {
    Key               string   // tokyo / delhi / ... / new_york
    NameZH, NameEN, NameJA string
    CountryZH, CountryEN, CountryJA string
    Lat, Lng          float64
    TZMin             int      // 标准时区偏移（分钟，手工表：与数据文档口径一致，不走经度推算 —— 如 Delhi +330、Karachi +300）
    SunriseMin        [12]int  // 逐月日出（当地 0 点起分钟数，照抄数据文档）
    SunsetMin         [12]int  // 逐月日落（同上）
}
```

- `cityGeoTable`：20 城全量表（键序 = 数据文档排名序）。
- `resolveCityGeo(key string, seed int64) *CityGeo`：
  - `""` → nil（默认城市，旧行为）；
  - `"random"` → `hashU64(seed ^ cityGeoSeedSalt) % 20` 确定性抽取（同 seed 复现同一座城，与房间 rng 纪律一致）；
  - 其余 → 键查找，未命中 nil（防御）。
- `SunTimesAt(g *CityGeo, cityMs int64) (rise, set int)`：
  - 城市当地时间 = `cityMs + TZMin*60000`（UTC 口径城市时钟 + 固定偏移）；
  - 月内线性插值：月份值视为**当月第 1 天**值，`(day-1)/daysInMonth` 向下一月插值（12 月向 1 月回绕，用插值终点 month's days）；
  - 输出当日日出/日落分钟数（连续、确定性、纯函数）。

### 2.2 房间接线

- 新字段：`cityKey string`、`cityGeo *CityGeo`（纯内存态，不进存档 —— 与 pendingOpts 现状一致，批次 27 §9 同款）。
- `applyOpts`：`opts.CityKey != ""` 时解析（**在 Seed 落位之后**，保证 random 用最终 seed）。
- **开局重锚纪元**：`StartLocked` 中（`gameStartedAt` 落位处）`r.cityEpochBaseMs = now.UnixMilli()` —— 城市时钟从服务器当前 UTC 时间开始，季节/月相与现实同步；随后仍按 `× TimeRatio` 推进（`cityClockMsLocked` 公式不动）。
  - 未开局房仍用构造期固定纪元（2025-01-01）做占位显示，行为同批次 27。
  - 暂停冻结逻辑不变（`pausedAccumMs` 扣除）。
- `TimeEnv` 追加 `CityGeo *CityGeo`（锁内快照，ws 广播路径透传）。

### 2.3 协议（BuildClientState 新增字段，omitempty 全兼容）

```json
"city_name": "东京",            // 选中城市的中文名（未选不下发）
"city_info": {                  // 选中城市才下发
  "key": "tokyo",
  "name": "东京", "name_en": "Tokyo", "name_ja": "東京",
  "country": "日本", "country_en": "Japan", "country_ja": "日本",
  "lat": 35.6762, "lng": 139.6503,
  "tz_offset_min": 540,
  "sunrise": "06:50", "sunset": "18:45",   // 城市当日（月内插值）HH:MM
  "sunrise_min": 410, "sunset_min": 1125
}
```

- `sunrise/sunset` 每次 BuildClientState 按当前 city_clock_ms 现算（廉价纯函数）。
- 建房载荷：`virtual_city.city_key`（`""`/缺省 = 默认城市；`"random"` = 随机）。

### 2.4 不变量

- `WeatherAt` / `CityDayIdx` 沿用批次 27 固定纪元派生（天气确定性不随开局纪元改变 —— 天气本来就是 `f(seed, 固定纪元日序)`）。
- `SeasonAt` 用城市时钟月 → 开局即现实当季。
- Agent 感知城市日期（agent_runner 城市时钟 Format）自动变为现实日期，零改动。

## 3. 前端设计（ClientWeb）

### 3.1 建房弹窗（VirtualCityCreateRoomModal）

- 时间比例上方新增「城市」下拉：默认虚拟城市（`""`）→ 20 城（显示中文名，如既有 `📋 调研` 硬编码先例）→ 🎲 随机（`"random"`）。
- 选中真实城市时 hint 行追加城市摘要（`{name}（{country}）· {lat},{lng}`）。

### 3.2 城市时间单例（cityTimeStore）

- 新增 `tzOffsetMin` + `sunTimes`（rise/set 01 分数）与 `setCityGeo()` 写入器；`sample()`：
  - `timeOfDay01 = ((cityMs + tzMs) % DAY + DAY) % DAY / DAY`（默认 tz=0，旧行为逐分不差）；
  - 返回 `sunrise01/sunset01`（无城市 = 0.25/0.75 缺省 = 批次 27 的 6:00/18:00）。
- `resetCityTime` 一并复位。

### 3.3 昼夜引擎（engine3d/DayNightCycle — 游戏无关扩展）

- `DayNightSample` 新增可选 `sunrise01?/sunset01?`（缺省 0.25/0.75）；
- 太阳角：`theta = π × clamp01((tod01 − rise) / (set − rise))` —— 日出→0、日落→π；夜间越界 sin<0 沉落地平线下（原有 dayFactor/晨昏配色/月光反相逻辑全部复用，零回归）。
- 引擎仍不感知"城市"概念，只认两个数值参数（CLAUDE.md §2.1 规则 5 不破）。

### 3.4 主界面（VirtualCityGamePage / CityClockText）

- 顶栏标题：`city_name`（按当前语言从 city_info 三语字段取）替换「虚拟城市」；
- 新增城市信息徽章：`🌅 {sunrise} · 🌇 {sunset}`，tooltip 带国家/经纬度/时区；
- `CityClockText`：有城市时按城市时区格式化（`ms + tzMin*60000` 走 UTC getters）；默认城市沿用浏览器本地格式（零回归）；
- 帧到达 effect：`setCityGeo(city_info)` 写入单例（驱动昼夜与显示）。
