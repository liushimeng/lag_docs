## 1. 定位与范围

阶段 6 交付「融券做空子系统」：玩家对唯一标的 `stock_index`（`ShortSymbol`，
`Market.StockIndex` 单一标的口径，元/份）开空仓获利/对冲。这是本游戏中**首个
杠杆类空头工具** —— 与做多资产（股票/基金/转债/CD）配对后，玩家才拥有完整的
多空表达能力，市场情绪面（融券余额/强平笔数）也随之下发 view。

- 纯引擎层：无锁、无 goroutine、无 IO、**零 rand 消费**（价格来自
  `Market.StockIndex`）—— 固定种子存量对局回归零偏移。
- **R6-1 双护栏**约束全房融券规模（§3）；**强平线**约束单头寸尾部风险（§4）。

## 2. broker 记账模型（关键取舍）

资金流经 `w.Pay`（I1 守恒），实体为 `EntityMarket`（LiberalMarket 券商承接）：

| 时点 | 流向 | 科目 | 金额 |
|------|------|------|------|
| 开仓 OpenShort | seat → market | CatBuy「融券开仓保证金」 | 市值 × 50% |
| 月度利息 | seat → bank | CatInterest「融券利息」 | 当期市值 × 8%/年 ÷ 12 |
| 平仓(主动/强平) | market → seat | CatSell「融券平仓结算」 | settle（§4.2） |

**卖券所得留存 broker 不落地**：开仓时 10000 份 × 3.50 元的「卖出款」 35,000 元
**不进入玩家现金** —— 玩家仅付出保证金 17,500 元（50%）。这是现实两融的简化：
券商代持卖券款作为履约担保，平仓时才统一轧差结算。若卖券款落地，玩家将获得
无成本流动性（等于 2 倍杠杆），破坏 I1 口径下的现金语义。

`FinancingBalanceCNY()`（short_selling.go:138-149）：融资余额 = **全房玩家贷款
余额 Σ Loans[].Balance + `ShortFinancingBaseCNY`（1000 万券商融出基数）** ——
玩家贷款为消费性融资、非两融口径，基数代表券商体系对全市场的融出规模，
使 R6-1② 分母在玩家零贷款时仍有合理量级。

## 3. R6-1 双护栏（OpenShort 开仓校验，short_selling.go:167-181）

```
① 单只融券余额 ≤ 流通市值 5%
   份数口径: openShortShares(symbol) + shares ≤ ShortFloatCapShares()
            = ShortFloatShares(2000 万份) × 5% = 100 万份
② 整体融券/融资余额比 ≤ 30%
   ShortBalanceCNY() + shares×price ≤ 30% × FinancingBalanceCNY()
   ShortBalanceCNY = Σ open 份数 × 当前股指(元)
```

- 拒绝码 `ErrWealthListingInvalid`，错误消息含护栏明细（份数/金额对照）。
- 测试 8 数值例（股指 3.50、融资基数 1000 万）：① 110 万份 > 100 万份拒绝；
  ② 90 万份 × 3.50 = 315 万 > 300 万（= 30% × 1000 万）拒绝；20 万份合规通过；
  已持 20 万份再开 70 万份（份数 ≤ 上限但余额 315 万 > 300 万）仍被 ② 拒绝。

参数校验序：玩家存活 → symbol 必须 `stock_index` → 份数 ≥ `ShortMinShares`(100)
→ ShortBook 非 nil → ① → ② → 现金 ≥ 保证金。头寸 ID `S<n>`（seq 自增，按开仓序）。

## 4. 强平线与平仓结算

### 4.1 触发（ShortMonthlyStep ②，short_selling.go:259-267）

```
浮亏 loss = (当前股指 − EntryPrice) × Shares
触发:   loss ≥ 70% × Margin        // ShortMarginCallLossRatio, ≈ 股价 +35%
保证金 = 开仓市值 × 50%             // ShortMarginRatio
```

强平调 `settleShort(pos, price, ShortStatusMarginCall)`，`MarginCallsLastMonth++`，
`market` 类事件播报。测试 7 数值例：10000 份 @3.50 开仓（保证金 17,500），
股价 ×1.36 → 浮亏 12,600 ≥ 12,250 → 强平，返还 4,900（= 17,500 − 12,600）。

### 4.2 结算（settleShort，short_selling.go:202-215，主动/强平共用）

```
pnl    = (EntryPrice − ClosePrice) × Shares
settle = max(Margin + pnl, 0)       // 钳 0
RealizedPnL 记 pnl 原值(未钳); market → seat CatSell
```

**亏损封顶 70%×保证金、极端路径 settle≥0 兜底**：月度强平检查发生在月结时点，
月度间暴涨 > 2× 的路径浮亏可超过保证金 —— settle 钳 0 保证**玩家最大损失 =
已付保证金**（尾部风险由 broker 承担，虚拟做市商吸收）。`CloseShort`（主动平仓，
short_selling.go:218-235）按持仓 ID + seat 匹配，非 open 状态拒绝重复平仓。

## 5. 融券利息（ShortMonthlyStep ①，short_selling.go:252-258）

- `ShortBorrowAnnualRate = 8%/年`，**按当期市值计息**（非开仓价）：
  `fee = Shares × 当前股指 × 0.08/12`，四舍五入到元，`CatInterest` 扣款 +
  `pos.BorrowFeeCNY` 累计。已平仓头寸（非 open）不计息、不重平（测试 7 末段）。

## 6. 月度推进与台账

`ShortMonthlyStep`（short_selling.go:241-269）为 SettleMonth **⑥B** 第 4 位
（settlement.go:168）：① 逐 open 头寸计息 → ② 逐 open 头寸强平检查。
`LastStepMonth` 记当月戳（§130 接线验证锚点）、`MarginCallsLastMonth` 月初清零
重计。`ShortBook.Positions` **保留已平仓头寸**（终态 closed / margin_call 可回看，
RealizedPnL / BorrowFeeCNY 留档）。nil / w nil / Market nil 安全。
