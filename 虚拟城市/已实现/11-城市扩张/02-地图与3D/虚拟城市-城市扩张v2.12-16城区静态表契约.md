## 1. 为什么需要本契约

城区 id 是贯穿全栈的**主键级标识**，被以下链路消费：

- **view 输出顺序**：`game.state.market.districts` 按 `DistrictDefs` 数组顺序输出（`districts.go` 头注释 L4–5）；
- **城市背景层**：`city` 包按数组下标聚合人口（`districtNames[i]` ↔ 玩家/居民 `district` 字段的下标语义）；
- **职业卡校验**：`profession.Card.Validate()` 经 `validDistrict` 拒绝非法区 id；
- **前端渲染**：`WEALTH_DISTRICTS` 顺序即 3D 场景/小地图/面板遍历顺序。

任何一方顺序错位 = 居民落错城区、房价对错行、面板串行。因此四方**逐字对齐**（id、顺序），并由 Go 测试 + §130 grep 双重守卫。

## 4. 各副本同步策略

### 4.1 前端 `WEALTH_DISTRICTS`（types/wealth.ts）

字段一一对应（字段名前后端不同但语义相同）：

| 后端 `DistrictDef` | 前端 `WealthDistrictDef` |
|--------------------|--------------------------|
| `ID` | `id` |
| `NameCN` | `nameZh` |
| `X` / `Z` | `x` / `z` |
| `Beta` | `houseBeta` |
| `BasePriceWan` | `basePriceWan` |
| `Color` | `color` |

派生导出（前端-only，扩表自动跟随）：`WEALTH_DISTRICT_IDS`（L1079–1080）、`wealthDistrict(id)`（L1082–1084）、`districtCenter(id)`（L1087）。`WealthDistrictId` union（L13–17）必须同步扩——`tsc --noEmit` 会在 `DISTRICT_FLOORS: Record<WealthDistrictId, ...>` 等 Record 键缺失时报错，形成类型层守卫。

### 4.2 `city` 包（不 import wealth，独立维护）

`city` 与 `wealth` 是同 game 下兄弟包，为避免反向依赖环（`wealth` → `city` 已存在），`city` 不 import `wealth`，独立维护两份：

- `city/calibration.go` L28：`districtCount = 16`（编译期数组长度，改小立即编译错误）；
- `city/backdrop.go` L232：`districtNames` 中文名数组，**顺序必须与 `DistrictDefs`/`districtIDs` 完全一致**（`DistrictPop` 快照按下标对齐下发 `game.state.city.districts`）。

同步策略与既有 `loader` 的 `districtIDs` 同款（`backdrop.go` L226–231 注释原文）。

### 4.3 `profession` 包（不 import wealth，独立维护）

`profession/card.go` L74–79：`districtIDs` 英文 id 切片，供 `validDistrict(id)`（L81）校验职业卡 `district` 字段。`profession` 不得反向 import `wealth`（`wealth` import `profession`，反向即环）——两处同步由 `loader_test` 覆盖（`card.go` L72 注释）。

### 5.3 前端类型守卫

`tsc --noEmit` 下 `Record<WealthDistrictId, [number, number]>`（`cityScale.ts` L23 `DISTRICT_FLOORS`）要求 union 每个成员都有键——漏配新区楼层区间直接编译失败；`wealthKeys.ts` 的 `WealthDict` 接口要求三语 locale 文件键齐全（i18n 层守卫）。
