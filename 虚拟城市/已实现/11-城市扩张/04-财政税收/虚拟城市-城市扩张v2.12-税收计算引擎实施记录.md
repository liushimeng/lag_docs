## 1. 一句话摘要

国库税收 = **七税聚合**：个税 + 社保（复用月结步骤 4 已缴快照，只汇总不重扣）+ 印花税 + 增值税 + 企业所得税 + 消费税 + 交易税（宏口径课税，R4-2 月末一次清算，不逐笔回溯扣款）。全部确定性算术，零 rand。

## 2. 设计动机：R4-2 聚合一次性清算

阶段 4 之前居民只有两笔税：月结步骤 4 的个税（`CatTax`）与社保（`CatSocial`），逐座位 seat→gov 缴纳。阶段 4 要把政府收入面扩到七税，若每笔交易/工资即时计税，则：

- 每笔 Ledger 写入都要回溯改写（stamp/trade 税嵌进交易路径，跨 P2 交易/拍卖/议价多入口，漏点风险高）；
- 逐笔浮点取整误差累积，破坏确定性对局回归。

R4-2 选择**月末一次清算**：日历月内所有经济活动照常发生（不动任何既有路径），月末 `CollectMonthTax` 扫一遍快照/流水/宏口径即可。代价是税收与课税行为有一个月的「账面滞后」，对月度粒度的模拟可接受。

## 3. 七税明细（TaxCounter，treasury.go L74–91）

```go
type TaxCounter struct {
    IncomeTaxTotal    int64 // 个税(汇总座位已缴 MonthlyIncomeTax)
    SocialSecurityTot int64 // 社保(汇总座位已缴 SocialSecurity)
    StampTaxTotal     int64 // 印花税(股票/房产交易流水 × StampTaxRate)
    VatTotal          int64 // 增值税(企业营收 × VatRate)
    CorporateTaxTotal int64 // 企业所得税(企业利润 × CorporateTaxRate)
    ConsumptionTaxTot int64 // 消费税(奢侈档生活支出 × ConsumptionTaxRate)
    TradeTaxTotal     int64 // 交易税(玩家间成交 × TradeTaxRate)
}
```

`Total()`（L85–91）七项求和（nil receiver 返回 0）。`MonthlyCounter` 挂在 `TreasuryState` 上，每次 `CollectMonthTax` 开头 `*c = TaxCounter{}` 清零（L124），不跨月累积。

### 3.1 税率常量（L41–47）

| 常量 | 值 | 税基 | 口径 |
|------|----|------|------|
| `VatRate` | 0.06 | `w.Labor.RevenueCNY`（企业部门营收） | 小规模纳税人简化档 |
| `CorporateTaxRate` | 0.15 | `max(0, RevenueCNY − WageBillCNY)`（企业应税利润） | 高新简化档 |
| `StampTaxRate` | 0.001 | 当月 `CatBuy` 流水（股票/房产买入） | 证券/不动产交易印花 |
| `ConsumptionTaxRate` | 0.10 | 奢侈档（`ConsumptionLevelSafe()==3`）座位当月生活支出 | 只课奢侈档，生存型消费免税 |
| `TradeTaxRate` | 0.001 | 当月 `CatTrade` 流水（玩家间成交额） | 场内交易税 |

## 4. CollectMonthTax 三段式（L116–163）

```
CollectMonthTax(w) → total
  ① 遍历存活座位      个税 += p.Monthly.Tax
                       社保 += p.Monthly.Social
                       消费税(奢侈档) += livingExpenseOf(p) × 10%
  ② 扫描当月 Ledger    印花税 += Σ CatBuy 流水 × 0.1%
                       交易税 += Σ CatTrade 流水 × 0.1%
  ③ Labor 部门口径     增值税 = RevenueCNY × 6%
                       企业所得税 = max(0, RevenueCNY − WageBillCNY) × 15%
  → t.Cash += total;返回 total
```

- **① 个税/社保/消费税**（L127–136）：只统计 `p.Alive` 座位。个税/社保直接取 `p.Monthly.Tax / p.Monthly.Social` 月结快照——**不重算、不重扣**（见 §5）。消费税税基 `livingExpenseOf(p)` 从 `p.Monthly.Detail` 取 `Key == "living"` 且金额为负的明细求和（L166–174），无明细 → 0。
- **② 印花/交易税**（L139–149）：`w.Ledger.MonthEntries(w.Month)`（ledger.go L275）过滤 `IsSeatEntity(e.From)` 的条目，按 `CatBuy` / `CatTrade` 分类乘税率（`+0.5` 四舍五入取整）。
- **③ 增值税/企业所得税**（L152–158）：`w.Labor == nil` 时整段跳过（P0 回退安全）。利润 ≤ 0 不课企业所得税。

**全路径不调用 `w.Pay`、不扣任何座位现金**——国库收入侧与座位现金流解耦（个税/社保在步骤 4 已扣过；宏口径税不从座位回溯追缴）。

### 4.1 ② 段两类税基的区分

| Ledger 类别 | 语义 | 课税 | 对应交易入口 |
|------------|------|------|-------------|
| `CatBuy` | seat → market 买入资产（股票/房产等） | 印花税 0.1% | 市场买入订单 |
| `CatTrade` | 玩家间资产成交（单条流水：From=买方座位 → To=卖方座位） | 交易税 0.1% | P2 挂单成交（listing.go L496/L536）/ 拍卖成交（auction.go L343），均经 `PaySeatToSeat`（listing.go L193） |

只看 `From` 一侧：市场卖出（market → seat，`CatSell`）的 From 不是座位，天然被 `IsSeatEntity(e.From)` 过滤——与真实证券印花税「卖方单边征收」相反，本实现取「买入/付方流水」口径（虚拟城市玩家的主操作是买入）。

> **与既有 `CatTradeFee` 的关系**：P2 成交时买方已实时缴纳「交易增值税」到 `EntityGov`（listing.go L498，`CatTradeFee` 类别）——那是阶段 4 之前就有的玩家侧交易费；⑨A 的 `TradeTaxTotal`（0.1%）是国库侧对同一成交额的宏口径汇总，**不经 Ledger、不追加扣款**。两者并存：玩家现金流只承担 `CatTradeFee`，国库收入口径同时计入宏口径交易税（与增值税/企业所得税同为宏口径课税，见总览 §6 通道②）。

### 4.2 七税数据源一览

| 税种 | 数据源 | 粒度 | 为 0 的条件 |
|------|--------|------|------------|
| 个税 | `p.Monthly.Tax`（月结步骤 4 快照） | 逐座位 | 工资 ≤ 起征线 / 座位死亡 |
| 社保 | `p.Monthly.Social`（同上） | 逐座位 | 无工资 / 死亡 |
| 消费税 | `livingExpenseOf(p)` × 10% | 逐座位（奢侈档） | 档位 ≠ 3 / 无 living 明细 |
| 印花税 | 当月 `CatBuy` Ledger | 逐条流水 | 当月无资产买入 |
| 交易税 | 当月 `CatTrade` Ledger | 逐条流水 | 当月无玩家间成交 |
| 增值税 | `Labor.RevenueCNY` × 6% | 部门总量 | `w.Labor == nil`（P0 回退）或营收 0 |
| 企业所得税 | `max(0, Revenue − WageBill)` × 15% | 部门总量 | 利润 ≤ 0 / Labor 为 nil |

## 5. 与既有税函数的复用关系（不重复造轮子）

| 既有函数 | 位置 | 阶段 4 用法 |
|----------|------|------------|
| `MonthlyIncomeTax(salary)` | `engine.go` L366 | 月结步骤 4（settlement.go L353）逐座位计算并 `w.Pay(seat→EntityGov, CatTax)` 缴纳；`CollectMonthTax` **只读** `p.Monthly.Tax` 快照汇总，不调用此函数重算 |
| `SocialSecurity(salary)` | `engine.go` L388 | 同上：步骤 4 已缴 `CatSocial`；国库只汇总 `p.Monthly.Social` |
| `PensionContribution(salary)` | `engine.go` L396 | 不入 TaxCounter——8% 养老金缴存是个人账户资产（gov→seat 回流 `CatPension`），不是政府可支配收入 |
| `ConsumptionLevelSafe()` | `player.go` | 消费税档位判定（==3 奢侈档） |

**快照口径的关键收益**：个税/社保的**计算**与**缴纳**仍单点在月结步骤 4，国库汇总与课税解耦——未来调整个税税率表只改 `MonthlyIncomeTax` 一处，TaxCounter 自动跟随。

### 5.2 典型工资的个税/社保（纯函数实算值）

| salary | 社保（×10.5%） | 应税所得 | 个税 | 入 TaxCounter 口径 |
|--------|---------------|---------|------|-------------------|
| 6,000 | 630 | 370 | 11 | 每座 641/月 |
| 10,000 | 1,050 | 3,950 | 185 | 每座 1,235/月（单测合成场景） |
| 20,000 | 2,100 | 12,900 | 1,170 | 每座 3,270/月 |

单测 `treasuryWorld`（treasury_test.go L16–23）用 salary 10000 合成 12 座位——`TestTreasuryCollectTax` 的期望值 12 × 185 = 2,220（个税）与 12 × 1,050 = 12,600（社保）即由此得出。

### 5.3 为什么个税/社保不走宏口径

个税/社保在阶段 4 之前已是**真实现金流**（座位现金实际减少、gov 实际入账 Ledger），具备玩家可感知性。若阶段 4 改为宏口径（对 Labor 工资总额课税），座位现金流会突变、存量对局回归全偏移。故维持「座位已缴 → 国库月末汇总」的两段式：**缴纳语义在步骤 4，收入归属在 ⑨A**。

## 6. 税收入库与月度闭环

```
CollectMonthTax 返回 total
  → TreasuryState.Cash += total        (L160–162)
  → 当月 History.Revenue = total       (SettleTreasuryMonth ⑨A/⑨E)
  → LastMonthRevenue = total           (下月财政支出上限的基准)
```

税收是国库现金的唯一「流入」来源（R4-1：国债发行不产生现金流入，见[国债文档](虚拟城市-城市扩张v2.12-国债发行与财政纪律实施记录.md)）。

### 6.1 全月数值走查（TestTreasuryCollectTax 场景）

12 座位 × salary 10000 + `Labor.RevenueCNY = 1,000,000` / `WageBillCNY = 120,000`（测试注入）：

```
① 个税     12 × 185   =   2,220
   社保     12 × 1,050 =  12,600
   消费税   无奢侈档座位 =       0
② 印花税   无 CatBuy   =       0
   交易税   无 CatTrade =       0
③ 增值税   100万 × 6%  =  60,000
   企业所得税 88万 × 15% = 132,000
─────────────────────────────────
⑨A 合计入库            = 206,820  → TreasuryState.Cash += 206,820
```

二次调用 `CollectMonthTax` 期望仍为 206,820（L95–97）——聚合器月初清零（L124），不跨月累积、不重复入库。

## 7. 精度与确定性

- 所有税率乘法 `int64(float64(x)*rate + 0.5)` 四舍五入取整，单税最小计税单位 1 元；
- 累加顺序固定（座位序遍历 + Ledger 顺序扫描），无浮点累加器（累加在 int64 域）；
- 零 rand：`TestTreasuryDeterministic` 同种子 6 个月 History 逐条一致。

## 9. 边界与已知简化

1. **消费税只覆盖「生活支出」明细**（`Key=="living"`）：股票买入走 `CatBuy`（课印花税），其他消费类目（`CatConsume`/`CatStudy` 等）不课消费税——奢侈档判定以生活档位为准，简化为单一税基。
2. **增值税/企业所得税按 Labor 上月口径**（与 treasury.go L114 注释一致）：`LaborMonthStep`（settlement.go L67，步骤 ②.0）在当月座位月结**之前**执行，内部按 `month := w.Month − 1` 扫描**上一个完整结算月**的 to-firms 流水 × 2.5 刷新 `RevenueCNY`（labor.go L103–105）——⑨A 读到的宏观税基滞后一个月。与 R4-2 的「账面滞后」同性质，月度粒度可接受。
3. **死亡座位不纳税**：① 段 `!p.Alive` 跳过；死亡当月已缴的个税/社保仍在当月 Ledger 中，但不再计入国库汇总口径（继承人受益的转移支付照常）。
