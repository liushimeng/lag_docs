## 1. 一句话摘要

新增 `TreasuryState` 政府财政国库（初始现金 500 万元），挂在 `World.Treasury`，随 `SettleMonth` 月末钩子 ⑨ 执行「税收汇总 → 转移支付 → 财政支出 → 国债月度处理 → 历史记录」五步闭环。纯引擎层：无锁、无 goroutine、无 IO、**零 rand 消费**——固定种子存量对局回归零偏移（§197 反例教训：引擎新增路径不得动 `w.Rand`）。

## 2. 设计动机

阶段 3 建成央行货币政策工具箱后，虚拟城市宏观面只有「货币」一条腿：居民缴税（月结步骤 4，seat→gov）与养老金回流（gov→seat）是仅有的政府现金流，财政支出侧完全空白。阶段 4 补齐「财政」第二条腿——税收汇总入国库、四类转移支付、五类预算支出、国债簿记——使政府成为有预算约束、有赤字纪律的经济主体，为阶段 4+ 财政部长 Bot LLM 接入预留受参数约束的执行原语。

### 2.1 三条硬约束（R4 系列）

| 约束 | 内容 | 落点 |
|------|------|------|
| **R4-1 禁止央行透支** | 财政对 `CentralBankState` **零写入**（唯一触碰是国债定价只读 `LPR5Y()`）；`gov:treasury` 与央行/银行/市场/企业/保险/系统外之间不存在任何 Ledger 通道；国债自持记账，发行不产生现金流入 | `ledger.go` L169–183 白名单 + `sovereign_bond.go` 头注释 |
| **R4-2 聚合一次性清算** | 七税不逐笔计算/扣款，月末 `CollectMonthTax` 一次遍历汇总，避免逐笔耗时与双重扣款 | `treasury.go` L112–163 |
| **R4-3 防躺平** | 失业救济 1–3 月等待期计 0、超 12 月系数衰减 0.7；低保需累计失业 ≥ 3 月门槛 | `transfer_payment.go` L26–37 |

## 3. TreasuryState 生命周期（treasury.go L50–110）

### 3.1 结构体字段（L50–71）

```go
type TreasuryState struct {
    Cash             int64               // 国库现金(元)
    BondsOutstanding int64               // 国债余额(sovereign_bond.go 簿记)
    LastMonthRevenue int64               // 上月财政收入
    LastMonthExpense int64               // 上月财政支出
    DeficitRun       int                 // 连续赤字月数(盈余清零)
    MonthlyCounter   *TaxCounter         // 当月税收聚合器(R4-2)
    Bonds            []*SovereignBond    // 存量国债明细
    EduCapital       int64               // 教育累计投入
    HealthCapital    int64               // 医疗累计投入
    InfraCapital     int64               // 基建累计投入
    History          []TreasuryMonthRecord // 最近 24 个月快照(环形)
}
```

### 3.2 关键常量（L30–38）

| 常量 | 值 | 语义 |
|------|----|------|
| `TreasuryInitialCash` | 5,000,000 | 初始国库现金 500 万元（政府启动资金） |
| `TreasuryHistoryLen` | 24 | History 环形缓冲长度（最近 24 个月） |
| `TreasuryMinMonthlyExpense` | 20,000 | 月支出下限：首月 `LastMonthExpense=0` 时不允许「阈值=0 → 永不发债」的退化 |

### 3.3 生命周期三阶段

1. **构造**：`NewTreasury()`（L105–110）——现金 500 万、聚合器非 nil、无国债无历史。`NewWorld` 初始化时接线（`engine.go` L205 `Treasury: NewTreasury()`）。
2. **月结**：`SettleMonth` ⑨ 钩子调 `SettleTreasuryMonth(w)`（L185–219）——每步可能改 Cash/Counter/Bonds/History。
3. **下发**：`BuildClientState` 透出 `treasury` 子结构（`view.go` L505–515），政府/观战者全量可见，无座位隐私。

`TreasuryState` 为 nil 时（存量对局反序列化兜底）`SettleMonth` 判 `w.Treasury != nil` 跳过（`settlement.go` L146）。

## 4. 月结编排 ⑨A–⑨E（SettleTreasuryMonth，L185–219）

```
SettleTreasuryMonth(w)                     [调用方持房间锁]
  ⑨A CollectMonthTax(w)        税收七税汇总 → Cash += 总额
  ⑨B PayTransferPayments(w)    四类转移支付(返回 总额, 受益人数)
  ⑨C ExecuteFiscalSpending(w)  五类预算支出(公共服务+财政直发)
  ⑨D MonthlyBondStep(w)        付息 → 到期兑付 → 必要发行
  ⑨E History 追加 + 裁尾(环形 24 条) + DeficitRun 更新
```

- **顺序锁定**：先收入（⑨A）后支出（⑨B–⑨D），使当月税收即时可用于当月转移支付；⑨D 在支出后再评估流动性缺口，发债决策更真实。
- **⑨E 赤字预警**（L211–218）：`Deficit = Revenue − Expense < 0` 时 `DeficitRun++`，盈余清零；`DeficitRun == 3` 时 `w.emitEvent("policy", -1, ...)` 播报「财政预警:连续 3 个月赤字…政府考虑发债融资」。
- **TreasuryMonthRecord**（L94–102）：`Month / Revenue / Expense / Deficit / TransferPaid / BondService / Beneficiaries` 七字段单月快照，是 History 环形缓冲的元素类型。

## 5. 与 SettleMonth 接线（settlement.go L140–148）

**接线位置的设计意图**：

- **在 ④.6 之后**：④.6 的 `ComputeSociety`（L135–138）计算贫困率/失业率等社会结构统计，财政月结不应污染其口径。
- **在 ④.65 之前**：转移支付/财政直发产生 `CatWelfare` Ledger 条目，必须赶在 `RecordFlowStat`（L150–152）聚合本月流水前进场，才能出现在当月资金流向视图（`distribution.go` L72 `CatWelfare: {FlowNodeGov, FlowNodePlayer}`）。
- **`economy_enabled=false` 整体跳过**：P0 回退模式（无经济循环）不跑财政，`TestSettleMonth_TreasuryWired` 后半段锁定此回归。

## 5.2 数值走查（单测合成场景，TestTreasuryCollectTax）

12 座位 × salary 10000、`Labor.RevenueCNY = 100 万 / WageBillCNY = 12 万`（测试注入值）：

| 税种 | 计算 | 金额（元） |
|------|------|-----------|
| 个税 | 12 × 185（`MonthlyIncomeTax(10000)`：应税 3950 × 10% − 210） | 2,220 |
| 社保 | 12 × 1050（`SocialSecurity(10000)`：10000 × 10.5%） | 12,600 |
| 增值税 | 1,000,000 × 6% | 60,000 |
| 企业所得税 | (1,000,000 − 120,000) × 15% | 132,000 |
| **⑨A 合计入库** | | **206,820** |

随后的同月支出（首月无国债）：⑨B 转移支付按实际座位状态逐人计发；⑨C 预算 = min(现金 × 5%, `LastMonthRevenue` × 110%)——首月 `LastMonthRevenue = 0` → 预算 = 0 → ⑨C 首月不支出。

> **首月边界**：`monthFiscalBudget`（fiscal_policy.go L86–106）读的 `LastMonthRevenue` 是**上月**收入（⑨E 才回写当月值），首月为 0 → `byRevenue = 0` → 预算 = min(25 万, 0) = 0。这是「量入为出」的有意设计：政府第一个月只收税不花钱，第二个月起才有预算基准。

## 6. 记账口径：四条通道（防双重计数，treasury.go L13–22 头注释）

| 通道 | Ledger？ | 现金流 | 理由 |
|------|---------|--------|------|
| ① 个税/社保汇总 | 否（只读快照） | 座位已在月结步骤 4 付至 `EntityGov`；国库只汇总入 `TaxCounter` | 不重复扣座位现金，避免二次征税破坏既有 I1 语义 |
| ② 印花/增值税/企业所得税/消费税/交易税 | 否 | 宏口径课税（对经济总量计税），只入国库现金 | R4-2 聚合清算，不逐笔回溯扣款 |
| ③ 财政采购（教育/医疗/基建）+ 国债还本付息 | **否** | 国库账内核算（Cash 直减 + Capital/BondService 累计） | `FirmScale=2.5`（labor.go L14）已含「政府+投资+外需」倍数——再记 to=firms 会双重计入企业营收，污染 `Labor.RevenueCNY` |
| ④ 转移支付/财政直发 | **是**（唯一走 `w.Pay` 的政府支出） | `from=EntityGovernment → seat, category=CatWelfare` | 触及座位现金，I1 守恒由 Pay 保证 |

## 10. 确定性保证（零 rand 消费）

财政全路径（税收/转移支付/支出/国债）不调用 `w.Rand`：

- 派发顺序 = 座位序遍历 `w.Players`（`[MaxSeats]*Player` 固定座位数组，engine.go L175，切片迭代天然确定——`PayTransferPayments` / `CollectMonthTax` 的 `for _, p := range w.Players`）；
- 国库不足时按座位序/发行序截断（不透支），无随机重排；
- `TestTreasuryDeterministic`（treasury_test.go L415–446）：同种子 20260921 各跑 6 个月，Cash / BondsOutstanding / History 逐条 `!=` 断言全等；顺带锁定 History 环形缓冲 25 次月结只保留 24 条。

## 12. 设计取舍备忘

1. **国债 60 月期限 × 游戏 420 月终局**（engine.go L142 主钟 `1..420`）：前 360 月发行的国债可在局内到期兑付，末 60 月发行的成为「永续悬置义务」——体现财政跨期约束而不强迫终局清算。
2. **公共采购不回流企业**：`FirmScale=2.5` 已把居民消费放大为 GDP 口径（含政府+投资+外需），财政采购若再写 `to=firms` 即双重计入（§6 通道③）。
3. **消费税只课奢侈档**（`ConsumptionLevelSafe() == 3`）：简化档位征收，避免对生存型消费课税导致贫困座位螺旋恶化。
4. **`PublicServiceIndex` 代理指标**：`SocietyStats` 无教育/医疗/基建字段，v2.12 以国库侧累计指数代理，v2.13 可上移至 SocietyStats（fiscal_policy.go L186–187 注释）。
