## 1. 一句话摘要

政府支出两条腿：**转移支付**（⑨B，四类按人评估、直达座位现金，`gov:treasury → seat, CatWelfare`）+ **财政支出**（⑨C，五类预算，其中教育/医疗/基建为公共采购账内核算、养老/失业为财政直发）。全部走 `w.Pay` 或 Cash 直减，国库不足按序截断、绝不透支。

## 2. 四类转移支付（transfer_payment.go）

### 2.1 规则总表

| 类型 | 枚举 | 公式 | 资格条件 |
|------|------|------|---------|
| 失业救济金 | `TransferUnemployment` | 2000 × 50% × 系数 = **1000 元/月（全额）** | 仍处失业期（`UnemployedMonths > 0`） |
| 低保补贴 | `TransferLowIncome` | `max(0, 1200 − 月收入) × 50%` | 累计失业 ≥ 3 月 **且** 月收入 < 贫困线 |
| 儿童津贴 | `TransferChildAllowance` | 200 元 × 6 岁以下孩子数 | `BirthMonths` 中出生 < 72 主钟月的孩子 |
| 养老金 | `TransferPension` | `PensionCNY ÷ 139` | `w.Age() >= 60` 且个人账户余额 > 0 |

常量定义 L21–44：`BasicLivingCostCNY=2000` / `UnemploymentBenefitRate=0.5` / `UnemploymentWaitMonths=3` / `UnemploymentDecayFrom=12` / `UnemploymentDecayFactor=0.7` / `PovertyLineCNY=1200` / `LowIncomeCoverRate=0.5` / `LowIncomeMinUnemployed=3` / `ChildAllowanceCNY=200` / `ChildUnderAgeYears=6` / `PensionAnnuityDivisor=139`。

### 2.2 失业救济金：R4-3 等待期 + 递减系数（L73–109）

```
unemploymentCoef(累计失业月数):
  1–3 月   → 0     (等待期:短期失业由储蓄/失业金个人承担)
  4–12 月  → 1.0   (全额 2000×50% = 1000 元/月)
  >12 月   → 0.7   (长期失业递减 → 700 元/月,防躺平)
```

**计数语义**（易错点）：`payUnemployment`（L98–109）先推进 `p.UnemployedAccumMonths++` 再按**新计数**取系数——预置 0/1/2 的座位计发时计数为 1/2/3，待遇均为 0（等待期）；预置 3 计发时为 4 → 首笔全额。

**两个字段正交**（player.go L183/L188）：

| 字段 | 语义 | 维护方 |
|------|------|--------|
| `UnemployedMonths` | **剩余**失业月数（失业事件设置，每月递减，0=再就业） | events.go L61/L81–82 |
| `UnemployedAccumMonths` | **终生累计**失业月数（月末仍失业 +1，只增不减） | transfer_payment.go L102 |

`UnemployedAccumMonths` 是**终生累计**口径（递减系数防躺平必须用累计而非当期），且在岗月不递增（L99–101 在职直接返回 0 不累计）。

**持续失业 15 个月的救济时间线**（`payUnemployment` 先 +1 再计发）：

| 失业月序 N（计发时累计值） | 系数 | 当月实发 | 累计已领 |
|--------------------------|------|---------|---------|
| 1 / 2 / 3 | 0（等待期） | 0 | 0 |
| 4 | 1.0 | 1,000 | 1,000 |
| 5–12 | 1.0 | 1,000 × 9 | 10,000 |
| 13 | 0.7 | 700 | 10,700 |
| 14 / 15 | 0.7 | 700 × 2 | 12,100 |

长期失业者月收入（救济 700 + 低保补差 ≤ 600）远低于典型 salary 10,000 的在职水平——再就业激励始终为正。

### 2.3 低保补贴：R4-3 双门槛（L113–130）

1. `UnemployedAccumMonths >= 3`——有稳定工作史的贫困者不领低保（低保面向失业致贫，不是普遍福利）；
2. `p.Monthly.Income < 1200`——补差 = `max(0, 1200 − income) × 50%`（收入 400 → 补 400；收入 0 → 补 600；收入 ≥ 1200 → 0）。只补缺口一半，保留劳动激励。

### 2.4 儿童津贴（L134–140 + L85–93）

`childrenUnder6(p, w.Month)`：遍历 `p.BirthMonths`（events.go L124 生育事件追加的主钟月份），`month − m < 72` 计数。**卡面初始子女不计**——`BirthMonths` 只追踪对局内生育事件，初始 2 孩家庭不因此多领（简化口径，避免卡面字段与事件流不一致）。

### 2.5 养老金（转移支付口径，L145–154）

`PensionCNY ÷ 139`，60 岁起。**不减 `PensionCNY`**——与月结步骤 2 的个人账户养老金（`PensionCNY × 0.04/12`，settlement.go L327–328）同口径：账户余额是「计发基数」而非可提取现金，139 仅为年金除数（中国社保个人账户计发月数标准值）。两者叠加构成老年座位的双重养老收入。**标准局可达性边界见 §6.2**。

### 2.6 统一发放通道 pay（L158–165）

```go
func (t *TreasuryState) pay(w *World, seat int, tt TransferType, amount int64) int64 {
    if amount <= 0 || amount > t.Cash { return 0 }   // 国库不足 → 不发,不透支
    w.Pay(seat, EntityGovernment, SeatEntity(seat), amount, CatWelfare, tt.String())
    t.Cash -= amount
    return amount
}
```

### 2.7 PayTransferPayments 月末派发（⑨B，L170–189）

按座位序逐人评估四类（失业 → 低保 → 儿童津贴 → 养老金），单人可叠加多笔；返回 `(发放总额, 受益人数)`——受益人数 = 当月收到**任意一笔**的座位数（History.Beneficiaries）。死亡座位跳过。

## 3. 五类预算支出（fiscal_policy.go）

### 3.1 FiscalBudget 预算五分法（L29–35）

| 类别 | 枚举 | 份额 | 落地方式 |
|------|------|------|---------|
| 教育 | `FiscalEdu` | 30% | 公共采购（账内核算 → `EduCapital`） |
| 医疗 | `FiscalHealth` | 25% | 公共采购（→ `HealthCapital`） |
| 养老 | `FiscalPension` | 20% | **财政直发**（60 岁座位平分，`CatWelfare`） |
| 基建 | `FiscalInfra` | 15% | 公共采购（→ `InfraCapital`） |
| 失业救济 | `FiscalUnemployment` | 10% | **财政直发**（`UnemployedMonths > 0` 座位平分，`CatWelfare`） |

和 = 1.0 由 `TestFiscalBudgetAllocation` 锁定；`fiscalCategoryCount` 哨兵 = 5 防新增类别漏配份额。

> **注意**：⑨B 转移支付（§2）与 ⑨C 财政直发（养老/失业 20%+10% 份额）是**两套并行机制**——前者按规则公式逐人计发（有等待期/门槛），后者按预算份额平分（无等待期）。直发是「普惠底仓」，转移支付是「精准补差」。

### 3.2 支出上限公式（monthFiscalBudget，L86–106）

```
budget = min( Cash × 5%, LastMonthRevenue × 110% )   // 量入为出,允许 10% 小幅赤字
if Cash < 100万: budget /= 2                          // 紧缩减半
budget = clamp(budget, 0, Cash)                       // 不透支(R4-1 精神:国库不为负)
```

| 常量 | 值 | 语义 |
|------|----|------|
| `FiscalSpendCashRate` | 0.05 | 月支出 ≤ 现金 × 5%（防坐吃山空） |
| `FiscalSpendRevenueMult` | 1.10 | 月支出 ≤ 上月收入 × 110%（量入为出 + 10% 赤字容忍） |
| `FiscalAusterityCash` | 1,000,000 | 紧缩线：现金 < 100 万支出减半 |

### 3.3 ExecuteFiscalSpending 执行（⑨C，L112–149）

1. **公共采购**（L123–139）：教育/医疗/基建三类份额 → `EduCapital/HealthCapital/InfraCapital` 累计 + `Cash` 直减，**不写 Ledger**（`FirmScale=2.5` 已含政府需求，防双重计入 `Labor.RevenueCNY`，见总览 §6 通道③）。
2. **财政直发**（L142–147 → `payFiscalDirect` L153–183）：份额预算平分给 eligible 座位（整除，余数留存；`each <= 0` 或无对象 → 0 支出，份额自动留存国库）。资格：养老 = `p.Alive && w.Age() >= 60`；失业 = `p.Alive && p.UnemployedMonths > 0`。
3. 返回实际支出总额（无符合条件直发对象时仅 70% 公共采购落地——`TestFiscalSpendingCap` 场景①）。

### 3.4 PublicServiceIndex 公共服务指数（L188–201）

`(EduCapital + HealthCapital + InfraCapital) ÷ 10000`，clamp [0, 100]——每累计 1 万元投入 +1 点。是教育/医疗/基建投入的可见性指标（view 下发 `public_service_idx`）；`SocietyStats` 暂无对应字段，v2.13 可上移（L186–187 注释）。

### 3.5 财政月数值走查（TestFiscalSpendingCap 场景①）

国库现金 500 万、上月收入 10 万、无 60 岁/失业座位（直发对象为空）：

```
budget = min(500万 × 5% = 25万, 10万 × 110% = 11万) = 11万
① 公共采购(70%): 教育 33,000 + 医疗 27,500 + 基建 16,500 = 77,000
   → EduCapital/HealthCapital/InfraCapital 累计, Cash 直减(不写 Ledger)
② 财政直发(30%): 养老 22,000 + 失业 11,000 → 无 eligible 座位 → 0(份额留存国库)
实际支出 = 77,000;LastMonthExpense 记 77,000(⑨E)
```

紧缩场景②：现金 90 万 < 100 万 → budget = min(4.5 万, 11 万) ÷ 2 = 22,500 → 实际 70% = 15,750。

## 4. 与 I1/I3 守恒的交互

| 支出 | Ledger 条目 | I1 影响 |
|------|------------|---------|
| 转移支付 4 类 + 财政直发 2 类 | `gov:treasury → seat, CatWelfare`（白名单唯一允许方向） | 座位现金 +，国库 Cash −，总量守恒（w.Pay 保证） |
| 公共采购 3 类 | 无 | 国库 Cash −，座位现金不变——公共服务以 Capital 指数形式沉淀 |

国库见底行为：转移支付 `pay` 单笔判定（L159）；财政直发按座位序截断（L174–176）——**都不透支、不产生负债**（发债是唯一融资手段，见[国债文档](虚拟城市-城市扩张v2.12-国债发行与财政纪律实施记录.md)）。

### 4.1 同月三座位对照（⑨B + ⑨C 叠加效果示例）

设定：主钟月 M=100（世界年龄 33 岁，全员同龄——`w.Age()` 是主钟口径，见 §6.2）；座位 A 在职；座位 B 失业第 5 个月（`UnemployedMonths>0`、计发时累计推进到 5，全额带）当月非工资收入 400（如租金）；座位 C 失业第 14 个月（计发时累计推进到 14，衰减带）且 10 个月前生育 1 孩。

| 项目 | A（在职） | B（短期失业低收入） | C（长期失业+幼儿） |
|------|----------|--------------------|------------------|
| ⑨B 失业救济 | 0（在职不累计） | 1,000（第 4 月起全额） | 700（>12 月 × 0.7） |
| ⑨B 低保 | 0（累计 0 < 3 门槛） | 400（(1200−400)×50%） | 600（假设月收入 0） |
| ⑨B 儿童津贴 | 0 | 0 | 200（1 孩 < 72 月龄） |
| ⑨B 养老金（÷139） | 0 | 0（年龄门，§6.2） | 0（同） |
| ⑨C 失业直发（10% 份额平分） | 0 | 参与 | 参与 |
| ⑨C 养老直发（20% 份额） | 0 | 0（年龄门） | 0（同） |
| **当月公式化转移合计** | **0** | **1,400 + 直发** | **1,500 + 直发** |

对照可见分流逻辑：在职者完全自食其力；短期失业者拿全额救济 + 低保补差；长期失业者救济衰减但津贴/低保兜底——两类机制（§3.1 注）互补而非互斥。

## 6. 设计取舍与已知边界

### 6.1 R4-3 的政策意图

等待期（1–3 月 = 0）模拟失业保险免赔期，过滤短期摩擦性失业；递减（>12 月 × 0.7）+ 低保门槛（累计 ≥ 3 月）共同抑制「失业比工作划算」的躺平稳态——全额 1000 元远低于典型 salary 10000，且低保只补缺口 50%。

### 6.2 年龄门的可达性边界（重要）

`w.Age()` 是**主钟世界年龄**（engine.go L294–300：`startAge + (Month−1)/12`，`MasterStartAge = 25`），不是逐座位年龄——全员同龄。标准局 420 个可玩月（engine.go L142 注释）中：

- 可玩月 1..420 对应年龄 25..**59**（月 420 时 `25 + 419/12 = 59`）；
- `finished = w.Age() >= TerminalAge(60)`（settlement.go L214）在 ⑤ 月份 +1 之后判定——年龄 60 只在终局判定的瞬间出现，可玩月内不存在。

因此三处 60 岁门在**标准局内不会打开**：⑨B `payPension`（L146）、⑨C 养老直发资格（fiscal_policy.go L143 `w.Age() >= 60`）、以及阶段 4 之前就存在的月结步骤 2 养老金回流（settlement.go L327 `age >= 60`）——三者共用同一主钟口径，行为一致。

**测试覆盖如实说明**：`payPension` 是四类转移支付中唯一**无直调单测**的（`TestSovereignBondNoCBOverdraft` / `TestSettleMonth_TreasuryWired` 走全链路但年龄门关闭，路径只执行到 `return 0` 分支）。若后续把 `TerminalAge` 上调或延长主钟激活该路径，应同步补直调单测（照 `TestTransferChildAllowance` 的座位注入法）。本阶段文档如实记录此边界，不视为缺陷。

### 6.3 直发平分 vs 公式计发

财政直发用平分（实现简、确定性强），精准性由 ⑨B 转移支付承担；两机制叠加后失业群体的月度政府转移 ≈ 公式金额 + 直发份额。

### 6.4 紧缩先于透支

现金 < 100 万先减半支出而非立即发债——发债（⑨D）在支出之后评估，只有紧缩后仍不足才触发（国债文档 §3）。
