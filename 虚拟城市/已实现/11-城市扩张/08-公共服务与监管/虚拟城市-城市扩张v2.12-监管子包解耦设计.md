## 1. 问题：为什么需要子包

四大监管（证监会/反垄断/消协/隐私）天然要读主包数据：

- 证监会要读 `World.Ledger`（CatBuy/CatSell 流水）与 `Player.Monthly.Income`；
- 反垄断要读/写 `World.SupplyChain`（15 节点 Capacity）；
- 消协要读 `Player.Monthly.Detail`（living/family 支出）。

若直接写在主包 `wealth` 里：监管逻辑与结算逻辑（settlement.go 已 700+ 行）、
公共服务（public_services.go 412 行）继续互相缠绕，单文件直逼 §4 1800 行
上限；且监管规则无法脱离 World 单测。

若放进独立子包并 import 主包拿数据：**`wealth` 已 import `regulators`**
（RegulatorBundle 持有其实例）→ 子包再反向 import 主包 = **循环依赖，
Go 编译器直接拒绝**。

## 2. 方案：子包零反向依赖 + 输入注入

铁律（4 个子包文件头同款声明）：**`regulators` 不 import `wealth` 主包**。
所有 World 数据经两类注入形态进入子包：

### 2.1 值类型输入（数据快照进、结果出）

| 子包 | 输入结构 | 字段（全部基础类型） |
|------|---------|---------------------|
| 证监会 | `TradeRecord`（securities.go:43-48） | Seat / Month / Side / AmountCNY |
| 消协 | `ConsumerRow`（consumer_protection.go:24-28） | Seat / MonthlyIncomeCNY / DoodadExpenseCNY |
| 隐私 | `SurveyAnswerInput`（data_privacy.go:18-22） | Seat / OptionIdx / Reason（字段与 `wealth.SurveyAnswer` 对齐） |

输出同样是纯值类型：`InsiderFine` / `OverconsumeWarning` / `SurveyAggregate`。

### 2.2 接口输入（需要回写的场景）

反垄断必须**写回** Capacity（分拆裁决）——用窄接口注入：

```go
type CapacitySource interface {
    CapacityOf(id string) float64
    TotalCapacity() float64
    SetCapacity(id string, capacity float64)   // 仅分拆裁决时被子包调用
}
```

（antitrust.go:30-34）三方法即子包对"产能数据源"的全部假设——注入 mock
即可脱离 SupplyChain 测试（public_services_test.go:98-109 `mockCapacity`）。

### 2.3 回调输入（按需查询）

证监会罚款封顶需要当月收入——`incomeOf func(seat int) int64` 回调
（securities.go:90），nil 或返回 ≤0 → 封顶 0（免罚）。避免为查一个数
传入整个 Players 数组。

## 3. 适配层：RegulatorBundle（主包侧）

主包 `public_services.go::RegulatorBundle.MonthlyStep`（:262-278）承担全部
"World → 子包"翻译，每监管一步适配：

| 步 | 适配内容 | 位置 |
|----|---------|------|
| ① 证监会 | `Ledger.MonthEntries(w.Month)` CatBuy(From=seat)/CatSell(To=seat) → `[]TradeRecord`；`incomeOf` 闭包读 `p.Monthly.Income`；罚款单 → `w.Pay` + 事件 | stepSecurities（:282-329） |
| ② 反垄断 | `supplyCapacityView{sc: w.SupplyChain}` 实现 `CapacitySource`（CapacityOf/TotalCapacity/SetCapacity 直读直写 Nodes）；nodeIDs 复制后 sort 升序双保险 | stepAntitrust（:358-375）+ supplyCapacityView（:331-356） |
| ③ 消协 | `livingExpenseOf` + `familyExpenseOf` 聚合 → `[]ConsumerRow`；警告 → `policy` 事件 | stepConsumer（:380-401） |
| ④ 隐私 | `MonthlyAudit(w.Month)` 纯计数 | :277 |

`supplyCapacityView` 是无状态 struct 适配器（`struct{ sc *SupplyChain }`），
`TotalCapacity` 按 `sc.nodeOrder` 固定序求和保浮点确定性——这是**同包直读**
的特权（子包拿不到 nodeOrder，只能靠接口的 TotalCapacity 单值）。

## 4. 依赖方向与收益

```
wealth(主包) ──import──▶ regulators(子包)     唯一方向，无环
     │                        │
 World/Ledger/SupplyChain    纯值类型 + CapacitySource + incomeOf 回调
     ▲                        ▲
     └────── RegulatorBundle 适配层 ──────┘
```

收益清单：

1. **可独立单测**：`TestAntitrust_MarketShare` / `TestSecurities_InsiderFine`
   等用裸输入直接驱动，不构造 World——测试即规则文档（60% 市占 → 3 月 →
   ×0.5；60 万反向 → 5000 封顶罚）；
2. **§4 行数纪律**：监管 4 文件合计 466 行，主包只增聚合层 ~180 行，全部
   远离 1800 上限；
3. **规则可枚举**：每个监管的全部常量（触发线/比例/冷却）集中在子包
   const 块，调参不动结算代码；
4. **复用预期**：v2.13 若给其他游戏（辩论/狼人杀经济面）加监管类裁判，
   子包可直接复用（零 wealth 依赖）。

## 5. 教训：闭包参数类型必须与子包签名逐字对齐

开发中真实编译错（主会话修复）：`stepSecurities` 的 `emit` 演练阶段曾把
seat 按 `int64` 传递，与子包 `InsiderFine.Seat int` 不匹配，**4 处编译错**。
落定口径：**座位一律 `int`**（与 `Player.Seat` / 子包全部输入结构一致）；
金额一律 `int64`（CNY 口径）。该约定已写入 securities.go 输入结构注释。

## 6. 与既有分层的关系

| 层 | 包 | 职责 |
|----|----|------|
| 引擎主包 | `wealth` | World 状态机、结算时序（settlement）、wire（view） |
| 领域子包（阶段 8 新增） | `wealth/regulators` | 监管规则纯函数（无状态机时序知识） |
| 既有同类先例 | `wealth/profession` / `wealth/city` | 职业卡 / 城市背景层——同为"主包 import 子包"单向依赖 |

`regulators` 是 wealth 引擎的**第三个领域子包**，沿用 profession/city 的
依赖方向先例；区别在于它需要**写回**（SetCapacity），故引入接口注入而非
纯值传递。
