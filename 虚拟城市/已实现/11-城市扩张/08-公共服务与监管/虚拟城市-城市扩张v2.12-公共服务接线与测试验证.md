## 2. ⑨G 时序设计（settlement.go:201-222）

插入位置：**⑨F（产业集群月步）之后、④.65（资金流向统计）之前**：

```go
if w.EconomyEnabled {
    if w.PublicSvc == nil   { w.PublicSvc = NewPublicServices() }
    if w.Regulators == nil  { w.Regulators = NewRegulatorBundle() }
    if w.Election == nil    { w.Election = NewCivicElection() }
    w.PublicSvc.MonthlyStep(w)
    w.Regulators.MonthlyStep(w)
    w.Election.MonthlyStep(w)   // Enabled=false 时 no-op(R8-2)
}
```

位置理由（注释留档 settlement.go:206-209）：

- **在 ⑨F 后**：不与财政月结（⑨A-⑨E）/ 产业集群（⑨F）抢锁序；
- **消费上游已就绪**：`Treasury.LastMonthExpense` ⑨E 已记（质量累积门控）；
  当月 Ledger 流水（⑨C 前的动作/结算）已齐（证监会扫描）；
  `Monthly.Income` ③ 已结算（消协/罚款封顶）；`Labor.Employment` ② 已步
  （就业直读）；`Society.Gini` ④.6 已算（选举满意度）；
- **在 ④.65 前**：当月新增的监管罚款/津贴流水（CatRegulatoryFine /
  CatWelfare）被同月 FlowStat 聚合捕获；
- **EconomyEnabled=false 完整跳过**：非经济房零开销；
- **nil 惰性初始化**：防直接构造（绕过 NewWorld）的 World 解引用——与
  阶段 6 FinMarket 同款守卫。

`AnnualEduStep` 挂 `AnnualAdjust` 尾部（settlement.go:727-736）：年度步语义
（0.1/年）不能进月步；同款 EconomyEnabled + nil 惰性守卫。

## 5. 开发中修复的 2 个真 bug

### 5.1 AnnualEduStep 浮点累积永不进位（逻辑 bug）

- 现象：`TestEducation_CognitionBoost` 10 年对拍 `Cognition == 6` 失败，
  恒为 5；
- 根因：`0.1 × 10` 浮点累加 = `0.999…9`，`accrual >= 1.0` 严格比较**永不
  成立**；
- 修复：`>= 1.0-1e-9` ε 容差（public_services.go:183）；
- 教训：**浮点进度条进位判定必须带 ε**；整数语义进度（K 资源 +1）优先
  考虑整数计数器 ×10 存储再除的写法（本处为保留 0.1 语义选 ε 方案）。

### 5.2 securities.go emit 闭包 seat 类型不匹配（编译错 ×4）

- 现象：`regulators/securities.go` 编译 4 处 `cannot use seat (variable of
  type int64) as int value`；
- 根因：聚合层 `emit` 闭包演练时 seat 按 `int64` 传，与子包
  `InsiderFine.Seat int` / `TradeRecord.Seat int` 不匹配；
- 修复（主会话）：座位统一 `int`（与 `Player.Seat` 一致）、金额统一
  `int64`（CNY）——约定写入《监管子包解耦设计》§5。
