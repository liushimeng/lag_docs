## 1. R8-2 完全可选设计：默认关闭 = 完全 no-op

`CivicElection.Enabled` 默认 **false**（`NewCivicElection`，civic_election.go:61-67），
`MonthlyStep` 入口即 return（civic_election.go:76-78）：

```go
if ce == nil || w == nil || !ce.Enabled {
    return // R8-2:默认关闭,零副作用(不动现金/不动事件/不动状态)
}
```

- **不动现金 / 不动事件 / 不动状态**——`MonthsRun` 都不递增；
  `TestCivicElection_Disabled`（public_services_test.go:189-201）对拍国库现金
  与 MonthsRun 双零断言；
- 动机：固定种子存量对局**回归零偏移**是阶段 2-8 全程硬纪律（阶段 6 起
  grep `w.Rand` = 0），选举是玩法层可选件，不能因为它改变存量对局轨迹；
- `MayorSeat = -1`（无市长）为关闭态的对外口径，view 下发
  `election_enabled=false` / `mayor_seat=-1`（view.go:267-271）。

## 2. 得票模型：30-40-30（ComputeVotes，civic_election.go:133-199）

```
综合得分 = 财富排名分 × 30% + 人脉分 × 40% + 社会满意度 × 30%
```

权重常量 `VoteWeightWealth / VoteWeightNetwork / VoteWeightSatisfaction`
= 0.30 / 0.40 / 0.30（civic_election.go:34-37），`TestCivicElection_VoteWeights`
逐座位锁定三权重公式（±0.01 容差）。

| 分项 | 公式 | 说明 |
|------|------|------|
| 财富排名分 | `(n−1−rank) ÷ (n−1) × 100` | 净资产**降序**排名归一：首富 100 分、末名 0 分；n=1 → 100 |
| 人脉分 | `clamp(Network, 0, 10) × 10` | Network 0..10 → 0..100 |
| 社会满意度 | `100 − 基尼 × 100` | **全城同值**——基尼取 `World.Society.Gini`（settlement ④.6 同月更早时点已算好）；Society nil（未开 economy）→ 基尼 0 → 满意度 100 |

设计语义：**财富 30% + 人脉 40%（选民关系网）+ 公共治理满意度 30%**——
人脉权重最高，模拟"地方选举靠关系网"；满意度项把阶段 7 基尼系数转化为
政治压力通道（不平等加剧 → 全员满意度同降 → 仅剩财富/人脉分差决定胜负）。

### 2.1 双重确定性 tie-break

- **排名口径**：净资产降序，**并列按座位升序**（civic_election.go:154-159）；
- **输出排序**：综合得分降序，**并列按座位升序**（civic_election.go:192-197）；
- 全程 `sort.SliceStable` + 纯算术，零 rand——同种子复选结果逐字节一致。

### 2.2 得分明细快照

`ElectionVote{Seat, Score, WealthScore, NetworkScore, Satisfaction}`
（civic_election.go:41-47）全部 json tag 下发（`last_votes`，view.go:272）——
前端可直接渲染票型分布（得票榜 + 三分项条形）。

## 3. 选举周期与月步流程（MonthlyStep，civic_election.go:75-106）

三步顺序锁定：**卸任校验 → 选举 → 津贴**（新市长当选当月即领首月津贴）。

1. **在任校验**：市长座位死亡/离座 → 播报离任事件、`MayorSeat = -1` 空缺
   （civic_election.go:82-89）；
2. **任期届满选举**：`w.Month − LastElectionMonth ≥ IntervalMonths` →
   `RunElection`。`ElectionIntervalMonths = 48`（4 年一届；≤0 回落默认值）。
   初始 `LastElectionMonth = 0` → **首届选举在第 48 月**；
3. **市长津贴**：见 §4。

`RunElection`（civic_election.go:111-129）：`ComputeVotes` 得分降序取首名
（并列已在内部按座位升序排定）；记录 `LastElectionMonth` / `LastVotes`；
无存活玩家 → 空缺播报返回 −1；当选播报事件含三分项分解（civic_election.go:125-127）。

## 4. 津贴通道：gov:treasury → seat（CatWelfare）

```go
if ce.MayorSeat >= 0 && w.Treasury != nil && w.Treasury.Cash >= MayorStipendCNY {
    w.Pay(ce.MayorSeat, EntityGovernment, SeatEntity(ce.MayorSeat),
        MayorStipendCNY, CatWelfare, "市长津贴")
    w.Treasury.Cash -= MayorStipendCNY
}
```

- **`MayorStipendCNY = 500`** 元/月（civic_election.go:33）；
- **唯一合法国库→座位通道**：`CatWelfare` 是 Ledger 白名单中 gov:treasury →
  seat 的唯一 category（ledger.go:85，阶段 4 定）——市长津贴复用转移支付
  通道，不新增白名单项；
- **国库不足不发**：前置 `Treasury.Cash >= 500` 守卫，不透支（R4-1 国债
  「不透支」同款纪律）；
- **I1 守恒**：走 `w.Pay`（engine.go:362），Ledger 留痕 from=gov:treasury
  to=seat:\<n\> category=welfare——资金流可追溯（阶段 4 FlowStat 自动聚合）。

`TestCivicElection_Stipend`（public_services_test.go:236-248）：国库 10,000 →
月步后 9,500 精确对拍（测试设 `LastElectionMonth=1` 避免当月触发重选，
同时锁「津贴与选举同月顺序：先选后发」）。

## 5. 卸任规则与空缺语义

| 场景 | 行为 |
|------|------|
| 市长死亡（settlement 死亡结算后下一 ⑨G） | 播报"市长(N 号位)离任"→ MayorSeat=−1，**当月无津贴**（③ 在校验之后） |
| 市长座位无玩家（p == nil） | 同上 |
| 空缺期 | 不补选——等下一届期（w.Month − LastElectionMonth ≥ 48）自动选举 |
| 无存活候选人 | RunElection 返回 −1，播报空缺事件 |

注意：卸任**不重置** `LastElectionMonth`——中途空缺的剩余任期照常计时，
届满才换届（议会制"不提前大选"取向，避免死亡密集期反复选举刷事件）。
