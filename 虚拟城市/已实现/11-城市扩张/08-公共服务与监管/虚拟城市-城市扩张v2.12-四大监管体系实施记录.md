## 1. 范围与聚合层

四大监管 = **证监会（内幕交易）+ 反垄断（分拆）+ 消协（过度消费预警）+
数据隐私（审计）**。`RegulatorBundle`（public_services.go:238-249）持有 4 个
子包实例并聚合统计：

| 字段 | 口径 |
|------|------|
| `Securities` / `Antitrust` / `Consumer` / `Privacy` | 4 监管实例（nil 惰性重建） |
| `FinesTotalCNY` | 累计**实收**罚款（现金钳后；4 监管合计） |
| `LastMonthFinesCNY` / `LastMonthWarnings` | 上月实收罚款 / 过度消费警告数 |
| `LastStepMonth` | §130 接线验证 |

月步顺序（`RegulatorBundle.MonthlyStep`，public_services.go:262-278）锁定：
**证监会 → 反垄断 → 消协 → 隐私**。全部零 rand、无锁、无 IO。

## 2. 证监会：内幕交易检测（regulators/securities.go）

### 2.1 检测算法（MonthlyStep，securities.go:90-156）

「7 日短线交易」在月粒度引擎中的代理口径（securities.go:20-23 注释）：
**大额开仓（≥ 50 万）后当月或次月内出现同座位大额反向操作** → 认定 insider。

两腿都须 ≥ `InsiderLargeTradeCNY`（500,000 元）：

```
① 跨月：上月大额买入(锚) × 当月首笔大额卖出(反向) → 罚；对称同理
② 当月：同月内先大额买入后大额卖出(按传入切片顺序=Ledger 时间序) → 罚
```

- **锚管理**：`prevLarge map[int][]TradeRecord`（seat → 上月大额锚）按月滚动
  （securities.go:145-154）——当月大额交易全部留作下月检测基准；
- **单锚单罚**：每条锚至多产出一笔罚款（跨月配对一锚一罚 securities.go:123-129；
  当月内层循环命中即 `break` securities.go:139）——防同锚重复计罚；
- **确定性**：`sortedSeats`（securities.go:168-176）座位升序遍历 map；
  传入切片保持 Ledger 顺序即时间序。

### 2.2 罚款公式与 R8-3 封顶（securities.go:105-118）

```
应罚 = 反向金额 × InsiderFineRate(5%)           // 四舍五入到元
封顶 = 当月月收入 × InsiderFineCapRate(5%)       // R8-3
实罚 = min(应罚, 封顶)；收入 ≤ 0 → 实罚 0（无收入免罚）
```

**R8-3 取舍**：无收入（失业）座位**认定但免罚**——计入 `InsiderCases`
案件数、不计入罚款（securities.go:112-115）。阶段 8 不引入「罚到负」路径
（与消协「失业不判过度消费」同款价值取向）。

### 2.3 应罚 vs 实收双口径（易混淆点，写测试前必读）

| 口径 | 字段 | 位置 |
|------|------|------|
| 应罚（封顶后、现金钳前） | `SecuritiesRegulator.InsiderTradeFines` / 单笔 `InsiderFine.FineCNY` | securities.go:64 / 58 |
| 实收（现金钳后） | `RegulatorBundle.FinesTotalCNY` / `LastMonthFinesCNY` | public_services.go:244-245 |

wealth 侧执行扣款（`stepSecurities`，public_services.go:282-329）：
`collect = min(应罚, max(p.Cash, 0))`——现金不足只收可收部分，不强扣为负；
`collect ≤ 0` 跳过。资金变动走 `w.Pay`（I1 守恒，engine.go:362）：

```go
w.Pay(f.Seat, SeatEntity(f.Seat), EntityGov, collect, CatRegulatoryFine, ...)
```

**`CatRegulatoryFine = "reg_fine"`**（public_services.go:53）：seat → gov
（`EntityGov`，个税同实体归集）——**不入 gov:treasury**（Ledger 白名单禁止
to=gov:treasury，ledger.go:170 注释；罚款是惩罚性归集而非财政收入，
与阶段 4 国库「只付不收」纪律不冲突）。事件播报 `policy` 类型
（public_services.go:325-327）。

### 2.4 输入适配：Ledger → TradeRecord

`stepSecurities` 扫描 `w.Ledger.MonthEntries(w.Month)`（public_services.go:287-302）：
`CatBuy` 取 `From=seat`（买入/做空开仓保证金）、`CatSell` 取 `To=seat`
（卖出/做空平仓结算）——**融券开平仓天然落入同一检测口径**（securities.go:41-42）。
`incomeOf` 回调注入 `p.Monthly.Income`（settlement ③ 已结算）。

## 3. 反垄断：市占分拆（regulators/antitrust.go）

### 3.1 规则（MonthlyStep，antitrust.go:74-115)

```
市占 = CapacityOf(id) ÷ TotalCapacity()
市占 > 40%(AntitrustShareTrigger) 连续 3 月(AntitrustConsecutiveMonths)
  → 第 1 月立案(Investigations+1，一次性)
  → 第 3 月分拆：SetCapacity(id, cap × 0.5)   // AntitrustSplitFactor
```

- **结构性一次性**：`splitDone` 标记后**不再二次分拆**（antitrust.go:97-109）——
  防节点在 40% 线附近反复触发无限减半；
- **断档清零**：市占回落 ≤ 40% → `excessRun = 0`（antitrust.go:110-112），
  重新连续计数；
- **防除零**：`cap ≤ 0 || total ≤ 0` 跳过该节点；
- 同月多节点可并行分拆；返回序 = nodeIDs 传入序。
- 状态面：`Investigations`（立案数）/ `Splits`（分拆数）/ `LastSplitNode`
  （快照展示）。

### 3.2 现状标定：休眠护栏

阶段 5 15 节点中最大节点 `food_wholesale` 产能占比 ≈ 23% < 40%
（antitrust.go:11-13 注释）——**常态对局本监管零触发**，只有外部冲击改写
Capacity 才可能激活。与 R8-3「监管不干扰正常市场」取向一致：监管是护栏
而非常驻玩家。

### 3.3 wealth 侧适配（stepAntitrust，public_services.go:358-375)

`supplyCapacityView`（public_services.go:331-356）把 `SupplyChain` 适配为
`CapacitySource`；`TotalCapacity` 按 `nodeOrder` 求和保浮点确定性。节点列表
**双保险确定性**：复制 `nodeOrder` 后再 `sort.Strings` 升序（public_services.go:366-367）。
分拆事件播报含市占/产能前后值（public_services.go:369-374）。

## 4. 消协：过度消费预警（regulators/consumer_protection.go）

「Doodad 突发消费」（现金流游戏原典的"副产品/挥霍"概念）月度检查：

- **判定**（`IsOverconsuming`，consumer_protection.go:55-60）：
  `Doodad 支出 > 月收入 × 50%`（`OverconsumeIncomeRatio = 0.5`）；
  **收入 ≤ 0 不判**——失业期强制消费不预警，与失业救济/强制降档逻辑不冲突；
- **口径**（public_services.go:380-401）：Doodad 支出 = 当月生活支出
  （`livingExpenseOf`，treasury.go:166 同口径 `Monthly.Detail key=living`）
  **+ 家庭支出**（`familyExpenseOf`，public_services.go:403-412 新增，key=family）；
  月收入取 `Monthly.Income`；
- **冷却**：同座位 6 月内不重复警告（`ConsumerWarnCooldownMonths = 6`），
  防事件刷屏；
- **性质**：教育提示**不罚款**——`WarningsTotal` 计数 + `policy` 事件
  （public_services.go:396-400）。

## 5. 数据隐私：审计与脱敏检查（regulators/data_privacy.go）

阶段 8 范围裁剪：**只做检查函数，不改引擎下发路径**。

- `MonthlyAudit(month)`（data_privacy.go:50-56）：月度例行审计计数
  （`AuditsRun` / `LastAuditMonth`），⑨G 第④步调用；
- `AggregateSurveyAnswers`（data_privacy.go:60-77）：调研逐座位回答 →
  **仅聚合**（选项计数 + 总数；座位号/自由文本理由**全部丢弃**）；
- `SnapshotPrivacyPass`（data_privacy.go:82-90）：公开快照脱敏检查——
  逐座位答案条数与未脱敏自由文本条数必须为 0，且 Counts 长度与选项数一致
  （防聚合口径漂移），三违一即 false。

**现状对齐**：`view.go::SurveyJSONFrom` 本就只下发 `AnswersCount` + 聚合
`Result`、从不下发 Answers 明细——本文件把该不变量**固化为可测试的检查
函数**，供 v2.13 接入调研快照构造路径（§130「检查函数先行」）。
