## 2. 数据收集与排序（ComputeSocietySnapshot 前半，society_stats.go:136-171）

- 样本：仅 `alive` 玩家（`p == nil || !p.Alive` 跳过）；n=0 直接返回空快照。
- 每人一行 `societyRow{seat, nw, inc}`（society_stats.go:112-116）：
  - `nw` = `p.NetWorth(w.Market)` —— 净资产（现金+资产−负债，Market 即时估值）；
  - `inc` = `p.Monthly.Income` —— 当月**总收入**（毛口径，不做税/社保扣除）。
- 排序（society_stats.go:154-159）：净资产**降序**，**并列按 seat 升序 tie-break**
  —— 零 rand 下排名稳定可复现，这是全文件确定性的根基（§6）。
- 产出两份序列：`Ranks`（seat → 降序排名，1=最富，供下月流动性对比）与
  `asc`（降序反转得到的升序数组，供基尼/五等分/Bottom50 复用，避免二次排序）。

## 3. giniCoefficient：升序加权公式（society_stats.go:267-281）

独立成包级函数（不并入 labor.go，**不改已有逻辑**），供财富/收入两处复用：

```
G = 2·Σ(i·x_i) / (n·Σx_i) − (n+1)/n      （x 升序，i 从 1 起）
```

与 labor.go::ComputeSociety 内联实现（labor.go:211-223）**同款公式**，边界规则
一致：

- `n < 2` → 0（单玩家/空场无分化意义）；
- `Σx ≤ 0` → 0（极端负债场景防除零/负值爆炸）；
- 负净资产样本结果可能越界 → 调用方 `clamp01` 夹取 [0,1]。

`clamp01`（society_stats.go:284-292）是 `goods.go::clampF` 的 [0,1] 特化，全部
占比/基尼出口统一夹取。

### 3.1 R7-1 截尾基尼（12 人自动退化为全量）

财富基尼在劳动经济学惯例上做两端截尾（剔除极端首富/赤贫对 n 敏感公式的扭曲）：

```go
trim := int(float64(n) * societyTrimFrac)   // societyTrimFrac = 0.001（两端各 0.1%）
snap.GiniWealth = clamp01(giniCoefficient(asc[trim : n-trim]))
```

（society_stats.go:173-175，常量 society_stats.go:34）

**关键取舍：12 人局 n×0.001 = 0.012，`int()` 截断 = 0 → 自动退化为全量计算**。
因此 12 人下 `GiniWealth` 与 labor.go `SocietyStats.Gini` 数值完全一致（双口径
对拍不产生分叉）；未来城市人口扩容（背景居民/更多真人）后截尾自动生效，无需
改代码。代码注释（society_stats.go:31-34）显式说明这一退化行为。

收入基尼（society_stats.go:177-183）对 `inc` 排序后全量计算，不做截尾 —— 收入
天然月度清零重算，极端值影响远小于存量财富。

## 4. Top1 / Top10 / Bottom50 份额（society_stats.go:185-203）

| 字段 | 人数取法 | 12 人局实际 | 财富求和来源 |
|------|---------|------------|--------------|
| `Top1Pct` | `max(1, ceil(n×1%))` | ceil(0.12)=**1 人** | `rows` 降序前 k 人 |
| `Top10Pct` | `max(top1, ceil(n×10%))` | ceil(1.2)=**2 人** | `rows` 降序前 k 人 |
| `Bottom50Pct` | `n / 2`（整除） | **6 人** | `asc` 升序**头部** bot 人（最穷一半） |

**小样本向上取整**（R7-2 关键取舍）：12 人按纯比例 1% 只有 0.12 人，直接取整
= 0 人 → Top1Pct 恒 0 失去区分度；`ceil` + `max(1,…)` 保证 Top1 至少 1 人、
Top10 至少 2 人（≥Top1，单调性由 `max(top1,…)` 锁死）。

兜底：`total ≤ 0`（全员负资产极端场景）三个份额全 0 不计算；正常路径每项
单独 `clamp01`（个别玩家负净资产可能使份额名义 >1）。

> 开发中修复 1 个真 bug：Bottom50 初版误取 `asc` **尾部**（即最富一半），
> 被 TestSocietyTopShares 的均匀分布对拍（期望 0.5）当场抓住，改为头部。详见
> 姊妹篇《社会指标接线与测试验证》§5。

## 5. 财富五等分（society_stats.go:205-222）

升序均分 5 组、**末组吃余数**（与 labor.go 收入五等份 labor.go:225-250 同构）：

- 12 人组大小 = `2,2,3,2,3`（`q*n/5` 整除切界，q=4 时 hi=n）；
- 占比 = 组内和 / 总财富，各组 `clamp01`；
- `n < 5` 或 `total ≤ 0` → 五组全 0.2（均匀兜底，与 labor.go 同款）；
- 与 `SocietyJSON.Quintiles`（收入五等份）语义区分：本字段在 wire 层命名
  `wealth_quintiles`（view.go:115），避免与既有 `quintiles` 混淆。

## 6. 确定性纪律（零 rand）

- 全文件**零 rand 消费**（无 `w.Rand` 引用）—— 纯排序 + 算术；
- 并列财富按 seat 升序 tie-break（§2）—— Go `sort.Slice` 非稳定排序，无
  tie-break 时并列名次受入座顺序波动影响；
- 收入基尼的 `sort.Float64s` 是稳定值排序（仅依赖数值，与顺序无关）；
- 固定种子存量对局回归零偏移（阶段 4-6 同款纪律）。

## 8. 关键取舍速查

1. **补全不重写**：labor.go ComputeSociety 一行未动；新指标走独立快照管道。
2. **R7-1 截尾在 12 人自动退化全量**：与 SocietyStats.Gini 数值一致，扩容后
   自动生效，无双口径分叉风险。
3. **Top 份额向上取整**：小样本区分度优先于严格人口比例。
4. **收入用毛口径 Income**：与 labor.go 可支配口径（扣税/社保）刻意区分 ——
   GiniIncome 衡量市场初次分配分化，Quintiles（labor）衡量二次分配后结果。
5. **零 rand + seat tie-break**：确定性是硬约束，不是优化项。
