## 5. 开发期 Bottom50 bug 修复记录

**现象**：实现 Bottom50Pct 时初版对升序数组 `asc` 取**尾部** `n/2` 人 ——
升序尾部是最富一半，指标含义完全反转（越不平等读数越高但方向是「最富 50%
占比」，与「后 50% 份额」语义相反，且均匀分布下应得 0.5 实得 0.5 恰好侥幸
对拍难辨，集中分布下方向性错误）。

**捕捉**：TestSocietyTopShares 的**均匀对拍断言**（12×5 万 → 期望 Bottom50=0.5）
+ 集中样本方向性断言（skew 场景 Bottom50 应**下降**）双重锁定 —— 集中样本
（90 万/9 万/10×1 万）下错误版本读数 0.10 vs 正确版本 ~0.45，方向断言直接
击穿。测试先行（先写对拍再写实现）使 bug 存活时间以分钟计。

**修复**（f60bb0db28 最终态，society_stats.go:197-198）：

```go
for i := 0; i < bot && i < n; i++ {
    sb += asc[i] // asc 升序头部 bot 人即最穷一半
}
```

**教训**：份额类指标（Top/Bottom）必须同时有「均匀分布精确对拍」与「集中
分布方向性」两类断言 —— 只有一类时，取错端这类 bug 在均匀样本上不可见。
