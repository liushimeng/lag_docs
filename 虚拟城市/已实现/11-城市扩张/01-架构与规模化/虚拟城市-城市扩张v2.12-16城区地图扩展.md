## 2. 设计目标：16 城区 + 80×80 地图

### 2.1 三方案对照

| 方案 | 城区数 | 地图尺寸 | 面积 | 城区底板 | 缩放比 | 决策 |
|---|---|---|---|---|---|---|
| A. 维持 8 城区 40×40 | 8 | 400m×400m | 160K m² | 8×8 | 1× | ❌ 拥挤 |
| B. 16 城区 80×80 | **16** | **800m×800m** | **640K m²** | **8×8** | **1/2×** | ✅ **采纳** |
| C. 25 城区 100×100 | 25 | 1000m×1000m | 1M m² | 8×8 | 1/2.5× | ❌ 比例失衡 |

> **关键约束**：**城区底板维持 8×8 单位不变**（80m×80m / 城区），
> 16 城区 = 16 × 8×8 = 1024 单位，刚好接近 80×80 = 6400 单位的 1/6
> （其余 5/6 是道路 / 绿化 / 水域）。

## 3. 地图 40×40 → 80×80 扩展

### 3.1 缩放策略

| 元素 | v2.60 | v2.62 | 缩放比 |
|---|---|---|---|
| 地图边长 | 40 单位（400m）| **80 单位（800m）** | 2× |
| 地图面积 | 1600 单位²（160K m²）| **6400 单位²（640K m²）** | 4× |
| 城区底板 | 8×8 单位（80m×80m）| **8×8 单位（不变）** | 1× |
| 城区数量 | 8 | **16** | 2× |
| 城区总面积 | 512 单位²（51K m²）| **1024 单位²（102K m²）** | 2× |
| 道路 / 绿化 | 1088 单位² | 5376 单位² | 5× |

## 5. 性能 / 兼容性影响

### 5.1 性能影响

| 操作 | v2.60（8 城区）| v2.62（16 城区）| 变化 |
|---|---|---|---|
| `districtByID(id)` O(N) 查找 | 平均 4 次比较 | 平均 8 次比较 | **可忽略** |
| 前端 `WEALTH_DISTRICTS.map` 渲染 | 8 个城区块 | 16 个 | +100% 渲染对象 |
| `DISTRICT_FLOORS` lookup | O(1) | O(1) | 无变化 |
| 后端 DistrictDefs 数组拷贝 | 8 × sizeof | 16 × sizeof | +800 字节 |
| 前端相机渲染 | 40 单位视野 | 80 单位视野 | LOD 不变（建筑数 × 2）|

### 5.2 兼容性矩阵

| 现有功能 | v2.62 兼容？| 备注 |
|---|---|---|
| `DistrictCount = 8` 常量 | **❌ 必须改 16** | districts.go:40 |
| `districtByID(id)` 查找 | ✅ | O(N) 自动适配 |
| `ValidDistrict(id)` | ✅ | 自动包含 16 |
| `DistrictCN(id)` | ✅ | 自动包含 16 |
| `WEALTH_DISTRICTS` 前端数组 | **❌ 必须追加 8** | wealth.ts |
| `WealthDistrictId` TS 类型 | **❌ 必须扩展** | types/wealth.ts |
| `DISTRICT_FLOORS` 楼层表 | **❌ 必须扩展** | cityScale.ts |
| 房间层随机分配城区 | ✅ | 16 个选项，更均匀 |
| 央行 / 财政对城区的政策 | ⚠️ | 新城区可能无政策 → v2.63 阶段 3 处理 |
| 调研 / 民意对城区的统计 | ✅ | 自动聚合 |
| 旧 8 城区 ID 兼容性 | ✅ | ID 不变，数据平滑迁移 |

### 5.3 数据迁移

v2.62 升级时：
- 旧存档的 8 城区 ID 全部保留
- 新存档可选 16 城区
- 后端 `districtByID` 对未知 ID 返回 nil（已是当前行为）
- 前端 `WEALTH_DISTRICTS_BY_ID[unknown]` 返回 undefined（已有兜底）

> **零数据迁移成本** — 新城区是"可选扩展"，旧房间仍跑 8 城区。

## 6. 与 12.5 「我方在底部」布局的对齐

CLAUDE.md §12.5：5 款多人游戏的界面布局统一规则 — 焦点玩家永远在屏幕底部。

**虚拟城市的特殊性**：
- 不是"对战"游戏，是"个人沙盘"
- 焦点玩家的"位置"是 `clientGameState.MySeat.district`（所在城区）
- §12.5 三模式都不直接适用（无对手）

**v2.62 适配**：把 `district` 渲染到地图底部 HUD（独立组件），
不在地图本体内旋转。具体实现 v2.62 阶段 2 由 `frontend-dev` SubAgent 实施。
