## 1. 现状（v2.60 已实现）

v2.60 已落地两类 LLM 调用方：

| AgentClassName | 注册常量 | 触发 | LLM 成本 |
|---|---|---|---|
| `LsmAgentGame-City-Player` | `class_names.go:213` | 月窗 `runOneBot` | 高（工具循环 + Memory）|
| `LsmAgentGame-City-Voice` | `class_names.go:224` | 月结后 `VoiceScheduler.Run` | 极低（无工具）|

### 1.1 当前 LLM 调用拓扑

```
房间 (MaxSeats=12)
├── 焦点 12 座 → City-Player Agent (12 LLM 调用/月,串行排队 agentSem=8)
└── Backdrop(200 居民)
    └── VoiceScheduler.Run(每月 4–32 次抽样) → City-Voice Agent
                              │
                              ▼
              llm.LinePool (全局 Provider 池并发治理)
                              │
                              ▼
              Provider × N (8 默认,可达 13)
```

### 1.2 关键约束（CLAUDE.md §14 / §14.1）

- **Anthropic 协议对齐**：所有 LLM 调用必须遵守 wire 格式（ContentBlock 按
  Type 收敛 / messages user/assistant 严格交替 / content 是 content-block
  数组）
- **出站 UA**：`User-Agent: <AgentClassName>/<AppVersion> <buildDateTime>`
  （class_names.go:7-9）
- **`llm.LinePool` 全局并发治理**：跨房间跨 Agent 的 LLM 配额池
- **Provider 配额**：单 Provider 默认 2 路并发上限（防 429 雪崩，
  参见文档 2 §2.1）

## 2. v2.61 的 "1+11+200" 分工

### 2.1 数字解读

| 数字 | 含义 | LLM 调用密度 |
|---|---|---|
| **1** | 1 名人类玩家（不是 LLM）| 0 |
| **11** | 11 个 bot 焦点玩家（LLM 决策者）| 11/月 |
| **200** | 200 名背景居民（程序化 + 抽样 LLM）| 4–32/月（默认 6）|
| **合计** | 12 焦点 + 200 背景 = 212 居民 | **17–43 LLM 调用/月** |

> **17–43 LLM 调用/月** = 极低成本。即使每个调用 8K tokens × 43 = 344K
> tokens/月，每局 25 分钟内完成，对 Provider 配额几乎无压力。

### 2.2 三种决策模式

v2.61 明确区分三种决策模式（每种对应不同的 LLM 调用密度）：

| 模式 | 触发 | LLM 调用 | 适用场景 |
|---|---|---|---|
| **bot 自主（默认）** | `cfg.City.DecisionMode = "bot"` | 12 + 6 = 18/月 | 全 Agent 模式（默认）|
| **玩家操作** | 人类在线时 | 12（bot）+ 0（玩家）+ 6（voice）= 18/月 | 混合模式 |
| **城市 LLM 抽样** | `cfg.City.DecisionMode = "city_llm"` | 12 + 6×k = 12–204/月 | 实验模式（v2.69 验收）|

> 注："城市 LLM 抽样"模式（每居民都问 LLM）v2.61 **不启用**，仅作未来扩展预留。

### 2.3 LLM 配额治理

```
              ┌─────────────────────────────────────┐
              │       llm.LinePool (全局池)         │
              │  按 Provider 数动态 Acquire/Release  │
              └──────────────┬──────────────────────┘
                             │
       ┌─────────────────────┼─────────────────────┐
       │                     │                     │
   ┌───┴────┐          ┌─────┴─────┐          ┌────┴────┐
   │ City   │          │  City     │          │ 其他游戏 │
   │ Player │          │  Voice    │          │(狼人杀/ │
   │ Sem=8  │          │  无信号量  │          │ 德扑...) │
   └────────┘          └───────────┘          └─────────┘
   12/月                6/月(默认)             按需
```

**配额策略**：

| 调用方 | 信号量 | Acquire 超时 | 月上限 |
|---|---|---|---|
| 12 bot City-Player | `agentSem=8`（房间级） | `decisionTimeout=20s` | 12 × 月数 |
| 200 居民 City-Voice | 无（共享 LinePool） | `voiceAcquireTimeout=15s`（`voice.go:27`） | 32 × 月数 |
| 其他游戏 | 各游戏自管 | 各游戏自管 | — |

**为什么 voice 不加信号量**：
- 抽样数量极少（默认 6/月），无并发压力
- voice 是"丢了无所谓"的（`voice.go:84` 失败静默丢弃）
- 加信号量反而增加死锁风险（voice 在月结**之后**跑，不阻塞月结）

## 4. 城市之声的 LLM 配额治理

### 4.1 调用流程（`voice.go::Run`）

```
VoiceScheduler.Run(b, month, onRecord)
  for _, idx := range b.PickVoiceCandidates(s.PerMonth) {  // 抽样
      vr, ok := s.speakOne(b, pool, month, idx)             // 极短对话
      if ok { onRecord(vr) }                                // 广播 city_voice
  }
```

**单次 `speakOne` 的 LLM 成本**：
- `voiceMaxTokens=128`（`voice.go:29`，极短对话上限）
- `voiceAcquireTimeout=15s`（`voice.go:27`）
- 无工具、无 Memory、纯文本输入输出
- 平均每条 voice：2K input + 100 output ≈ 2.1K tokens

**月成本（默认配置 6 条）**：6 × 2.1K = 12.6K tokens/月（**几乎免费**）

### 4.2 失败处理（CLAUDE.md §130 失败容错）

```go
// voice.go:79-85 — 失败全部静默丢弃,不阻塞月结
if pool == nil || pool.Total() == 0 {
    return // 无线路:本月整体跳过(不算失败,下月池恢复再抽)
}
for _, idx := range b.PickVoiceCandidates(s.PerMonth) {
    vr, ok := s.speakOne(b, pool, month, idx)
    if ok { onRecord(vr) }
    // 失败 → 丢弃本条,下月再抽,绝不 panic
}
```

**v2.61 增强**（CLAUDE.md §130 必须接线验证）：
- 失败的 voice 计入 `backdrop.voices[]` 环形缓冲的"未达"槽（占位 nil）
- 月末 `Snapshot` 输出"本月 voice 成功率"（前端可见）
- 连续 3 月成功率 < 50% → 上调 `voicePerMonth` 自动减半（自愈）

### 4.3 抽样策略（CLAUDE.md §13 公平性）

`b.PickVoiceCandidates(n)` 抽样规则（`backdrop.go::PickVoiceCandidates`）：
1. **优先 stressed / 失业居民**（叙事价值高）
2. **其次按城区均匀**（避免全部抽自金融CBD）
3. **最后随机补足**（兜底）
4. **每位居民每月最多 1 次**（`flagVoiced` 防重复）

200 居民下默认 6 条抽样 = 3% 抽样率，stressed 居民约 8%（baseline）
→ 6 条有 ~50% 概率包含至少 1 条 stressed（叙事密度足够）。

## 5. 焦点玩家的 LLM 配额

### 5.1 调用流程（`agent_runner.go::runOneBot`）

```go
// agent_runner.go:1015
AgentClass: string(agentroot.AgentClassCityPlayer),
// 每次 runOneBot = 1 次 LLM 调用（带工具循环,可能多次 tool_use）

// manager.go:432-438 — agentSem 信号量
case r.agentSem <- struct{}{}:
    defer func() { <-r.agentSem }()
    ... // 跑 runOneBot
```

**单次 `runOneBot` 的 LLM 成本**（典型）：
- Input: 8K tokens（system + 工具定义 + 月初状态）
- Tool use 循环：1–5 次（`agent_runner.go` 限流）
- Output: 2K tokens（动作 + speak）
- **典型 ~10–30K tokens / 次**

**月成本（12 焦点玩家 × 30K）**：360K tokens/月（约 $0.50–2 取决于 Provider）

### 5.2 限流与超时

| 限制 | 值 | 出处 |
|---|---|---|
| 单次决策超时 | 20s | `manager.go::decisionTimeout` |
| 月窗总时长 | 8–60s（自适应，文档 2）| `MonthWindowFor` |
| 文本截断 | 100 字 | voice；bot 暂未截断（>100 字符的 speak） |
| 工具调用轮数 | ≤ 5 / 轮 | `agent_runner.go` 限流 |
| driver 令牌桶 | 30s | `狼人杀Agent设计.md` |

### 5.3 失败处理（CLAUDE.md §197 流式续命）

- LLM 超时 → Provider 重试（`agent_runner.go` 已有 retry 逻辑）
- 月窗超时未 submit → `markUnsubmittedBotsLocked` 写入系统超时摘要
  （`room.go:607-627`）
- 月窗结束**不**回写（`agent_runner.go:554` 拒绝旧上下文）

## 6. LLM 配额预算汇总

### 6.1 月度 LLM 调用预算（v2.61 默认配置）

| 调用方 | 月调用次数 | 单次 tokens | 月总 tokens | 占比 |
|---|---|---|---|---|
| 12 bot City-Player | 12 | 10–30K | **120–360K** | 90%+ |
| 6 voice City-Voice | 6 | 2K | **12K** | < 5% |
| 合计 | **18** | — | **132–372K** | 100% |

### 6.2 与其他游戏对照

| 游戏 | LLM 调用/月 | 备注 |
|---|---|---|
| 狼人杀 13 人局 | 78+（13 玩家 + 法官 + 解说） | `狼人杀Agent设计.md` |
| 德州扑克 6 人局 | 30+（每轮每玩家 1 次） | `德州扑克规则与协议.md` |
| **虚拟城市 12 焦点 + 200 背景** | **18–43** | **本文档** |

> 虚拟城市的 LLM 调用密度**远低于**狼人杀 / 德扑 — 因为虚拟城市的
> LLM 是"每月决策一次"，而狼人杀 / 德扑是"每轮决策一次"。

### 6.3 跨游戏全局配额（CLAUDE.md §14 LinePool）

全局 `llm.LinePool` 同时被多个游戏共享，**虚拟城市 Agent 必须遵守
LinePool.Acquire(ctx)**：

```go
// voice.go:27 — 15s ctx 超时
ctx, cancel := context.WithTimeout(ctx, voiceAcquireTimeout)
defer cancel()
pool.Acquire(ctx) // 阻塞直到有线路 / 超时
defer pool.Release()
```

虚拟城市 Agent **不能**直接调 Provider HTTP，必须经 LinePool — 这是
CLAUDE.md §14 的硬约束，已在 v2.60 落地（`voice.go:78` 调 `s.Pool()`）。

## 7. 与决策模式的交互

### 7.1 bot 自主模式（默认）

```yaml
# LsmAgentGame.conf
city:
  decision_mode: "bot"  # 默认
  voice_per_month: 6
  max_residents: 200
```

| 触发 | LLM 调用 |
|---|---|
| 月窗开始 | 12 bot City-Player |
| 月结后 | 6 voice City-Voice |
| 月末 | 0 |
| **合计** | **18/月** |

### 7.2 玩家操作模式（人类在线）

> 与 bot 自主模式 LLM 成本一致 — 玩家操作 = 玩家发动作，
> bot 仍跑 City-Player。

| 触发 | LLM 调用 |
|---|---|
| 玩家动作 | 0（HTTP 直入引擎）|
| 月窗开始 | 12 bot City-Player |
| 月结后 | 6 voice City-Voice |
| **合计** | **18/月** |

### 7.3 城市 LLM 抽样模式（v2.61 预留，v2.69 验收）

> **本期不实现**，仅在配置 schema 留字段。

```yaml
# LsmAgentGame.conf
city:
  decision_mode: "city_llm"  # 实验模式
  voice_per_month: 32        # 上限
  llm_sample_rate: 0.5       # 200 居民中 50% 抽样 = 100 条/月
```

**预期 LLM 调用**：12 bot + 100 voice = **112/月**（仍是狼人杀的 1.4×），
但 200 居民"每人都发声"会失去"抽样叙事"价值 — 这是 v2.69 阶段再审议。
