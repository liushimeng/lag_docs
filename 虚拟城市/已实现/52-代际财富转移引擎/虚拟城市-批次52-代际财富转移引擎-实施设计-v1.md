## 2. 实施裁决表（契约 → 本实现的唯一口径）

| # | 契约原文 | 本批次裁决 | 理由 |
|---|---------|-----------|------|
| D1 | `PlayerFamily` 4 个纯派生字段，不持久化 | **不新增 Player 派生 struct**。父母/子女状态由 `family.go` 的**纯函数**按 `(Player, World.Month, seat)` 推导；需要跨月累积的量（教育档位、赡养/教育累计、回流累计）落在 Player 新增**持久字段**上 | 「纯派生」与「教育档是决策结果」互相矛盾 —— 决策必须落状态 |
| D2 | 子女数「按开局种子 + birth_rate 抽样 0~2」 | **以既有单一事实来源为准**：`Family.Children` = 卡面初始（`Card.ChildrenCount`）+ `BellEvents` 事件生育（`BirthMonths` 追加）。**不再二次抽样**，防双重计数 | 与 `transfer_payment.go`「卡面初始子女不计，仅追踪生育事件」的既有口径衔接；卡面初始子女另由 D3 补年龄 |
| D3 | 子女年龄派生 | 事件生育：`age = (Month − BirthMonths[i]) / 12`（既有）；**卡面初始子女**：确定性散列 `seedChildAge(seat, idx) ∈ [2, 12]`，第 i 个初始子女年龄递减 2 岁（长幼有序） | 无落库字段；同 seed 同对局可复现 |
| D4 | 父母寿命「50 岁起每年 5% 离世」 | **确定性散列单调模型**：`deathAge(seat) = min{A ≥ 50 : hash16(seat, A) < 0.05×65536}`；`ParentsAlive ⟺ ParentsAge < deathAge(seat)`。`ParentsAge = p.Age + 25`（p.Age 已含主时钟推进） | 纯函数、单测可锁；「最小 A」保证单调（死了不会复活），不消耗 `w.Rand` 流（不扰动既有事件序列） |
| D5 | 父母健康 `good/fair/poor` | 派生：`ParentsAge < 62 → good`；`62..71 → fair`；`≥72 → poor`。赡养倍率 fair ×1.5 / poor ×2.5（契约 §4.2） | 与年龄单调一致，避免额外随机 |
| D6 | 继承人是「seat:配偶 / seat:child:X」 | **继承人为板外实体**：12 座位互为陌生人，配偶/子女非座位。遗产经 Ledger **离开座位账簿**到新实体 `EntityFamily = "family"`（`CatInheritance`），计入 `InheritanceLog`（`to_seats` 恒空数组 = 板外）。无配偶无子女 → 归 `EntityWorld` | 保住「财富离开当期可测净资产」的真实性与双式记账；不虚构座位间亲属关系 |
| D7 | 继承人 `InheritanceCNY` 下月入账 | 契约字段保留（协议兼容），**板外继承恒为 0**；`my.inheritance_cny` 仅在出现座位间继承的未来扩展时非零 | 不留悬空字段（§130）：值域与文档同时写明 |
| D8 | 遗产总额 `Cash + ΣAssets.Value − ΣLoans.Balance` | 先扣丧葬费 ¥5,000（floor 0）再分；分配完成后**清零死者 Cash/Assets/Loans**（死者账簿归零，防资产被后续逻辑双花）。身故理赔（P1-4）已入死者 Cash，**自然并入遗产池** —— 契约 §3.4「保险理赔留 P2 补」在此顺手闭合 | HandleDeath 本就是「未来死因唯一入口」，接口不改 |
| D9 | 触发时机「玩家死亡当月 SettleMonth 末」 | **`HandleDeath` 内理赔完成后立即调用** `DistributeInheritance(seat)`（含一切死因：事件/事故）；破产出局（eliminate）不触发（契约 §3.4 防道德风险） | HandleDeath 是唯一死亡入口，在此接线最稳；SettleMonth 末再调会有同月双触发风险 |
| D10 | 赡养触发：父母任一在世 + 父母年龄 ≥ 60 | 同契约。`BaseSupportCNY = 1500`；健康倍率 fair ×1.5 / poor ×2.5；`AbilityAdjust`：本人 NetWorth < 全房存活中位数 → ×0.5。月结自动扣款（非动作），入 `Monthly.Detail` 与 Ledger `CatFamilySupport` | 真实世界赡养是刚性支出；另留自愿加赡养动作（D13） |
| D11 | 教育升级：一次性 ¥200,000 + 月度 ¥3,000 | 同契约。子女年龄 ∈ [3,18] 且未私立才可升；月度教育费在子女 19 岁起停止。`PrivateEduMask []bool` 与子女序对齐（卡面初始在前、事件生育在后） | 子女序稳定（D3 保证初始在前） |
| D12 | 教育 ROI：「成年 +20% SalaryBase」 | **裁决为「子女回流」**：子女年龄 ≥ 22 后按月回流 `ChildSupportCNY = 1500 × (1 + 0.2 × 私立)` 给玩家（记 `CatChildSupport`，玩家收入侧）。累计回流入 `ChildSupportReceivedCNY` | 12 座位对局内子女不成为新座位，「+20% 初始薪资」无可作用对象；回流保住 ROI 的经济闭环（私立投入 → 子女成年后反哺） |
| D13 | 工具 17→19 且列了 4 个新工具 | 采纳**既有工具分组风格**（参照 `ToolInsurance` 吸收 3 动作）：新增 **1 个分组工具 `ToolFamily = "family"`**，下辖 4 个 sub-command：`query` / `plan_inheritance` / `pay_support_extra` / `upgrade_education`。`query`/`plan_inheritance` 免预算；`pay_support_extra`（自愿加赡养，上限 NetWorth×30%，入 `CatFamilySupport`，累计进代际贡献分）与 `upgrade_education` 耗 1 动作预算 | 与 vcplayer 工具表分组风格一致；契约「17→19」计数与列表自相矛盾，按分组口径落地并回写 |
| D14 | 终局「代际贡献分」与 FI/满意度并列 | `FinalScore` 增 `FamilyScore float64`（json `family_score`）：`min(100, (EducationTotalCNY + FamilySupportTotalCNY×0.3) / 20000)`（契约 §9.2 权重 0.3）。**总分权重再平衡**：`total = fi×0.45 + life×0.25 + social×0.15 + family×0.15`（原 0.5/0.3/0.2）。结局阈值不变 | 契约明确「新增 1 维」；权重再平衡保证 family 真实进总分，四维归一 1.0 |
| D15 | `FamilyStatsJSON` / `InheritanceEventJSON` | 采纳契约字段；`inheritance_log` 保留最近 **5** 条；`family` 房间级汇总并入 `ClientState` | 契约原样 |
| D16 | GameOverModal / FamilyPanel / i18n | 全部采纳（§8）；FamilyPanel 为 `EconomyPanel` 内 **CollapsibleSection 折叠区**，默认展开「家庭」首段、其余可折叠 —— 遵循 CLAUDE.md §7.1 错误展示与控件防溢出/防重叠/防留白要求 | UI 规约 |

## 4. 遗产继承算法（`DistributeInheritance`）

```
HandleDeath(seat, cause):            // insurance.go,唯一死亡入口
  1. p.Alive=false; Ending=accident_death(既有)
  2. 寿险/意外险理赔入死者 Cash(既有)
  3. DistributeInheritance(seat)     // 本批次新接线(§130:写完即 grep 验证)
     estate = max(0, p.Cash + Σassets.Value − Σloans.Balance − FuneralCNY)
     married? → spouse 50%; 剩余 50% 子女均分(0 子女 → 配偶 100%)
     无配偶有子女 → 100% 子女均分;无配偶无子女 → 100% EntityWorld
     Pay(deadSeat→EntityFamily, share, CatInheritance, "遗产继承-配偶"/"-子女n")
     (无配偶无子女分支 → Pay(deadSeat→EntityWorld, estate, CatInheritance, "遗产充公"))
  4. 清零 p.Cash; p.Assets=nil; p.Loans=nil
  5. w.InheritanceLog append {FromSeat, ToSeats:[], AmountCNY, Month}; 保留最近 5 条
  6. emitEvent("life", seat, "...身故,遗产 ¥x 由配偶/子女继承")
```

- **金额恒 ≥ 0**（丧葬费后 floor 0；Pay 前 clamp 到死者 Cash 可付额度，防透支）。
- 房贷随清零转移：资产+负债一并进池再净额分配（契约 §3.4「按揭延续」→ 本实现为**净额一次清算**，
  因板外继承人不持有房贷账户）。
- 幂等：同 seat 二次调用时 estate=0 直接返回，且仅记一次 log。

## 11. 实现偏差记录（backend-dev 实施后回写，2026-10-02）

> 维护规约 §1「任何实现偏差先改文档再改码」的回写节。4 处偏差均已代码内注记：

| # | 偏差 | 理由 | 落地 |
|---|------|------|------|
| E1 | D4 的「玩家当前年龄」不取 `p.Age` | `Player.Age` 只在发卡时置值、此后恒定（view 亦按开局年龄展示）；直接用会令父母年龄不随主时钟推进。补 `playerAgeNow(p) = p.Age + (Month-1)/12`，父母 = 该值 + 25；**不改 `p.Age` 语义**以免波及 view/城市外观 | `family.go::playerAgeNow` |
| E2 | D6/D3.3「EntityFamily 只收不付」自相矛盾 | 既要 family 零出账，又定义 `CatChildSupport: {Family→Player}`。按「照 EntityGov 白名单守卫风格」落地：**只收代际三类（inheritance/family_support/education）、只付 CatChildSupport→seat**；T8 按此钉死 | `ledger.go` 白名单 |
| E3 | 丧葬费走真实 Pay | 伪代码只说「先扣」；若从 estate 静默扣除再清零死者 Cash，会破坏 I1 双式守恒。实现为 `Pay(seat→firms/world, CatLiving, "丧葬费")` 后再分配 | `family.go::DistributeInheritance` |
| E4 | 卡面初始子女年龄随钟推进 | D3 只定义开局年龄；不推进则教育窗 [3,18] / 回流 22 岁永不触发。当前年龄 = `seedChildAge + (Month-1)/12`；事件生育仍走既有 `(Month−BirthMonths[i])/12` | `family.go::childAgeOf` |

另注：`ParentsAliveCount` 按「父母仍在世的**存活玩家户数**」计（父母模型为户级单一 alive 标志，非双亲分别计数）；
`family_enabled` 全链路（config → manager → room → World）零值→true，与 `insurance_enabled` 同款归一。
