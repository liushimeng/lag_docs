## 3. 契约（前后端共同事实源，改动须双侧同步）

### 3.1 确定性解析配方（新增 `ServerGo/citychrome/recipes.go`）

**实测字段布局（2026-10-23 经 29008 底座真实拉取 `qt.gtimg.cn` 逐字段核对）**：

```
v_<前缀><代码>="…~…"      A股(sh)/深(sz)/港股(hk)/美股(us) 四者布局一致
  [1]=名称  [2]=代码  [3]=当前价  [4]=昨收  [5]=今开
  [30]=时间  [31]=涨跌额  [32]=涨跌幅(%)  [33]=最高  [34]=最低

v_hf_<品种>="a,b,c,…"       外盘期货/贵金属（逗号分隔）
  [0]=最新价  [1]=涨跌幅(%)  [2]=买  [3]=卖  [4]=高  [5]=低  [6]=时间  [12]=日期  [13]=名称
```

> ⚠️ **纠正历史错误**：`sites.go::categoryHints` 原写「`[32]=涨跌额 [33]=涨跌幅 [31]=时间`」，**整体偏移 1**；实测为 `[31]=涨跌额 [32]=涨跌幅 [30]=时间`。这正是 LLM 手工解析易错的根因，本批次一并修正文案。

**涨跌幅口径（关键决策）**：**不信任站点的 pct 字段**，一律服务端自算 `(price-prev)/prev*100`。实测三例与站点字段完全吻合（-1.4813 vs -1.48 / -3.0323 vs -3.03 / -2.5990 vs -2.60）。`prev<=0` 时才回退取站点字段，回退顺序 `[32] → [31] → [33]`（取首个可解析且 `|·|≤20` 的值）。

**配方表**：

| recipe | 适用正文 | 字段口径 |
|---|---|---|
| `tencent_quote` | `v_sh000001="1~上证指数~000001~3658.03~3713.03~…"` | `name=[1] code=[2] price=[3] prev=[4] time=[30] change=[31] pct=[32]`；pct 服务端自算 |
| `tencent_hf` | `v_hf_GC="4036.75,-0.58,…,纽约黄金"` | `price=[0] pct=[1] name=[13]`，symbol = 变量名去 `hf_` 前缀 |
| `auto` | 任意 | 依次尝试 `tencent_quote` → `tencent_hf`，**首个命中 ≥1 条即用**；全不命中返回 `matched=false` 且**不产出任何报价** |

**币种推断**（变量名前缀）：`sh`/`sz`→CNY、`hk`→HKD、`us`→USD、`hf_`→USD，其余留空。

**校验**：`price<=0` 或非有限 → 丢该行；`change_pct` 钳制 `[-100,100]`；单次解析上限 64 行；配方是**纯函数、无 IO**。

**输出形态**（回灌 LLM）：
```
【结构化解析·recipe=auto→tencent_quote·命中 8 条】
[{"symbol":"000001","name":"上证指数","price":3658.03,"change_pct":-1.48,"currency":"CNY"}, …]
```

> **`sina_quote` 本批次不实现**：新浪行情依赖 Referer、字段布局随品种分叉（简版 `s_` 与个股版不同），而腾讯行情已覆盖全部 5 个行情类目且免鉴权无反爬。`auto` 链因此保持两步、误判面更小。

### 3.2 前置修复：`evalStringValue` 取值 Bug（本批次必须先修）

底座 `BatchEval` 的 `result` 字段实测为**裸 JSON 字符串**：
```json
{"index":0,"ok":true,"result":"v_sh000001=\"1~上证指数~000001~3658.03~…\""}
```
Go 侧 `EvalItemResult.Result` 是 `json.RawMessage` ⇒ 保留原始 JSON 编码（外层引号 + `\"` 转义）。而批次77 的 `evalStringValue()` 只认 `{"type":"string","value":…}` 形状 ⇒ `json.Unmarshal` 必然报错 ⇒ 落到兜底分支返回**带转义的原文**。

后果两重：① 交给 LLM 的正文全是 `\"` 噪声；② **任何正则解析器在转义文本上匹配不到** ⇒ 确定性解析永远拿不到数据。

**修复**：先按裸字符串解（`json.Unmarshal(r, &s)`），再退回 `{type,value}` 形状，最后才兜底原样。

### 3.3 工具集（10 → 11 个）

| 工具 | 变化 | 契约 |
|---|---|---|
| `web_read` | **新增 3 个可选参数** | `url`（必填）；`max_chars`（缺省 3000，钳制 500..8000）；`wait_selector`（可选 CSS selector，≤200 rune）；`wait_ms`（可选，缺省 0，钳制 0..15000）；`parse`（可选 recipe id，缺省 `auto`）。执行顺序 = **打开(domcontentloaded) → 等待元素(可选) → 读 title+body → 确定性解析(可选)**。返回体**结构化块在前、正文片段在后**，结构化块不得被截断丢失。 |

## 6. 风险与回退

| 风险 | 缓解 |
|---|---|
| 腾讯字段下标漂移 | **不信任站点 pct 字段**，一律 `price=[3]`/`prev=[4]` 自算；`prev` 缺失才回退站点字段并按 `|·|≤20` 择优；下标已用 2026-10-23 实测样本锁定 |
