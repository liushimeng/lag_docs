# 虚拟城市 — 全民驱动统一架构与抽样展示层设计 v1

> **批次**：17-CityHuman 全民驱动（重构）｜ **日期**：2026-09-24 ｜ **性质**：架构契约（后端）
> **取代声明**：本文取代本目录已删除的 00/01/02/03/04 五份文档。
> **目标**：虚拟城市的**每个居民都是 `LsmAgentGame-City-Human`** —— 删除"12 名深度居民"的双层模型，
> 让 Backdrop(10 万)居民为**唯一事实来源**；UI 上的 12 个展示位 = 当月从 Backdrop 中**随机、均匀抽样**的代表，
> 不存在固定/特权/深度层；抽样逐月滚动（cursor 轮转）实现跨月公平覆盖。
>
> **沿革注记（2026-09-26，批次 25）**：本文「12 展示位 = Backdrop 抽样代表」落地为
> **座位数 = clamp(resident_count, 10, 12)**（N≤12 时 N 居民恰 = N 个常驻 City-Human Agent，
> 驱动层抽样数 = N − 座位数）；驱动层 `PerMonth` 不再被 `llm_lines` 放大，
> 且每 Agent LLM 调用限速 1–2 次/现实分钟。详见
> [`../25-居民Agent统一与LLM调用节流/01-方案与实施记录-v1.md`](../25-居民Agent统一与LLM调用节流/01-方案与实施记录-v1.md)。

## 1. 分层总览（统一后）

```
创建城市(resident_count 10..100000)
  └─ 服务端: 零座位概念,仅建 Backdrop(N 背景居民)
       ├─ 档案自动加载: 10 万卡 → 锚定到居民(异步)
       ├─ 市场引擎: World.Market/CB/财政(城市整体)
       ├─ 驱动层: 每月 PerMonth 名背景居民轮次(线程池 + 线路池)
       │         └─ 其中 12 名抽样展示居民投影到 UI(AgentClassCityHuman 驱动)
       └─ 经济层: TickMonth 数值演化(消费 set_intent 加成)
```

**关键不变量**：
- Backdrop 是唯一居民数据源（income / expense / savings / domain / district / age / flags / intent）。
- UI 仍展示 12 个居民位（来自 cursor 抽样，逐月滚动），由 `LsmAgentGame-City-Human` 驱动。
- 不存在"深度层 vs 背景层"区分 —— 每个居民都深度模仿真实人类（系统提示词 = 档案人格，Context = 月度状态 + 氛围 + 邻居 + 通用工具）。
- LLM 线路池（`llm.LinePool`）由驱动层统一消费，全局并发 = Σ 线路数。

## 2. 抽样展示层

### 2.1 月抽样机制

复用 `city.Backdrop.PickDriverCandidates(count, cursor)`（已在 `backdrop.go` 实现）的**cursor 全域轮转**：

| 参数 | 值 |
|------|-----|
| 月抽样数 | `MaxSeats = 12`（= UI 展示位） |
| 公平性 | cursor 原子推进，窗口内 stressed/失业优先，其余随后 |
| 跨月覆盖 | N=10 万 / 12 月 ≈ 8333 月一圈（约 694 年游戏时间）；实际 per_month 由 `CityDriverPerMonth` 控制 |
| 同月不重复 | 置 voiced 位（与城市之声共享月度去重） |

### 2.2 数据投影

`World.Players[12]` 不再持有独立经济状态（Cash/Assets/Loans/Policies），改为 Backdrop 抽样居民的**只读投影**：

| 字段 | 来源 |
|------|------|
| Persona（姓名/年龄/职业/域/城区/人格） | `Backdrop.DriverBrief(i).Name/Occupation/...` |
| 月度收入/支出/储蓄 | `brief.Income / Expense / SavingsCNY` |
| 压力位 / 就业 | `brief.Stressed / Employed` |
| 城区氛围 | `room.cityAmbianceSource()` |
| 附近居民 | `Backdrop.DriverBrief(i).Neighbors` |

`vcplayer.Agent` 的 46 经济工具（buy/sell/loan/insure/trade 等）**随深度层退役** —— 仅保留与 Backdrop 兼容的 2 工具（`set_intent` / `speak`），与背景居民驱动层共用 `city/commonToolDefs`。

## 3. 居民驱动层（`city/driver.go` 不变）

`ResidentDriver` 继续以线程池 + 线路池驱动居民轮次（System=档案人格 / Context=月度状态 / Tools=set_intent+speak），唯一变化：

- 删除 `driverMinPerMonth=0` 的"仅深度层"语义 —— **所有居民都被驱动**，`PerMonth` 直接控制月抽样数（缺省 8，clamp [1,64]）。
- 配置键 `city_driver_per_month` 不再有 0=关闭的语义，改为 0=缺省 8（归一）。

## 4. 房间接线（`room_city.go`）

`startCityLocked` 装配 `ResidentDriver`（总与 VoiceScheduler 互斥，driver 优先）。月结后 `launchCityDriver` 调用 `drv.RunMonth(b, month, onVoice)` —— 其中 12 名被抽中的居民同时作为 UI 展示位。

**不再有** `EnsureAgents` / `agentSem` / `vcplayer.Agent` 月度决策循环 —— 驱动层统一完成。

## 5. 配置（`config/config.go`）

| 键 | 缺省 | 说明 |
|---|---|---|
| `city_driver_enabled` | true | 驱动层总开关 |
| `city_driver_workers` | 4 | 线程池 worker 数 clamp [1,16] |
| `city_driver_per_month` | 8 | 月抽样数 clamp [1,64]（0 归一为 8） |
