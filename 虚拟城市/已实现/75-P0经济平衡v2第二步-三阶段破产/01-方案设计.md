### 2.2 为什么「三阶段破产」是最大杠杆

批次 74 失败样本画像（`02-实施记录.md` §7 B75-1）：**多为净值为正的后期座位**。
现行规则 = 「月末现金连续 3 月 < 0 → `liquidate` → 清算后现金仍 < 0 → `eliminate`」。
即：**流动性危机（可变现资产 > 负债）被直接判死**。这与真实社会「困难期 → 重组 → 仍资不抵债才破产」
完全相反，正是 G5/G11 残余的主因。

### 2.3 家庭支出重复计入（B75-2）

`monthly_expense` 实测（4000 张真实卡抽样，`income_monthly` / `monthly_expense`）：

| 分组 | n | median(`monthly_expense`/income) |
|---|---:|---:|
| 全体 | 3,946 | 0.585 |
| 已婚 1 孩 | 1,759 | 0.541 |
| 已婚 2 孩 | 412 | 0.685 |
| 已婚 3 孩 | 21 | 0.699 |

⇒ `monthly_expense` **随子女数上升**，是**家庭总消费**（与批次 74 方案 §2.3 一致）。
引擎却在步骤 5 **再叠加**「配偶 2,000 + 每孩 5,000 + 赡养 1,000」（`settlement.go:623-633`），
导致已婚有孩家庭 median 总生活支出/收入 = **1.16**（63.5% 已婚有孩卡总支出 > 收入，未计房租与税）。

> ⚠️ **关键约束（实施后修正，2026-10-22）**：MC 门禁用 `profession.SyntheticCards`
> （`montecarlo.go:361`），合成卡 `Marital="single"`、`ChildrenCount=0`、`EldersDependent=0`
> ⇒ **家庭加项在步骤 5 恒为 0**，故 B75-2 的**步骤 5 修正**对门禁零影响。
> **但 `splitEngel` 的比例切分仍会影响门禁**：钟声事件（M60/M120）会让合成卡座位**游戏内结婚/生育**，
> 比例切分改变其消费篮子结构 ⇒ 商品价格/CPI 轨迹轻微偏移。实测位移为噪声级
> （≤ 0.5pp / Gini +0.012），门禁结论无一改变。**教训：合成卡只屏蔽「卡面家庭字段」，
> 不屏蔽「游戏内事件产生的家庭结构」** —— 门禁相关性不可由卡面字段直接推断。

## 3. 公式契约（权威）

> 全部改动由 `World.BalanceV2Enabled` 总开关控制；`false` = 批次 74 口径**逐字段一致**
> （旧 `liquidate`/`NegativeCashMonths` 路径原样保留，供 T6 旧口径回归）。

### 3.1 状态机

```
Normal ──月末 Cash<0 且 Cash ≥ GraceFloor──▶ H1(困难期, 不记破产)
H1 ──H1 到期仍负 / Cash<GraceFloor / 连续两月无法付息──▶ R1(协助重组)
H1 ──月末 Cash ≥ 0──▶ Normal(恢复)
R1 ──重组后基础月现金流 ≥ 0 且 Cash ≥ 0──▶ Normal(恢复)
R1 ──重组后基础月现金流仍 < 0 且 清算后 资产 < 负债──▶ B1(正式破产 / 出局)
```

### 3.2 GraceFloor

```text
GraceFloor(p) = −min(max(30000, 3 × SurvivalCoreM1(p)), 100000)
```

- `SurvivalCoreM1` 复用批次 74 `balance_v2.go::survivalCoreM1`（基础租 + 0.6 × 卡面支出）。
- 现金 ≥ GraceFloor ⇒ 视为**流动性困难**（H1）；< GraceFloor ⇒ 直接 R1。

### 3.3 H1 困难期

| 项 | 契约 |
|---|---|
| 触发 | 月末 `Cash < 0` 且 `Cash ≥ GraceFloor` |
| 时长 | 首次 **6 月**；`w.Month − LastHardshipEndMonth ≤ 24` 的重复触发 ⇒ **3 月** |
| 强制节俭 | `forcedFrugal` 增加条件「H1/R1 观察期」（§3.3.2 条件③） |
| 停加班 | H1 内 `work_overtime` 动作拒绝；`OvertimeThisMonth` 不发放 |
| 禁止新增 | H1 内禁止新增贷款、禁止买入非债券风险资产（`actions.go` 守卫） |
| 消费贷/信用贷 | **只付利息、本金延期**；不记逾期、不扣信用分、不产生 5% 罚息 |
| 房贷 | 可**一次性**申请 12 月期限延长或利率重定价，前提：调整后月供 ≤ 家庭常规收入 35% |
| 自动生效 | 失业保险、基础租上限（批次 74 已落）自动生效 |

### 3.4 R1 协助重组

1. 先用现金与流动资产补足欠息；**不得因现金短暂为负直接清空房产**。
2. 消费贷/信用贷**首次**重组：本金 ×0.5、免息、**60 期**；24 月内重复重组 ⇒ **36 期**。
3. 保留自住房条件：重组后 `房贷 + 物业 + 基础生活 ≤ 常规收入 × 55%`，且保留 3 月生存金。
4. 信用分**下限 400**（不归零）；24 月内新杠杆禁用；其后每期按时还款每 6 月 **+10**，上限 **550**。
5. 动作冻结 **1 月**（仅禁止非还款 / 非保险动作）；**不得冻结工资、失业保险与被动收入**。

### 3.5 B1 正式破产

- **仅当** R1 后仍无法形成非负基础现金流，**且**清算后 `总资产 < 总负债` ⇒ `Alive = false`、`Ending = EndingBankrupt`。
- 清算顺序：流动资产 → 非自住房产 / 商铺 → 自住房；房产按市价 **70%** 强制变现。
- `BankruptCount` 计清算事件次数；**正式出局必须额外满足 B1 条件**（「一次流动性危机 ≠ 死亡」）。
- 出局者保留终局净资产曲线与历史 Ledger；财富分布统计按**终值**纳入（G9 口径）。

### 3.6 预测基础月现金流（B1 判据）

R1 后「能否形成非负基础现金流」的**唯一**判据（禁止引入新的随机抽样或额外月结）：

```text
predictedBaseCashFlow(p) = p.Monthly.Net + Σ_loans (oldMonthlyPayment − newMonthlyPayment)
```

- `p.Monthly.Net` = 最近一次月结的 `收入 − 支出`（已含贷款月供、生活、税社保、家庭）。
- `oldMonthlyPayment` = 最近月结时该贷款的实付（月供 + 逾期罚息）；`newMonthlyPayment` = 按 R1 条款
  （本金 ×0.5、免息、60/36 期、H1 只付息）重算的月供。
- 纯算术、零 rand；对无贷款座位退化为 `p.Monthly.Net`。
- `predictedBaseCashFlow(p) < 0` **且** 清算后 `总资产 < 总负债` ⇒ B1。

### 3.7 家庭支出口径（B75-2）

```text
living      = Card.Expense × infl × consumptionLevelMult[level]   # 家庭总生活消费(含初始配偶/子女/赡养)
familyAdd   = 仅游戏内新增成员: 新生儿 × livingChildCNY + 新结婚配偶 × livingSpouseCNY
              (初始卡面成员已含在 monthly_expense 内 ⇒ 不加)
Pay(seat → firms, living + familyAdd, CatLiving)
```

- `splitEngel` 改为**比例切分**（金额守恒）：按成员构成权重（本人 1.0 / 配偶 1.0 / 每孩 1.0 / 每位老人 0.5）
  把 `living + familyAdd` 切到八大类，**不再**用固定 CNY 常数扣减。
- 生育事件（`events.go:115`）新生儿、结婚事件（`events.go:96`）新配偶 = 游戏内新增 ⇒ 计费。
