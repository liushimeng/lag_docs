## 2. 主 Agent 独立复核：发现并修复的两处缺陷

> backend-dev 交付后，主 Agent **独立复跑** `go build` / `go vet` / 全包 `go test`（183.1s，全绿），
> 并逐行复核 `bankruptcy_v2.go` 与 `settlement.go` 接线，**发现两处契约违例 bug 并当场修复**
> （均已补回归测试钉死）。

### 2.1 缺陷①：「连续两月无法付息」计数被**逐笔贷款重置**

- **现象**：`settlement.go` 步骤 6 的 H1 只付息分支内，`p.HardshipUnpaidMonths` 在**贷款循环体内**逐笔赋值
  （可付息 ⇒ 置 0；结构性不可付 ⇒ ++）。多笔消费贷时，后一笔正常即把前一笔的计数抹成 0。
- **契约违例**：方案 §3.6.1「连续两月无法付息 ⇒ R1」是**座位级**判据，不得按单笔贷款判定。
- **后果**：座位滞留 H1 超出契约时长（首次 6 月 / 重复 3 月），H1→R1 转换被推迟。
- **修复**：改为座位级 —— 循环内只置局部标志 `structuralUnpayable`，循环结束后统一
  `if structuralUnpayable { p.HardshipUnpaidMonths++ } else { p.HardshipUnpaidMonths = 0 }`。

### 2.2 缺陷②：`enterHardship` 清零计数 ⇒ R1 触发器**永不生效**

- **现象**：`bankruptcy_v2.go::enterHardship` 内 `p.HardshipUnpaidMonths = 0`。
  但步骤 6（贷款步）已算出本月计数，步骤 7 随即 `enterHardship` 把它**抹平** ⇒
  计数永远停在 1，`stepH1` 的 `HardshipUnpaidMonths >= 2` 条件**永不成立**。
- **契约违例**：方案 §3.6.1「连续两月无法付息 ⇒ R1」这条 R1 触发路径**整条失效**。
- **修复**：`enterHardship` 不再清零该计数（计数归零只在 `exitHardship` 恢复时发生）。

### 2.3 回归测试

新增 `TestBalanceV2_HardshipUnpaidCounterSeatLevel`（T15，夹具：大额消费贷月息 8,333 > 常规收入 5,000
⇒ 结构性付息不能，**在前**；小额贷月息 8 可付，**在后**）：

- M1：`HardshipUnpaidMonths == 1`（座位级计数，未被后一笔抹掉）；
- M2：`InR1 == true`（连续两月无法付息 ⇒ 触发重组），且未出局。

> 该测试在修复前**同时暴露缺陷①与缺陷②**，修复后 PASS。

familyLivingAddV2(p) =
    (p.Family.Marital == "married" && p.Family.SpouseIncome > 0 ? livingSpouseCNY : 0)   // 游戏内新配偶
  + len(p.BirthMonths) × livingChildCNY                                                   // 游戏内新生儿

### 5.4 偏离 brief 的两点（已上报并采纳）

1. **「本项对合成卡零影响」只对步骤 5 成立，对 `splitEngel` 比例切分不成立** ——
   实施方做了**隔离实验**证明：只回退步骤 5（保留新切分）⇒ 门禁数值与新版本**逐位相同**；
   只回退切分（保留新步骤 5）⇒ 数值回到基线。机理：钟声事件（M60/M120）让合成卡座位**游戏内结婚/生育**
   ⇒ 比例切分下「本人份额」缩小、配偶/子女篮子变大 ⇒ 商品篮子需求结构变化 ⇒ 价格/CPI 轨迹轻微偏移。
   位移量级 = MC 噪声级（≤ 0.5pp / Gini +0.012），**门禁结论无一改变**。
   ⇒ **主 Agent 据此修正了批次 75 设计文档 §2.3 的错误论断**（原写「B75-2 对门禁零影响」）。
2. **额外改了 `predictedBaseCashFlow` 的家庭 outflow**（超出 brief 的「只改步骤 5 与 splitEngel」）——
   理由：该函数是 B1 破产判据的现金流预测，口径必须与实际月结一致，否则系统性高估流出 ⇒ 误判 B1，
   使 B75-2 的修正被抵消。该函数仅在 `BalanceV2Enabled=true` 下可达 ⇒ **旧口径路径零影响**。

## 6. 偏离方案的设计决策（B75-1 共 6 项，须 reviewer 复核；B75-2 的 2 项见 §5.4）

| # | 偏离 | 理由 |

| 3 | 自住房保留条件（55%）**仅告警不强制出售** | 按字面条件绝大多数持房贷座都会触发抛售；B1 清算顺序「非自住 → 自住(70%)」已提供保护。严格化归批次 76 单独 A/B |
| 4 | 房贷展期后仍超 35% ⇒ 月供按 35% **clamp** | 保证契约「调整后月供 ≤ 35%」恒成立 |

## 9. 批次 75 沉淀的通用教训（供后续批次复用）

1. **状态机的「计数器」字段不得在状态迁移函数里清零** —— 若计数器在同月的其它步骤累加，
   迁移时清零会使其**永远到不了阈值**（本批缺陷②：「连续两月无法付息 ⇒ R1」整条失效）。
   归零只应发生在「恢复/退出」路径。
2. **判据必须先定「作用域」**（座位级 / 贷款级 / 家庭级），再写实现。本批缺陷①即
   「贷款级」实现被当成「座位级」契约用。
3. **「某字段对门禁零影响」不可由卡面字段直推** —— 须做**隔离实验**（只回退 A / 只回退 B），
   因为游戏内事件会合成出卡面没有的结构（本批：钟声事件的婚育）。
4. **A/B 护栏 verdict 恒 `guard_breach` 时，A/B 结论不可用** —— 须先修护栏口径（B76-5）再谈胜负。
