## 4. 本批的四个工程教训

### 4.1 「贴地钉扎」把小误差和大错误混为一谈

`export_glb` 前的「钉扎到 minY=0」用于纠正倾斜件端头 / 收分柱帽的**几毫米**误差。
但它判定的是「组内最低点 < 0 就整组上抬」——**把「水平偏移」误当成「埋进地下」**：

- 球门立柱沿 Blender Z（水平宽轴）分置在 ±3.60 m，几何完全正确，却让整组被抬 3.66 m；
- 连带 15 m 灯杆凭空长高 23%，而 bbox 守卫要超 ±5% 才报、报出来也不知道是「哪个件」。

**处置**：钉扎加容差（`PIN_TOLERANCE_M = 0.05`），超容差**只告警不抬**，并点名是哪一组。
「宁可让模型穿模，也不静默把整组抬变形」——后者会污染所有下游读数。

### 4.2 Blender 的 `make_box(size)` 是 (X 宽, **Y 水平进深**, **Z 高度**)

与 three.js `BoxGeometry(w, h, d)` = (宽, **高**, 进深) 的**中间槽位相反**。
本件因此踩了两次：把 66 m 的场地基面立成 66 m 高的墙、把 0.12 m 的标线做成 32 m 高的板。
已在 `build_sports_field.py` 顶部用整段注释锁死这条契约。

**根因不是笔误而是 API 的静默性**：`obj.scale = (x, y, z)` 对 (0.12, 7.32, 0.12) 这种
「看起来合理」的三元组不会报任何错。**`make_box` 目前是全项目最容易静默写错的入口**，
建议后续批次给 `__common__.py` 加一个 `make_box_wdh(name, w, d, h, pos)` 语义化别名。

### 4.3 `make_material(alpha<1)` 单独设 Principled Alpha 不足以让 glTF 导出 BLEND

exporter 读的是材质的**渲染方式**（Blender 4.2+ 的 `surface_render_method`，5.x 里旧的
`blend_method` 只是兼容属性）。不设就导出成 OPAQUE —— 体育场围网的 alpha 0.35 网片
渲成一堵**实心灰墙**。已在 `make_material` 内统一补上（对批次 41 的车窗玻璃同样生效）。

### 4.4 ★ 全城级既存缺陷：`Road.tsx` 把路面**居中**在 `from` 上

**这是本批最有价值的发现，与体育场本身无关，是被它暴露的。**

`Road.tsx` 的路面几何是 `PlaneGeometry(roadWidth, len)`（**居中**），而组放在
`position={[from[0], 0, from[1]]}`、`rotation=[0, angle, 0]`，`angle = atan2(dx, dz)`
使组局部 +Z 即 from→to 方向。缺 `+len/2` ⇒ **每条路的沥青面沿轴线反向平移半条长度**。

| 证据 | 内容 |
|---|---|
| 同源对照 | `RoadMarkings.partMatrix` 里**做了** `lz = len/2` 补偿（人行道/标线正确）—— 两条路基在同一组变换下互相错开半条路 |
| 量测反推 | 体育场北侧 `edgeLink` 裁剪后 `from=(10.55, 42.2)`、`len=13.5`；实测其 mesh 世界 AABB = `x[8.20,12.90] z[35.50,48.90]`，与「居中」预测 `[41.7,55.3]` 偏移 −6.2 完全吻合，与「从 from 起铺」预测 `[42.2,55.3]` 不符 |
| 视觉佐证 | 城市全景截图里路侧路灯（按 `from→to` 布点）与路面明显错位；主干道北半幅缺路面、南端伸出城外 |

**影响面**：全城 57 条路段的沥青面。修复 = `position` 的 z 加 `len / 2`（一行）。
修复后主干道正确贯穿 `z ∈ [-48, 48]`，路灯 / 人行道 / 信号灯 / 垃圾桶全线对齐。

**教训**：这类缺陷能长期存活，是因为**没有一条判据把「路面」和「路的其它所有消费者」
放在同一个断言里**。`lampsForRoad` / `roadsideBinsForNetwork` / `partMatrix` 都假设
路占 `[from, to]`，唯独 `Road` 不 —— 少一个断言，多一条错半条路的路基。

## 5. 保留地机制（新增 `cityLandmarks.ts`）

体育场占地 110×74 m，两侧都必须让开：

```
  cityLandmarks（leaf，零 import）
       ▲                          ▲
       │                          │
  roadNetwork.ts             cityObstacles.ts
（路段在保留地边界截断）      （isBuildable 让开）
```

**为什么必须抽 leaf**：`cityObstacles` 本身 import `roadNetwork`（复用 `pointSegDist`），
反向 import 会成环。

**为什么是「截断」而不是「整段拒绝」**：拒绝会让「金融副中心 ↔ 体育新城」彻底断开、
体育新城只剩一条高速联络线；截断后道路止于体育场围栏外侧，语义等价于
**「路在场馆前庭 terminates」**——这正是真实城市里大型场馆的做法（体育馆 / 机场）。

**离线回归**（`/tmp/roads47.ts`，随会话工具不入库）：

```
保留地 {"minX":4.5,"maxX":15.5,"minZ":34.8,"maxZ":42.2} 总路段 57
  ○ 仅贴边 connector conn-fin_sub_center~sports_new_city [24,30] -> [15.5,36.07]
  ○ 仅贴边 edgeLink edge-sports_new_city [10.55,42.2] -> [13.82,55.30]
✅ 无路段穿越体育场保留地
```

修复前的同一脚本输出：`相交路段数 2`（`conn-fin_sub_center~sports_new_city` 与
`edge-sports_new_city` 两条的**端点都在体育场中心**，直接横穿跑道与内场）。
