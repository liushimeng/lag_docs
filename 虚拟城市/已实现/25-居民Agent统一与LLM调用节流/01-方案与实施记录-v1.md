## 1. 背景与动机（用户反馈 3 项，2026-09-26）

创建城市时「背景居民规模」选 10，暴露三个问题：

| # | 用户反馈 | 根因摘要 |
|---|---------|---------|
| 1 | 「选 10 应该加载 10 个居民，应该是 10 个 `LsmAgentGame-City-Human` 才对」 | 实际是 **12 个常驻座位 Agent + 每月 8 条背景居民抽样轮次**（共约 20 个 City-Human 身份），与居民规模 N=10 无任何数量关系 |
| 2 | 「13 条 LLM 线路池每个都被调上百次；应为每居民 1 个 City-Human、平均每分钟 1–2 次」 | 月循环被提前结算无限加速 + wake 无界排队无去重 + 每决策最多 3 轮 tool loop，把 13 条线路打满（实测 ~97 次/分上限，均摊每 key ~450 次/小时） |
| 3 | 「虚拟城市的时间 1 分钟对应现实 1 小时，时间系统修正」 | 全库不存在「时/分」级城市时钟（只有模拟月 tick + 年龄轴）。经确认（2026-09-26 问答）语义为：**现实 1 分钟 = 城市 1 小时（60× 加速），城市时钟与月结 tick 解耦，只作叙事/日夜层** |

## 2. 现状分析（实施前代码事实）

### 2.1 「背景居民规模」全链路（字段是通的，语义不对）

- 前端：`ClientWeb/src/components/virtualCity/VirtualCityCreateRoomModal.tsx:57-65`
  `RESIDENT_MIN=10 / MAX=100000 / DEFAULT=10` → `resident_count`（顶层 payload，
  `VirtualCityLobbyPage.tsx:93`）。
- API：`ServerGo/api/room_api.go:52` `ResidentCount`；`mergeVirtualCityBodyFields`（:186-217）
  顶层优先并入 `cfg.ResidentCount`。
- service：`room_service_crud.go:285-294` clamp（`clampVirtualCityResidentCount`，:852-868：
  `v<=0 → 10000`，`<10 → 10`，`>MaxResidents → max`）；**不落 DB**，只进内存
  `pendingOpts`（`manager.go:195-223`）→ `room.applyOpts`（`room.go:288-321`）。
- 唯一消费点：`room_city.go:96` `city.NewBackdrop(r.ResidentCount, ...)` +
  `room_city.go:155-158 anchorCityProfiles(N)` —— **N 只决定背景居民数据条数**。

### 2.2 两套 City-Human 身份并存（问题 1 根因）

| 层 | 数量 | 载体 | LLM 节奏 | 工具 |
|---|---|---|---|---|
| 座位 Agent | **恒 12**（`room_service_virtual_city_fill.go:18` `wealthDeepSeatCount=12`，`room_service_crud.go:234-236` 强制覆盖） | `vcplayer.Agent`（`manager.go:410` 唯一创建点） | 每模拟月 1 轮决策 ×≤3 次 LLM（`agent/vcplayer/run.go:164`） | 17 个经济工具 |
| 背景居民 | N 条纯数据（`city/backdrop.go:110-128`，「数据不是 goroutine」） | `city.resident` | `ResidentDriver` 每月抽 `PerMonth` 条（默认 8，`config.go:1248-1250`；被 `room_city.go:127-131` 的 `PerMonth=max(PerMonth, llm_lines)` 放大到 13） | `set_intent` + `speak` |

两者共用 `AgentClassName="LsmAgentGame-City-Human"`（`agent/class_names.go:214`），
但**座位 persona 与背景 persona 是两条独立 rng 流**（`room.go:465-472` vs
`room_city.go:186-187`），17 批次「12 展示位 = Backdrop 抽样代表」的注释未落地。
N=10 时还出现**数量倒挂**：房间 12 个 Agent > 10 个居民。

### 2.3 LLM 调用放大链（问题 2 根因 A/B/C）

全库虚拟城市仅 3 个 LLM 调用点：座位决策 `vcplayer/run_llm.go:26/55`、
驱动层 `city/driver.go:244`、城市之声 `city/voice.go:154`（月结/记忆/校准/央行文本均不调 LLM）。
放大链：

- **A. 月循环无节拍下限**：`SubmitMonth` 最后一座即刻推 `settleCh`（`room.go:853-862`），
  `trySettle` 未到 `NextMonthAt` 也结算（`room.go:738-743`）→ `month_ms`（默认 8s）只是上限，
  实际月速被压到「最慢 bot 决策时长」，月结后立刻 `wakeBots()`（`room.go:809-810`）。
- **B. wake 无界排队且无「本月已决策」去重**：`runOneBot` 满槽时无条件起 goroutine
  阻塞排队（`room.go:1212-1226`）；`BeginDecision` 只挡并发不挡已提交
  （`agent_runner.go:34-57`）；`EndDecision` 跨月时 `wakeBots()` **全员重跑**
  （`agent_runner.go:59-72`）→ 同月同居民可跑 2–N 轮决策。
- **C. 每决策最多 3 轮 LLM**（`run.go:164`），且 `check_state`/`view_listings` 不耗动作预算
  （`run.go:269-276`）→ 恒定打满 3 轮。
- 叠加：`PerMonth=max(8, llm_lines)`（`room_city.go:127-131`）把线路数当任务预算（反直觉）；
  `LLM.MaxRetries=3`（`config.go:1053-1056`）失败时一次 Chat 最多 4 次上游 HTTP。

**量级验证**（`LsmAgentGame.log`）：13 线路 × 1 座位/线路的令牌通道严格轮转均摊
（`llm/linepool.go:182-208` 预填交错 + FIFO Acquire）→「13 个 provider 各上百次」
= 总调用 1300+ 的均摊投影。历史日志另有 4678 条 `callProvider error`（9/23 熔断重试风暴，
峰值 909 次/分）佐证无节流下的失控面。
健康检查（`registry.go:1325-1402`，HEAD 无 key、5 分钟一次）/ seed / prompt 构造均排除。

### 2.4 时间系统现状（问题 3）

- 只有两级时间：模拟月（`World.Month`，`engine.go:143`，`settlement.go:277` +1）与年龄
  （`Age()=startAge+(Month-1)/12`，`engine.go:331-337`）。
- 现实换算唯一点：`MonthMs`（`room.go:103`，clamp `[3000,30000]`，默认 8000ms）；
  前端 `MonthTicker.tsx:48-72` 显示「第 X 月 · Y 岁 + 倒计时 Ns」，
  `VirtualCityGamePage.tsx:56-64` 的 `fmtElapsed` 是**现实已运行时长**。
- 全库无「时/分」城市时钟、无昼夜循环（多批次文档明确「另立专项」）。

## 3. 方案设计

### 3.1 目标语义（本批次契约）

1. **居民 ↔ Agent 统一**：创建城市时选 `resident_count=N` ⇒ 该城的
   `LsmAgentGame-City-Human` 常驻 Agent 数 = `min(N, 12)`；N≤12 时**恰好 N 个**
   （N=10 ⇒ 10 个座位 Agent，0 条额外驱动轮次）。N>12 时 12 个座位 Agent 代表全城，
   驱动层按预算抽样其余居民（每月 `PerMonth=min(cfg.PerMonth, N-座位数)` 条，
   **删除 `PerMonth=max(PerMonth, llm_lines)` 放大**）。
2. **调用节流**：每个 City-Human（座位 Agent 或驱动轮次）**平均每现实分钟 1–2 次 LLM**。
   以「每 Agent 令牌桶（容量 2，每 30s 补 1 枚）」实现；单轮 tool loop 仍最多 3 轮，
   但每轮消耗 1 枚令牌，桶空即中止并提交。月结固定走 `NextMonthAt`（删除全员提交提前
   翻页快路径），使模拟月节拍 = `month_ms`，一局 420 月 ≈ 56 分钟不变。
3. **城市时钟**：现实 1 分钟 = 城市 1 小时（60×），**与月结解耦**，纯叙事/展示层。
   HUD 显示「M月D日 HH:MM」+ 时段（清晨/白天/傍晚/夜晚）；暂停时间不计入。

### 3.3 LLM 调用节流（问题 2）

| 改动 | 文件 | 内容 |
|---|---|---|
| 月节拍回归 | `game/virtual_city/room.go` | `SubmitMonth` 删除 `settleCh` 快路径（:853-862）；`trySettle` 删除「全员提交即结算」分支（:738-743）——月结固定在 `NextMonthAt`。watchdog（`watchdog.go:34`，`MonthMs×1.5`）不变 |
| wake 去重 | `room.go` / `agent_runner.go` | ① `wakeBots` 跳过 `p.Submitted` 座位；② `BeginDecision` 增加「本月已决策」标记（`agentDecisionDone[seat]==month` 拒绝）；③ `runOneBot` 删除无界排队 goroutine（`room.go:1212-1226`）→ per-seat 单槽 pending；④ `EndDecision` 跨月只补 wake 本座位 |
| 令牌桶限速 | `agent/vcplayer/`（新 `rate.go`）+ `city/driver.go` | 每 Agent 令牌桶：容量 2、每 `agent_llm_min_interval_ms`（默认 30000）补 1 枚；`callProvider` 前取令牌，桶空则本轮跳过（座位 Agent 走规则回退意图并 `submit_month`，驱动条目丢弃）。配置键 `virtual_city.agent_llm_min_interval_ms`，缺省 30000，clamp [5000, 300000] |
| tool loop 计费 | `agent/vcplayer/run.go:164-263` | 每轮 LLM 调用消耗 1 枚令牌；桶空中止 round 循环；修 **`appendMessages` 双重追加 bug**（`run.go:242-253`：超预算分支 `:245` append 后 `break`，外层 `:253` 再 append 一次 ⇒ 重复 tool_use/tool_result，费 token 且可能触发上游 400） |
| 线路数≠任务数 | `room_city.go:127-131` | 删除 `PerMonth = max(PerMonth, L)` |
| 可观测性 | `vcplayer` / `city/driver.go` | 补 LLM 调用计数（对齐 `wwplayer/agent_llm_stats.go` 形态）：per-room 累计 `seat_calls / driver_calls / voice_calls + 按 model_key 分布`，每 60s 汇总一行 `virtual_city llm rate` 日志（含每分钟速率），供 E2E 断言「每居民 1–2 次/分」 |
| MaxTokens | `agent/vcplayer/run.go:39` | 4096 → 1024（月度意图短文，超量） |

**修复后量级**：10 居民 × ≤2 次/分 = **≤20 次/分**（N=10 全房）；13 线路不再打满；
均摊每 key ~1.5 次/分 ≈ 90 次/小时，符合「每居民 1–2 次/分」。

**明确不改**：`LLM.MaxRetries`（全局共用，降它波及狼人杀/辩论）；`MonthWindowFor`
等死代码清理降为 P2（可顺手删 `manager.go:434-473` 无调用点的 `wakeBots/wakeOne/
runAgentMonth`，须先 grep 验证零调用）。

### 3.4 城市时钟（问题 3，60× 叙事层）

| 改动 | 文件 | 内容 |

### 3.5 与既有契约的关系

- **HTTP 契约不变**：`resident_count` / `month_ms` / `llm_lines` 字段名、clamp 区间全部保留；
  仅消费语义变化。`AgentClassName="LsmAgentGame-City-Human"`、错误码不动（定位声明 §5.5）。
- **`llm_lines` 语义收窄**：只控房间并发配额（信号量容量 `resizeAgentSemLocked`），
  不再放大每月驱动条数。
- **月节拍语义回归**：`month_ms` 从「上限」回归「节拍」（一局 420 月 × 8s ≈ 56 分钟，
  对齐 P0 产品文档）。
