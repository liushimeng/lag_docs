## 2. 根因分析：「系统对话已停用」报错（需求 3）

### 2.1 下发链路（既有，零改动）

```
LsmAgentGame.conf [city_system].enabled
  → main.go 启动时一次性读入：cfg.CitySystem.Enabled
  → gameSvcWs.SetCitySystemRuntime(enabled, cfg, registry)   // ws/game_service_virtual_city_system.go:61
  → s.vcSystemEnabled（GameService 字段，进程生命周期内不变）
  → game.state 帧：cs.SystemAgentEnabled                      // ws/game_service_virtual_city.go:292/297
  → 前端 gameState.system_agent_enabled === false ⇒ 面板内联红条 + 禁发
```

### 2.2 定性

- 配置开关**只在进程启动时读一次**；conf 改动后必须重启进程才生效。
- 本批排查时点：`LsmAgentGame.conf` 中 `city_system.enabled=true`（2026-11-03 18:26 写入），
  运行进程 v1.0.0-649c6794a4（2026-11-04 14:07 启动）已读到 true。
  **用户所见报错来自更早的进程态**（conf 修正前的旧进程 / 旧前端构建）。
- 代码链路无缺陷；**修复 = 重建重启 + 新房验证**（旧房 `game.state` 帧随重启后
  任意新帧即时刷新为 true，无需清理房间）。

### 2.3 本批防御性加固（新增，可选但建议）

1. **启动可见性**：`main.go` 在 `SetCitySystemRuntime` 后打一条 INFO 日志
   （`city system runtime`：`enabled` / `model_key` / `max_steps`），
   此后「是否停用」一条日志即可定性，不再需要翻代码。
2. **规则文件纠错（CLAUDE.md §29.6）**：`errcode.go` 实际为
   `35059 ErrVirtualCitySystemAgentDisabled` / `35060 Busy` / `35061 AgentNotFound`
   （35058 已被批次 68 `ErrVirtualCityPredictionRunNotFound` 占用，取值顺延）；
   CLAUDE.md §29.6 误写为 35058/35059/35060 —— 本批把 CLAUDE.md 改对，
   conf(.example) 注释（写 35059）**本来就正确，不动**。

## 3. 前端设计（frontend-dev 工作面）

### 3.1 浮窗拖拽（需求 1）

**交互**：
- 以窗口 header（`__head`）为拖拽把手：`pointerdown` → `setPointerCapture` →
  `pointermove` 位移 → `pointerup` 提交；期间 header 光标 `grabbing`。
- **拖拽中直接改元素 style（不setState）**：pointermove 高频重渲染浪费，
  仅在 `pointerup` 把最终位置提交 store；React 只在提交时重渲染一次。
- **双击 header 复位**默认位（清除持久化位置）。
- **视口钳制**：位置以左上角 `{x, y}` 记；约束
  `x ∈ [-(w-120), innerWidth-120]`、`y ∈ [0, innerHeight-56]`
  （水平至少留 120px 可见、垂直至少留 header 高度可抓回）。
- **窗口 resize 重钳制**：mount + `resize` 事件把持久化位置拉回视口。
- **窄屏（≤900px）禁用拖拽**：保持既有贴底满宽形态（媒体查询已钉死布局）；
  JS 侧 `matchMedia('(max-width: 900px)')` 命中时忽略 pointerdown。
- 最小化浮动条（`__minbar`）位置不随拖拽联动（保持左下角），仅展开窗口可拖。

**状态与持久化**：
- `store/virtualCitySystem.store.ts` 增 `dialogPos: { x: number; y: number } | null`
  与 `setDialogPos`（null = 默认位，渲染时不写 inline style，走 CSS 基础规则）。
- localStorage 键 `vc-sysdialog-pos-v1`：读取时校验有限数字并钳制，非法静默丢弃。
- 换房（`roomId` 变化）不清位置（窗口位置是纯 UI 偏好，与房无关）。

**CSS**（`styles/virtualCitySystemDialog.css` 只追加）：
- `__head` 加 `cursor: grab; user-select: none; touch-action: none;`
  （`touch-action:none` 保证触屏拖拽不被滚动劫持）；
  拖拽激活类 `__head--dragging { cursor: grabbing; }`。
- §26 三件套：纯交互态类，不引入新颜色，无动画（不涉及 `@keyframes`）。

**i18n**（`virtualCitySystem-{zh,en,ja}.ts` 同步新增）：
- `virtualCity.systemDialog.dragHint`：zh「拖拽移动窗口；双击标题栏复位」/
  en "Drag to move; double-click header to reset" /
  ja「ドラッグで移動、タイトルバーのダブルクリックでリセット」（header `title` + `aria-label`）。
- header 增 `data-testid="virtualCity-system-dialog-head"` 供验收断言。

### 3.2 顶栏按钮常显与激活（需求 2）

- `pages/VirtualCityGamePage.tsx`：**移除** `{!systemDialogDisabled && …}` 包裹，
  按钮无条件渲染（`systemDialogDisabled` 变量继续作为面板 `disabled` prop 使用，
  停用时窗口内仍显示内联红条 —— 信息量优于整钮消失）。
- 点击行为：`setSystemOpen(true)`；`SystemDialogPanel` 内新增
  `useEffect([open])`：`open === true ⇒ setMinimized(false)`
  （覆盖所有打开路径的「激活」语义：关闭态 → 打开、最小化态 → 还原）。
- 原批次 81 §8「停用隐藏入口」策略由本条**显式取代**；`CLAUDE.md` §29.8 同步备注。

### 3.3 非目标

不改 WS 帧契约、不改消息渲染（`SystemDialogMessage`）、不改最小化条形态、
不加窗口缩放（resize）；键盘移动无障碍暂不提供（鼠标/触屏 + 双击复位已覆盖主路径）。

### 4.2 目录内联改「紧凑索引」+ `list_scenarios(group)`（随扩容的必要改造）

**问题**：`prompt.go` 把全目录（kind/名称/强度/描述/参数）内联进 system。
101 个 × 全描述 ≈ 10k+ rune，每个请求都带；`list_scenarios` 全量返回同样
远超 `tool_result_limit`（4000 rune）会被截断。

**方案**（`agent/citysystem/`）：
1. `prompt.go` 拆两个函数（保留原 `ScenarioCatalogText` 语义于 Detail）：
   - `ScenarioCatalogIndex()`：紧凑索引——组头 `[组名] N 个` +
     每行 `- kind 名称(L3;参数:goods)`，**不含描述**；
     101 行 ≈ 3.2k rune，system 内联用它，并提示
     「完整描述用 list_scenarios(group=组名) 按组获取」。
   - `ScenarioCatalogDetail(group string)`：单组全量（kind/名称/强度/描述/参数），
     单组最大 21 个 × ≈100 rune ≈ 2.1k < 4000 ✓。
2. `tools.go` `list_scenarios` InputSchema 增可选 `group`
   （enum = 六个组名），描述改为
   「缺省返回全目录紧凑索引；传 group 返回该组完整描述」。
3. `dispatch.go`：`case ToolListScenarios` →
   `group==""` 返回 Index；合法组名返回 Detail；未知组名返回失败文本（is_err）。
4. `roleText` 内联段措辞同步更新；`BuildSystemBlocks` 签名不变。
5. 同步更新 `prompt_test.go` 锚点与工具 schema 断言。

**prompt cache 注意**（§14.3）：system 前缀仍逐字节稳定；目录再扩容只改
`scenario_catalog_batch8X.go` + 本索引函数，不触碰三段式头。
