## 1. 背景

《虚拟城市模拟系统 · 自迭代优化规范》§十四要求「运行时 provider 可超 8 个，调用方从不感知数量」。
City-Chrome 采集 Agent 此前固定使用 `city_chrome.model_key` 一条线路，
运营侧无法按线路切换采集质量/成本。本批给采集 Agent 加**可选线路策略**。

## 2. 交付内容（按代码事实）

| 落点 | 内容 |
|---|---|
| `ServerGo/api/room_api.go` | 建房 body 增 `city_chrome_line`（顶层或 `virtual_city` 子对象均可携带；>128 rune ⇒ 400） |
| `ServerGo/service/room_service.go` | `VirtualCityRoomOptions.CityChromeLine` 落到房间选项 |
| `ServerGo/main.go` | 建房时调 `cityChromeSvc.SetLinePolicy(opts.CityChromeLine)`（server 级单例，后建房覆盖） |
| `ServerGo/citychrome/service.go` | `SetLinePolicy` 透传到 Agent |
| `ServerGo/citychrome/agent.go` | `SetLinePolicy` / `LinePolicy`；`LinePolicyRandom = "random"`；空串 = 沿用 `cfg.ModelKey`（旧行为零回归）；`random` = 每个 mission 从线路池按 `concurrency_lines` 加权随机取线，池空回退配置 `model_key` |
| `ServerGo/citychrome/mission_log.go` | `MissionRecord` 增 `model` 字段，记录本次采集任务实际使用的线路 |
| 前端 | `VirtualCityCreateRoomModal.tsx` 建房弹窗增「采集 Agent 线路」下拉（默认「只随机」，可固定到线路池中某模型）；`VirtualCityLobbyPage.tsx` 透传；zh/en/ja 三语文案（`virtualCityLinePool-*.ts`） |

## 3. 语义与边界

- **取值**：`""`（缺省）= 沿用服务端 `city_chrome.model_key`；`"random"` = 每次 mission 加权随机；
  其余 = 固定 model key（须存在于线路池，否则回退配置 `model_key`）。
- **作用域**：server 级单例（数据通道与房间无关），**后建房覆盖前值**。
- **遥测**：`MissionRecord.model` 落盘到 `missions[]`，看板「采集」子页可回溯每条任务走的线路。
- **零回归**：缺省（不传 `city_chrome_line`）⇒ 行为与批次 65–78 完全一致。

## 5. 遗留

- 「只随机」默认值为**策略选择**，非线路选择：具体线路仍由线路池按权重随机，
  若需要「固定某线路且可观测命中分布」需批次 81+ 补线路池命中率统计。
