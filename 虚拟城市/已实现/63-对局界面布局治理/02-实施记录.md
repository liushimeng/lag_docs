## 3. 未能完全实测的项及原因

- **e（actionbar+ticker 合计）**：观战页（`/virtual-city/spectate/:id`）按设计**不渲染** ActionPanel（`{!spectator && <ActionPanel/>}`），故无法在观战态量到 actionbar 高度。已做的代码层保障：`.virtualCity-ticker { flex:0 0 auto; max-height:140px }` + `.virtualCity-actionbar { flex:0 0 auto }`（防被 column flex 压扁）。非观战态（人类入座）下 actionbar 自然高度由内容决定，且可折叠（批次 20 AB-1）。
- **f（指标卡 scrollWidth）**：观战态下 `BehaviorPanel` 返回空态占位块、无 `virtualCity-behavior__stat/__metric` 元素，`MacroPanel` 的价差表单元格虽有 `__macro__cell` 类但观战态数据为空时可能不渲染。代码层已加 `min-width:0; overflow-wrap:anywhere; font-variant-numeric: tabular-nums`，非观战态下生效。
- **g（折叠后高度）**：`.virtualCity-sidebar__panels` 是 `flex:1 1 auto`（撑满 sidebar 剩余高度），容器高度由 sidebar 决定，折叠 CityStatsPanel/BotPanel 改变的是**面板区内部内容高度**（可滚动范围），不改变容器高度。折叠功能本身验证通过（toggle 切换 + LS 持久化），其价值在非观战态下让 Tab 面板拿到更多滚动空间。

> ⚠ **准确性更正**：方案 §2.2 要求「`CityStatsPanel` 与 `VirtualCityBotPanel` 接入 `CollapsibleSection`」——
> 实测这两个组件**此前已接入**（`CityStatsPanel.tsx:130` / `VirtualCityBotPanel.tsx:146`，
> 且 `git status` 显示两文件本批**未修改**），折叠 + `virtualCity.ui.collapsed.{city_stats,bot_panel}`
> 持久化早已就位。本批**未重复接线**，只验证其可用；上表 e/f/g 三项「⚠」的根因同上（观战态量不到），
> 非本批引入的缺陷。
