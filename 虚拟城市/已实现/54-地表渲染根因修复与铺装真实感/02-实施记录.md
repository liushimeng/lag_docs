## 1. 实施内容

### 1.1 代码改动（唯一文件：`ClientWeb/src/engine3d/textureCache.ts`）

1. **`startLoad` 占位纹理对象化**（方案 A）：
   - 采用 `THREE.TextureLoader.load()` **同步返回的纹理对象**（image=null 占位）
     作为 entry.tex 立即入缓存；采样参数（colorSpace / mag/minFilter /
     anisotropy / wrap / repeat）抽为 `applyTextureOpts` 在创建时同步施加
     （回调入参 `loaded` 与同步返回值是同一对象，无需二次施加）。
   - `startLoad` 增加幂等守卫（`CACHE.get(key)` 命中即返回）——
     支撑下方渲染期 get-or-create 的 StrictMode/并发双调安全。
2. **`useSharedTexture` 渲染期 get-or-create**：useState 初始化器直接
   `startLoad(...)` 并返回占位纹理 —— 首个消费者首帧即持稳定 map 引用，
   材质首编译即带 USE_MAP。原「useEffect 建好 entry 再 setTex」路径对
   **首个消费者**必然错过首编译（effect 在首帧之后才跑），是本缺陷的
   第二大根源（第一根源是 r3f 不设 needsUpdate）。
3. 失败哨兵 / `url===''` 返回 null / `clearTextureCache` / `useSharedPBR` /
   `withPBR` 语义全部不变；游戏侧零改动。

### 1.2 已知取舍

- 加载窗口内占位纹理在 GPU 侧采样为 (0,0,0,1) 黑（WebGL 未上传纹理规范
  行为），本地资产毫秒级到达，仅首帧可能闪过；验收以稳态帧为准。
- 失败路径（资产 404，生产构建中不可能出现：URL 全部来自 import.meta.glob）
  map 由有转无同样缺 needsUpdate —— 与修复前失败行为等价（修复前 = 永远无
  map 走降级色），不劣化。
