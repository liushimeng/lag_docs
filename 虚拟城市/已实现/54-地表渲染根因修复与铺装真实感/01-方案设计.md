## 1. 问题现象与 CDP 实证链

### 1.1 现象

白昼（晴天正午）全城地表呈**均质亮白**：80×80 城市基底、32 块区底板、
沥青路面、人行道全部白成一片，道路标线消失；夜间则整体偏暗灰、看不出异常。
建筑（GLB 内嵌贴图）、树木（实例化材质）不受影响。

### 1.2 实证链（2026-10-10 CDP 观战实测，room `32a93d1f`）

| # | 实验 | 结果 | 结论 |
|---|---|---|---|
| E1 | 读取 160×160 地面 mesh 材质 | `map` 已挂载 urban_base 贴图，`map.colorSpace='srgb'`，`map.image.complete=true`，逐像素读图为 (55,59,66) 深灰 | 贴图对象、数据、色彩空间全部正确 |
| E2 | 染红实验：`material.color.set('#ff0000')` | 地面变**亮红**而非暗红 | **着色器未采样 map**（若 USE_MAP 生效，深灰贴图会把红压成暗红） |
| E3 | 关闭雾、扫描全场大平面 | y=0~2 之间无任何覆盖物；雾 near=120/far=240，街景机位 3~15 m 处亦白 | 排除雾 / 覆盖层 / 天空穹顶 |
| E4 | `material.needsUpdate=true` 一发 | 地面立刻呈现深灰 urban_base 纹理，全城恢复对比度 | **根因 = 着色器程序未随 map 到达重编译** |

### 1.3 根因机理

`useSharedTexture`（`ClientWeb/src/engine3d/textureCache.ts`）的设计是
**加载完成前返回 `null`**，加载完成后 `setTex(loaded)` 触发 re-render，
`map={tex ?? undefined}` 由 r3f `applyProps` 赋值到 `material.map`。

但 **r3f 8.17.10 的 `applyProps` 不会为 `map` 等影响 program defines 的
属性变更设置 `material.needsUpdate`**（已在 node_modules 源码确认零命中；
three r169 的 program cache key 含 map 有无，version 不变则沿用旧程序）。
于是：

```
首帧编译：map=null → 程序无 USE_MAP → 白 color 直通
贴图到达：map=Texture，但程序不重编译 → map 被静默忽略 → 全白
```

这正是「声明了却从不接线」家族的渲染版：属性接了，**着色器没接**。

### 1.4 波及面（全部为 useSharedTexture/useSharedPBR 消费者）

- `VirtualCityCityMap.tsx::Ground`（urban_base / asphalt_main）—— 白得最严重
  （`color: tex ? '#ffffff' : '#141a24'`，tex truthy 但 map 不生效 = 纯白）
- `DistrictBlock.tsx` 32 块区底板（districts/<id>）+ 草地/广场覆盖层
- `Road.tsx` 沥青路面、`RoadMarkings.tsx` 人行道/标线合并 mesh
- 运河水面、滨海/沙漠/森林边缘地表、停车场、公园地面等 props 层

GLB 内嵌贴图（建筑/车辆/行人，GLTFLoader 在首渲染前完成解析绑定）与
程序化纯色件（路缘/路灯）不受影响 —— 与观测一致。

### 1.5 为何此前批次截图「看起来正常」

历史验收截图多拍摄于 HMR 重挂载后（材质随 remount 以 `done=true` 的缓存
同步拿到贴图，首编译即带 USE_MAP）或夜间低对比场景；生产冷启动路径
（用户首次打开）稳定复现全白。本次为用户冷启动真实路径的首次白昼截图曝光。

## 2. 修复方案比选

| 方案 | 做法 | 判定 |
|---|---|---|
| **A. 占位纹理对象（本批采用）** | `startLoad` 直接采用 `THREE.TextureLoader.load()` **同步返回的纹理对象**（image=null 占位），参数（colorSpace/wrap/repeat/anisotropy）在创建时同步设置；组件首帧即拿到稳定纹理对象，`map` 首编译即有 USE_MAP；图片到达后 `needsUpdate` 重上传 | 单点修复、惠及全部消费者；加载窗口内该纹理采样为黑（与多数降级色同为暗色，可接受） |
| B. 逐组件补 needsUpdate | 每个用 `map={tex}` 的材质加 `useEffect(() => { mat.needsUpdate = 1 }, [tex])` | 改动面数十处、必然漏接（§130 反模式），否 |
| C. r3f 层面打补丁 | patch applyProps | 污染依赖、升级即失效，否 |

**方案 A 细节**：

- `startLoad`：`const tex = LOADER.load(url, onLoad, undefined, onError)` —
  TextureLoader 内部即「先建纹理、图片到达后填 image + needsUpdate」，
  与方案 A 语义完全一致，只是把返回对象立刻放进 entry.tex。
- 缓存 key / 失败哨兵 / `url===''` 返回 null / `clearTextureCache` 语义全部不变。
- 失败路径（404 几乎不可能：URL 全部来自 import.meta.glob 已打包资产）：
  `entry.tex=null` 并通知 → 组件 `map=undefined`；此时「map 移除」同样缺
  needsUpdate，会停留在 USE_MAP 程序 —— 与现网失败行为等价（现网失败 =
  永远 null 无 map），不劣化，登记为已知取舍。
- 加载窗口的采样色：未上传纹理在 WebGL 中采样为 (0,0,0,1) 黑 —— 地面窗口期
  由深灰降级色变为一瞬纯黑，本地资产毫秒级到达，**验收以最终帧为准**。
