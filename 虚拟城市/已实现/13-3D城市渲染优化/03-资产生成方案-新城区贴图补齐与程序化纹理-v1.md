## 2. 双轨生成策略

### 轨道 1 · AI 生成（首选，`generate_wealth_city_assets.py` 扩展）

在 `FACADES` / `ROOFS` 字典追加 8 城区描述词，并新增 `DISTRICTS_V2` 底板清单
（底板当前在 `generate_wealth_assets.py::DISTRICTS`，v2 城区追加在同文件或新函数，
保持 skip-if-exists 续跑语义）。每区描述词须含：建筑风格、材质、色调（与
`types/wealth.ts::WEALTH_DISTRICTS` 的城区色呼应）、正视/俯视角度声明。

prompt 基调表（节选）：

| 城区 | facade 关键词 | district 底板关键词 |
|---|---|---|
| logistics_port | 集装箱堆场立面、金属波纹板、灰蓝色 | 俯视港口堆场、集装箱网格、灰色地坪 |
| hightech_park | 现代玻璃办公楼、浅灰铝板 | 俯视科技园区、规则路网绿化带 |
| edu_district | 红砖学院教学楼、白色窗框 | 俯视校园、操场绿地红砖建筑 |
| medical_city | 白色医院大楼、浅蓝玻璃、规整窗格 | 俯视医疗园区、白色建筑群 |
| industrial_park | 标准厂房、锯齿屋顶侧墙、金属灰 | 俯视厂区、灰色厂房矩阵 |
| central_park | （低层景观建筑、木格栅） | **俯视公园绿地、园路蜿蜒、湖面** |
| transport_hub | 车站大跨钢构、玻璃幕墙 | 俯视枢纽站场、轨道与广场 |
| cultural_creative | 创意园彩色立面、涂鸦元素 | 俯视文创园、彩色低层错落 |

运行：`cd python-generate-image-tool && python3 generate_wealth_city_assets.py --only facades,roofs,districts`
（skip-if-exists，旧 8 城区已存在的文件不会被重生）。

### 轨道 2 · 程序化生成（兜底，`3d_script/procedural_city_textures.py`）

**无外部 API 依赖**（纯 Pillow），输出与轨道 1 同名同尺寸文件。
当 Ark API 不可用/失败 3 连时，用本脚本补齐全部缺口文件。
前端「贴图缺失 → 纯色」兜底仍然保留，但目标是 32 张全部落盘。

- 确定性 seed = FNV-1a(文件名)，重跑产物一致。
- 立面：底色 + 窗格矩阵（楼层数 × 开间数，窗洞深色 + 高光边）+ 底部裙楼色带。
- 底板：城区底色 + 噪声斑块 + 道路网格暗线；central_park 为绿底 + 园路曲线 + 湖面块。
- 屋顶：平顶灰 + 设备方块阴影；坡屋顶区给红/灰瓦条纹。

运行：`python3 3d_script/procedural_city_textures.py`（幂等，`--force` 覆盖）。

### 轨道优先级

已有文件**绝不覆盖**（两轨同守 skip-if-exists）；AI 轨道产物的艺术性优先，
程序化轨道只填空洞。未来重生成某区：手动删文件后跑轨道 1。

## 3. `3d_script/` 目录规约

- 用途：3D 模型/纹理/几何相关的**生成脚本**（Python），与 `python-generate-image-tool`
  （AI 图像子模块）并列但**自包含**——不依赖子模块、不依赖外部 API。
- 文件命名：`snake_case.py`；每个脚本头部 docstring 写明产物清单与目标路径。
- 依赖仅允许 Pillow（`requirements` 注明版本）；禁止新增重型依赖（torch 等）。
- 产物一律写入 `ClientWeb/src/assets/images/wealth/**`，脚本不自带产物副本。

## 4. 验收

1. 32 张目标 PNG 全部存在且非 0 字节；`file` 命令确认为 PNG 且尺寸正确。
2. `npm run build` 后 `dist` 内能找到新贴图（glob 打包成功）。
3. 游戏内 16 城区无「纯色底板城区」（除 central_park 绿底是设计意图）。
4. 脚本幂等：连跑两次 `procedural_city_textures.py`，第二次输出 "skip" 且不改变文件 hash。
