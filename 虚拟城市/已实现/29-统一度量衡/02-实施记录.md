## 1. 结论摘要

1. **12 个批次 19 遗留 GLB 全部重导出**，脚本从「作者自定 Y-up 摆放」**重写为 Blender Z-up 原生摆放**
   （不是事后旋转——逐轴缩放不等时事后旋转会把车轮压成椭圆），并显式 `transform_apply(location, rotation, scale)` 烘焙；
   世界包围盒 = 目标 **±0.00%**（12 项全 0.00%）。
2. **用户主诉消除**：垃圾桶由「20 m ⌀ × 10 m 高」的巨型圆柱 → ⌀0.48 m × 0.83 m 的路侧小件、落位由悬空 y=0.5 → **y=0 贴地**；
   行人由横躺 8.6 m「原木」→ 直立 1.67 m；车辆出现 12 m 公交且不再半埋。
   二分反证：隐藏 5 个 `TrashCan_*` instancedMesh 后巨型圆柱全部消失 ⇒ 症状与该子树一一对应。
3. **核心不变量「GLB ≡ 程序化 fallback」成立**：`disable-blender-models=1` 全程序化路径与 GLB 路径的
   `vehicles` / `pedestrians` 包围盒**逐位相同**。
4. **补上两个自动护栏**（这本是根因：规约只在实施记录 + 零校验）：
   `3d_script/verify_glb_aabb.py`（资产出厂，22/22 PASS，负例可 FAIL）+ `engine3d/glbSizeGuard.ts`（消费进场，dev-only，17/17 绿）。
5. **判据 6 / R2b 朝向项已结案**（主 Agent 决策 = **修法②**：**不重导资产**，改消费端 yaw —— 约定重定基为
   「**车辆长轴 = 局部 +X**」；`Vehicle.tsx` 的 `angle` 由 `atan2(dx, dz)` 改为 `atan2(-dz, dx)`）：
   复编译后实测 **50/50 辆车长轴对齐行进方向**（`avg |局部 +X · 行进| = 1.000`）。
   原「车辆正面 = +Z」的立项判断**事实基础有误**（车辆模型长轴本就在 +X，且该资产刚通过尺寸/落地验收）
   ⇒ 车辆（长轴 +X）与行人（向前 +Z）**两条约定并存、各自自洽**，见 §5 **L-C1（已结案）** 与方案 §3.1 / §4.1。
6. **一处漏检机制被记录**：本次"公式对、模型轴不对"骗过了判据 4（GLB 与 fallback **一致地错**，两路径一致这条不变量掩盖了它）
   ⇒ `glbSizeGuard` 目前**不校验朝向**，登记为遗留 **L11**。

### 5.1 L-C1 结案记录：车辆朝向（决策 = 修法②，2026-09-27）

**问题**（立项推导，事实部分成立、结论改判）：资产长轴在局部 **+X**（`vehicles/bus.glb` 实测 `X 1.200` = 车长），
而消费端 `angle = Math.atan2(dx, dz)` 在数学上把**局部 +Z** 对齐行进方向（仓库自带 three 复算：局部 +Z·行进 `= 1.000`、局部 +X·行进 `= 0.000`）
⇒ 当时判断"车辆长轴与行进方向垂直 90°，须重导资产为长轴 Z"（即修法①）。

**决策**：主 Agent 裁决采纳**修法②（改 yaw，不重导 GLB）**。理由：
① R2b「车辆正面 = +Z」的**事实基础是错的** —— 车辆模型（GLB 与 fallback 同口径）长轴本就在 +X，
且该资产是本批次**刚验收定稿**的（尺寸 / 落地 / material group 归并均已过验）；
② 把长轴统一到 Z-forward 需重跑 4 个 build 脚本 + 重导 4 个 `.glb` + 同步改 fallback 几何与 18 个细节件坐标轴，
改动面更大且会**作废刚完成的尺寸验收**；③ 改 yaw 是**零风险单点改动**且不触碰资产。
⇒ **约定重定基**：**车辆约定 = 长轴局部 +X**；**行人约定 = 向前局部 +Z**；**两条约定并存、各自自洽，勿互相 align**。

**实施**（`ClientWeb/src/components/virtualCity/props/Vehicle.tsx`，**仅此一文件**）：

```
- angle: Math.atan2(dx, dz)      // 把局部 +Z 对齐行进方向 ⇒ +Z 是车宽轴 ⇒ 车长轴垂直行进 90°（横着开）
+ angle: Math.atan2(-dz, dx)     // 把局部 +X（车长轴）对齐行进方向
```

推导（已写入代码注释）：three 绕 Y 旋转 θ 时局部 `+X = (cosθ, 0, −sinθ)`，欲其 `= (dx, dz)/L`
⇒ `cosθ = dx/L` 且 `sinθ = −dz/L` ⇒ `θ = atan2(−dz, dx)`。
**未受影响项**：`lane.ox/oz` 未动（由行进向量直接算，与 yaw 无关）；`sprite`（Billboard）分支经读 drei 源码确认不受影响
（Billboard 每帧取相机世界四元数并左乘父级世界四元数的逆 ⇒ 父 group 的 Y 旋转被精确抵消）。

**实测验收**（复编译后真实浏览器，新建全 Agent 城，量测 **50 辆车**）：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| `avg |局部 +X · 行进方向|` | 0.000 | **1.000** |
| 长轴对齐行进方向的车数 | 0 | **50 / 50** |
| `avg |局部 +Z · 行进方向|` | 1.000 | 0.019 |

> 修复前的 `1.000 / 0` 是**同一环境、同一批实例矩阵**实测所得 —— 即"局部 +Z = 行进方向"这一事实的直接证据（也是 L-C1 立项推导的实证）。

**门禁**：`npx tsc --noEmit` 退出码 0；`npm run build` ✓ built（**14.01s**）。
