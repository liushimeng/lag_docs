## 1. 背景与目标

### 1.1 现状：9 个平级 Tab

虚拟城市对局页右侧栏此前是 9 个**平级** Tab（`VirtualCityGamePage.tsx` 的 `tabs[]`，分 2 组）：

| # | Tab id | 面板组件 | 原分组 | 数据性质 |
|---|---|---|---|---|
| 1 | `finance` | `FinancialPanel` | data | 个人财务 |
| 2 | `market` | `MarketPanel` | data | 模拟内市场 |
| 3 | `ledger` | `LedgerPanel` | data | 账簿流水 |
| 4 | `economy` | `EconomyPanel`（含调研入口） | data | 消费/劳动力/社会 |
| 5 | `market-trade` | `MarketTradePanel` | trade | 挂单/交易/借贷/信息市场 |
| 6 | `insurance` | `InsurancePanel` | trade | 保险 |
| 7 | `behavior` | `BehaviorPanel` | data | 行为金融画像 |
| 8 | `macro` | `MacroPanel` | data | 宏观泡沫/流动性 |
| 9 | `realtime` | `RealtimeBoard` | data | **外部真实世界行情/新闻** |

### 1.2 为什么现在做：三条问题

| 问题 | 现象 | 后果 |
|---|---|---|
| **① 语义割裂** | 8 个「模拟内」Tab 与 1 个「外部真实世界」Tab 平级混在同一排；Tab 之间无信息架构解释，用户无法回答「**这座城市现在怎么样**」 | 每次都要逐个点开 9 个 Tab 拼图；外部数据与内部数据的边界在视觉上完全消失 |
| **② 分类缺失** | 没有「一眼看全」的总览；每个 Tab 都是单一子系统的纵切视图，横切问题（财政 vs 就业 vs 市场 vs 外部）无处可看 | 观察者/科研用途（《定位声明》§6 预测运行）缺少「一屏读数」入口 |
| **③ 信息密度不均 / 层级倒挂** | `realtime` 独占一个一级 Tab，内部却有 **8 个子 Tab**（总览/A股/港股/美股/贵金属/期货/比特币/新闻）——**层级倒挂**；反之 `behavior`/`macro` 半屏留白 | 两级 Tab 语义相反；窄侧栏（380px）里 9 个长标签换行后被 `max-height:112px` 裁切（批次 62 实测教训） |

### 1.3 目标

1. **单一入口**：侧栏只有「虚拟城市 - 实时看板」一个看板容器，内部按 3 组组织 11 个维度 Tab。
2. **分类清晰**：3 组 = `城市运行 city` / `市场金融 market` / `外部实时 external`，组标签可见。
3. **目录双源**：**前端静态目录为渲染权威**（首屏不依赖网络），**后端目录为校验/补充源**。
4. **离线可用**：外部通道离线（`code=35053`）时看板骨架（标题条 + 11 Tab + 城市总览 + 数据源清单）照常渲染。
5. **零行为回归**：既有 9 个面板的**内部行为、交互、跨面板跳转**（`onTradeTab('market-trade')` / `onViewLedger()`）全部保持不变。

### 1.4 非目标（本批明确不做）

- 不做 tick 级高频行情、不做后端 OHLC 持久化（沿批次 65 §8 边界）。
- 不做看板布局自定义 / Tab 顺序拖拽 / 面板尺寸持久化。
- 不做后端新业务字段（城市总览 100% 由既有 `game.state` 聚合）。
- 不改既有 9 个面板的内部渲染逻辑与数据口径。
- 不改 `RealtimeBoard` 的 8 个子 Tab 结构（外部实时是本看板的一个维度，不是替代品）。

## 2. 设计原则

| # | 原则 | 落地判据 |
|---|---|---|
| **P1** | **统一单一入口** | 侧栏只保留一个看板容器；既有面板组件**源码零改动**复用，只换外壳 |
| **P2** | **分类多 Tab** | 3 组 11 Tab，组标签常驻；Tab 短名（≤4 汉字）防窄栏换行裁切（批次 62 教训） |
| **P3** | **目录双源、渲染权在静态** | 前端 `dashboardCatalog.ts` 决定 Tab 是否存在；后端 `dimensions[]` 只按 id 覆盖 `title_key` / `group`，**未知 id 一律忽略** |
| **P4** | **离线可用** | 通道离线 → `code=35053` 但 `data.dashboard` 仍完整返回；前端按「离线降级」处理，**只更新徽章，不进错误通道** |
| **P5** | **不新增后端字段** | 城市总览 39 项 KPI 全部来自既有 `game.state` 路径（§7.1），零平行账本、零新协议字段 |
| **P6** | **可折叠防留白** | 每个维度面板包 `BoardSection`（统一标题条 + 折叠），折叠状态**按维度 id 记忆** |
| **P7** | **零行为回归** | 既有面板内部逻辑、跨面板跳转、WS 帧、store slice 一律不动 |

> **P3 为什么不让后端目录当权威**：目录承载的是「Tab 可达性」这一**功能契约**。
> 若让后端目录覆盖前端，一次后端改版漏发 `city-overview` 就会让用户**看不到城市总览**。
> 后端目录因此是**观测与补充手段**，不是**控制手段**。

## 3. 看板信息架构

### 3.1 一级分组与 11 个维度 Tab

| # | 维度 id（= Tab id） | 组 | 中文短名 | 面板组件 | `title_key` |
|---|---|---|---|---|---|
| 1 | `city-overview` | `city` | 城市总览 | `CityOverviewPanel`（**新建**） | `virtualCity.dash.dim.cityOverview` |
| 2 | `finance` | `city` | 财务 | `FinancialPanel` | `virtualCity.dash.dim.finance` |
| 3 | `ledger` | `city` | 流水 | `LedgerPanel` | `virtualCity.dash.dim.ledger` |
| 4 | `economy` | `city` | 经济 | `EconomyPanelWithSurvey` | `virtualCity.dash.dim.economy` |
| 5 | `behavior` | `city` | 行为 | `BehaviorPanel` | `virtualCity.dash.dim.behavior` |
| 6 | `macro` | `city` | 宏观 | `MacroPanel` | `virtualCity.dash.dim.macro` |
| 7 | `market` | `market` | 行情 | `MarketPanel` | `virtualCity.dash.dim.market` |
| 8 | `market-trade` | `market` | 交易 | `MarketTradePanel` | `virtualCity.dash.dim.marketTrade` |
| 9 | `insurance` | `market` | 保险 | `InsurancePanel` | `virtualCity.dash.dim.insurance` |
| 10 | `realtime` | `external` | 外部实时 | `RealtimeBoard`（**保留 8 子 Tab**） | `virtualCity.dash.dim.realtime` |
| 11 | `datasources` | `external` | 数据源 | `DataSourcesPanel`（**新建**） | `virtualCity.dash.dim.dataSources` |

**分组语义**：

- `city` **城市运行** —— 城市/居民/个人在模拟内怎么活（总览、财务、流水、经济、行为、宏观）。
- `market` **市场金融** —— 资产与风险的交易面（行情、交易、保险）。
- `external` **外部实时** —— 与本模拟**无因果**的真实世界数据与其来源说明（外部实时行情、数据源清单）。

> **边界声明**：`external` 组数据**只读展示**，对模拟内经济**无写作用**；
> 唯一例外是批次 66 已落地的外盘情绪锚**微偏置**（股票 ±0.3% / 黄金 ±0.2% 封顶），
> 其口径与零回归契约以批次 66 文档为准。

### 3.3 Tab id 契约

- **id 是契约**：后端 `dimensions[].id`、前端 `VirtualCityPanelTab` 联合类型、静态目录 `id`、折叠记忆键，四处**必须逐字一致**。
- **零改名**：既有 9 个 id（`finance` / `market` / `ledger` / `economy` / `market-trade` / `insurance` / `behavior` / `macro` / `realtime`）
  **一个都没改** ⇒ `ActionPanel` 的 `onTradeTab('market-trade')`、`GameOverModal` 的 `onViewLedger()`（`→ 'ledger'`）**天然继续有效**。
- 新增 2 个 id：`city-overview` / `datasources`。
- `VirtualCityPanelTab` 联合类型在 `virtualCity.store.ts`（权威）与 `VirtualCityGamePage.tsx`（历史遗留的局部重复声明）**两处**；
  本批扩展 store 侧并**消除页面侧重复**（页面不再声明 Tab 联合类型与 `tabs[]` 数组）。

## 4. 数据体系设计

### 4.1 维度目录（`dimensions`，11 条）

每条维度描述「一个 Tab 是什么、从哪来、什么口径、什么单位、多久刷一次」：

| 字段 | 类型 | 语义 | 取值约束（后端常量） |
|---|---|---|---|
| `id` | string | 维度标识 = 前端 Tab id | 11 个固定值（§3.1） |
| `group` | string | 所属一级分组 | `city` / `market` / `external` |
| `title_key` | string | i18n 键（完整键，含 `virtualCity.` 前缀） | `virtualCity.dash.dim.*`（11 条统一前缀） |
| `source` | string | 数据来源类型 | `game_state` / `citychrome` / `static` |
| `scope` | string | 数据作用域 | `self`（仅本人可见）/ `room`（全房间可见）/ `global`（与房间无关） |
| `unit` | string | 主量纲（前端格式化口径） | `cny` / `pct` / `index` / `count` / `text` / `mixed` |
| `refresh` | string | 刷新节奏 | `push`（WS 推送）/ `realtime`（外部通道）/ `monthly`（按月）/ `static`（不变） |

**11 条具体取值**（后端 `dashboardDimensions` 包级目录，**顺序即前端默认 Tab 顺序**，切片下标是契约的一部分）：

| # | `id` | `group` | `title_key` | `source` | `scope` | `unit` | `refresh` |
|---|---|---|---|---|---|---|---|
| 1 | `city-overview` | `city` | `virtualCity.dash.dim.cityOverview` | `game_state` | `room` | `mixed` | `push` |
| 2 | `finance` | `city` | `virtualCity.dash.dim.finance` | `game_state` | `self` | `cny` | `push` |
| 3 | `ledger` | `city` | `virtualCity.dash.dim.ledger` | `game_state` | `self` | `cny` | `push` |
| 4 | `economy` | `city` | `virtualCity.dash.dim.economy` | `game_state` | `room` | `mixed` | `push` |
| 5 | `behavior` | `city` | `virtualCity.dash.dim.behavior` | `game_state` | `self` | `mixed` | `push` |
| 6 | `macro` | `city` | `virtualCity.dash.dim.macro` | `game_state` | `room` | `mixed` | `push` |
| 7 | `market` | `market` | `virtualCity.dash.dim.market` | `game_state` | `room` | `index` | `push` |
| 8 | `market-trade` | `market` | `virtualCity.dash.dim.marketTrade` | `game_state` | `room` | `cny` | `push` |
| 9 | `insurance` | `market` | `virtualCity.dash.dim.insurance` | `game_state` | `self` | `cny` | `push` |
| 10 | `realtime` | `external` | `virtualCity.dash.dim.realtime` | `citychrome` | `global` | `mixed` | `realtime` |
| 11 | `datasources` | `external` | `virtualCity.dash.dim.dataSources` | `static` | `global` | `text` | `static` |

- `title_key` **11 条全部走统一前缀** `virtualCity.dash.dim.*`（不复用既有 `virtualCity.tab.*` 键）——
  好处：看板外壳的文案**自成一体**，可整组替换/多语化；代价：与既有 Tab 键**并存**（不冲突，仅冗余）。
  既有 `virtualCity.tab.*` / `virtualCity.rt.tab` 键**保留**（`RealtimeBoard` 组件与其它页面仍在用）。
- `scope` 与观战态的关系：`self` 维度（财务/流水/行为/保险）在观察者身份下 `game.state.my` 为 `null`，
  沿**各面板既有降级行为**处理；`city-overview` 是 `room` 作用域 ⇒ 观战者与条件触发者看到的读数**完全一致**
  （《定位声明》§7 观察者语义）。

## 5. 接口契约

### 5.1 `GET /api/virtual_city/dashboard`（需登录）

**路由**：`router.go` 的 `vcRt := r.Group("/api/virtual_city")`（已挂 `middleware.AuthRequired`）→ `vcRt.GET("/dashboard", vcDashboardAPI.Dashboard)`。
**装配**：`main.go` 用**同一个** `cityChromeSvc` 单例构造 `api.NewVirtualCityDashboardAPI(cityChromeSvc)`（**不新建 citychrome 实例**）。

**请求**：无参数（全局数据，与房间无关；不需要 `roomId`）。

**响应**（HTTP **200**；`code` 在 body 内，沿用仓库统一 `Result{code,message,data}` 信封）：

```jsonc
{
  "code": 0,
  "message": "ok",
  "data": {
    "dashboard": {
      "schema_version": 1,                       // int，当前 1
      "generated_at": 1750000000,                // unix 秒
      "dimensions": [ /* 11 条，顺序 = §4.1 */ ],
      "data_sources": [ /* 22 条，顺序 = §4.2 */ ],
      "realtime": {                              // ≡ citychrome.Feed
        "channel": { "status": "online", "detail": "", "last_ok_at": 1750000000 },
        "updated_at": 1750000000,
        "categories": { "a_share": { "updated_at": 0, "source": "", "quotes": [], "history": {} } },
        "news": []
      }
    }
  }
}
```

**字段表**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `data.dashboard.schema_version` | int | ✅ | 目录结构版本（当前 `1`；结构变更即 +1）。前端展示为「数据版本 v{n}」 |
| `data.dashboard.generated_at` | int64 | ✅ | 生成时刻（**unix 秒**，非毫秒） |
| `data.dashboard.dimensions` | array | ✅ | **固定 11 条**；顺序即 Tab 渲染顺序（后端下标是契约） |
| `data.dashboard.data_sources` | array | ✅ | **固定 22 条**；按 `category` 分组渲染（分组顺序 = 首次出现序） |
| `data.dashboard.realtime` | object | ✅ | 与 `citychrome.Feed` **字段逐字同构**：`channel` / `updated_at` / `categories` / `news` |

### 5.2 错误语义

| 场景 | `code` | HTTP | `data.dashboard` | 前端行为 |
|---|---|---|---|---|
| 正常 | `0` | 200 | 完整 | 正常渲染 |
| **外部通道离线**（`enabled=false` / 底座不可达） | **35053**（`ErrCityChromeChannelOffline`，**复用批次 65 既有码**） | 200 | **仍完整返回**（11 维度 + 22 数据源 + `realtime.channel.status="offline"` + `detail` 写明原因 + 空 `categories` / 空 `news`） | 渲染**完整骨架** + 徽章显示「通道离线」；**不弹错误** |
| 未登录 | 既有鉴权中间件语义 | 既有 | 无 | 走既有登录流程 |

> **为什么离线不报错**：`35053` 是**可预期的降级状态**（通道没起来），不是操作失败。
> 若把它当失败弹全局 toast，用户每次进房都会看到一条红色报错。
> 契约明确：**`code != 0` 但 `data.dashboard` 完整 ⇒ 一律按「离线降级」处理，只更新徽章，不进错误通道。**
>
> **本批不新增错误码**：`35058`（批次 68）仍是虚拟城市已用最大值；本批复用 `35053`。
> （注：`35100–35104` 为 City-Human 感知/移动段，与本端点无关。）

### 5.3 前端取数的一个硬约束：`http()` 会丢弃 body

仓库统一 `http<T>()` 在 `code != 0` 时**抛 `ApiError` 并丢弃 body** ⇒ 直接用它会把「离线但完整」的目录一起丢掉。
前端 `api/virtualCity.ts::fetchVirtualCityDashboard()` 因此走**双路径**：

1. 先走 `http()` —— 保留 401 会话过期 / 统一错误语义；
2. **仅当** `e.code === 35053` 时，用**裸 `fetch`**（带 `Authorization: Bearer`）兜底取回完整 `data.dashboard`；
   取不到则返回**空目录骨架**（`dimensions: []` / `data_sources: []` / `realtime: null`），**不抛错**；
3. 其它错误码**照常抛出**，由调用方按 §7.1 展示。

> 这条是**端点契约的一部分**，不是前端实现细节：任何后端改动若让离线时的 `code` 不是 35053，
> 前端兜底路径就会失效（目录丢失 ⇒ 数据源面板空态）。后端改 `code` 必须同步改前端常量
> `VIRTUAL_CITY_DASHBOARD_CHANNEL_OFFLINE`。

### 5.4 与既有 `/api/virtual_city/realtime_board` 的关系

| 端点 | 保留？ | 载荷 | 消费方 |
|---|---|---|---|
| `GET /api/virtual_city/realtime_board` | ✅ **保留不删** | `{feed: Feed}` | 批次 65 `RealtimeBoard`、批次 66 遗留消费方、外部脚本 |
| `GET /api/virtual_city/dashboard` | ✅ 新增 | `{dashboard: {…, realtime: Feed}}` | 批次 69 看板外壳（目录 + 快照一次拉齐） |
| `POST /api/virtual_city/realtime_board/refresh` | ✅ 保留 | `{accepted, queued_category}` | 看板标题条刷新按钮 + `RealtimeBoard` 面板内刷新（60s 限流 35054） |

- `dashboard.realtime` 与 `realtime_board` 的 `feed` **字段逐字同构**（后端实现上就是**同一个 `citychrome.Feed` 对象**，不存在两份序列化）。
- **前端只保留一份实时状态**：`virtualCity.store.ts` 的 `realtimeFeed` slice 同时被两端点与 WS 帧写入。
  **禁止**新增第二个实时 store slice（否则 WS 帧与 HTTP 快照会互相覆盖）。
- **写入纪律（已落地）**：写 `realtimeFeed` 前先判 `if (!useVirtualCityStore.getState().realtimeFeed)` ——
  快照**不得覆盖**已有的 WS 数据；快照**取不到时也不置空**（避免冲掉已有数据）。

**渲染规范**：

- 6 组 = 6 个分组块（`.virtualCity-dash__ov-group`），组内 KPI 以「标签 + 数值」网格（`__ov-grid` / `__ov-item`）呈现。
- **缺失值一律显示「—」**（不用 0、不用空白）—— 0 与「无数据」在科研读数里语义完全不同。
- **数值格式化一律走既有工具**（`formatCny` / `formatPct`，`types/virtualCityFormat.ts`），**不自己写格式化逻辑**。
- **外盘情绪锚 `active === false` ⇒ 显示「未激活」**（`virtualCity.rt.exo.inactive`），**不显示 0.0** ——
  批次 66 零回归契约规定 inactive 时 bias 恒精确 0.0，显示成「0.00%」会误导为「外盘确实无影响」。
- **观战态**：`my === null` ⇒ 「资产与金融」组的 3 行个人指标显示「—」；
  城市级指标照常显示 ⇒ 观战者与条件触发者看到的**城市级读数完全一致**（《定位声明》§7 观察者语义）。
- **对局未就绪**：`gameState === null` ⇒ 渲染既有空态块（`virtualCity-panel__empty` + `virtualCity.panel.waiting`），**不崩溃**。

### 7.2 数据源清单面板（`DataSourcesPanel`）

**定位**：向观察者**说明「外部实时数据从哪来」**，是《定位声明》§6「可观测 + 可追责」诉求的落地之一。

**渲染规范**：

0. 面板顶部一行**标题**「数据源清单」（`virtualCity.dash.sources.title`），与其它维度面板的标题职责一致。
1. 按 `category` **分组**（`Map` 插入序 = 后端给定顺序），每组一个小节头（分类名 + 条目）。
2. 每个条目：**站点名** + 「官网 ↗」外链（`target="_blank" rel="noopener noreferrer"`）+ **用途**一行。
3. **空态**：`data_sources` 为空（端点不可达 / 目录为空）⇒ 渲染既有空态块（`virtualCity.dash.sources.empty`），
   **不显示空白面板**、**不弹错误**。
4. 外链**不触发游戏内任何动作**；**不因此新增任何后端调用**（`url` 已在目录里，前端直接开）。

> **安全边界**：本面板只**展示** URL，**不在服务端抓取**这些站点 ——
> 服务端抓取是批次 65 `City-Chrome` 的职责，且必须遵守「不登录 / 不绕验证码 / 同站点 ≥10s」纪律。
> 两者**不得混用**（避免绕过纪律的直连抓取）。

## 11. 实现现状对照与已知偏离

> 本节记录**方案初稿 → 落地实现**的偏离，供回溯与后续批次收敛。

| # | 项 | 方案初稿 | 落地实现 | 影响 |
|---|---|---|---|---|
| **D1** | 目录枚举值 | `source: game_state/realtime_feed/static`；`scope: personal/city/global`；`refresh: monthly/realtime/on_demand/static` | **后端为准**：`source: game_state/citychrome/static`；`scope: self/room/global`；`refresh: push/realtime/monthly/static` | 前端静态目录仍用初稿口径（`realtime_feed` / `catalog` / `room` / `global` / `push` / `static`）。**这 4 个字段不参与渲染**（合并只覆盖 `title_key` / `group`），故无功能影响，但**文档性字段口径不一致** ⇒ 遗留 L2 收敛 |
| **D2** | 折叠状态持久化 | localStorage 按 tab id 记忆 | **组件内 `useState<Record<id, boolean>>`**，会话内记忆，刷新页面复位 | 功能可用但不达「跨会话记忆」的初稿目标 ⇒ 遗留 L1 |
| **D3** | 标题条刷新语义 | 重新 `GET /dashboard`（刷目录） | `POST /realtime_board/refresh`（触发采集）+ 回读一次快照 | 与「刷新 = 看新行情」的用户心智一致；目录为静态无需刷新。**优于**初稿 |
| **D4** | `realtime` 维度的折叠 | 建议不包 `BoardSection` | **同样包 `BoardSection`**，改为隐藏其内部 `.virtualCity-rt__head` | 折叠行为 11 个维度统一；徽章/时间/刷新三件由外壳统一提供，避免重复 |
| **D5** | 数据源分类 i18n | 建议英文分类 id + i18n 键 | 后端下发**中文 `category` 字符串**，前端直接渲染 | **英文/日文界面下分类仍为中文** ⇒ 遗留 L2 |
| **D6** | 城市总览分组归属 | 初稿：6 组均**城市级** | 落地：「资产与金融」组含 `my.cash` / `my.net_worth` / `my.fi_index` 三项**个人**指标 | 观战态下这三行显示「—」；与「财务」维度有部分重叠，但**总览一屏可读性**优先 |
| **D7** | `title_key` 复用 | 初稿：复用 `virtualCity.tab.*` 既有键 | 落地：**11 条统一新前缀** `virtualCity.dash.dim.*` | 既有键保留（`RealtimeBoard` 等仍在用），不冲突；看板文案自成一体 |
| **D8** | 离线取数 | 初稿：直接读 body | 落地：`http()` 在 `code≠0` 抛错丢 body ⇒ **35053 时裸 `fetch` 兜底** | 契约的一部分（§5.3）；后端改离线 `code` 必须同步前端常量 |
