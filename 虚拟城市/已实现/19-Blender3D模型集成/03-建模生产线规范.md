# Blender 建模生产线规范（§20260928-01）

> **性质**：本文件是 [`CLAUDE.md §27.0`](../../../../CLAUDE.md) 的**展开版**——纪律条文本身在
> CLAUDE.md（唯一事实来源），此处只写「怎么做」：工序、检查清单、命令、验收判读。
> 与 CLAUDE.md 冲突时**以 CLAUDE.md 为准**。

## 1. 适用范围

- **工作面**：`3d_script/build_*.py` + `ClientWeb/src/assets/models/**/*.glb`（art-designer 职责线，§13.1-4）。
- **工具**：本机 `/usr/local/bin/blender` = **Blender 5.2.1 LTS**，headless 直接调，无需外部美术资产。
- **不适用**：前端渲染接线（`engine3d/`）走 frontend-dev；尺寸口径仍受 §27.3-4/7 约束。

## 2. 六条硬性纪律

| # | 纪律 | 为什么（历史教训） |
|---|------|------------------|
| 1 | **开工前先检索真实参考** | 批次 19 的 11 个 GLB「像玩具」根因是凭想象建模，没查真实比例 |
| 2 | **按资产逐个建，禁止一次性做完** | 大而全的脚本无法 review、无法单件返工，出问题只能整体重写 |
| 3 | **统一色调 + 经年磨损** | 各脚本各写 hex，全城材质不统一；干净如新的塑料感不符合写实 |
| 4 | **可拉 SubAgent 分工** | 单 Agent 串行做「调研→建模→材质→渲染」质量不稳定 |
| 5 | **质量优先于时间与 credit** | 不许为省 token 走「差不多能渲染」的捷径 |
| 6 | **每批资产渲染检查，不通过返工** | 导出成功 ≠ 合格；没看过图的 GLB 视为未交付 |

## 3. 标准工序（不可跳步）

```
① 结构调研 ──→ ② 单资产建模 ──→ ③ 材质/磨损 ──→ ④ 渲染验收 ──→ ⑤ 尺寸护栏 ──→ ⑥ 合批提交
   (检索)         (build_*.py)      (色板)          (render_preview)   (verify_glb_aabb)
```

### ① 结构调研

- 检索目标物件的**真实比例 / 结构分层 / 常见材质**（WebSearch 或查既有资产）。
- 结论**写进脚本头部注释**再动手，形如：

  ```python
  # 参考：市政消防站为 2 层砖混，占地约 24×16 m，坡屋顶红瓦 + 白色铝制卷帘门 ×2 + 警灯塔。
  # 尺寸取自公开建筑设计规范；世界单位按 cityScale.METERS_PER_UNIT=10 授权（见 CLAUDE.md §27.3-4）。
  ```

- 尺寸的唯一事实来源仍是 `ClientWeb/src/components/virtualCity/cityScale.ts::REAL_DIMS_M`，
  调研只用来**校验**该表，不要另立一套。

### ② 单资产建模

- 一次只做一个 `build_<name>.py`，导出一个 `.glb`。
- 硬约束（CLAUDE.md §27.3）全量继承，重点复述：**Z-up 摆放**、**尺寸烘焙进顶点**（节点 scale 必须
  identity）、**`minY=0` 贴地 + X/Z 居中**、**GLB 尺寸 ≡ 前端程序化 fallback 尺寸**。
- 复用 `__common__.py` 的 `make_box / make_cylinder / make_sphere / join_objects / export_glb`，
  不要每脚本重造轮子。

### ③ 材质与经年磨损

- 颜色一律取 `__common__.py::CITY_PALETTE` 语义键（`concrete` / `asphalt` / `brick` / `steel` /
  `glass` / `foliage` / `rust` / `paint_road` / `wood` …），**不要在脚本里裸写 hex**。
- 表面经 `weathered_pbr(obj, color, rough, metal, wear=…)` 叠加污渍/脏化：Noise 驱动的色斑 +
  Roughness 调制。目标是「**经年但仍看得出材质**」——不是脏到糊成一团。
- `wear=0` 时不得新增节点（与 `apply_pbr` 等价），便于对照回归。
- **迁移按脚本逐个做**：现存 20 个 `build_*.py` 里散落 70+ 个各自为政的 hex
  （`#2f7a3a` / `#3a8a45` / `#2e8b57` 都是"树的绿"），`CITY_PALETTE` 就是为收口它们而设。
  纪律 2 要求一次只交付一个资产，**不要在一个提交里横扫全部脚本**。

> ⚠️ **程序化磨损不经 glTF 导出**：glTF 规范没有 Noise Texture 对应物，`export_glb()` 会静默
> 丢弃节点图，导出的 GLB 只剩纯色基值。故 `weathered_pbr()` 目前只对 **Blender 内预览 / 打光评估**
> 与**后续贴图烘焙源**有效；要让磨损在**游戏内**可见，须另烘 basecolor + roughness 贴图
> 并走前端 PBR 管线——**该链路尚未实现**。这是 §130「声明了却从不接线」的高危点，
> 实现烘焙前不要对外宣称磨损已上线。

### ④ 渲染验收（门禁，不可省）

```bash
# 读 .glb，按包围盒自适应摆相机 + 三点布光 → PNG
blender --background --python 3d_script/render_preview.py -- \
  ClientWeb/src/assets/models/civic/city_hall.glb /tmp/prev_city_hall.png --view iso

# 换视角复查（iso 看不出的侧躺/错轴，front / side 一眼可见）
blender --background --python 3d_script/render_preview.py -- \
  ClientWeb/src/assets/models/civic/city_hall.glb /tmp/prev_city_hall_front.png --view front
```

**必须用 Read 工具真的看一眼图**，再按下列判读表决定放行 / 返工：

| 判读项 | 不通过的表现 |
|--------|-------------|
| 构图 | 物件没入画 / 贴脸特写 / 缩成小芝麻（相机自适应失效） |
| 姿态 | 侧躺（Z-up 写反）、悬空、陷地 |
| 比例 | 与参照物对比失真（这是批次 19/26/29 三轮返工的共同根因） |
| 穿模 | 构件互相穿插、悬浮零件 |
| 材质 | 全黑 / 全白 / 塑料感 / 脏到看不出本色 |
| 统一 | 与同批其它资产的色调明显不同群 |

### ⑤ 尺寸护栏

```bash
python3 3d_script/verify_glb_aabb.py        # 世界/几何双口径 + 节点 scale identity + 直立/贴地
```

非零退出码即失败。新增或重导资产后必跑。

### ⑥ 合批提交

- `3d_script/*.py` **入库**（唯一可复现源码，§27.3-8）。
- `.blend` / `__pycache__/` / 量测 JSON / 预览 PNG **不入库**（`.gitignore` 已收口）。
- 前端接线与 `REAL_DIMS_M` 的改动按 §13.2 串行交接给 frontend-dev。

## 4. SubAgent 分工（纪律 4）

| 工序 | 职责 | 产出 |
|------|------|------|
| 结构调研 | 检索真实比例 / 结构 / 常见材质 | 脚本头部注释中的参考结论 |
| 建模 | 几何 + 尺寸（§27.3 全量硬约束） | `build_<name>.py` + `.glb` |
| 材质 | `CITY_PALETTE` + `weathered_pbr()` | 材质调用 |
| 灯光渲染 | 出图、判读、列不达标项 | 预览 PNG + 验收结论 |

> **串行依赖**：同一件资产内部 ①→②→③→④ 顺序不可打乱，**不要把同一脚本拆给多个 Agent 改**。
> 并行只对**多件资产之间**成立（一次派 N 个 Agent 各做一个资产）。

## 5. 已知边界

- `render_preview.py` 是**质检工具**，出图不等于游戏内最终观感——游戏内还有 `useSharedPBR`、
  IBL、昼夜轮替等叠加，真实观感仍需 CDP 视觉验收（见 `30-3D比例与昼夜季节收口`）。
- 预览图不参与构建，体积不进 `.glb` 的 500 KB 预算。
- **本机无 GPU**（EGL_BAD_MATCH，走 llvmpipe 软件光栅）：1280×960 @ 32 采样单图约 60–100 s，
  **批量渲染必须串行**。CI 里不适合当每资产门禁，只适合 §2-6 的人工/Agent 验收环节。
- Blender 5.2.1 的引擎枚举只有 `BLENDER_EEVEE`（`BLENDER_EEVEE_NEXT` 是 4.2 过渡期产物，5.x 已回并），
  `render_preview.py` 按 `BLENDER_EEVEE → CYCLES` 顺序回落。
- 色彩变换默认 `Standard` 而非 AgX：AgX 会把高饱和红绿压成灰奶白、纯白压成米色，
  恰好掩盖材质问题。灯强按「Standard 下不过曝」反推。
- `weathered_pbr()` 的程序化磨损**不经 glTF 导出**（见 §3 提示框），游戏内可见性待烘焙链路落地。
- **iso 视角背景偏平**：巨大地面铺满画幅、天地近同明度（地面反照率已从 0.36 压到 0.22 缓解，
  未根治；根治需上渐变地或缩小地台）。构图/比例/姿态判读不受影响。

## 6. 首轮渲染暴露的资产缺陷（待逐件返工）

> 出图验收抓出的真实问题，作为后续资产排期清单。**未擅自改数据**——纪律 2 要求逐资产交付。

| 资产 | 缺陷 |
|------|------|
| taxi | 车顶灯牌悬空有缝；驾驶室右后侧深色楔形面穿出轮廓；头/尾灯是戳出车身的薄片；车轮无轮眉且半埋车身 |
| oak_tree | 树干右侧有一根穿出的黑色树枝残茬 |
| sedan | 车顶是悬空方盒；轮胎凸出翼子板 |
| city_hall | 钟楼与屋顶材质完全同参（Base Color / Roughness / Metallic 三项一致），顶视像素级同色 —— 需拆分材质 |

## 7. 遗留候选

- **程序化磨损烘焙成贴图**，接入前端 PBR 管线（§3 提示框的前置）。
- `CITY_PALETTE` 逐脚本迁移 70+ 处散落 hex（见 §3-③）。
- `render_preview.py` 渐变地台，根治 iso 背景偏平。
