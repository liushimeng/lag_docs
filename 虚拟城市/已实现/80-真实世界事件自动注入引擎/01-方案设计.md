# 批次 80 · 真实世界事件自动注入引擎（RealWorld → WorldEvent → Scenario）

> 日期：2026-10-23 ｜ 分支：`main`（§10.1）
> 起因：《虚拟城市模拟系统 · 自迭代优化规范》§五「真实世界信息 → 虚拟城市事件流」——
> 采集层（批次 65）、归一化层（FeedStore）、分级调度（批次 76）、注入引擎（批次 68 场景引擎）
> 均已具备，**唯独缺「事件层 → 注入层 → 反馈层」自动链路**：真实世界数据目前只以
> 「外盘情绪锚」（批次 66，±0.3%/月微偏置）影响城市，无法自动生成「世界事件」、
> 无法自动注入既有场景引擎、无法留痕「事件 → 参数变化 → 城市结果」因果链。
> 本批补齐该链路，产出《规范》§五 的可判定闭环。
> 权威衔接：批次 65《CityChrome实时数据通道与实时看板》、批次 66《真实行情市场联动》、
> 批次 68《预测运行报告》（场景引擎 `scenario.go`）、批次 69《实时看板统一重构》。

- 事件对 3D 场景的可视化表现（《规范》§六.2.3，留后续）。

## 2. 架构总览（数据流）

```
真实网站 → go-web-debug-tool → citychrome.FeedStore（批次 65）
                                        │  Feed() / Snapshot() 纯内存读
                                        ▼
                    main.go 装配层 adapter（唯一同时 import 两侧的位置）
                      Feed → []virtual_city.WorldEventInput（中性结构）
                                        │  Manager.SetWorldEventSource(fn)
                                        ▼
   game/virtual_city/world_event.go（纯函数：无 IO、无 RNG、无 citychrome import）
     DeriveWorldEvents(input, now) → []WorldEvent
       规则表 R1–R10（确定性阈值）→ 事件指纹 key（幂等）
                                        │  room.trySettle 锁内 refreshWorldEventsLocked()
                   ┌────────────────────┼──────────────────────────────┐
                   ▼                    ▼                              ▼
        幂等闸门（World.WorldEventSeen）   映射表（事件 → 既有 scenario kind）   安全阀
                                                          │
                                                          ▼
                             applyScenarioToWorld（批次 68 场景引擎，逐位复用）
                                商品价格/供给 · 失业率 · 股指/黄金/房价 · 国库 · 选举
                                                          │
                    ┌─────────────────────────────┼────────────────────────┐
                    ▼                             ▼                        ▼
          World.WorldEventLog（环 ≤50）   居民 prompt「■ 世界事件」   game.state.world_events
          （反馈层：事件 → effects → 次月 outcome 快照）        （看板事件流子页）
```

**关键决策**：
1. **复用而非重写**：注入一律走既有 `applyScenarioToWorld`（批次 68）——不新增平行账本、
   不改场景目录语义，事件只是「自动按下扳机的人」。已有 10 种场景 kind 覆盖
   市场/政策/社会/自然灾害/未知灾难五类，正好对上《规范》§五.3 的例子。
2. **引擎纯度**：`game/virtual_city` 不 import `citychrome`；中性结构
   `WorldEventInput` + `Manager.SetWorldEventSource(fn)` 依赖反转注入（批次 66 同款范式）。
3. **确定性优先**：`DeriveWorldEvents` 无 RNG、无时钟依赖（`now` 入参）、同输入同输出 ⇒
   可全量单测、可复现。
4. **零回归硬契约**：无事件 ⇒ **不调用** `applyScenarioToWorld` ⇒ `SettleMonth` 逐位一致
   （固定 seed 双跑比对）；事件派生与注入**不消费任何 RNG**（§92a 存量对局零偏移）。
5. **安全阀**：自动注入是「系统替人做决定」，必须限流——每月 ≤2 条、强度 ≤L3、
   沿用既有活动场景上限 8；且总开关 `auto_scenario_enabled` 可一键回退。

## 3. 后端设计

### 3.1 新文件 `ServerGo/game/virtual_city/world_event.go`（规则引擎，纯函数）

```go
// WorldEventQuote 中性真实报价（装配层从 citychrome 映射；引擎不感知来源）。
type WorldEventQuote struct {
    Category  string  // "a_share"|"hk"|"us"|"metal"|"futures"|"crypto"
    Symbol    string  // 站点口径代码/名称
    Name      string  // 显示名
    ChangePct float64 // 百分数口径（0.82 = 0.82%）
    UpdatedAt int64   // Unix 秒
}

// WorldEventNews 中性新闻头（装配层从 citychrome 映射）。
type WorldEventNews struct {
    ID          string // md5(title+url) 前 12 位（幂等键的一部分）
    Title       string
    Source      string
    URL         string
    PublishedAt int64
}

// WorldEventInput 是引擎的唯一入参（中性、无 IO）。
type WorldEventInput struct {
    Quotes []WorldEventQuote
    News   []WorldEventNews
}

// WorldEvent 是派生出的世界事件（事件层产物）。
type WorldEvent struct {
    Key       string  // 幂等指纹（见 §3.3）
    Rule      string  // 规则 id：R1..R10
    Kind      string  // 事件类型：equity_crash|gold_spike|crypto_crash|commodity_inflation|
                     //            policy_easing|policy_tightening|earthquake|tsunami|
                     //            extreme_disaster|survey_pulse
    Severity  int     // 1..3（强度档；映射到场景 L1..L5 时受上限裁剪）
    Direction string  // bullish|bearish|neutral
    Scope     string  // market|policy|disaster|macro|society
    Title     string  // 中文标题（看板/居民可见）
    Detail    string  // 一句话说明（触发依据，含关键数值）
    Magnitude float64 // 触发量（% 或 1）
    Source    string
    URL       string
    ObservedAt int64
    // 映射结果（引擎内一并给出，房间层只做执行）
    ScenarioKind  string // 批次 68 场景 kind
    ScenarioMag   int    // 注入强度 L1..L5（规则表原始档位；超安全阀上限 ⇒ 跳过注入并留痕）
    ScenarioDur   int    // 持续月数（0 = 用场景默认）
    ScenarioTarget string // 如 policy_shock 的 "loose"/"tight"；缺省 ""
}
```

**规则表（阈值写死为常量，禁运行时配置漂移）**：

| 规则 | 触发条件（全部报价保鲜 ≤72h） | Kind | 场景 kind | 注入强度 | 持续 | target | severity |
|---|---|---|---|---|---|---|---|
| R1 | 权益（a_share/hk/us 全体报价）均值 ≤ **-2.0%**，**或**类目内单标的跌幅 ≤ **-3.0%** | equity_crash | market_crash | **L1**（重度：均值 ≤ -3.5% 或极值 ≤ -5.0% → **L2**） | 4 | — | 2（重度 3） |
| R2 | metal 类目均值 ≥ **+2.0%**，**或**黄金类标的涨幅 ≥ **+2.0%** | gold_spike | market_crash | **L1** | 3 | — | 2 |
| R3 | crypto 均值 ≤ **-5.0%**，或单标的跌幅 ≤ **-8.0%** | crypto_crash | market_crash | **L1** | 3 | — | 2 |
| R4 | futures 均值 ≥ **+3.0%** | commodity_inflation | goods_price_shock | **L1** | 6 | — | 2 |
| R5 | 新闻标题含 降准/降息/减税/宽松/刺激 | policy_easing | policy_shock | **L1** | 6 | `loose` | 2 |
| R6 | 新闻标题含 加息/收紧/紧缩/上调利率/去杠杆 | policy_tightening | policy_shock | **L1** | 6 | `tight` | 2 |
| R7 | 新闻标题含 地震/6级/7级/8级/9级 | earthquake | earthquake | **L2**（≥7级 → **L3**） | 6 | — | 3 |
| R8 | 新闻标题含 海啸/风暴潮/洪水/台风 | tsunami | tsunami | **L2** | 9 | — | 3 |
| R9 | 新闻标题含 重大事故/矿难/爆炸/停产/停摆 | extreme_disaster | extreme_disaster | **L2** | 12 | — | 3 |
| R10 | 新闻标题含 调研/问卷/民调 | survey_pulse | survey_pulse | **L1** | 3 | — | 1 |

- **统计口径**：「均值」= 该统计集合内**有效报价** `ChangePct` 的算术平均；
  R1 的统计集合 = a_share ∪ hk ∪ us **全体报价**（与批次 66 `eqAvg` 同口径：报价等权，
  非类目等权）；R2/R3/R4 的统计集合 = 对应类目内全部报价。
  「极值」= 集合内 `ChangePct` 的最小/最大值。集合为空 ⇒ 该规则不命中。
- **报价保鲜窗口 72h**（同批次 66 `exoFreshWindowSec`），过期报价不参与判定。
- 新闻判定只扫 `PublishedAt` 在 72h 内且标题非空的新闻；**命中即取最新一条**（同规则同事件取最新）。
- 关键词表写死为包级切片（`worldEventKeywordRules`），每条含 `kind`/`scenario`/`target`/`keywords`。
- **R2「黄金单日涨超 2%」正是《规范》§五.3 的举例**（单标的口径）。

> ⚠ **强度档校准（2026-10-23 修订，勿回退）**：批次 68 场景引擎的幅度按
> `profile × magnitude` **线性放大**（`scenario.go`：`old*(1+pct*mag)`），
> 即 `market_crash` 的 L3 = 股指瞬时 **−18%**、L5 = −30%。
> 该量级适合**人工**推演「崩盘」，直接拿真实行情信号自动注入会打穿城市经济。
> 故本批**自动注入一律用 L1/L2 档**（`market_crash` L1 = 股指 −6%），
> 强度上限仍由 `auto_scenario_max_magnitude`（默认 3）兜底，
> 灾害类（R7–R9）用 L2（6 级地震 ≈ 现金损失 2% + 供给 −4%）符合真实量级。

### 3.2 事件指纹与幂等（规范 §五.5「同一事件不得重复注入」）

```
行情类事件：key = "rw:" + rule + ":" + 类目集合 + ":" + dayBucket(UpdatedAt/86400)
新闻类事件：key = "rw:" + rule + ":" + news.ID
```

- 行情类按**自然日**分桶：同一天同一规则只注入一次（次日行情再跌可再次触发）。
- 新闻类用既有新闻 ID（md5(title+url) 前 12 位）⇒ 同一新闻永不重复注入。
- 幂等集合存 `World.WorldEventSeen map[string]bool`（惰性初始化，nil 安全）。

### 3.3 注入与安全阀（房间层）

- 触发点：`room.trySettle` **月结前**（与 `refreshExoLocked` 同位置、同锁纪律 §92a）调用
  `refreshWorldEventsLocked()`：
  1. 读 `r.worldEventSource()`（纯内存快照，禁止回调房间）；nil ⇒ 直接返回。
  2. `DeriveWorldEvents(input, now)` 得候选事件列表。
  3. 逐条过幂等闸门（`World.WorldEventSeen`）与安全阀（本月已注入数 < `maxPerMonth`、
     `ScenarioMag ≤ maxMagnitude`、**同 scenario kind 本月已注入过则跳过**、
     活动场景数 < `scenarioMaxActive`）。
  4. 通过者调 `applyScenarioToWorld(...)`（**持房间锁**，复用批次 68 全链路）。
  5. 写 `World.WorldEventLog` 记录（事件 + 即时 effects + 待回填 outcome）。
- 安全阀参数（config `city_chrome{}`）：
  | 键 | 默认 | 语义 |
  |---|---|---|
  | `auto_scenario_enabled` | `true` | 总开关；false ⇒ 不派生、不注入（前端显示「自动注入已关闭」） |
  | `auto_scenario_max_per_month` | `2` | 每月自动注入条数上限 |
  | `auto_scenario_max_magnitude` | `3` | 自动注入强度上限（L1..L5） |
- **同 kind 去重**：每月同一种 `scenario_kind` 至多自动注入 1 次
  （R1/R2/R3 都映射 `market_crash` ⇒ 同日只取一条，避免同一类冲击重复计入）。
- **人工注入优先级更高**：人工 `ApplyScenario` 不受上述上限约束；自动注入遇活动场景满额则跳过本条。

### 3.4 反馈层（事件 → 参数变化 → 城市结果）

```go
// WorldEventOutcome 次月城市结果快照（因果链终点）。
type WorldEventOutcome struct {
    Month        int     `json:"month"`
    CPIYoY       float64 `json:"cpi_yoy"`
    Unemployment float64 `json:"unemployment_rate"`
    StockIndex   float64 `json:"stock_index"`
    GoldPrice    float64 `json:"gold_price"`
    GoodsPriceIdx float64 `json:"goods_price_index"`
    ResidentCashTotal float64 `json:"resident_cash_total"`
}

// WorldEventRecord 事件记录（World.WorldEventLog 环 ≤50，新→旧）。
type WorldEventRecord struct {
    Key           string           `json:"key"`
    Rule          string           `json:"rule"`
    Kind          string           `json:"kind"`
    Severity      int              `json:"severity"`
    Direction     string           `json:"direction"`
    Scope         string           `json:"scope"`
    Title         string           `json:"title"`
    Detail        string           `json:"detail"`
    Magnitude     float64          `json:"magnitude"`
    ScenarioKind  string           `json:"scenario_kind"`
    ScenarioMag   int              `json:"scenario_magnitude"`
    Source        string           `json:"source"`
    URL           string           `json:"url"`
    ObservedAt    int64            `json:"observed_at"`
    Injected      bool             `json:"injected"`
    InjectedMonth int              `json:"injected_month"`
    Effects       []ScenarioEffect `json:"effects"`  // 即时参数变化（批次 68 结构复用）
    Outcome       *WorldEventOutcome `json:"outcome"` // 次月结果快照（待回填）
}
```

- **回填时机**：事件注入后的**下一次** `SettleMonth` 结束 ⇒ `fillWorldEventOutcomes(w)` 写 outcome
  （当月 CPI/失业率/股指/黄金/商品价格指数/居民现金合计）⇒ 形成完整因果链。
  注入发生在月结**之前**（`trySettle` 内）⇒ **同一次**月结结束即回填；`Outcome.Month == InjectedMonth`。
- **`InjectedMonth` 语义**：注入时刻主钟为 M（`SettleMonth` 前）⇒ 场景自 M+1 月起生效 ⇒
  `InjectedMonth = M+1`（**生效月**；与 `ScenarioAppliedRecord.AppliedMonth = M` 相差 1）。
  安全阀计数与看板 `injected_this_month` 均按生效月口径，三处自洽。
- 未注入的事件（被安全阀拦下）也入日志（`Injected=false`），看板可显示「已观测未注入（达上限）」；
  其**不写幂等集合**（下月额度释放后可重试，日志按 key 原地 upsert）。

   - **零回归**：固定 seed 两次 `SettleMonth`（一：无事件源；二：源返回空）**逐位相等**；
     有事件时 `ScenarioApplied` 增 1 条且 `WorldEventLog` 增 1 条；
   - 安全阀：每月条数上限 / 强度上限 / 活动场景满额 ⇒ 跳过且日志记 `Injected=false`；
   - 反馈链：注入后一次月结 ⇒ outcome 被回填且字段非零；
   - prompt：有事件 ⇒ 含「世界事件」段；无事件 ⇒ 整段省略。
2. `tsc --noEmit` + `npm run build` 通过（前端零 TS 报错）。
3. E2E（rebuild 后）：建房跑 ≥2 月 ⇒ `game.state.world_events.items` 可见；
   通道离线 ⇒ `items: []` 且对局月结照常（零阻塞）。

   `已实现/README.md` 索引补第 80 行；`CLAUDE.md` §28 追加 §28.5 批次 80 摘要。

## 6. 风险与回退

| 风险 | 缓解 |
|---|---|
| 自动注入改变存量对局动态 | 通道离线/无事件 ⇒ 零回归；安全阀限流；`auto_scenario_enabled=false` 一键回退 |
| 规则误判（如「加息」出现在评论性标题） | 关键词表集中一处、易调；命中仅影响 1 强度档；日志留痕可复盘 |
| 同一新闻重复入账 | 指纹含新闻 ID，Feed 侧亦已 md5 去重 |
| 事件注入叠加打穿经济 | 沿用场景引擎安全区间（价格指数 10~10000、活动场景 ≤8）+ 每月 ≤2 条 |
| 与人工注入语义混淆 | 记录 `Source`/`Rule`/`AutoInjected` 可区分；日志与 `ScenarioApplied` 分离 |
