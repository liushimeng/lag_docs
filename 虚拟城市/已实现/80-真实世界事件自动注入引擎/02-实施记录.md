## 3. 关键决策与偏差（均已回写方案 §3.1/§3.4）

1. **强度档校准**（实现前修订方案）：批次 68 幅度按 `profile × magnitude` 线性放大（L3 market_crash = 股指瞬时 −18%）⇒ 自动注入一律 L1/L2（R1 重度/R7 ≥7 级 → L2/L3）。实测今日行情（A 股均值 −1.72%、极值 −3.07%）命中 R1 极值判据 → L1 −6%，量级合适。
2. **强度上限语义**：`ScenarioMag > max` ⇒ **跳过**注入并留痕（非裁剪），保证「安全阀可判定验收」成立。
3. **`InjectedMonth` = 生效月**（注入时刻 M ⇒ M+1；`ScenarioApplied.AppliedMonth` = M），安全阀按生效月计数，看板 `injected_this_month` 同口径。
4. **被拦事件不写幂等集合**：下月额度释放后可重试；日志按 key 原地 upsert，不产生重复行。
5. **同 kind 月度去重**：R1/R2/R3 同映射 `market_crash`，同月只注入一条。
6. **前端「事件流」子页不受行情通道空态闸门约束**：数据源是 `game.state.world_events`，通道离线恰是「无事件」常见成因，必须可达。

## 4. 教训

- **L1（阈值用真实数据校准，勿拍脑袋）**：方案初稿的 R1 阈值/强度是纸面推断；开工前用**当日真实 feed**（均值 −1.72% / 极值 −3.07%）代入，才发现「类目均值 ≤ −2%」当天不触发、而「单标的 ≤ −3%」触发——极值判据（正是《规范》§五.3「黄金单日涨超 2%」的单标的口径）不能省；同时用场景引擎的线性放大公式反推 L1/L2 才是安全档。
- **L2（服务重启清空 feed）**：E2E「无事件」首因是 `FeedStore` 纯内存——rebuild 后通道回到「等待首次 mission」，须先手动 refresh 采到报价再验注入链路。
- **L3（观战 WS 帧形状）**：`game.month` 帧的 payload **本身**即状态增量（含 `world_events`），别只认 `payload.state`。
