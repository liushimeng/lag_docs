## 1. 根因与修复（P0-1 · 假停用）

### 1.1 根因复现（协议层，修复**前**的运行实例）

用与前端**完全同构**的 WS 序列（`game.spectate` → `game.state`，即前端每 8 秒
轮询的那一帧）打当前运行实例：

```
system_agent_enabled = False      ← 服务端 [city_system] enabled=true（启动日志实证）
FAIL: system_agent_enabled 不是 true ⇒ 前端会误判「系统对话已停用」
```

⚠ 取样必须**按 seq 匹配应答**：`game.spectate` 会触发一次**广播** `game.state`
（seq=0，带正确开关），若按「首个 game.state」取样会误取广播帧、掩盖缺陷 ——
这正是该缺陷长期未被发现的原因（正常观战路径先收到正确的广播帧，8 秒后被
轮询应答覆盖）。

### 1.2 修复：构造入口收口

`ServerGo/ws/game_service_virtual_city.go` 新增**唯一构造入口**：

```go
func (s *GameService) vcClientState(roomID string, viewer int,
    r *virtual_city.VirtualCityRoom, world *virtual_city.World) *virtual_city.ClientGameState
```

内部 `BuildClientState(...)` → `cs.SystemAgentEnabled = s.vcSystemEnabled` → 返回。

4 个构造点全部改走它（各自原有语义一字不变）：

| 构造点 | 原语义 | 改后 |
|--------|--------|------|
| `game_service_virtual_city.go` 座位广播 | `r.Engine()` | `s.vcClientState(roomID, seat, r, world)` |
| `game_service_virtual_city.go` 观战广播 | `r.Engine()` | `s.vcClientState(roomID, -1, r, world)` |
| `game_service_xiangqi.go` `game.state` 玩家分支 | 未开局 ⇒ `PlaceholderWorld` 兜底 | `s.vcClientState(req.RoomID, seat, r, eng)` |
| `game_service_xiangqi.go` `game.state` 观战分支 | 未开局 ⇒ 回 30001 | `s.vcClientState(req.RoomID, -1, r, r.Engine())` |

**契约零变更**：字段名 `system_agent_enabled`、`bool`、恒定下发（无 `omitempty`）。

### 2.1 P1-6 投递范围裁决（实现口径）

| 事件 | 投递范围 | 理由 |
|------|---------|------|
| `agent_start` / `text` / `thinking` / `tool_start` / `tool_result` / `report` / `error` / `agent_end` | **仅发起用户** | 会话存储已按 `roomID/userID` 隔离，是「用户 ↔ 系统」私有对话 |
| `show_command`（Agent 工具 `focus_camera` / `apply_display` 派发） | **仅发起用户** | 3D 相机是客户端本地状态，全房强拉相机是骚扰 |

| `agent_message`（其它 Agent 来信） | 全房 | 来信入队 `incomingKey(roomID)`，注入所有用户下一轮 |

⚠ 两条孪生帧（`game.virtual_city_system_event` 与 `game.virtual_city_show_command`）
**必须同范围投递**，否则前端只收到其中一条 ⇒ 显示指令丢失（批次 85 C2 的教训）。

### 2.2 `cleared` 事件的定向裁决（超出方案裁决表的一项）

`cleared`（前端点「清空对话」时 `handleVirtualCitySystemReset` 直发，不经
`Agent.emit`）原为全房广播。本批改为**定向发起者**：会话存储按
`roomID/userID` 隔离（`agent.Reset(userID)` 只清该用户），而前端 store 的
`cleared` 分支**无条件清空全部消息**（`virtualCitySystem.store.ts`）⇒ 保持全房
广播意味着 A 点「清空对话」会**清掉 B 的面板**。发起者自身仍收到（前端本地已
清空，幂等）。

**`TestMCSmoke` 失败定性：存量 / 环境性，与本批无关。** 证据链：

   120s CI 回归防护上限），非逻辑失败；
