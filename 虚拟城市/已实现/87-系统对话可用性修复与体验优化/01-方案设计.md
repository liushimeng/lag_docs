# 批次 87 · 系统对话可用性修复与体验优化

> 日期：2026-11-06 ｜ 分支：`main`（§10.1）
> 起因：用户报「虚拟城市的 💬 系统对话窗口提示 *⚠️ 系统对话已停用（服务端
> `[city_system] enabled=false`），暂不可发送指令*，功能不可用」。
> 实证结论：**服务端 `[city_system] enabled=true`、Agent 正常运行** —— 这是一条
> **假停用**告警，根因在 WS `game.state` 应答路径漏盖开关字段（详见 §2）。

> 场景目录扩充》、批次 84《全维度事件体系与 Agent 双向对话》、批次 85《全维度
> 状态视图与物体级显示控制》、批次 86《可靠性与可观测性》。

## 1. 现象复现与事实核对

| 核对项 | 事实 | 证据 |
|--------|------|------|
| 配置开关 | `[city_system] enabled: true` | `LsmAgentGame.conf:181`（`LsmAgentGame.conf.example:327` 同值） |
| 进程运行态 | `enabled: true` | `LsmAgentGame.log`：`{"msg":"city system runtime","enabled":true,...}`（最近一次 2026-11-06 11:41:56） |
| 前端判定 | `gameState?.system_agent_enabled === false` ⇒ 停用 | `ClientWeb/src/pages/VirtualCityGamePage.tsx:107` |
| 前端轮询 | 每 **8 秒** 发一次 `game.state` | `ClientWeb/src/pages/VirtualCityGamePage.tsx:160` |
| 后端应答 | `game.state` 应答**未盖** `system_agent_enabled` | `ServerGo/ws/game_service_xiangqi.go:644`（观战分支）、`:767`（玩家分支） |

⇒ **复现路径**：进入任意虚拟城市房间 → 8 秒后前端拿到 `game.state` 应答 →
`system_agent_enabled` 为 Go 零值 `false`（字段无 `omitempty`，**恒定下发**，
`ServerGo/game/virtual_city/view.go:120-124`）→ 前端判为「服务端停用」→ 内联
红条 + 发送按钮禁用 ⇒ **整个系统对话窗口不可用**。

## 2. 根因（P0-1）

### 2.1 开关字段的赋值链路只有一条

`ClientGameState.SystemAgentEnabled` 由 **WS 层**在构造完快照后覆盖：

```go
// ServerGo/ws/game_service_virtual_city.go:291-297（广播路径 —— 正确）
cs := virtual_city.BuildClientState(...)
cs.SystemAgentEnabled = s.vcSystemEnabled // ← 只有这里盖
```

而虚拟城市的客户端快照共有 **4 个构造点**：

| # | 构造点 | 是否盖开关 | 触发场景 |
|---|--------|-----------|---------|
| 1 | `game_service_virtual_city.go:291`（座位广播） | ✅ | 月结 / 动作后广播 |
| 2 | `game_service_virtual_city.go:296`（观战广播） | ✅ | 同上 |
| 3 | `game_service_xiangqi.go:644`（`game.state` 观战应答） | ❌ **漏** | **前端 8s 轮询** |
| 4 | `game_service_xiangqi.go:767`（`game.state` 玩家应答） | ❌ **漏** | **前端 8s 轮询** |

`handleGetState`（`ServerGo/ws/game_service_xiangqi.go:556`，跨游戏共用函数）
在 `virtual_city` 分支直接 `BuildClientState` 后 `sendOK`，**没有任何一处提到
`SystemAgentEnabled`** —— 该字段是 `bool` 零值 `false`，且**没有 `omitempty`**，
于是每帧都以下「明确停用」的形态下发。

### 2.2 为什么这是「结构缺陷」而非「一处笔误」（§130 反例）

§130「声明了却从不接线」的反面：**声明了、接线了、但只接了一半**。同类的
`system_agent_enabled` 属于**服务端配置派生的布尔量**，只要它继续由「每个调用点
各自记得赋值」的方式承载，就必然随新调用点（HTTP 快照、回放、导出……）再次漏盖。

⇒ **修法不是补一行赋值，而是收口构造入口**（§3.1）。

## 4. 方案设计

### 4.1 P0-1：虚拟城市客户端快照**唯一构造入口**（后端）

**新增**（`ServerGo/ws/game_service_virtual_city.go`）：

```go
// vcClientState 构造虚拟城市客户端快照并盖上 City-System 入口开关。
// **唯一构造入口** —— 4 个调用点（座位广播 / 观战广播 / game.state 玩家 /
// game.state 观战）统一走它,杜绝再次漏盖 system_agent_enabled(批次87 P0-1)。
func (s *GameService) vcClientState(roomID string, viewer int,
    r *virtual_city.VirtualCityRoom, world *virtual_city.World) *virtual_city.ClientGameState
```

* 内部：`BuildClientState(...)` → `cs.SystemAgentEnabled = s.vcSystemEnabled` → 返回。
* `world` 由调用方决定（广播路径传 `r.Engine()`；`game.state` 玩家分支沿用
  `PlaceholderWorld` 兜底；`game.state` 观战分支保持「未开局即 30001」的原语义）。
* **契约不变**：字段名 `system_agent_enabled`、类型 `bool`、**恒定下发**（无
  `omitempty`）—— 前端判定逻辑零改动。

**回归测试**（`ServerGo/ws/`，新增 `game_service_virtual_city_system_flag_test.go`）：

1. `enabled=true` 时，`game.state`（玩家分支 / 观战分支）应答载荷
   `system_agent_enabled == true`；
2. `enabled=false` 时为 `false`；
3. **构造入口收口性**：`grep` 断言 `ServerGo/ws/` 内 `BuildClientState` 的
   虚拟城市调用点**只能**出现在 `vcClientState` 内（防回归）。

### 4.2 P1-6：会话事件按**发起用户**定向投递（后端）

**语义裁决**（避免"一刀切"破坏既有行为）：

| 事件类别 | 投递范围 | 理由 |
|---------|---------|------|
| `agent_start` / `text` / `thinking` / `tool_start` / `tool_result` / `report` / `error` / `agent_end` | **仅发起该轮的用户** | 会话内容是「用户 ↔ 系统」的私有对话（存储已按 user 隔离） |
| `show_command`（由 Agent 工具 `focus_camera` / `apply_display` 派发） | **仅发起用户** | 3D 相机是**客户端本地**状态；全房强拉相机是骚扰 |
| `show_command`（由 City-WebGL-Show 房间级 bus handler 派发） | 全房 | 批次 84 §4.3.3「自动渲染显示」的既有语义，保持不变 |
| `agent_message`（其它 Agent 来信） | 全房 | 来信是**房间级**事件（入队 `incomingKey(roomID)`，注入所有用户的下一轮） |

**实现路径**（§29.1 治理：`ServerGo/agent/citysystem/` 属 City-System Agent
**专属实现面**，由该 Agent 的独立 SubAgent 实施）：

1. `Agent` 的事件发射回调签名由 `func(SystemEvent)` 改为
   `func(userID string, ev SystemEvent)`；
   * `Run` / `runLoop` / `callLLM` 内的发射点带 `userID`；
   * `bus_handler.go` 的 `agent_message` 发射带空 `userID`（房间级）；
2. WS 层装配（`getOrCreateSystemRoomAgent`）据此分流：
   * `userID != ""` ⇒ `hub.BroadcastTo(userID, ...)`；
   * `userID == ""` ⇒ `hub.BroadcastRoomIncludingSpectators(roomID, ...)`（现状）；
3. `show_command` 的 `game.virtual_city_show_command` 孪生帧同步按同一范围投递
   （前端双帧去重逻辑 `cityShowCommandDedup` 不变）。

> ⚠ **兼容性**：前端**零改动**即可受益（本来就只认自己收到的帧）。旧前端连到
> 新后端 ⇒ 事件变少但语义正确；新前端连旧后端 ⇒ 保持批次 81–86 的全房广播行为
> （不回归）。

### 4.3 P1-2：服务端拒绝**必须可见**（前端 + 后端微调）

**前端**（`hooks/useVirtualCitySystemAgent.ts`）：新增 `game.error` 分支。

* **过滤**：只处理 City-System 相关错误码 —— `35059`（停用）/ `35060`（并发）/
  `35061`（Agent 未注册）/ `35062`（无回应）/ `35063`（回包超长）/
  `35064`（分组未知）/ `35065`（显示指令非法）/ `35001`（房间不存在）。
  其余 `game.error`（其它游戏的帧）**一律忽略**（P2-8：`game.error` 无 `room_id`）。
* **双通道展示**（§7.1）：
  1. 内联：向会话流追加一条错误消息（`role='assistant'` + `error` 字段），
     复用既有 `SystemDialogMessage` 的红条渲染；
  2. 全局：`reportGlobalError({ message, severity: 'error' })`。
* **`35059` 特判**：服务端明确说「已停用」⇒ 前端把「停用」状态**写进本地
  store**（而不是只依赖 `game.state` 字段）⇒ 面板红条与按钮禁用立即生效，
  且不再允许继续发送。

**后端**（可选、低风险）：`handleVirtualCitySystemMessage` 在
`!s.vcSystemEnabled` 分支已回 `35059`（现状正确），无需改动；仅在错误帧中
**补 `room_id`**（`sendError` 增一个带 `room_id` 的变体）—— 便于前端按房间
过滤（P2-8 收口）。**本批实施**：新增 `sendErrorRoom` 并在 City-System 三个
handler 内使用。

### 4.4 P1-3 / P1-4：乐观 busy + 看门狗解锁（前端）

* **发送即置 busy**：`sendMessage` 内 `useVirtualCitySystemStore.getState().setBusy(true)`
  （store 新增 `setBusy`），不等 `agent_start` ⇒ 连点被前端自身挡住（不再撞 35060）。
* **看门狗**：发送后启动定时器（`BUSY_WATCHDOG_MS = 200_000`，与服务端
  `request_timeout_ms`（默认 180s）+ 20s 余量对齐），到点仍未收到
  `agent_end`/`error` ⇒ 自动解锁 `busy` + 追加一条内联提示
  「本轮超时未返回，请重试或稍后再问」+ `reportGlobalError`（severity `warning`）。
* **断连兜底**：WS 断开（`wsClient` 的 close 事件）⇒ 清 `busy` + 提示
  「连接已断开，正在重连…」。

### 4.5 P1-5：连接指示器改用**传输层**连接态（前端）

* 面板的连接圆点改读 `wsClient.connected`（传输层）⇒ 空闲时显示「已连接」；
* `store.connected` 保留（语义收窄为「最近一次交互可达」），但**不再**作为
  面板指示器的唯一来源。

### 4.6 前端「停用」判定契约（锁定）

| `game.state.system_agent_enabled` | 面板 | 发送 |
|---------------------------------|------|------|
| `true` | 正常 | 允许 |
| `false` | 内联红条（停用说明） | 禁止 |
| **字段缺失**（旧后端） | 正常 | 允许（向后兼容，`=== false` 判定已满足） |

⇒ 前端补单测锁定上表三行（当前判定逻辑已正确，本批只加**防回归**用例）。
