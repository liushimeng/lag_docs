# 批次 81 · City-System 主 Agent 与「系统对话」

> 日期：2026-11-03 ｜ 分支：`main`（§10.1）
> 起因：虚拟城市定位 v3.0（全 Agent 城市模拟与预测运行系统）之后，人类的角色是
> **观察者 + 条件触发者**。既有「场景推演台」（批次 68/80）是**表单驱动**的：人类
> 必须先理解「场景 kind / 强度档 / 目标品类」这套机器语言，再手动填表注入。
> 本批把它升级为**对话驱动**：人类用自然语言说「最近物价涨得太厉害，帮我注入一个
> 强度 3 的商品价格冲击，持续半年」，由 `LsmAgentGame-City-System` 主 Agent 理解
> 意图、选场景、调工具、控制模拟、并把 3D 视角拉到事发地 —— **对话即控制面**。
>
> 权威衔接：批次 65《CityChrome实时数据通道与实时看板》、批次 68《预测运行报告》、
> 批次 80《真实世界事件自动注入引擎》、批次 69《实时看板统一重构》、
> `虚拟城市定位声明-全Agent真实城市模拟器.md` §6/§7。

**关键决策**：

1. **对话即控制面，而非新表单**：`LsmAgentGame-City-System` 是**唯一**控制入口；
   场景目录、参数语义、指标含义全部进系统提示词 + `list_scenarios` 工具，
   人类不需要学机器语言。
2. **引擎零改动**：System Agent 的工具**只调用既有房间 API**（`ApplyScenario` /
   `Pause` / `LaunchSurvey` / `ListScenarios` / `PredictionReport`）+ 新增一个
   **只读** `SystemSummaryText()`。不新增平行账本、不改经济语义。
3. **显示与决策分离**：`City-WebGL-Show` 不决策「做什么」，只把「看哪里」翻译成
   结构化显示指令；渲染由前端既有 3D 引擎执行（服务端无图形、无 three.js）。
4. **总线是可扩展点**：新 Agent 只需 `hub.Register(class, handler)` 即被 System
   发现（`list_agents` 工具动态列出），**无需改 System 代码**（§130 反例）。
5. **零 RNG / 零回归**：System Agent 是**人类触发**的旁路，不参与月结；
   场景注入复用批次 68 `applyScenarioToWorld`（确定性、不消耗 `w.Rand`），
   自动注入仍走批次 80 规则引擎 ⇒ 固定 seed 双跑逐位相等的契约不破。

## 3. 后端设计

### 3.1 `ServerGo/agent/citybus/`（新包，Agent 消息总线）

> 职责：Agent 之间的**注册 / 寻址 / 请求-响应 / 单向投递**。不感知 LLM，不感知引擎。

```go
// bus.go
type Message struct {
    From    string // AgentClassName
    To      string // AgentClassName
    Type    string // "message" | "run_display" | "collect" | "broadcast" | ...
    RoomID  string
    Payload any
    TraceID string
}

type Handler func(ctx context.Context, msg Message) (any, error)

type Hub struct { /* map[string]Handler, key = class 或 roomID+"|"+class */ }

func Default() *Hub
func (h *Hub) Register(class string, handler Handler) error
func (h *Hub) RegisterRoom(roomID, class string, handler Handler) error
func (h *Hub) UnregisterRoom(roomID, class string)
func (h *Hub) Send(ctx, roomID, from, to, typ string, payload any) (any, error) // 房间级优先，回退类级
func (h *Hub) Post(ctx, roomID, from, to, typ string, payload any) error         // 单向，不等回复
func (h *Hub) Agents() []string                                                    // 已注册类级 Agent 清单
```

**注册点**（`main.go` 装配层，唯一同时 import 多侧的位置）：

| Agent | 注册 | handler 行为 |
|---|---|---|
| `LsmAgentGame-City-WebGL-Show` | 房间级（每房一个 DisplayAgent） | 调 `DisplayAgent.Run(ctx, payload)` → 返回显示指令 |
| `LsmAgentGame-City-Chrome` | 类级 | 触发一次采集 mission（`citychrome.Service` 既有 API） |
| `LsmAgentGame-City-Human` | 房间级 | 向本房全体居民 Agent 广播一条「系统公告」，下一轮月度决策可见；返回居民摘要 |
| 未来 Agent | — | 只需 `Register`，System 侧 `list_agents` 自动可见 |

**并发与超时**：`Send` 用 `sync.Mutex` 保护 map；handler 在**调用方 goroutine** 执行
（WS handler goroutine），由调用方 `context` 控制超时（默认 120s）。
`Post` 投递到有缓冲 channel（cap 64），满则丢弃并记日志（不阻塞 WS）。

### 3.2 `ServerGo/agent/citysystem/`（新包，主 Agent）

**文件划分**（单文件 ≤1800 行，§4）：

| 文件 | 职责 |
|---|---|
| `types.go` | `Config` / `Agent` / `SystemEvent` / `ToolCallRecord` |
| `prompt.go` | 系统提示词角色段（**唯一事实来源**）+ 场景目录内联文本 |
| `tools.go` | 10 个工具的 Anthropic wire 定义 + `ToolNames()` |
| `dispatch.go` | 工具派发（→ 房间 API / bus / citychrome） |
| `context.go` | `ConversationStore`：按 `roomID+"/"+userID` 存会话，容量裁剪 + 摘要压缩 |
| `agent.go` | `Agent` 构造 / `Run(ctx, userText)` ReAct 主循环 / LLM 调用（流式续命 §197） |

```go
type Config struct {
    ModelKey        string
    MaxSteps        int           // 单轮 ReAct 步数上限（默认 8）
    MaxMessages     int           // 单会话消息上限（默认 40，超出裁剪）
    RequestTimeout  time.Duration // 单轮总超时（默认 180s）
    ToolResultLimit int           // 单个工具结果回灌上限 rune（默认 4000）
}

type Agent struct {
    RoomID   string
    ModelKey string
    room     *virtual_city.VirtualCityRoom
    registry LLMRegistry
    hub      *citybus.Hub
    store    *ConversationStore
    emit     func(SystemEvent)   // 事件流出（WS 层注入）
    lineMu   sync.RWMutex
    linePolicy string            // "" | "random" | 固定 model key
}
```

**ReAct 主循环**（`Run`）：

```
1. 取会话上下文（ConversationStore.Get(roomID, userID)）
2. 追加 user 消息
3. 构造 system = sysprompt.EnsureHead([]SystemBlock{{roleText}}, AgentClassCitySystem)
4. emit(agent_start)
5. for step := 0; step < MaxSteps; step++ {
       resp := callLLM(ctx, system, messages, BuildTools())   // ChatStreamAccumulate + 字节续命
       emit 所有 text_delta（前端打字机）
       if len(resp.ToolUses()) == 0 { break }
       for _, tu := range resp.ToolUses() {
           emit(tool_start{tool, input})
           res := Dispatch(ctx, tu.Name, tu.Input)
           emit(tool_result{tool, text, is_err})
           messages = append(messages, assistant(resp.Content), user(tool_result))
       }
   }
6. 持久化 assistant 最终文本到会话；emit(agent_end)
```

**Context 管理**（`context.go`）：

- 键 `roomID + "/" + userID`；值 = `[]llmtypes.Message`（不含 system，system 每轮重建）。
- **容量裁剪**：超过 `MaxMessages` 时，保留**最近** N-10 条 + 前 10 条（保底），
  中间丢弃；不阻塞、不调 LLM 压缩（成本考量）。
- **摘要压缩**（可选，`Compact` 方法）：把最旧的一半交给 LLM 压成一段中文摘要，
  作为一条 `user` 消息插回；本批实现接口 + 单测，**默认不触发**（避免额外 LLM 开销）。
- **重置**：`handleSystemReset` 清空对应用户会话（前端「清空对话」按钮）。

**系统提示词**（`prompt.go`）要点：

1. 身份：`LsmAgentGame-City-System`，虚拟城市系统主 Agent。
2. 城市背景：全 Agent 真实城市模拟（非游戏），居民=`City-Human`，
   真实数据=`City-Chrome`，3D 显示=`City-WebGL-Show`。
3. 能力边界：**只能**用工具控制；不能编造数据；注入前必须确认场景 kind 与强度。
4. 场景清单：由 `list_scenarios` 动态获取（提示词只给分组与总数）。
5. 输出规范：中文；先一句话说**要做什么**，再调工具；最后说**做了什么 + 关键指标**。
6. 安全：不得代替人类做不可逆操作（本批所有工具均为可逆或可观测）。

**10 个工具**（`tools.go`，Anthropic wire）：

| 工具 | 参数 | 行为 |
|---|---|---|
| `inject_scenario` | `kind` / `magnitude` / `duration_months?` / `target?` / `note?` | → `room.ApplyScenario`（35002/35055/35056/35057 原样回灌） |
| `list_scenarios` | — | 返回 40 个场景目录（分组 / 名称 / 描述 / 默认强度 / params） |
| `query_city_state` | `scope` = overview\|market\|labor\|treasury\|election\|all | → `room.SystemSummaryText(scope)`（**新增只读**） |
| `query_world_events` | — | → `room.WorldEventLogView()`（批次 80 反馈链） |
| `query_prediction_report` | `run_id?` | → `room.PredictionReport(runID)`（批次 68） |
| `control_simulation` | `action` = pause\|resume\|status | → `room.Pause(userID, bool)`（权限沿用房主校验 35011） |
| `launch_survey` | `question` / `options[]` | → `room.LaunchSurvey`（既有调研引擎） |
| `focus_camera` | `district?` / `x?` / `z?` / `mode?` | → `hub.Send(roomID, System, City-WebGL-Show, "run_display", …)` |

### 3.3 `ServerGo/agent/citywebgl/`（新包，渲染显示 Agent）

**职责**：把「看哪里 / 怎么显示」翻译成**结构化显示指令**；不做 LLM 决策之外的图形工作。

```go
// command.go
type DisplayCommand struct {
    Type      string  `json:"type"`      // focus_district|focus_point|set_mode|highlight_district|annotate|clear
    District  string  `json:"district,omitempty"`
    X, Z      float64 `json:"x,omitempty"`
    Mode      string  `json:"mode,omitempty"`      // orbit|fly
    Text      string  `json:"text,omitempty"`
    Color     string  `json:"color,omitempty"`
    TraceID   string  `json:"trace_id,omitempty"`
}

// agent.go
type Agent struct {
    ModelKey string
    registry LLMRegistry
    emit     func(DisplayCommand)
}
func (a *Agent) Run(ctx context.Context, req DisplayRequest) ([]DisplayCommand, error)
```

**工具**（显示原语，6 个）：`focus_district` / `focus_point` / `set_mode` /
`highlight_district` / `annotate` / `clear_display`。
每次工具调用即产出一条 `DisplayCommand`（`emit` 出去）。

**两种调用路径**：
1. **LLM 路径**（自然语言）：`Run(ctx, {text})` → ReAct（≤3 步）→ 指令序列。
2. **结构化路径**（System Agent 的 `focus_camera` 工具）：直接构造指令，**不过 LLM**
   （省一次模型往返，视角跟随要快）。`SystemAgent` 侧按参数是否完整决定走哪条。

**房间级注册**：`ws` 层在建房/首次对话时 `hub.RegisterRoom(roomID, AgentClassCityWebGLShow, handler)`；
房间销毁时 `UnregisterRoom`。

**语义**（与批次 79 `city_chrome_line` 完全同构）：
- `""` / 缺省 = 沿用服务端配置 `city_system.model_key`（旧行为，零回归）
- `"random"` = 每个对话轮次从 LLM 线路池按 `concurrency_lines` 加权随机取线（**建房弹窗默认**）
- 其余 = 固定 model key

### 3.7 配置

`LsmAgentGame.conf` 增 `city_system{}` 段（与 `city_chrome{}` 并列）：

```ini
[city_system]
enabled = true
model_key = "DeepSeek"
max_steps = 8
max_messages = 40
request_timeout_ms = 180000
tool_result_limit = 4000
```

`config.CitySystemConfig` + `CitySystemConfigResolved()` 归一（缺省值同上）。

## 8. 风险与回退

| 风险 | 缓解 |
|---|---|
| LLM 乱调工具 / 死循环 | `MaxSteps=8` + `RequestTimeout=180s`；工具结果限长；`MaxActiveScenarios=8`（既有） |
| LLM 成本 | 每轮 ≤8 次调用；上下文 ≤40 条；线路池复用 |
| Agent 编造指标 | 所有指标经 `query_city_state` / `query_prediction_report` 真实工具；提示词禁止编造 |
| 系统 Agent 影响存量对局 | 只读 + 复用既有注入通道；不消耗 RNG；无事件时零偏移 |
| 建房线路策略与 Chrome 冲突 | 两个独立策略字段（`city_chrome_line` / `city_system_line`），互不覆盖 |
| 前端白屏 | `t(映射表[id])` 恒返回字符串（记忆 `i18n-map-miss-blanks-panel`）；i18n key 三语同步 |

**一键回退**：`[city_system] enabled=false` ⇒ WS 帧返回 35058（新增错误码），
前端隐藏 `💬 系统对话` 按钮（`game.state` 增 `system_agent_enabled` 字段）。
