## 1. 设计目标

P0 的 Ledger 已预留 `insurer` 实体但无任何交易，《规则》§6.7 的四险种数值
（重疾 / 百万医疗 / 定期寿险 / 意外）一直是纸面设计。当前健康事件
（`events.go::BellEvents`，每 60 月按 health_grade 掷骰，费用 U(10,000, 200,000)）
让玩家**全额自付**医疗费——「因病致贫」只作为破产的隐性来源存在，玩家没有任何
对冲工具。

| 现状缺口 | 真实世界对应 | 教育价值 |
|----------|-------------|---------|
| ❌ 无保险可买 | 消费型商业险四件套 | 保险不产生收益，只转移风险 |
| ❌ insurer 实体空转 | 保险公司保费池 / 赔付池 | 保费是**支出**不是**投资** |
| ❌ 重疾全额自付 | 重疾险定额给付 + 百万医疗报销 | 5–20 万 → 5 千–2 万的风险转移 |
| ❌ 无意外事件 / 无身故 | 意外伤害与身故、寿险杠杆 | 定期寿险是家庭责任定价 |
| ❌ Agent 无风险决策维度 | 保费预算占收入 5%–10% | 风险评估与预算锚点 |

**核心原则（《规则》§6.7 原文）**：保险不产生收益，只转移风险。未买保险触发大病
自付 5–20 万；买了保险自付降至 5 千–2 万。

## 2. 险种定义与保单数据模型

### 2.1 险种静态表（`game/wealth/insurance.go`，常量即契约）

| kind | 中文名 | 基准年保费（25 岁） | 规则区间（《规则》§6.7） | 保额 / 赔付规则 | 等待期 |
|------|--------|--------------------|--------------------------|----------------|--------|
| `critical_illness` | 重疾险 | ¥5,000 | 3,000–8,000 | 确诊重疾一次性给付 **¥400,000**（30–50 万中值，P1 新定）；**终身限赔 1 次**，赔付后保单终止 | 3 月 |
| `medical_million` | 百万医疗险 | ¥1,000 | 500–1,500 | 住院医疗费报销 **90%**（《规则》§11.2.5），比例报销型，无次数上限 | 1 月 |
| `term_life` | 定期寿险 | ¥2,000 | 1,000–3,000 | 身故给付 **¥1,000,000** 入遗产池；保至 60 岁终局（期满未身故不返不赔——消费型教育点） | 3 月 |
| `accident` | 意外险 | ¥350 | 200–500 | 意外伤残给付保额 50%（¥250,000）；意外身故给付全额 **¥500,000** 入遗产池 | 0（次日生效，游戏内即当月生效） |

```go
// policyDef 险种静态定义(2026-09-19 §财商流P1-4 新定)。
type policyDef struct {
    BasePremiumCNY int64 // 基准年保费(25 岁档)
    LowCNY         int64 // 规则区间下限(clamp 用)
    HighCNY        int64 // 规则区间上限(clamp 基数,随 CPIFactor 放宽)
    CoverageCNY    int64 // 定额给付保额(名义锁定;medical_million 为 0=比例报销)
    ReimburseRatio float64 // 报销比例(仅 medical_million=0.9,其余 0)
    WaitingMonths  int    // 等待期(游戏月)
}

var policyDefs = map[string]policyDef{
    "critical_illness": {BasePremiumCNY: 5000, LowCNY: 3000, HighCNY: 8000, CoverageCNY: 400000, WaitingMonths: 3},
    "medical_million":  {BasePremiumCNY: 1000, LowCNY: 500,  HighCNY: 1500, ReimburseRatio: 0.9, WaitingMonths: 1},
    "term_life":        {BasePremiumCNY: 2000, LowCNY: 1000, HighCNY: 3000, CoverageCNY: 1000000, WaitingMonths: 3},
    "accident":         {BasePremiumCNY: 350,  LowCNY: 200,  HighCNY: 500,  CoverageCNY: 500000, WaitingMonths: 0},
}
```

### 2.2 保单结构（`player.go` 新增）

```go
// Policy 一张有效/历史保单(2026-09-19 §财商流P1-4 新定)。
// 每位玩家每险种最多 1 张有效保单(硬约束)。
type Policy struct {
    Kind             string  `json:"kind"`               // 4 险种之一
    AnnualPremiumCNY int64   `json:"annual_premium_cny"` // 当前年保费(年结按年龄档×CPI 重定价)
    CoverageCNY      int64   `json:"coverage_cny"`       // 保额(名义,投保时锁定;医疗险 0)
    StartMonth       int     `json:"start_month"`        // 生效月(投保当月)
    PaidMonths       int     `json:"paid_months"`        // 已缴月数
    GraceActive      bool    `json:"grace_active"`       // 处于宽限期(上月断缴,本月兜底)
    Active           bool    `json:"active"`             // 有效中(含宽限期);失效/退保/赔付终止 → false
    CPIFactor        float64 `json:"cpi_factor"`         // 投保时 1.0,年结 ×(1+clamp(CPIYoY,0,0.10))
    ClaimsTotalCNY   int64   `json:"claims_total_cny"`   // 累计已赔付(展示用)
}

// Player 新增字段:
//   Policies map[string]*Policy `json:"-"` // key=kind;nil=从未投保
```

### 2.3 保单状态推导（view 层共用，**不写库**）

```go
// PolicyStatus 保单展示状态(由 Active/PaidMonths/GraceActive/StartMonth 派生)。
func (p *Policy) Status(nowMonth int) string {
    if !p.Active { return "lapsed" }              // 失效(断缴超宽限/退保/重疾赔付终止)
    if p.GraceActive { return "grace" }           // 宽限期(保障仍有效)
    if nowMonth-p.StartMonth < policyDefs[p.Kind].WaitingMonths { return "waiting" } // 等待期(不赔)
    return "active"                                // 有效且可理赔
}
```

- `waiting` 状态：保费照扣，出险**不赔不退**（消费型，P1 新定；事件文本提示等待期）。
- 每险种限 1 张**有效**保单；失效/终止后允许重新投保（等待期重新计算，P1 新定）。

## 3. 投保与退保规则

### 3.1 `buy_insurance` 动作

ACTING 阶段动作，`Action{Type: "buy_insurance", Kind: "<4 险种之一>"}`
（复用 `Action.Kind` 既有字段，无 Action struct 变更）。

校验链（顺序锁定，首个失败即返回）：

| # | 校验 | 失败错误码 |
|---|------|-----------|
| 1 | `cfg.Wealth.InsuranceEnabled == true` | 35041 |
| 2 | 通用校验①–④（协议 §4：playing / acting / alive / budget / 观战者拒收） | 35002/35004/35005/35006/30011 |
| 3 | `kind` ∈ policyDefs | 35037 |
| 4 | 该险种无 Active 保单 | 35038 |
| 5 | 主时钟年龄 `w.Age() ≤ 55`（56 岁起禁止新投保，P1 新定；现实长期险投保上限） | 35040 |
| 6 | 现金 ≥ 首月保费（= 年保费/12，见 §4.1 定价公式） | 35007 |

执行效果：

1. 创建 `Policy{StartMonth: w.Month, AnnualPremiumCNY: 定价(§4.1), CoverageCNY: def.CoverageCNY, Active: true, CPIFactor: 1.0}`，写入 `p.Policies[kind]`。
2. **当月立即扣缴首月保费**（`Pay(seat, SeatEntity(seat), EntityInsurer, monthly, CatPremium, "<险种中文名>保费")`）；后续月份由月结统一扣缴（§4.2）。
3. `p.LastActionText = "投保重疾险(年缴 ¥5,000)"` 等人读文本；广播 `game.event{type:"action"}`。
4. 消耗 1 点本月动作预算（与既有动作一致）。

### 3.2 `cancel_insurance` 动作

`Action{Type: "cancel_insurance", Kind: "<险种>"}`。

校验：通用校验 + kind 合法（35037）+ 存在 Active 保单（35039）。

执行效果（消费型规则，P1 新定）：

- **零现金价值**：不退还任何已缴保费（4 险种均为消费型，现实一致；
  教育点：退保损失是保险决策成本）。
- 立即 `Active=false`，次月起不再扣缴。
- 广播 `game.event{type:"action"}`；消耗 1 点动作预算。

### 3.3 年龄档与定价公式

年龄一律取**主时钟** `w.Age()`（与协议 `game.state.age` 同源；文档池差异卡的
`Player.Age` 仅展示用途，不进定价——P1 新定，与 P0 时钟语义一致）。

```go
// agePremiumMult 年龄加价系数(P1 新定;真实医疗险自然费率的简化)。
func agePremiumMult(age int) float64 {
    switch {
    case age < 35:  return 1.0
    case age < 45:  return 1.25
    case age < 50:  return 1.6
    default:        return 2.0 // 50–55
    }
}

// 定价(P1 新定): 年保费 = clamp(Base×ageMult×CPIFactor, Low, round(High×CPIFactor))。
// CPIFactor 定义见 §4.3;规则区间随 CPI 同步放宽(通胀下名义保费允许突破 2025 锚点)。
```

校验：25 岁投保四险种年保费 = 5000/1000/2000/350，全部落在《规则》§6.7 区间内；
50 岁重疾险 = 5000×2.0 = 10,000 → clamp 至 8,000（区间上限，CPIFactor=1 时）。

## 4. 月结保费流

### 4.1 扣缴位置（`settlement.go` 月结 7 步，**顺序锁定**）

在**步骤 3（固定支出）末尾**追加保费扣缴（《规则》§3.5 月结流程中保险费属保障支出，
与 §5.1 固定支出表「保险费 = 年缴保费 ÷ 12」一致；架构文档 §9.2 步骤 3 的既有
科目顺序不变，仅追加）：

```
步骤3 固定支出：贷款月供/月息 → 房租 → 物业 500 → 【新增】各 Active 保单月保费
```

### 4.2 扣缴与断缴规则（`insurance.go::SettlePremiums`）

```go
// SettlePremiums 单座位月保费扣缴(月结步骤3 末尾调用;逐保单处理)。
//
//   monthly = round(AnnualPremiumCNY / 12)
//   现金充足 → Pay(seat→insurer, monthly, CatPremium);PaidMonths++;GraceActive=false
//   现金不足 → 本月不扣:
//     首次断缴 → GraceActive=true(宽限期 1 个月,保障继续有效,事件提示)
//     宽限期次月仍不足 → Active=false(失效 lapse,事件提示;下月可重新投保)
//
// 保费计入 Monthly.Expense + detail{key:"insurance"}(三表展示);
// 现金允许为负的既有逻辑不变(保费不足时不强扣,不新增 NegativeCashMonths 触发路径)。
func (w *World) SettlePremiums(p *Player)
```

- 宽限期设计取现实「60 天宽限期」的游戏月简化 = **1 个月**（P1 新定）。
- 失效后**不自动复效**；重新投保走 §3.1 全流程（等待期重算）。
- 破产停赛（`StoppedMonths>0`）与出局（`!Alive`）座位：不扣缴、不宽限推进，
  保单原样冻结（P1 新定；破产重组期间保单不散失是游戏规则简化）。

### 4.3 CPI 与年龄重定价（年结，`AnnualAdjust` 尾部追加）

```go
// RepricePolicies 年结保费重定价(每 12 月,AnnualAdjust 既有循环内追加)。
//
//   CPI 取值:w.Goods.CPIYoY(P1 经济循环引擎,就绪时);
//     未就绪/economy_enabled=false → 回退 w.CB 的外生 CPI → 再回退 0(纯 P0 行为,不调整)。
//   每张 Active 保单:
//     CPIFactor ×= (1 + clamp(cpiYoY, 0, 0.10))
//     AnnualPremiumCNY = clamp(round(Base×ageMult(w.Age())×CPIFactor), Low, round(High×CPIFactor))
func (w *World) RepricePolicies(p *Player)
```

- 保费**随年龄档上浮 + 随 CPI 累积上浮**（自然费率，不锁投保价——P1 新定；
  理由：4 险种均为 1 年期消费型短险逻辑，续保重定价是真实世界常态）。
- 保额**名义固定**（`CoverageCNY` 投保锁定后不变）。⚠️ 取舍：定额给付型
  （重疾/寿险/意外）真实世界即名义保额，**通胀侵蚀保额本身就是教育点**，
  与通胀传导引擎文档 §2 的「货币幻觉」主题呼应，故赔付基数不做 CPI 放大；
  百万医疗为比例报销（90%），赔付额天然跟随实际医疗费波动。本契约以此满足
  「保费与赔付基数随 CPI 浮动」：保费显式 CPI 联动，报销型赔付隐式联动，
  定额型赔付的名义固化是刻意保留的教学语义。

## 5. 理赔流

### 5.1 医疗/重疾理赔（对接既有健康事件）

改造点：`events.go::BellEvents` 健康事件分支，在既有
`Pay(seat→consumerPayTo(), cost, CatMedical)` **之后**调用理赔管线：

```go
// SettleMedicalClaims 医疗事件理赔(P1-4 新定)。isMajor = cost ≥ 100000
// (与 events.go 既有重疾判定阈值一致,不改事件生成本身)。
//
//   百万医疗(Status=="active"):claim = round(cost × 0.9)
//     → Pay(insurer→seat, claim, CatClaim, "百万医疗报销")
//     → 玩家实际自付 = cost × 10%(规则「自付降至 5 千–2 万」的报销制实现)
//   重疾险(Status=="active" 且 isMajor):一次性给付 CoverageCNY(400,000)
//     → Pay(insurer→seat, ..., CatClaim, "重疾理赔")
//     → 赔付后保单终止(Active=false,定额给付型单次赔付合同终止,现实一致)
//   等待期(waiting)/宽限期(grace 视为可赔)/未投保:不赔,维持全额自付。
//   ⚠️ grace 状态可赔:宽限期保障有效(§4.2 宽限期语义)。
```

¥400,000，百万医疗报销 ¥108,000」）+ Ledger 双式记录（`CatClaim`）+
`Policy.ClaimsTotalCNY` 累加。

## 6. Ledger 激活与守恒

### 6.1 `ledger.go` 修改契约（激活 insurer）

1. 新增 category 常量：
   ```go
   CatPremium = "premium" // 保费(座位→保险公司)
   CatClaim   = "claim"   // 理赔(保险公司→座位)
   ```
2. `validFromTo`：删除「insurer has no trades in P0」硬拒分支，替换为方向白名单：
   ```go
   // insurer 只与座位交易:seat→insurer 仅 CatPremium;insurer→seat 仅 CatClaim。
   if to == EntityInsurer && category != CatPremium { ... }
   if from == EntityInsurer && category != CatClaim { ... }
   ```
3. `EntityInsurer` 常量注释由「P0 预留，无交易」改为「保险公司：保费收 / 理赔付（P1-4 激活）」。

### 6.2 守恒不变量（验收锚点）

- **I1 座位守恒不变**：所有保费/理赔仍走 `World.Pay`（一端座位，同记账同扣款），
  `VerifySeatConservation` 语义不变。
- **I4（新增）insurer 收支可核算**：
  ```go
  // EntityNet 实体净流入 = Σ(to=entity) − Σ(from=entity)(调试/验收用)。
  // insurer 净额 = Σ保费 − Σ理赔 = 保险公司利润(可为负,大灾年亏损是教学内容)。
  func (l *Ledger) EntityNet(entity string) int64
  ```
- **I2 不变**：`WorldInjectCount` 仍 = 座位数（保险不经 world 注入）。
- 保险公司**不做破产模拟**（P1 新定）：insurer 是无限偿付能力的系统实体，
  与 bank/market 同级；保险公司经营风险留 P2+。

## 13. 不做的事（写入 P2+）

- ❌ 保险公司经营模拟（偿付能力 / 定价博弈 / 再保险）：insurer 恒为无限偿付系统实体。
- ❌ 商业养老险 / 企业年金（《规则》§6.8）：属养老金线，与社保养老金合并到 P2。
- ❌ 社保医保报销比例细化（《规则》§6.7「住院报销 70%」）：现状医疗费全额自付
  语义不变，百万医疗报销叠加在既有数值上；社保线改造留 P2。
- ❌ 核保 / 健康告知 / 既往症拒赔：12 Agent 无医疗史复杂度，等待期是唯一风控。
- ❌ 保单贷款 / 分红险 / 万能险：储蓄型保险与「保险不产生收益」原则冲突，不引入。
- ❌ 自然灾害集体事件联动财险（车险 / 家财险）：随 §11.3 集体事件线留 P2。
