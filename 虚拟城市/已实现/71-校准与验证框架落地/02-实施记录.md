## 1. 批次目标（回顾）

把两份**「只有设计稿、代码零实现」**的文档，第一次变成**可执行的代码**：

- 《虚拟城市模拟校准与验证框架》v2.0 —— 29 项校准基础设施，逐项检索结果：**完整覆盖 1 项、半覆盖 5 项、零实现 23 项**；
- 《虚拟城市-P0经济平衡修复与蒙特卡洛验收方案 v1》§4.2（I1/I2/I4/I6/I8）、§5（G1–G12）、§6（T1–T14）—— **零实现**。

**根因不是"没写"，是"账本边界从未声明"**：国库直改现金、活期↔定期互转、场景伤害、遗产清零 —— 4 处
**不经 `World.Pay` / `Ledger`** 的现金变动，让"部门资金流量加总 = 0"在字面上无法成立，
于是所有守恒类断言都写不出来。

**解法**：不消灭账外调整（会波及 view / 实体白名单 / 历史对局），而是**把每一笔账外调整登记成带原因的流水**，
让 I1 用「账本净流 + 账外净流」闭合。**先让账能对上，别的才有资格谈。**

**结果**：**账外调整账** + **七条可执行不变量**（I1/I2/I3/I4/I5/I6/I8）+ **引擎状态哈希** +
**运行级采集与 D 指标** + **5 条红线判定** + **看板第 12 维度「校准」**，并结清批次 70 的 L1–L10 遗留。

**改动规模**：**35 个代码文件**（后端 20 / 前端 15），**+3876 / -89** 行；**文档 4 份**（含 1 张实机截图）。

## 5. 实现取舍

| 取舍 | 选择 | 理由 |
|---|---|---|
| **账外调整：消灭 vs 登记** | **登记**（`OffLedgerBook`） | 消灭要改 `Ledger` 实体白名单 / 新增 category ⇒ 波及 view / 财务面板 / 历史对局兼容，收益不抵风险；登记则**把隐藏的记账边界变成显式可审计的清单**，同样是科研级改进 |
| **I1 的闭合式** | `p.Cash == 注入 + 账本净流 + 账外净流` | 三者**独立维护**（账本由 `Record` 增量、现金由 `Pay` 改动、账外由登记簿）⇒ **不是恒真式**；任一条路径被绕过立即变红 |
| **I8 的部门边界** | 声明为「Ledger 内实体集合」，国库另由 I3 守 | 国库**按设计**不走 Ledger（`treasury.go` 头注释）⇒ R-I2 字面在国库侧不成立；两条不变量合起来覆盖全系统 |
| **I4 的性质** | 定位为**口径契约护栏**（独立重算 vs `p.NetWorth()`），非守恒律 | 文档 §4.2 的「净资产 = 现金 + Σ资产 − Σ贷款」是定义式陈述；真正有价值的是**独立重算对比**——一旦有人改 `NetWorth` 语义，检查器立刻逼同步口径文档与所有消费点。另有「篡改即变红」反证测试 |
| **I5 的覆盖面** | 引擎状态（玩家/市场/央行/国库/商品/劳动力/社会/产业链/账本/账外），**排除** transcript / 事件文本 / 时间戳 / LLM 产物 | 居民 LLM 决策的确定性属 **R0**（批次 73+）；本批只保证**引擎级**可复现，这是 R0 的地基而非 R0 本身 |
| **哈希算法** | 固定 FNV-1a 64，**不用 `hash/maphash`** | `maphash` 按进程随机播种 ⇒ 跨进程不可比，D9 会失去意义 |
| **状态哈希的 map 纪律** | `Asset.Extra` 只取**派生标量**（rate / district / self_occupied），**绝不遍历 map** | Go map 迭代顺序随机 ⇒ 遍历即引入不确定性 |
| **浮点入哈希** | `math.Float64bits` 取 8 字节 | `fmt.Sprintf("%v")` 的输出随精度/平台漂移 |
| **审计接线位置** | `settlement.go:317`（`w.Month++` **之前**） | 与 `predictionMonthStep` 同侧；B13 金标回归证明**零模拟偏移** |
| **红线 vs 不变量** | 红线**不中止运行**，只高亮 + 记入 `RunRecord` | 红线是「越界告警」（需回炉调参），不变量破裂才是「立即中止」 |
| **未实现的红线** | R-E1/E2、R-B2–B6 **前端不显示** | 显示未实现的红线会造成「全部通过」的假象（比不显示更危险） |
| **`RunRecord` 写盘** | 本批**仅内存** | 写盘需先定目录 / 保留期 / 并发写策略 ⇒ 批次 72 |
| **前端未知枚举** | 回退显示后端 `name` 字段 | §12 纪律：映射表漏项 ⇒ 白屏或裸 undefined；回退链保证「永不崩、永不裸」 |

## 6. 发现的既有代码缺陷（**未擅自改数值语义，待裁决**）

### 6.1 【真缺陷·待裁决】`bias.go::settleDeferredPayments` 少计违约实付额

```go
if due > p.Cash {
    if p.Cash > 0 {
        w.Pay(p.Seat, SeatEntity(p.Seat), w.consumerPayTo(), p.Cash, CatConsume, "延期支付(现金不足,违约)")
        extra += p.Cash        // ← w.Pay 已把 p.Cash 扣为 0 ⇒ 此处恒加 0
```

**事实**：`w.Pay` 把 `p.Cash` 扣到 0 后，紧跟的 `extra += p.Cash` 加的是 **0**。
后果：现金不足违约时，月结 `expense` **少计**该笔实付款，且「延期支付贴现成本」备注**不播报**。

**关键澄清（不要误判为"钱凭空消失"）**：钱**已经进账本**（`w.Pay` → `Ledger`），
I1 守恒在违约分支**依然成立**。这是**支出口径少计**问题，**不是**货币创造/湮灭问题。

**正确的修复公式（与正常分支同形）**：正常分支是 `extra += due − d.AmountCNY`（本金已在延期月确认，
本月只确认 30% 贴现成本）；违约分支实付 `paid`（< `due`），故应为
**`extra += paid − d.AmountCNY`**（`paid` 须在 `w.Pay` **之前**取值）。
`paid < d.AmountCNY` 时该值为**负** ⇒ 触发**冲回/核销**语义。

**为何本批不改**：该值进入 `p.Monthly.Expense` ⇒ 喂 **FI 指数** ⇒ 影响终局评分与结局分布 ⇒
改它等于**改模拟结果**，需先做产品/设计裁决（违约是「核销本金」还是「按实付冲回」），并重跑校准。
**纪律：测量层批次不夹带数值语义变更。** → 登记为批次 72 遗留 **N10**。

### 6.2 【已在本批处置】`bias.go` 的 `p.Cash = 0` 属**假账外**

`w.Pay` 已把该笔现金记入账本，此处 `p.Cash` 已是 0 ⇒ 登记额**恒为 0**。
仍选择**登记**（reason `deferred_default_clear`），使「所有直接写 `p.Cash` 的位置都已声明」**字面成立**。

### 6.3 【已在本批处置】第 7 处国库现金改动

市长津贴（`civic_election.go`）发生在国库月结**之后**（⑨G），不在 `LastMonthExpense` 口径内
⇒ 登记 `TreasuryState.OtherExpense` 参与 I3 恒等式（见 D2）。**未**改任何经济数值。

### 6.4 账外现金变动的穷举核验

`grep -rn "p\.Cash +=\|p\.Cash -=\|p\.Cash = "`（排除注释）最终命中 **5 处**，
与「**4 处真账外 + 1 处假账外**」完全一致，且**每处 ±8 行内必有 `offLedgerRecord` 调用**
（该枚举已固化为 **B1 断言测试**：命中数必须 = 5、文件分布必须 = {`actions`×2, `scenario`, `family`, `bias`}）：

| 位置 | 性质 | 登记 reason |
|---|---|---|
| `actions.go::actDeposit` | 真账外 | `savings_deposit`（−） |
| `actions.go::actWithdraw` | 真账外 | `savings_withdraw`（+） |
| `scenario.go` 居民现金损失 | 真账外 | `scenario_damage`（−） |
| `family.go` 死者账簿清零 | 真账外 | `estate_clear`（−） |
| `bias.go` 延期支付违约 | **假账外** | `deferred_default_clear`（恒 0） |

> `listing.go::PaySeatToSeat`（`from→to` 双方直改现金）**看着像账外，实为账内** ——
> 它**先** `Ledger.Record` **再**改现金，**未**登记账外（登记了会导致 I1 重复扣减而红）。
