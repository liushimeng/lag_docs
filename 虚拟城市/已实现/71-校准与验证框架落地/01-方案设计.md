## 1. 问题定位

### 1.1 设计稿说了什么，代码做了什么

《模拟校准与验证框架》v2.0 定义了 29 项校准基础设施（采集模板 24 字段 / 居民级 12 字段 /
事件级 7 字段 / R-I1–R-I6 / R-E1–R-E6 / R-B1–R-B6 / 蒙特卡洛 / 敏感度 / A-B / 仪表盘 / 回填机制）。
逐项静态检索结论：**完整覆盖 1 项（R-I1 座位守恒）、半覆盖 5 项、其余 23 项零实现**。

更关键的是**账本边界从未被显式声明**，导致「不变量」在字面上无法成立：

| 事实 | 位置 | 后果 |
|---|---|---|
| 国库现金**直改 `t.Cash`**，不经 `World.Pay` | `treasury.go:161` / `fiscal_policy.go:137,179` / `transfer_payment.go:163` / `sovereign_bond.go:116,136` | 文档 R-I2「部门资金流量加总 = 0」在国库侧字面不成立（**设计选择**，非 bug，但未声明） |
| 活期↔定期互转**不经 Ledger** | `actions.go:1391`（`p.Cash -= amt`）、`actions.go:1410`（`p.Cash += amt`） | 座位现金变动**没有对手方**，双式账本不闭合 |
| 场景伤害**不经 Ledger** | `scenario.go:754`（`p.Cash -= dmg`） | 灾害抹去的财富**凭空消失**，社会总财富口径失真 |
| 遗产清算**直接清零**死者现金 | `family.go:453`（`p.Cash = 0`） | 未分配遗产部分**静默蒸发** |
| 引擎**无状态哈希** | 全库 `grep state_hash` 零命中 | R-I5「同 seed 双跑逐月哈希一致」无载体 |
| 运行级采集**零写盘** | `virtual_city/` 生产代码 `os.WriteFile` 零命中 | §4.1 的 24 字段采集表、§8.1「埋点缺失视为运行无效」全部无法满足 |

### 1.2 为什么这批必须先做

1. **R0 复现的前置**：批次 68 裁决「R0 同种子孪生未实现」的**唯一理由**是「居民 LLM 决策缓存不存在」。
   而 R0 的另一半前提——**引擎级确定性**——目前**也没有护栏**（无哈希、无双跑对拍）。
   本批交付的 `StateHash()` + I5 双跑断言，就是 R0 的地基。
2. **70 个批次的累积欠债没有回归网**：批次 20–70 改了大量经济子系统（产业链 / 金融市场 / 财政 /
   保险 / 代际转移 / 泡沫 / 场景推演），但**没有任何一条护栏断言「钱没凭空多也没凭空少」**。
   一处 `p.Cash +=` 写错，全城经济结论静默失真，而现有 414 个单测**全绿**。
3. **科研级定位的最低门槛**：用户定位声明把虚拟城市定位为「科研级城市模拟程序」。
   一个不能自证账本闭合的模拟器，不配叫科研级。

## 3. 账外调整账（OffLedgerBook）

### 3.1 定位

**账外** = 现金发生了变动，但**没有对应的 Ledger 双式条目**。这不是错误，是**记账边界**——
但它必须**被声明、被登记、可被审计**，否则 I1 守恒永远红，且没人知道钱去哪了。

本批的立场：**不消灭账外调整**（消灭会波及 view / 白名单 / 历史对局），
而是**把每一笔账外调整登记成一条带原因的流水**，并让 I1 用「账本净流 + 账外净流」口径闭合。

### 3.2 数据结构

```go
// ServerGo/game/virtual_city/offledger.go（新建）

// OffLedgerReason 账外调整原因（枚举值即 i18n / 审计口径）。
const (
    OffLedgerSavingsDeposit = "savings_deposit" // 活期→定期（座位内部划转）
    OffLedgerSavingsWithdraw = "savings_withdraw" // 定期→活期（座位内部划转）
    OffLedgerScenarioDamage  = "scenario_damage"  // 场景冲击对居民现金的直接损失
    OffLedgerEstateClear     = "estate_clear"     // 遗产清算后死者账簿清零
)

// OffLedgerEntry 单条账外调整登记（不可变）。
type OffLedgerEntry struct {
    Month  int    `json:"month"`
    Seat   int    `json:"seat"`
    Reason string `json:"reason"`
    Amount int64  `json:"amount"` // 有符号：正 = 座位现金增加，负 = 座位现金减少
    Note   string `json:"note"`
}

// OffLedgerBook 账外调整登记簿。
type OffLedgerBook struct {
    Entries []OffLedgerEntry // 环形缓冲，cap 200
    SeatNet [MaxSeats]int64  // 逐座累计账外净流（I1 闭合用；O(1) 读取）
    Total   int64            // 全书累计账外净流
}
```

### 3.3 登记点（**恰好 4 处**，逐点核对）

| # | 位置 | 现状 | 登记额 |
|---|---|---|---|
| 1 | `actions.go::actDeposit` | `p.Cash -= a.AmountCNY` | `−AmountCNY`（`savings_deposit`） |
| 2 | `actions.go::actWithdraw` | `p.Cash += a.AmountCNY` | `+AmountCNY`（`savings_withdraw`） |
| 3 | `scenario.go`（居民现金损失） | `p.Cash -= dmg` | `−dmg`（`scenario_damage`） |
| 4 | `family.go`（死者账簿清零） | `p.Cash = 0` | `−p.Cash`（`estate_clear`，**在清零前取值**） |

> ⚠ **纪律**：这 4 处是**穷举**。新增任何直接写 `p.Cash` 的代码，**必须**同提交登记，
> 否则 I1 立刻红。落地时用 `grep -rn "p\.Cash +=\|p\.Cash -=\|p\.Cash = " ServerGo/game/virtual_city/`
> 断言命中集合恰为这 4 处（`bias.go:508` 的 `p.Cash = 0` 位于 `w.Pay(...)` 之后，
> 此时 `p.Cash` 已被 Pay 扣为 0 ⇒ 登记额恒 0，**登记但金额为 0**）。

### 3.4 读取入口

```go
func (b *OffLedgerBook) Record(month, seat int, reason string, amount int64, note string)
func (b *OffLedgerBook) SeatNetFlow(seat int) int64
func (b *OffLedgerBook) Total() int64
func (b *OffLedgerBook) Recent(n int) []OffLedgerEntry
```

## 4. 七条回归不变量（I1–I8）

### 4.1 汇总

| ID | 名称 | 判据 | 严重级 | 触发动作 |
|---|---|---|---|---|
| **I1** | 座位现金守恒 | 逐座：`p.Cash == 初始注入 + Ledger 净流 + 账外净流` | 致命 | 立即中止运行 |
| **I2** | world 注入唯一性 | 每座恰好 1 条 `from=world`，month = 0 | 致命 | 立即中止运行 |
| **I3** | 国库收支闭合 | `Δ国库现金 == LastMonthRevenue − LastMonthExpense` | 致命 | 立即中止运行 |
| **I4** | 资产负债口径契约 | 独立重算 `现金 + 养老金 + Σ资产市值 − Σ贷款余额` == `p.NetWorth(m)` | 致命 | 立即中止运行 |
| **I5** | 引擎状态哈希 | 同 seed 双跑逐月 `StateHash()` 一致 | 致命 | 判不可复现缺陷 |
| **I6** | 场景注入留痕 | 每条注入记录含 kind/magnitude/target/duration/seed/snapshot | 严重 | 报告不得引用 |
| **I8** | 系统净流闭合 | 全实体 Ledger 净流之和 == 0；座位组与非座位组互相抵消 | 致命 | 立即中止运行 |

> **编号沿用《P0经济平衡修复与蒙特卡洛验收方案 v1》§4.2**（I1 / I2 / I4 / I6 / I8），
> 新增 I3（国库，源于《校准框架》R-I3）与 I5（状态哈希，源于《校准框架》R-I5）。
> **跳过 I3 旧号**（旧 I3 = 「总额法货币分层」，已由央行引擎实现且不属本批口径），沿用新占位不冲突。

### 4.2 I1 座位现金守恒（口径细化）

```
p.Cash  ==  injectAmount(seat)              // I2 保证恰好 1 条 world→seat 注入
          + Σ Ledger 净流(seat, 全部月份)     // to=seat 减 from=seat
          + OffLedgerBook.SeatNet(seat)       // 声明过的账外调整
```

**实现要点**：
- `Ledger` 增**增量维护**的 `SeatNets [MaxSeats]int64`（`Record` 内更新），
  避免每次检查 O(entries) 全扫（480 月 × 34k 条不可接受）。
- `injectAmount(seat)` 从 `Ledger` 的 `from=world` 条目取（I2 校验只有 1 条）。
- 座位**出局**（`Alive=false`）后 `p.Cash` 被清零 ⇒ 该座在**出局月之后**不再参与 I1 断言，
  但**出局当月**必须成立。实现：以 `p.Ending` / `p.Alive` 与出局月标记判定。
  —— ⚠ 若实现中发现无法可靠区分「出局月」与「出局后」，**在报告里写明并采用保守口径**
  （出局后仍断言，若失败则登记为「已知例外」而非静默跳过）。

### 4.3 I3 国库收支闭合

- `SettleTreasuryMonth`（`treasury.go`）**开头**快照 `Cash` 到 `TreasuryState.PrevMonthCash`。
- 恒等式：`Cash − PrevMonthCash == LastMonthRevenue − LastMonthExpense`。
  （依据：`IssueBonds` 只记 `BondsOutstanding`、**不动现金**（`sovereign_bond.go:73-97`）；
  国库全部 6 处现金变动都在 `SettleTreasuryMonth` 窗口内。）
- ⚠ **若该恒等式在实跑中失败** ⇒ 说明存在第 7 处未声明的国库现金改动。**不得**为了让检查变绿而
  放宽恒等式；应定位该改动点并登记。

### 4.4 I4 资产负债口径契约

- 检查器**独立重算**（不调用 `p.NetWorth`）：
  `现金 + 养老金 + Σ AssetValue(asset, market) − Σ Loan.Balance`
- 与 `p.NetWorth(market)` **逐座逐月比对**，差值必须为 0。
- 本质是**口径契约护栏**：一旦有人改动 `NetWorth` 语义（如加入 `SavingsDeposit`），
  检查器立刻红，逼同步更新口径文档与所有消费点。
- 附加断言：`Loan.Balance >= 0`、`AssetValue >= 0`（不得出现负资产）。

### 4.5 I6 场景注入留痕

`ScenarioAppliedRecord`（`scenario.go:102`）当前字段：`ID / Kind / Magnitude / AppliedMonth / Note / At`。
**缺**《场景推演》§7.3 要求的 `target / duration / seed / snapshot_id` ⇒ **补齐 4 个字段**：

```go
Target        string `json:"target"`         // 作用范围（城区/行业/商品类目；空 = 全域）
DurationMonths int   `json:"duration_months"` // 持续月数
Seed          int64  `json:"seed"`           // 注入时的 run_seed
SnapshotID    string `json:"snapshot_id"`    // 关联的基线快照 id（可为空 = 无基线 run）
```

- **兼容**：新增字段一律**不带 `omitempty`**（缺省零值下发），旧前端忽略未知键即可（§130 纪律）。
- I6 判据：每条记录的 `Kind != ""` 且 `Magnitude ∈ [1,5]` 且 `AppliedMonth > 0` 且 `DurationMonths >= 1`
  且 `Seed != 0` ⇒ 通过。
- `Seed` 由房间层 `r.seed` 注入（`scenario.go` 的 `applyScenarioToWorld` 需拿到 seed；
  若该函数签名不含 seed，则由调用方在构造记录时补齐）。

### 4.6 I8 系统净流闭合

```
Σ 所有实体净流 == 0                                  （全账本闭合）
座位组净流 + 非座位组净流 == 0                       （分组闭合，等价式）
```

- 实现：`Ledger` 增 `EntityNets map[string]int64`（`Record` 内增量维护），
  或复用已有的 `EntityNet(entity)` 全扫实现（**性能**：I8 每月全扫 = 480 × 34k ≈ 16M 次，可接受；
  但若实测超预算，改增量）。
- **口径声明**（写入代码注释与本档）：**国库不走 Ledger**，故 I8 的「部门」集合 =
  `seat:* / bank / market / gov / firms / insurer / world / family / gov:treasury`。
  国库侧由 **I3** 单独守恒。两条不变量合起来覆盖全系统。

## 5. 引擎状态哈希（StateHash）

### 5.1 契约

```go
// ServerGo/game/virtual_city/statehash.go（新建）
// StateHash 返回引擎状态的 64 位 FNV-1a 摘要（16 位十六进制字符串）。
// 覆盖范围：玩家账目 / 市场 / 央行 / 国库 / 商品 / 劳动力 / 社会结构 / 产业链 / 集群 / 账本摘要。
// 排除范围：transcript / 事件文本 / 观测时间戳 / 任何 LLM 决策产物（决策缓存属 R0，另批）。
func (w *World) StateHash() string
```

### 5.2 纳入与排除

| 纳入（决定模拟状态） | 排除（不影响状态或不可复现） |
|---|---|
| `Month` / `Age` | `Transcripts` / `BotContexts` / `LastSenses` |
| 每座：现金 / 定期 / 养老金 / 信用分 / 精力·人脉·认知 / 失业月 / `Alive` / `Ending` / `BankruptCount` | `Events[].Text`（自由文本；`Type` 可纳入） |
| 每座资产：`Kind` / `Units` / `CostCNY` / `OpenMonth` / 派生的 rate·district·self_occupied | 任何 `time.Now()` 派生量 |
| 每座贷款：`ID` / `Kind` / `Principal` / `Balance` / `AnnualRate` / `MonthsLeft` | `NextMonthAt` 等墙钟字段 |
| `Market`：股指 / 金价 / 债息 / 房价指数 / 周期相位 | `LastMonthAtUnix` 等时间戳 |
| `CB`：M0 / M1 / M2 / 政策利率 / LPR | |
| `Treasury`：现金 / 国债余额 / 上月收入支出 | |
| `Goods`：CPI / 各类价格指数 | |
| `Labor`：失业率 / 就业率 / 营收 / 工资总额 | |
| `Society`：Gini / 三圈层人数 / 总财富 | |
| `SupplyChain` / `Clusters` 快照字段 | |
| **账本摘要** `Ledger.Digest`（`Record` 内增量 FNV） | |
| **账外摘要** `OffLedgerBook` 累计净流 | |

### 5.3 稳定性纪律（**必读**）

1. **禁止 `map` 迭代**：Go 的 map 迭代顺序随机。哈希 `Extra map[string]any` 时**只取派生的标量**
   （rate / district / self_occupied），**不得**遍历 map。
2. **浮点用 `math.Float64bits`** 取 8 字节，禁止 `fmt.Sprintf("%v")`（格式会随精度/平台漂移）。
3. **整数用定长小端字节**（`binary.LittleEndian.PutUint64`），禁止字符串拼接。
4. **切片顺序**：资产 / 贷款按稳定键排序（资产按 `Kind+district`，贷款按 `ID`）后再哈希。
5. **哈希算法固定 FNV-1a 64**（不用 `hash/maphash`——它按进程随机播种，跨进程不可比）。
6. `Ledger.Digest` 在 `Record` 内增量更新（与 `Entries` 同序），**不重算全表**。

### 5.4 用途

- **I5**：同 seed 双跑逐月比对（测试内）。
- **D9**：运行级采集的 `state_hash` 字段（《校准框架》§4.1）。
- **R0 地基**：批次 72+ 的决策重放缓存以本哈希为一致性判据。

## 6. 运行级采集与 D 指标

### 6.1 逐月审计快照

```go

type MonthlyAudit struct {

```

- `World.Audits []MonthlyAudit`（新字段，`engine.go` 的 `World` 结构体加；**惰性初始化，nil 安全**）。
- 写入点：`SettleMonth` 末尾（`settlement.go`），**在 `w.Month++` 之前**，与
  `predictionMonthStep`（`settlement.go:310`）同侧。
- **零 rand 消费**：检查器与哈希**不得**调用 `w.Rand`（否则会移动随机序列 ⇒ 存量对局回归偏移）。
  这是硬纪律：新增代码不得改变任何既有随机序列。

### 6.2 D 指标

| 指标 | 定义 | 来源 |
|---|---|---|
| **D2 货币扩张倍数** | `Σ 期末总资产 ÷ Σ 期初总现金` | 期初现金 = `Ledger` 的 `from=world` 注入总额；期末总资产 = `Σ (Cash + SavingsDeposit + PensionCNY + Σ AssetValue − Σ Loan.Balance)` |
| **D3 结局分布** | 自由 / 小康 / 温饱 / 破产 四类占比 | `FinalScore.Ending`（`settlement.go` 枚举：`winner`/`affluent`/`ordinary`/`indebted`/`bankrupt`）；**未终局时用当期 `p.Ending` 近似**（`Ending` 字段在 `FinalScores` 里赋值，未跑终局时为空 ⇒ 改用 `Alive` + 净值分档） |
| **D5 破产率** | `BankruptCount > 0 的座位 ÷ 总座位` | `p.BankruptCount` |
| **D6 收益率** | 各资产品类年化收益率 | `Asset` 按 `Kind` 归类（`stock_index`/`bond`/`gold`/`house:*`/`shop:*`）；用 `CostCNY` 与当前市值算持有期收益；**无持仓的品类不产出条目**（不补 0，避免污染均值） |
| **D9 状态哈希** | `StateHash()` | §5 |
| 辅助 | 失业率 / CPI / Gini / 满意度 / 总财富 / 存活座位 / 账外净额 | 既有字段直读（`Labor` / `Goods` / `Society`） |

> **D2 口径说明**：《校准框架》§2.2 定义为「周期末全体居民**总资产** ÷ 周期初全体**现金**」。
> 本批按字面实现（总资产含 `SavingsDeposit` 与 `PensionCNY`），并在报告里写明该口径，
> 因为它与央行 `MoneyMultiplier`（M2/基础货币）**不是同一个量**，两者不可混用。
