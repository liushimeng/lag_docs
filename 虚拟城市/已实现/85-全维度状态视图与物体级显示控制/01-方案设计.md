# 批次 85 · 全维度状态视图与物体级显示控制

> 日期：2026-11-05 ｜ 分支：`main`（§10.1）
> 起因：批次 84 把场景目录扩到 **1,203 条 / 13 个维度**，City-System 工具 11→17、
> WebGL-Show 显示原语 6→14。但**注入之后的观察侧没跟上**：用户注入「供水管道破裂」
> 再问「基础设施怎么样」，Agent 拿到的回答**根本不提正在发生的那件事**。
> 本批补上「**看得见自己做了什么**」的观察闭环，并把显示控制从**城区/图层粒度**
> 下沉到**物体粒度**。
>
> 权威衔接：批次 84《全维度事件体系与 Agent 双向对话》、批次 81《CitySystem-Agent
> 与系统对话》、批次 68《预测运行报告》、批次 80《真实世界事件自动注入引擎》。

---

## 1. 问题诊断（代码实证）

### 1.1 注入侧已扩容，观察侧没跟上

批次 84 的 `query_city_state` 已扩到 13 个 scope（`dispatch_ext.go:304-326`），实测：

| scope | 现状 | 问题 |
|-------|------|------|
| `infrastructure` / `public_health` / `transport` / `culture` / `daily` | ✅ 返回真实派生数据（产业链节点 / 公共服务 / 商品价格指数 / 教育质量 / 消费篮子） | **不提本维度的活动场景** |
| `environment` | ❌ `dispatch_ext.go:387-389` 恒返回「环境生态子系统未启用」 | 用户刚注入「物种入侵」，问环境却答「未启用」 |
| `security` | ❌ `dispatch_ext.go:390-395` 只给市场监管罚款（治安维度空） | 同上，刚注入「盗窃案件」却看不到 |

**根因**：新维度的经济后果已经落进既有旋钮（`Goods`/`Labor`/`Treasury`/`Election`），
但**没有一条「当前这个维度正在发生什么」的读出通道**。用户视角就是「我做了什么系统看不见」。

### 1.2 显示控制停在城区/图层粒度

批次 84 的 14 个显示原语，实测边界（`03-实施记录.md` §8）：

| 边界 | 位置 | 影响 |
|------|------|------|
| `focus_entity` 对**车辆实例**解析不到 | `cityEntityResolver.ts` 无车辆位置注册表 | 「把视角拉到那辆红色卡车」做不到 |
| `labels` 图层只覆盖**城区悬浮信息卡** | drei `<Html>` 门户不吃父级 `visible` | AgentHuman 名牌/发言气泡无法随图层隐藏 |
| `set_filter` 是**图层粒度**不是逐物体 | 引擎无逐物体材质调光入口 | 「只高亮所有医院」做不到 |

这三条都直接落在需求 2「控制虚拟城市各种**物体、物品、以及相关 3D 模型**的显示行为」上。

### 1.3 居民对话的令牌桶不能共享

批次 84 装配层为了让 `ask_agent → City-Human` 真的走 LLM，缓存了
per-(房间,座位) 的 City-Human Agent（`main.go::cityHumanAnswerer`）。但房间内的
真实居民 Agent 存在未导出的 `r.agents`，**没有句柄** ⇒ 缓存实例与游戏内实例
**各持一套令牌桶**（`03-实施记录.md` §8 第 13 条）。

后果：对话问答不计入房间 LLM 统计，且若配额按桶计，实际消耗是双份口径。

## 2. 目标与非目标

**本批做三件事**：

1. **维度状态视图**：13 个 scope 的 `query_city_state` **全部**返回实质信息，
   且**每个 scope 都带上本维度的活动场景与相关世界事件**（观察闭环）。
2. **物体级显示控制**：`focus_entity` 支持车辆；`labels` 图层补全；
   `set_filter` 下沉到「类别 → 实例」粒度。
3. **居民对话令牌桶共享**：`game/virtual_city` 导出座位 Agent 句柄，装配层
   切到共享桶；旧 `Register` 迁移 `RegisterWith` 补能力描述。

**非目标**（本批刻意不做）：

- **不新增 `World` 持久化状态字段** —— 维度状态视图一律从**既有状态 + 活动场景 +
  世界事件**派生（零 RNG、零回归）。
- **不建环境/治安引擎子系统** —— 那是独立批次（要新 World 状态 + 月结逻辑 +
  数值标定），本批只把「维度正在发生什么」如实读出。
- **不做碳排放核算 / 园区选址 / 车辆行为 AI** —— 对账表 §15 后续候选，另立批次。
- **不修 `TestMCSmoke` 存量门禁** —— 经济平衡欠账属独立批次。

## 3. 后端设计

### 3.1 维度状态视图（City-System · 观察闭环）

#### 3.1.1 新增只读 API（`game/virtual_city/room_system_agent.go` 或新文件）

```go
// SystemDimensionStatus 返回一个维度的「正在发生什么」视图(只读、持锁、不回调房间)。
// dim 取 13 个分组名(与 ScenarioGroup* 常量一致);未知维度返回空视图。
func (r *VirtualCityRoom) SystemDimensionStatus(dim string) DimensionStatusView

// DimensionStatusView 维度状态视图。
type DimensionStatusView struct {
    Group      string                   // 维度名
    ActiveScenarios []ScenarioBrief     // 本维度进行中的场景(新→旧)
    RecentEvents    []WorldEventBrief   // 本维度相关世界事件(新→旧,≤5)
}

// ScenarioBrief 场景摘要(只含读出需要的字段)。
type ScenarioBrief struct {
    ID, Kind, Name string
    Magnitude      int
    RemainingMonths int
    Target         string
    AppliedMonth   int
}

// WorldEventBrief 世界事件摘要。
type WorldEventBrief struct {
    Title, Kind, Source string
    ObservedAt          int64
    Injected            bool
}
```

**判定「本维度」**：`scenarioDefFor(kind).spec.Group == dim`（既有 kind→group 映射，
L1/L2/L3 全覆盖）。世界事件按 `WorldEventRecord.Kind` / `ScenarioKind` 的分组归集；
归不到具体维度的事件不计入（宁缺勿滥，不编造）。

**纪律**：只读、持 `r.mu`、**禁止回调房间**（§92a）、nil 安全、返回副本。

#### 3.1.2 `query_city_state` 全 13 scope 补观察闭环

每个 scope 的输出**末尾追加一段**（非空时才加）：

```
【本维度进行中】
- 供水管道破裂 L3(剩 4 月,作用范围 全域,注入于 M7)
【相关世界事件】
- 东财行情:沪指收涨 1.2%(已注入 / 未注入)
```

- 5 个已有实质数据的 scope：追加上述两段（**既有内容一字不动**，零回归）。
- `environment` / `security`：**重写**为「活动场景 + 世界事件 + 可得的最接近指标」，
  **删除**「子系统未启用」这种空答复。可得指标例如：
  - `environment` → 粮食/食品类商品价格指数（生态影响经供给传导）、旅游/文娱消费
  - `security` → 市场监管罚款（保留）、居民现金损失（`CashDamageFrac` 类场景）、
    社会信任相关场景计数
  - **没有数据就说「暂无该维度指标」**，但**活动场景与世界事件必须给**。
- 两段都为空时输出「当前该维度无进行中场景、无相关事件」（明确而非空白）。

#### 3.1.3 新增工具或扩既有？

**不新增工具** —— 复用 `query_city_state`（13 scope 已枚举）。理由：17 工具是
批次 84 刚定的稳定面，再加工具会推高模型选择成本；观察闭环属于「查询城市状态」
的自然语义。

**但 `query_world_events` 扩一个可选参数** `dimension`（空 = 全部），
按维度过滤世界事件 —— 让「刚才那个地震后续怎么样了」可直接查。

### 3.2 物体级显示控制（City-WebGL-Show + 前端）

#### 3.2.1 车辆实例位置注册表

前端新增 `components/virtualCity/cityVehicleRegistry.ts`：

```ts
// 登记/注销车辆实例的世界坐标(由 Vehicle 组件每帧/每 N 帧上报)。
export const vehicleRegistry = {
  register(id: string, pos: {x:number; z:number}, kind?: string): void,
  unregister(id: string): void,
  lookup(id: string): {x:number; z:number} | null,
  nearest(x: number, z: number): string | null,
  ids(): string[],
};
```

- `cityEntityResolver.ts` 的 `focus_entity` 解析链补一级：`vehicle:<id>` → 注册表。
- 命名约定与既有 `resident:seat:<n>` / `building:<区>:<序>` 并列，**不改既有解析顺序**
  （零回归）。
- 未命中仍回 `entity_not_found`（**不静默、不瞎聚**）。

#### 3.2.2 `labels` 图层补全

drei `<Html>` 门户不吃父级 `visible` —— 解法是把「是否渲染名牌/气泡」作为
**受控渲染条件**（不渲染 = 不进 DOM），由 `cityShowStore.layers.labels` 驱动：

- `AgentHuman` 的名牌与发言气泡、`CityAnnotationLabel`、城区悬浮信息卡
  **统一受 `labels` 图层开关**。
- 与既有「图层注册表」口径一致（批次 84 的 7 图层）。
- ⚠️ **不得**用 `opacity: 0` / `display: none` 糊弄（§26 反模式）—— 就是不渲染。

#### 3.2.3 `set_filter` 下沉到「类别 → 实例」粒度

引擎若无逐物体材质调光入口，**不强行造**；改为扩展 filter 的**匹配口径**：

- `category` 支持更细的匹配：图层名（既有）/ 物件类别（如 `hospital`/`school`/
  `park`，取自批次 28 的 `objectInfo` 物件注册表类别）/ 车辆类型。
- `mode=highlight`：命中类别的实例**保留原色**，未命中**降为低饱和**（用既有
  材质的 `color` 乘子，**不动几何、不改 shader**）。
- 若现有材质系统无法安全做到逐实例调色 ⇒ **退化为「按类别显隐」**并在
  `cityShowAdapter` 的 notice 里明说「当前实现为类别显隐」，**不静默吞**。

### 3.3 居民对话令牌桶共享

#### 3.3.1 `game/virtual_city` 导出座位 Agent 句柄（**唯一**对该包的改动）

```go
// AgentForSeat 返回座位上的 City-Human Agent(未启动/越位返回 nil)。
// 只读取句柄,不改任何游戏状态;供装配层共享 LLM 令牌桶与调用钩子。
func (r *VirtualCityRoom) AgentForSeat(seat int) *vcplayer.Agent
```

- **只读**、持 `r.mu`、返回既有实例指针（不新建、不改生命周期）。
- 越界 / 未启动 / 非居民返回 `nil`。

#### 3.3.2 装配层切共享桶

`main.go::cityHumanAnswerer` 的取 Agent 顺序改为：

1. `room.AgentForSeat(seat)` —— 命中即用**游戏内实例**（与月度决策共用令牌桶 +
   共用 `BindLLMCallHook`，对话消耗计入房间 LLM 统计）；
2. 未命中再回退既有缓存实例（**保留兜底**，不影响已有行为）。

**零回归**：`AgentForSeat` 返回 nil 时行为与批次 84 完全一致。

#### 3.3.3 旧 `Register` 迁移 `RegisterWith`（补能力描述）

批次 84 的 `hub.Describe` 对旧 `Register` 注册的 Agent 显示「未登记描述」
（§8 第 10 条）。本批把剩余旧调用迁到 `RegisterWith` / `RegisterRoomWith`，
让 `list_agents` 对**全部** Agent 给出能力描述。

**不做**：不改 `Register` 的语义（向后兼容）。

### 7.1 编译与单测

```bash
cd ServerGo && go build -o LsmAgentGame main.go && go test ./...
cd ClientWeb && npx tsc --noEmit && npm run build
```

### 7.2 联调（integration-tester）

1. 注入「供水管道破裂」→ 问「基础设施怎么样」⇒ 回答**含该场景**（名称/强度/剩余月）。
2. 注入「物种入侵」→ 问「环境生态怎么样」⇒ **不再答「未启用」**，含活动场景。
3. 注入「盗窃案件」→ 问「公共安全怎么样」⇒ 同上。
4. 注入后触发世界事件 → 问「刚才的地震后续」⇒ `query_world_events(dimension=自然灾害)` 命中。
5. `focus_entity` 用 `vehicle:<id>` ⇒ 视角拉到该车；无效 id ⇒ `entity_not_found` 提示。
6. 关闭 `labels` 图层 ⇒ 名牌/气泡消失；开启 ⇒ 恢复。
7. `ask_agent → City-Human` ⇒ 对话消耗**计入房间 LLM 统计**（共享桶生效）。
8. 13 维度 × 1 场景注入 ⇒ 13 个 scope 全部有实质回答。

## 8. 风险与回滚

| 风险 | 缓解 | 回滚 |
|------|------|------|
| 维度状态视图引入 World 读放大 | 持锁只读、复用既有 `scenarioDefFor` map 索引 | 删追加段即可 |
| `AgentForSeat` 被误用于写操作 | 签名只返回指针、注释明示只读；单测断言不改状态 | 删该方法 |
| `set_filter` 逐实例调色破坏材质 | 优先退化为类别显隐并**明示**，不强行造 shader | 只回退 filter 分支 |
| 车辆上报每帧 setState 卡顿 | **节流**（每 N 帧 / 位置变化阈值） | 关闭上报 |
| labels 图层改「不渲染」影响既有视觉 | 单测断言默认开启时 DOM 不变 | 默认值保持 true |
