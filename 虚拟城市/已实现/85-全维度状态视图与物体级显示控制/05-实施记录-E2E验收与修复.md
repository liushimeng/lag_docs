## 3. E2E 挖出的 3 个真缺陷（已修）

### 3.1 F1 —— 6 个维度没有 `query_city_state` scope ⇒ 观察闭环失效（最要紧）

**现象**：13 维度各注入 1 场景后问「X怎么样」——
- 7 个**有专属 scope** 的维度（基础设施/公共卫生/环境生态/公共安全/交通物流/文化教育/民生日常）⇒ **正确**答出活动场景；
- **6 个没有专属 scope** 的维度（市场与经济/政策与治理/社会与舆情/自然灾害/未知灾难/科技与新文明）⇒ 模型**不调 `query_city_state`**，直接误答「进行中场景：无」——**刚注入的场景看不见**。

**根因**：scope 枚举只映射到 7 个维度组，6 个原始维度组无 scope 可调，模型面对「自然灾害怎么样」找不到匹配值就不调工具。

**修复**：scope 枚举 **6 → 19**（6 既有 + **13 个中文维度名**，与 `virtual_city.ScenarioGroup*` 常量**同值**），
模型可直接把 `list_scenarios` 维度索引里的组名当 scope 传。批次 84 的 7 个英文旧键经
`canonicalCityStateScope` 别名归一**继续接受**（不在枚举，零回归）。
6 个新维度 scope 的实质内容**全部来自真实引擎字段**（市场与经济 = CPI/股指/黄金/房价；
政策与治理 = 国库/利率/信贷/选举；社会与舆情 = 基尼/总财富/圈层；自然灾害 = 食品价格 + 产业链），
`未知灾难`/`科技与新文明` 引擎无专属子系统 ⇒ 如实「暂无该维度专属指标」+ 活动场景计数，**绝不编造**。

### 3.2 C7 —— 「取消筛选」不可达

**现象**：`apply_display{category:""}` 被「失败:至少给出一个显示参数」拒掉。
**根因**：`buildDisplayRequest` 把**空 `category` 当作「没给参数」**丢弃。
**契约**：`set_filter` 的 `category` 为空 = **取消筛选**（前端 `cityShowAdapter.ts` 已实现）。

**修复**：`buildDisplayRequest` 改 3 值返回 `(req, cancelFilter, err)` ——
**category 键存在**（Go 逗号 ok 形式）即「已给出」，空串/纯空白/JSON null ⇒ `cancelFilter=true`；
**没传键**才是缺参。产出走 **`citysystem` 侧直产指令 + `emitCommands`**，不经总线。

> ⚠️ **契约陷阱（值得记住）**：`displayRequest.category` 带 `omitempty`，空值在
> **总线 JSON 往返时会被静默丢掉**，无法区分「没给」与「给了空」。
> `citywebgl/structured.go` 对空 category 也是静默丢弃。
> ⇒ 凡是「空值有语义」的字段，**镜像结构的 `omitempty` 就是陷阱**；
> 改一侧必须双侧同步（§29.10 已注明），必要时绕开总线直产指令。

### 3.3 C2 —— `focus_entity` 无效 id 无提示（**四个机制叠加**）

**现象**：`focus_entity{entity_id:"vehicle:nope-b85"}` 下发后 DOM 无 `entity_not_found` 提示。
**实证复现**：真实链路单测证明 `applyDisplayCommand` 必产 notice；确定性帧注入（绕开模型、
对页面真实 WebSocket 派发 MessageEvent）复现 ⇒ **SC 帧送达即出条**「未找到车辆：nope-b85」。
E2E 的「无 notice 无报错」由**四个机制叠加**：

| # | 机制 | 证据 | 修复 |
|---|------|------|------|
| 1 | **关窗期间 notice 永不渲染** | `phase2c.log` 实证 `open dialog failed: Locator.click: Timeout` —— C2/C5/C6 全程对话窗**关闭**，`SystemDialogPanel` 早退只渲染标注 | notice 在关窗/最小化时**转入消息流留痕**（`role:'notice'` 行，复用既有样式，零新增 CSS/i18n） |
| 2 | **页面 WS 重连后不重新入房** | 90s 内两次注入点返回 `no-open-socket`；`VirtualCityGamePage` 的 join effect **只在 mount 发一次** `game.spectate`，重连后对房间广播**永久失聪** | hook 级 `onOpen` 补发 `game.spectate`/`game.join`（按 `mySeat` 分流，首连跳过防双发） |
| 3 | **SE 通道是死代码** | `system_event{kind:show_command}` 的 `data` 是**扁平指令**，而 `d_command` 只认嵌套 `data.command` ⇒ 双帧设计实际只剩单通道，**丢一条帧即丢指令** | `d_command` **双形状兼容**（嵌套 + 扁平），SE 通道复活，双帧真正互为兜底 |
| 4 | **模型行为不稳定** | 工具描述写「entity_id 严禁臆造」，模型有时直接拒绝调用（`tools=[]`） | （服务端线决策）E2E 应改用「上下文出现过但已失效」的 id |

**附加加固**：去重收窄为「**首条必达、只吞邻近重复**」（2s 窗口 + 128 容量）——
用户重试/模型重调不再被 LRU 永久吞掉；回调抛错 `forgetShowCommand` 撤账让孪生帧重试；
`onShowCommand` 加 try/catch + `reportGlobalError`（§7.1 绝不静默）。

## 5. 已知边界（新增登记）

| # | 边界 | 归属 |
|---|------|------|
| 1 | **页面级重连不入房**的另一半在 `VirtualCityGamePage` 的 join effect（mount-only）；hook 级补发只覆盖系统对话链路 | 建议页面 owner 在 `useVirtualCity`/join effect 增 `onOpen` 重入房，覆盖全部 `game.*` 帧 |
| 2 | `displayRequest`/`DisplayCommand` 镜像结构的 `omitempty` 会让**空值有语义**的字段静默丢失 | 凡空值有语义的字段须绕开总线直产指令，或双侧同步去 `omitempty` |

| 5 | `scope=all` 输出零变更；6 个新维度内容经各自 scope 查，未追加进 `all` | 设计取舍 |
| 6 | 社会结构指标（基尼/圈层）首月月结后才可得 | 如实只给可得项 |
| 7 | **外部无法强制注入 show_command** —— `game_service.go` 的客户端帧 switch 无 show_command 注入口，前端无 debug 钩子 ⇒ 显示指令只能经 LLM 产生，E2E 无法绕开模型直驱 | **测试开口缺失**：建议后续加「测试专用注入帧」或「提示词白名单」，否则 `entity_not_found` 等负向分支只能靠单测覆盖 |
| 8 | `labels` 图层**恢复有约 4s 软渲染延迟**（关闭即时、重开 6→6 需 t+4s） | E2E 断言 settle 必须 ≥ 4s，3.5s 会误判（本轮初判 FAIL 即此因） |

## 7. 教训（写给后续批次）

1. **单元测试全绿 ≠ 功能可用** —— 本批 3 个真缺陷全部是活体验收抓到的：
   F1 是「模型不调工具」（单测只测工具本身）、C7 是「参数存在性判据」（单测用了非空值）、
   C2 是「跨层送达 + 渲染时机」（单测 mock 了 `entityApi`）。
2. **测试脚本的判据要先对契约** —— 6 条 FAIL 里 4 条是判据问题（选错类别、等错指令、
   把 35057 当 35055、要求模型必须撞枚举）。**判 FAIL 前先读实现**。
3. **UI 类验收必须先确认目标元素在场** —— phase2c 因 `Locator.click` 超时导致对话窗全程关闭，
   三条 notice 用例集体假阴性。**断言前先 assert 容器存在**。
4. **`omitempty` 是「空值有语义」字段的陷阱** —— 镜像结构跨包 JSON 往返会静默丢空值。
