## 2. 现状分析（实施前代码事实）

### 2.1 工具层：47 个定义、三处散落

| 文件 | 数量 | 内容 |
|---|---|---|
| `vcplayer/tools.go` | 31 | P0 基础 18 + P1 央行/银行 5 + 明斯基/提前还款 2 + P1-2 经济循环 3 + P1-4 保险 3 |
| `vcplayer/tools_trade.go` | 12 | P2 挂牌/议价/借贷/担保/拍卖/信息 |
| `vcplayer/tools_sense.go` | 4 | see / hear / smell / move |

47 个工具全部平铺进每次 LLM 请求的 `tools[]`（`BuildTools()`），代价：
- **token 开销**：47 段 name+description+schema ≈ 6–8 KB/请求，全部月度决策都要背；
- **选择精度**：`take_loan` vs `apply_loan_with_credit`、`repay_loan` vs `early_repay` vs `repay_p2p_loan`
  这类近义工具 LLM 常选错；`move_district` 自批次 12 起就是 `move` 的兼容别名（tools.go 注释「下个大版本删除」）；
- **重复语义**：`buy_asset`/`sell_asset`/`buy_house` 同属资产交易；`deposit_savings`/`withdraw_savings` 同一账户两方向；
  4 个 `query_*` 全是无副作用查询。

**引擎侧 `ToolRunner` 接口 39 方法不动** —— 收敛只发生在 Agent 侧 wire 定义 + 派发层，
dispatch 把（工具, op）映射回原接口方法，`game/virtual_city` 引擎零改动、经济语义零漂移。

### 2.2 座位居民的三层断裂（批次 34 §2.1 遗留）

| 层 | 载体 | 3D 呈现 | 位置同步 | 冒泡 |
|---|---|---|---|---|
| 焦点层（座位居民 ≤12，LLM 决策） | `Player` + `vcplayer.Agent` | **圆柱 token**（AgentToken，职业色 + 头像 sprite） | ❌ 按「城区内环形落位」摆，不看 `LocalPos` | ✅ 仅 speak（chat.message → speechBubbles） |
| 背景层（1 万居民） | `city.Backdrop` | ✅ 批次 34 `char_*.glb` 真实行人 | ✅ crowd manifest（确定性布点） | 部分（city_voice 锚市政厅，不锚本人） |
| 展示层 | PedestrianV3 | — | — | — |

具体缺口：
1. **AgentToken 不用 `LocalPos`**：`VirtualCityCityMap.tsx::tokenLayout` 只按 district 聚合 +
   `districtSeatOffset` 环形摆位 —— Agent 调 `move` 后 `p.LocalPos` 变了，地图上圆柱不动。
2. **bot 动作不广播 game.state**：`agent_runner.go::apply`（848 行）成功后只 `hooks.OnEvent`
   （game.event 文本）；**人类动作路径**（ws `handleVirtualCityAction`）则 `broadcastVirtualCityState`。
   ⇒ bot 的 `local_pos`/`district` 变更要等下一次月结状态广播才可见。
3. **`players[]` 不带位置**：`PlayerJSON` 无 `local_pos`（只在 `my.local_pos` 本人 + `bot_contexts[].local_pos`
   观战可见）—— 3D 同步需要全座位可见的位置字段。
4. **动作无气泡**：`game.event`（type=action/move, seat, text）已经实时广播且进了前端 `eventFeed`，
   但没有任何组件把它渲染到人物头顶 —— 数据已通，只缺最后一跳。

### 2.3 已有可复用资产（本批次零新建）

- **8 个原型 GLB**：`ClientWeb/src/assets/models/characters/char_{business,casual,worker,elder,student,service,formal,parent}.glb`

## 3. R1 · 工具收敛 47 → 21

### 3.1 收敛原则

1. **同一引擎系统 → 一个工具 + `op` 参数**（挂单簿/银行账户/保单/副业…）；
2. **纯查询类合并**（4 个 `query_*` → `query_finance(scope)`）；
3. **兼容别名删除**（`move_district` —— 批次 12 遗留，dispatch 分支一并删）；
4. **感知四件套 `see`/`hear`/`smell`/`move` 与 `speak`/`check_state`/`submit_month` 原样保留**
   （用户硬性要求 + 月度循环骨架）；
5. **`ToolRunner` 接口不动**：dispatch 层做（工具,op）→ 接口方法映射，引擎零改动。

### 3.2 新工具表（21 个）

**感知与基础（7，全部原样保留）**

| 工具 | 参数 | 说明 |
|---|---|---|
| `see` | — | 视觉 ≈500m（每月 ≤2，不耗预算） |
| `hear` | — | 听觉 ≈100m（每月 ≤2，不耗预算） |
| `smell` | — | 嗅觉 ≈50m（每月 ≤2，不耗预算） |
| `move` | destination?, mode | 区内 walk/run；跨区 bus/metro/taxi（耗预算） |

### 3.3 预算语义的接线方式（§130 防丢）

旧 `isBudgetAction(name)` 按工具名判预算，合并后同名工具不同 op 预算不同 ⇒
`dispatchToolResult` 增 **`Budget bool`** 字段，由 dispatch 层按（工具, op）置位；
`run.go` 计数改用 `res.Budget`。语义逐条对齐旧表（不耗预算的例外仅：
check_state / submit_month / see / hear / smell / savings 全部 / query_finance 全部 /
bank_loan.probe / insurance.status / market_listing.view / answer_survey —— 与旧 47 工具
`isBudgetAction` 例外表 {check_state, submit_month, view_listings} + 各自描述文案完全一致）。
speak 计数保持旧语义（既占动作计数又有 2 次/月独立限额）。

### 3.4 prompt 同步

`prompt.go` §4/§5/§6/§7 段与 `UserPrompt`（副业小节、经济环境段、收尾句）、
`TradeStrategyHint`（引用 view_listings/create_loan_listing/sell_info/add_guarantor/list_asset）
全部改为新工具名。**不改任何经济数值与规则文案**。

### 3.5 兼容性

- 同月决策中途部署：旧名 tool_use 会收到「未知工具」错误回喂，LLM 下一轮自愈；
  服务重启即新开局，无持久化影响。
- `ToolNames()`/`TradeToolNames()` 与单测断言同步改 21；`agent_runner.go::apply` 的
  `vcplayer.ToolMoveDistrict` 引用改为仅 `vcplayer.ToolMove`。

## 4. R2 · 座位居民实体化（3D 人物 + 位置同步）

### 4.1 协议增量（`game.state.players[]`）

`PlayerJSON` 增两字段（全座位可见；位置/外观是公开信息，与 `my.*` 财务不对称无关）：

```go
// 区内归一化坐标 [0,1]²（与 my.local_pos / bot_contexts[].local_pos 同源）。
LocalPos []float64              `json:"local_pos"`
// 3D 人物外观投影（批次 34 crowd 同款推导；nil = 未知 → 前端兜底 char_casual）。
Avatar   *AvatarJSON            `json:"avatar,omitempty"`
```

```go
// AvatarJSON — 座位居民 3D 人物外观（复用批次 34 原型体系）。
type AvatarJSON struct {
    Archetype string `json:"archetype"` // char_business|...（city.ArchetypeFor 推导）
    Gender    string `json:"gender"`    // m|f|u
    Age       int    `json:"age"`       // 开局年龄（原型判据用，整局稳定）
    Domain    int    `json:"domain"`    // 0..25 L1 行业域（-1 未知）
    Wealth    int    `json:"wealth"`    // 0..3 财富档
}
```

**推导口径**（与 crowd 完全同源，保证座位居民与背景居民观感连续）：
- `Archetype = city.ArchetypeFor(StartAge, domainIdx, WealthTierFor(Salary, Savings), Gender, Employment, ChildrenCount)`
  —— 用**开局卡面**（Salary/Savings/StartAge）而非运行时净资产 ⇒ 原型整局稳定不闪变；
- 发卡时把 L1 域名存进 `Player.Domain`（`buildCardPoolLocked` 已有 `DomainCard.Domain`，
  顺带存 `cardPoolDomains`，`drawCardLocked` 随卡带出）；
- `city.domainIndex` 为小写私有 —— 在 city 包补导出 `DomainIndexOf(name) int`。

### 4.2 bot 动作后实时广播（打破「等月结才见」）

`agent_runner.go::apply` 成功路径在 `hooks.OnEvent` 之后补一行 `hooks.OnState(roomID)`
（锁外）—— 与人类动作路径（ws 层 broadcastVirtualCityState）对齐。
频度评估：≤12 bot × ≤3 动作/月，month_ms 默认 60s ⇒ ≤0.6 次/秒全量状态广播，
与既有 see/hear/smell 各自触发的 OnState 同量级，无性能风险。

### 4.3 前端：AgentToken → 真人 3D 人物

新组件 `AgentHuman.tsx` **替换** map 中的 AgentToken 渲染（同名导出保持接线点不变亦可，
本批次直接替换并删除旧圆柱渲染分支）：

| 项 | 实现 |
|---|---|
| 身体 | `modelUrl('characters', archetype)` GLB + 材质槽换色（复用 PedestrianV3 的克隆/换色/dispose 套路，appearance 由 `crowdFormula.appearanceFor` 从 avatar 字段推导） |
| 站位 | `districtCenter(district) + (local_pos − 0.5) × 5.6`（城区底板 8×8 内缩 ±2.8，与人行道带同量级） |
| 移动 | 目标点变化 → 以 `clamp(dist/8s, 0.12, 1.8)` 世界单位/s 步行前往（区内=步行速，跨区=交通工具速），行走时 mixer timeScale 1，到位后 0.2（原地轻微晃动即「等公交」观感）；朝向 = 行进方向 |
| 保留 | 名牌 Html（座位/昵称/职业 emoji/状态/净资产/🤖）、isMe 金环、a11y、objectInfo 悬浮卡 |
| 删除 | 圆柱体 + 头像 Billboard sprite + emoji 兜底（3D 人物本身取代） |
| 性能 | ≤12 个人物 GLB clone（各自 1 mixer）；DC 净变化 ≈ +(人形 mesh) −(圆柱+sprite) ≈ +12~24，默认视角预算内可承受（批次 28 A5 行人不实例化口径不变） |

降级链与批次 34 一致：GLB 缺失/`disable-blender-models=1` → 程序化 6-mesh 行人几何
（复用 PedestrianV3 几何常量），avatar 缺失 → `char_casual` + 职业色。

### 4.4 与 crowd 的关系

座位居民（≤12）与背景行人（≤110）**并存不互斥**：前者是权威 LLM 居民（有 LocalPos），
后者是背景人流（确定性布点）。同底板落点域不同（±2.8 vs 采样全域），碰撞概率低且无
机制意义，不做避让。

## 5. R3 · 实时冒泡

### 5.1 座位居民动作气泡（数据已通，补最后一跳）

- **数据源**：`store.eventFeed` 中 `seat === 本人座位` 且 `type ∈ {action, move, sense}` 的
  最新一条，TTL 8s（speak 气泡 12s 在其上方，两者可并存）。
- **后端小增量**：See/Hear/Smell 成功后广播一条 `type="sense"` 的 game.event
  （text 即现有摘要「环顾金融CBD:看见 5 人…」）——**不入 `World.Events`**（不污染
  月度事件流与 see 感知回读），仅广播。`type="sense"` 不参与前端
  `myActionsUsed`（该选择器只数 action/move）计数，零干扰。
- **图标映射**：action→💭、move→🚶、sense→👀（hear/smell 文案自带语境）。

### 5.2 speak 气泡（已有，保持）

批次 23 链路不动：`chat.message(from_role=bot)` → `useVirtualCitySpeech` →
`speechBubbles[seat]` → 人物头顶 12s。本批仅把渲染从圆柱顶挪到 3D 人物头顶。

### 5.3 市民之声锚定到本人（CityVoiceBubbleLayer 升级）

现状：city_voice 气泡恒挂市政厅上空。本批：
1. 新增 `crowdRegistry.ts`：`Map<residentIndex, {x,z}>` 模块级注册表；
   `PedestrianV3` 接受可选 `trackIndex` prop，useFrame 内同步自身位置（纯 Map.set，零分配）；
2. `CityVoiceBubbleLayer` 拆出 `名字:正文` 后，在 `gameState.city.crowd.entries` 里按
   `name` 匹配上街居民 → 命中则气泡锚定该行人当前位置（头顶 y≈2.0），
   未命中/户内 → 回落市政厅锚点（现状不变）。

### 5.4 样式

复用 `.virtualCity-speech-bubble`，动作气泡加 `--action` 变体（左侧 2px 竖条 + 💭 图标，
背景/描边对比度 ≥ 4.5:1，§26 合规）；不新增 keyframes（reduced-motion 天然满足）。
