## 1. §27.0-1 真实形态调研

真实天空按云型分三族，形态与配色都不同：

| 云型 | 真实形态 | 视觉特征 | 本批落笔 |
|---|---|---|---|
| 积云 cumulus | 底部受凝结高度限制而**平坦**，顶部对流隆起（cauliflower 分瓣） | 顶部受光亮白 RGB(255,255,255)，底部背光冷灰 RGB(171,178,188)；边缘柔和、内部有自阴影 | `generate_cumulus()`：**各向异性高斯 metaball 求和**造形 + 底部平切 + 垂直明度梯度 + 内部自阴影 |
| 层云 stratus | 大片均匀灰层，无立体感、无 cauliflower 结构 | RGB(163,168,174)~(196,199,203)，明度范围窄、顶略亮底略暗 | `generate_stratus()`：强横向拉伸低频场（cw≪ch）+ 窄动态范围 |
| 卷云 cirrus | 高空冰晶丝缕，**沿风向横向拉长** | RGB(232,236,242) 均匀冷白（各向同性散射，无垂直梯度），薄、半透明 | `generate_cirrus()`：高频场沿 **X 轴**压扁后横向 pad |

**昼夜云色**（`cloudTintFor()`，调制 `material.color` 而非改贴图）：

| 时段 | 云色 | 依据 |
|---|---|---|
| 正午 | `#f2f6fb` 近白微冷 | 云自身反照率最高 |
| 午后 | `#eef2f7` 略暖白 | — |
| 日出/日落前后 | `#e8955c` → `#b45f45` 橙红 | 低角度太阳的**米氏前向散射**，真实云在日落时整片泛橙 |

| 深夜 | `#2a3040` 暗蓝，亮度压到 0.16 | 真实夜空里云几乎不可见，只比背景略亮 |

## 3. 实施中推翻的三处（**本批最有价值的部分**）

### 3.1 生成器首版：积云是「电视雪花」而非云团

用 fbm 噪声直接阈值化造云形，出来的贴图是高频噪点（判读时像电视雪花）。
**根因**：云是**大尺度团块 + 边缘破碎**，不是高频细节。
**修法**：积云改用 **metaball（各向异性高斯团块求和）** 造形，
中频扰动只用于「打碎边缘」，形状本身来自团块布局。

### 3.2 生成器第二版：卷云被拉成**竖条**

`_grid(w, h, cw, ch)` 里 `cw=5, ch=9` 写成了「x 频率高」，
结果每列独立变化 ⇒ 输出竖条纹。**卷云是横向丝缕**。
连续踩了两次方向坑（卷云压 Y、层云 `cw=14,ch=3`），
根因是**「格数多 = 变化快 = 条纹沿该轴」**这个换算关系两次都想反了。
正解：`cw ≪ ch` ⇒ 每格横跨多列、纵向只占少数行 ⇒ 横向条纹。

### 3.3 半透明贴图的 RGB 不能乘 shape mask

首版把云形 mask 同时乘进 RGB 和 alpha，结果云在场景里渲成**灰团**而不是白云。
**半透明贴图的形状由 alpha 承担，RGB 必须是物体固有色**。
这条对任何「贴图自带 alpha 的半透明精灵」都成立。

## 4. 渲染侧推翻的三处（批次 16 的尺度被实测证伪）

### 4.1 云是「道具尺度」，不是「天空尺度」 ★本批核心

| 项 | 批次 16 旧值 | 真实/本批终值 | 差距 |
|---|---|---|---|
| 单片云宽 | 2.2~3.6 世界单位 = **22~36 m** | 400~1100 m（40~110 单位） | **~25×** |
| 街景抬头张角 | arctan(30/680) ≈ **2.5°** | 12°~20° | ~7× |

**CDP 实测证据**（不是推断）：
- 投影审计：41/46 个云网格**确实在画面内**，中位数占屏高 **9.5%**（尺度没问题）
- 但正午蓝天背景 `[85,137,196]`，云区混色后 `[108,152,203]` —— **只亮 15/255**
- 「亮于背景 +22」的像素占比 **0.00%**
- 把 opacity 拉到完全不透明（×6.3）也只升到 **1.44%**
  ⇒ **问题不在透明度，在张角**

### 4.2 云只铺在城市正上方一小片 ⇒ 只能近乎天顶看到 ★第二核心

修正 4.1 后云确实变大了，但仍然**几乎看不见**。逐层排查（每一层都排除了一个假因）：

| 排查动作 | 结果 | 排除了什么 |
|---|---|---|
| 投影审计（世界坐标 → NDC） | 41/46 在画面内，中位占屏高 9.5% | 不是「飞到画面外」 |
| 材质读数 | `map=256x128`、`opacity=0.644`、`color` 正确 | 不是贴图缺失 / 透明度 |
| 近拍单朵云（相机贴到云前 55 单位） | **云形态完全正确**（底平顶团块、alpha 柔边、夜色染成 `#3d3a44`） | 不是贴图 / 接线 / 昼夜着色 |
| `all` vs `noClouds` 逐像素差分 | 平均差 **0.11**，`>10` 的差异像素 **0.00%** | 不是「有贡献但不明显」 |
| 强制纯红不透明 + 关 alphaTest + 摘贴图 | **仍 0 像素** | 不是 alphaTest 逐像素 discard |
| 关视锥剔除 `frustumCulled=false` | **仍 0 像素** | 不是背面/剔除 |
| 同一场景塞一个裸 mesh（同位置） | **正常显示**（0.48% 像素差） | 不是渲染管线 / readPixels 失效 |

根因：**旧布点半径只有 25~70**（城市正上方一小片），
于是任何街景位置看云的仰角都是 `atan(190/70) ≈ 70°`（近乎天顶）；
而 drei `<Billboard>` 的朝向由**应用相机**决定、不是诊断相机 ——
从下方看过去就是**背面**，`side: FrontSide` 直接背面剔除 ⇒ 云「消失」。

> 这个症状极具迷惑性：网格在视锥内、尺寸正确、贴图正常、连强制不透明都渲染 0 像素，
> 而同场景新 mesh 正常 —— 差点误判成渲染管线坏了、或者去调透明度。
> **真正该问的是「这个东西在物理上应该出现在哪个方向」**，而不是「它为什么没画出来」。

**修法**：水平铺开半径 25~70 → **30~330**。真实云层一直延伸到地平线；
铺开后远云仰角降到 `atan(190/300) ≈ 32°`，正是人抬头能看到的自然云高。
上界 330 同时与天穹半径 500（`sqrt(330²+200²)≈386` < 500）及相机 `far=800` 相容。

### 4.3 云层顶低于相机上限（批次 32 抬高了相机却没回头看云）

批次 16 的注释写「相机最高点 ≈45」，那是 `OrbitControls(maxDistance=80, maxPolar=1.2)`
时代的上界。批次 32 引入自由视角后 `FREE_VIEW_BOUNDS.max[1] = 140`，
**相机能飞到 y=140 而云只有 y=60~80 ⇒ 可以飞到云层之上**，物理上错误。
此注释与 `cloudsFor` 自批次 16 起从未与 `freeViewColliders.ts` 对账。

**修法**：云底一律高于相机上限 —— 积云 175~215、层云 240~280、卷云 320~370；
最远点 `sqrt(389²+366²) ≈ 534`… 实测铺开半径上界 389 时最远点仍在
天穹半径 500 与相机 far 800 之内（CDP 实测 `maxHorizRadius=389`、`yRange=[174,366]`）。

### 4.4 连带修正：三个按旧尺度标定的常量

| 常量 | 旧值 | 新值 | 依据 |
|---|---|---|---|
| `CLOUD_BASE_TEX` | 0.35 | **0.92** | 0.35 是按 22~36 m 道具云标的；贴图自身 alpha 峰值 0.90 ⇒ 0.35 时有效逐像素 alpha 仅 0.14，真实积云是会**遮蔽**天空的 |
| 天气系数下限 | 无 | **0.35** | `cloudOpacity` 表晴天 0.10 是为「点缀性小云」设计的；云成天空主体后晴天 0.10 会把天空清空，而真实晴天仍有疏散淡积云 |
| `CLOUD_WRAP_X` | ±42 | **±340** | ±42 会落在 40~110 单位宽的云体**内部** ⇒ 云被拦腰折断；±340 时一次跨越需 ~38 min，正常对局内基本不触发 |

## 5. 验收中抓到的第四个 bug：`cloudTintFor` 的金色时段是**死代码**

首版用 `noonOffset = |tod - 0.5| * 2` 当「距正午多远」，阈值 0.72 / 0.88。
但该式在**日落**（tod=0.75）时只有 **0.5**，永远够不到 0.88 ⇒ `#e8955c` 从未返回过。
离线断言实测到的时刻表：

```
17:00 #f2f6fb  ← 仍是正午白
18:00 #f2f6fb  ← 仍是正午白（应为橙）
18:30 #3d3a44  ← 直接跳到夜云色
```

**tsc / build / 实拍截图全部无感** —— 因为截图恰好都落在别的时间段，
而「某个分支从未被执行」这件事没有任何门禁会报。

**修法**：按**真实昼弧**归一化 —— 以太阳正午 `(sunrise+sunset)/2` 为 0、
半昼长 `(sunset-sunrise)/2` 为 1；夜间同理按真实夜弧归一化。
这样也自动适配批次 33 引入的**逐月日出日落**（不同城市、不同纬度昼长不同）。

**护栏**：新增 `scripts/ci/check_cloud_tint.mjs` ——
从 `CloudLayer.tsx` **原样抽取**该函数（不复制逻辑，避免「测的不是真代码」），
跑 17 条断言（正午/午后/金色/日出/入夜/深夜/夜间亮度/夏至长昼），
含一条**死代码回归哨兵**（「金色时段确实出现过」）。非零退出码即失败。

## 7. 本批方法论教训

1. **「能跑」不等于「对」——尺度必须与被审对象的物理量纲对账。**
   批次 16 的云通过了 tsc、构建、出图、CDP 全部门禁，跑了 40+ 批次没人发现，
   因为**没有任何一条判据检查「云在天空里的张角」**。
   与批次 47（路面偏移半条）、批次 49（漏 `u()` 换算）是同一类缺陷。
2. **一次只改一个物体，但要和它的所有消费方对账。**
   云的高度常量在批次 16 定，批次 32 改了相机上限却没回头看 —— 与批次 38
   「五套布局各自为政」同源。**对账清单：谁消费了这个值。**
3. **渲染缺陷排查先做「隔离 + 投影 + 差分」三项预判，再动参数。**
   本批先差点把 `WeatherFX` 的雨粒子当成云渲染缺陷返工，又差点把
   「云在画面外/被剔除」误判成透明度问题。
   有效顺序是：**差分定位（有没有贡献）→ 投影定位（在哪、朝哪）→ 近拍定位（长什么样）**。
4. **半透明精灵贴图：形状归 alpha，色彩归 RGB。** 见 §3.3。
5. **「某个分支从未被执行」需要专门的哨兵断言。**
   §5 的金色时段死代码通过了全部既有门禁；把它变成一条
   「该值确实出现过」的断言，是唯一能挡住这类退化的手段。

## 8. 登记的遗留

| # | 事项 | 说明 |
|---|---|---|
| L1 | 云量（覆盖率）与云浓度（opacity）被混为一谈 | `cityTimeStore.ts` 的 `cloudOpacity` 表（0.10~0.90）同时承担「天上有多少云」和「云有多厚」两件事。真实天气主要改**覆盖率**，浓度变化小。本批用「基准 + 下限」绕开，未改表（该表与服务端 `time_weather.go` 是镜像契约，改动需前后端同步） |
| L2 | 无云影 | 云不在地面投下移动的阴影。本批明确不做，列为独立批次候选 |
| L3 | 无体积云 | 当前仍是 billboard 叠加。体积云（raymarch）性能开销大，SwiftShader 环境下不可接受 |
| L4 | 云量偏稀疏 | 14 团 / 71 mesh 在晴天（系数下限 0.35）下仍略显稀疏。加密会推高 DC（现 +25），需与批次 28 的 DC 预算一并权衡 |
