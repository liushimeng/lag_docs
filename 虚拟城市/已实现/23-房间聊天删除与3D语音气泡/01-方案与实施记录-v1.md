> **版本**：v1 ｜ **日期**：2026-09-25 ｜ **状态**：已实施
> **定位**：虚拟城市是全 Agent 城市模拟器（§2026-09-22 定位声明），不需要「人 ↔ Agent」的房间文字聊天。
> 本批次做两件事：

> 2. **3D 语音气泡**：Agent 居民的公开发话不再落在聊天列表，而是**在 3D 地图对应居民的头顶冒泡**；

## 1. 背景与动机

虚拟城市房间内有三类「说话」数据（详查报告见 §6），但只有「座位居民公开发话」依赖房间聊天面板展示。
全 Agent 定位下，房间内的人类聊天没有受众（Agent 不读聊天面板，居民发言靠 hear 感知走内存环形缓冲），
聊天面板沦为纯展示组件且与「全 Agent 模拟器」定位相悖。

**产品决策**：居民的每句话都应该**长在地图上**——说话即冒泡，城市本身就是聊天记录。

## 2. 现状分析（实施前代码事实）

### 2.1 三条发言数据通道（后端 → 前端）

| 通道 | 数据源 | 传输 | 前端消费方（删除前） |
|---|---|---|---|
| ① 座位居民公开发话 `speak`（area） | `agent_runner.go:489-531` → `ChatService.SendFromBot`（chat_service.go:821） | WS `chat.message`（`from_role='bot'`）+ 落库 `t_lsm_game_chat_message` | **房间聊天面板**（唯一出口） |

### 3.3 3D 语音气泡（前端新增）

#### 3.3.1 数据流设计

```
chat.message (from_role='bot') ──► useVirtualCitySpeech(roomId) ──► store.speechBubbles[seat]
                                                                      │ (VirtualCityCityMap 订阅)
                                                                      ▼
game.event type='city_voice' ──► store.eventFeed（已有）──► CityVoiceBubbleLayer（市政厅上空）
```

- **座位居民发言**：新增 `hooks/useVirtualCitySpeech.ts`（挂在 `VirtualCityGamePage`，与 useVirtualCity 并列）。
  直接 `wsClient.on('chat.message', ...)`，过滤 `room_id` 匹配 + `from_role === 'bot'`；
  按 `from_user_id === p.account` 命中座位（兜底 `from_agent_name === p.model_display`），
  写入 store。**不走 useChat**（它会发 chat.subscribe/chat.history，本批次正要让虚拟城市与聊天服务脱钩）。
- **市民之声**：不新增订阅 —— `useVirtualCity` 已把 `game.event` 推进 `store.eventFeed`，
  气泡层直接按 `type === 'city_voice'` 取最近条目（与 MonthTicker 同一数据源，零新订阅）。

#### 3.3.2 Store 契约（`store/virtualCity.store.ts` 新增切片）

```ts
export interface VirtualCitySpeechBubble {
  seat: number;          // 发言者座位号（≥0）
  name: string;          // 显示名（model_display #座位 或昵称）
  text: string;          // 展示文本（前端再截 60 字）
  ts: number;            // Date.now()，过期判定基准
}
// state:
speechBubbles: Record<number, VirtualCitySpeechBubble>;  // key = seat，每座位只留最新一条
// action:
setSpeechBubble(b: VirtualCitySpeechBubble): void;       // 同座位覆盖
```

过期不在 store 做（避免定时器），由渲染端按 `ts` 判定（§3.3.3）。

#### 3.3.3 渲染设计

**A. 座位居民气泡 —— 扩展 `AgentToken.tsx`**

- 新增可选 prop：`speech?: { text: string; ts: number } | null`。
- 气泡用现成的 `<Html distanceFactor={12}>` 模式（名牌 L142-166 同款），锚点在名牌上方
  （名牌锚点 y 基础上 +0.9，避免遮挡职业色 token 与金环）。
- 过期：`BUBBLE_TTL_MS = 12000`。组件内 `useEffect` 按 `ts` 设 timeout 置本地 `expired`，
  新 speech 到来（ts 变化）重置。**同座位新发言顶掉旧气泡**（store 已保证只留最新）。
- 结构（§26.3 三件套：JSX className + CSS 规则 + @keyframes + prefers-reduced-motion）：

```tsx
{speech && !expired && (
  <Html center distanceFactor={12} position={[0, TAG_Y + 0.9, 0]} zIndexRange={[40, 0]}>
    <div className="virtualCity-speech-bubble" role="status">
      <span className="virtualCity-speech-bubble__text">{clip(speech.text, 60)}</span>
    </div>
  </Html>
)}
```

- `VirtualCityCityMap.tsx`：L404-419 渲染 AgentToken 处，`speech={speechBubbles[p.seat] ?? null}`
  （`const speechBubbles = useVirtualCityStore((s) => s.speechBubbles)`）。

**B. 市民之声气泡 —— 新增 `CityVoiceBubbleLayer.tsx`（components/virtualCity/）**

- 锚点：**市政厅（city_hall）模型上空**（civic 区地标，坐标从 CivicLayer/LandmarksLayer 的现状常量取；
  实现时 grep city_hall 落位，导出共享常量 `CITY_HALL_BUBBLE_ANCHOR`，无现成常量则在放置处新增并复用）。
- 数据源：`useVirtualCityStore((s) => s.eventFeed)` 过滤 `type === 'city_voice'`，取 **最近 2 条**且 `ts` 在 TTL 内
  （eventFeed 条目若无 ts 字段则在 pushEvent 时补 `_ts`，或层内记录首次见到 event id 的时间）。
- 事件 text 形如 `"名字:文本"`（room_city.go:371），按第一个 `:` 拆出 `name` 与正文。
- 多条垂直堆叠（新在上），类名 `virtualCity-speech-bubble virtualCity-speech-bubble--voice`，
  带「🗣 名字」前缀行。
- 该层挂在 `VirtualCityCityMap` 场景内（StreetPropsLayer 附近），**不依赖座位**。

**C. 样式（追加到 `styles/virtualCity-city3d.css`）**

| 规则 | 要点 |
|---|---|
| `.virtualCity-speech-bubble` | 深色底 `rgba(16,20,28,0.85)`（≥45% 不透明，§26.2-2）+ 白字 `#fff`（对比度 ≥ 4.5:1）+ 圆角 10px + 下方小三角尾巴（`::after`）+ max-width 220px + 1.5 行截断 |
| `.virtualCity-speech-bubble--voice` | 色相区分（青蓝边框/图标），前缀行 `.virtualCity-speech-bubble__name` 高亮色 |
| `@keyframes virtualCity-speech-pop` | scale 0.6→1 + fade-in，240ms |
| `@media (prefers-reduced-motion: reduce)` | 动画降级为纯淡入/无动画（§26.3 硬约束） |

**D. 观战者**：冒泡对玩家与观战者完全一致（数据帧本来就连观战者一起广播），无分支。

### 3.4 删除后的人类发言兜底

- 人类（含观战者）在虚拟城市房间发 `chat.send`/`chat.whisper` → 收到 35104 `chat.error`。
  前端已无入口，正常用户不可达；API 直调者得到明确错误码。
- 大厅聊天（lobby scope）**不受影响**。
