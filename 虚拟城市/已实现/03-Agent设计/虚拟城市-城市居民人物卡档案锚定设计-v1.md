## 1. 背景与差距分析

### 1.1 现状（2026-09-21 探索核实）

| 层 | 现状 | 差距 |
|---|------|------|
| 12 座位 LLM Agent | ✅ `pool=docs` 时 `loader.Draw(12)` 抽人物卡 → `Card` → prompt `MyCard`（room.go:404、agent_runner.go:1043） | 无 |
| 城市背景居民（1~10 万） | ⚠️ `city.NewBackdrop` **纯合成**（≈20B/人紧凑结构，seed+calib 确定性）；人物卡仅用于**统计校准**（`BuildCalibTable` 抽样构建域收入分布） | **每个居民没有自己的档案卡** |
| 城市之声（city/voice.go） | ⚠️ LLM persona 用代号 `"U1024·老城区"`（codenameLocked，backdrop.go:404 注释明言「背景居民不解析真实姓名卡」） | 无真实姓名/职业/人格 |
| 前端 CityStatsPanel | ⚠️ 仅聚合统计（就业率/中位收入/8 区人口/最近 8 条之声文字） | 无个体居民档案 UI |
| REST | 仅有 `GET /professions`（精选卡+池状态）与 survey 两端点 | 无居民档案查询端点 |
| 知识库规模 | Loader 设计时 75,115 张；**当前实际 100,267 张**（100,174 个 md，其中 `_框架`/`_交付说明` 下 38 份框架文档被 `_` 前缀目录规则排除后剩 100,267 张人物卡） | 注释/文档数字过时（按实际 walk 数动态化） |

### 1.2 目标（本设计交付）

1. **建房 → 档案自动加载**：`resident_count ≥ 1` 的房间，Start 后后台流水线从文档池
   **不重复抽 n 张人物卡路径 → 并行读取解析 frontmatter → 锚定到居民**；
   锚定完成后居民的收入/支出/储蓄/年龄/行业/城区全部来自真实档案。
2. **每人一份档案**：任意居民（含城市之声发声者）可查 `ResidentProfile`
   （姓名/职业/人格/opening_hook/5 年目标/婚姻/健康档…），来源即
   `lag_docs/虚拟城市/玩家职业设计/**.md` 的 frontmatter。
3. **10 ~ 100,000 并行规模**：10 张秒级完成；100,000 张水合后台异步约 100s（4 核
   dev 机实测，期间合成数值兜底，**不阻塞开局、不阻塞月结**），进度经 Snapshot 下发前端。
4. **主界面兼容**：城市之声显示真实「姓名·职业」；新增居民档案抽屉（分页/搜索/详情）；
   建房弹窗与 i18n 同步。

## 2. 总体设计

```
Start(锁内)                          后台 goroutine（绝不持 r.mu）
startCityLocked
  ├─ NewBackdrop(n, rng, calib)      ← 合成兜底数值(现状不变)
  └─ go anchorCityProfiles()
       1. loader.DrawPaths(n, rng2)        仅抽路径,0 IO(索引已建)
       2. SetProfileProgress(hydrating,0,n,poolSize)
       3. loader.HydrateBatch(paths, workers, progress)
          │   worker pool 并行 读文件+解析 frontmatter(绕过 LRU)
          │   progress → atomic done (每 512 张回写)
       4. City.AnchorProfiles(cards)       Backdrop.mu 内:写 profiles[] + 覆盖居民数值
       5. emit game.event{type:"city_profiles"}   ← 锁外 BroadcastHooks(现状 emit 模式)
```

- **锚定前**：合成数值兜底（现状行为），城市之声用代号 —— 零回归。
- **锚定后**：居民数值=档案值，`TickMonth` 演化在档案初值上继续叠加；
  城市之声/档案抽屉/REST 全部走真实档案。
- **确定性**：`rng2` 由房间 seed 派生（独立流）→ 同 seed 同索引 → 同路径集 → 同档案
  （与 Backdrop 合成的确定性契约同构）。

## 3. Loader 批量契约

**新文件 `ServerGo/game/wealth/profession/loader_batch.go`**（loader.go 已 420 行，
不往里加；同 package）。契约注记「本文档 §3」。

```go
// DrawPaths 返回 n 个不重复的相对路径(仅索引洗牌,零文件 IO)。
// 语义与 drawPairs 的前缀 Fisher-Yates 一致:n > 池大小时返回全池洗牌结果;
// 池为空/根目录缺失返回 nil。调用方负责后续水合。
func (l *Loader) DrawPaths(n int, rng *rand.Rand) []string

// PoolSize 返回当前索引条数(未建索引时触发 ForceIndex)。
func (l *Loader) PoolSize() int

// HydrateBatch 并行读取并解析 paths 对应的人物卡(绕过 LRU 直读,避免批量
// 水合把单卡缓存 256 上限挤穿)。workers clamp [1, 64],默认 min(32, NumCPU×4)。
// 返回:(成功卡(带 L1 域名,顺序与 paths 中成功者一致), 失败相对路径)。
// progress 非 nil 时每完成 512 张回调一次 (done, total);最终必然回调 (total, total)。
// 单卡失败:计 parseFail 同款 Warn 日志,跳过不中断。
func (l *Loader) HydrateBatch(paths []string, workers int, progress func(done, total int)) ([]DomainCard, []string)
```

实现要点：
- 复用 `l.ForceIndex()` / `l.parseFile(rel)`（parseFile 已含 frontmatter 提取 + mapCard）；
  **批量路径不走 `loadCard` 的 LRU**（`parseFile` 直读）。
- worker pool：`sync.WaitGroup` + 带缓冲任务 chan；结果按完成序 append（顺序无关，
  AnchorProfiles 前调用方可洗牌 —— 本设计直接按完成序使用，rng 语义集中在 DrawPaths）。
- progress 的 done 计数用 `atomic.Int64`；HydrateBatch 自身并发安全、可重入。
- 同时把 loader.go 头注与文档池设计文档里「75,115 张」「75k」等静态数字改为
  「以 `PoolSize()` 实测为准（2026-09-21 实测 100,267）」的动态表述。

## 4. Backdrop 档案锚定契约

**新文件 `ServerGo/game/wealth/city/profile.go`**；Backdrop 增字段（backdrop.go）。

```go
// ResidentProfile 单名居民的档案投影(全部来自人物卡 frontmatter;未锚定居民
// 没有 profile —— ProfilesPage/ProfileOf 对其返回 ok=false)。
type ResidentProfile struct {
    Index       int      `json:"-"`              // resident 下标
    CardID      string   `json:"card_id"`        // 人物卡编号(N1051443 / P01)
    Name        string   `json:"name"`           // 化名
    Occupation  string   `json:"occupation"`     // 职业
    DomainName  string   `json:"domain_name"`    // L1 域展示名
    District    string   `json:"district"`       // 城区展示名(锚定时由 HomeDistrict 映射)
    Age         int      `json:"age"`
    Income      float64  `json:"income"`         // 月收入(元,档案值;后续月结演化可变)
    Expense     float64  `json:"expense"`
    Savings     float64  `json:"savings"`
    Employed    bool     `json:"employed"`       // 锚定 income>0;其后随演化 flags
    Stressed    bool     `json:"stressed"`       // 锚定 savings < 3×expense;其后随演化
    Personality string   `json:"personality"`    // 「、」连接(2-4 词)
    OpeningHook string   `json:"opening_hook"`   // 档案开场白(≤60 rune,超长已截)
    Goal        string   `json:"goal"`           // goals[0](5 年目标)
    Marital     string   `json:"marital"`        // single|married
    HealthGrade string   `json:"health_grade"`   // A|B|C
    SourceFile  string   `json:"source_file"`    // 相对路径(审计:可回溯源 md)
}
```

Backdrop 新增（未导出字段 + 导出方法）：

```go
// 新增字段(backdrop.go Backdrop struct)
profiles     []ResidentProfile // 与 residents 同长;未锚定位为零值+Anchored=false
profStatus   int               // 0=idle 1=hydrating 2=ready 3=failed
profDone     int               // 已水合张数(进度;mu 内读写即可,无需 atomic)
profTotal    int
profPoolSize int               // 文档池索引总数(展示「卡池 10 万」)

// 导出方法(全部 mu 内完成;AnchorProfiles 是一次性热替换)
func (b *Backdrop) SetProfileProgress(status, done, total, poolSize int) // 供编排 goroutine 回写
func (b *Backdrop) AnchorProfiles(cards []profession.DomainCard, sourceFiles []string) int // 返回锚定成功数
func (b *Backdrop) ProfileOf(idx int) (ResidentProfile, bool)   // 城市之声/单卡详情用
func (b *Backdrop) ProfilesPage(offset, limit int, q string) ([]ResidentProfile, int, ProfileProgress)
//  ↑ q 非空时线性扫 name/occupation/card_id 包含匹配(100K < 5ms);返回(页, 命中总数, 进度)
type ProfileProgress struct {
    Status   string `json:"status"`    // idle|hydrating|ready|failed
    Done     int    `json:"done"`
    Total    int    `json:"total"`
    PoolSize int    `json:"pool_size"` // 文档池人物卡总数(≈100,267)
    Anchored int    `json:"anchored"`  // 已锚定居民数
}
func (b *Backdrop) ProfileProgress() ProfileProgress
```

**AnchorProfiles 语义（数值覆盖规则）**：

| resident 字段 | 档案来源 | 规则 |
|---|---|---|
| `income` | `Card.Salary` | clamp [0, 200000]（对齐 backdrop incomeMax） |
| `expense` | `Card.Expense` | clamp [0, ∞)，0 → 兜底 `income×0.5` |
| `savings` | `Card.Savings` | clamp [0, ∞) |
| `age` | `Card.StartAge` | clamp [18, 70] |
| `domain` | `DomainCard.Domain`（路径 L1 段 → 域索引） | 解析失败保持原值 |
| `district` | `Card.HomeDistrict` → `profession.DistrictIDs()` 下标 | 未命中保持原值 |
| flags.employed | `income > 0` | 失业卡（income=0）如实失业 |
| flags.stressed | `savings < stressExpenseMonths×expense` | 对齐合成判定 |
| `profiles[i]` | 全量投影 | `SourceFile` 取 sourceFiles[i] |

- `len(cards) < len(residents)`（池不足）：只锚定前 `len(cards)` 名，其余保持合成 ——
  Snapshot 的 `Anchored` 如实披露。
- `TickMonth` 之后锚定：档案值直接覆盖演化值（档案是事实来源）；此后演化照常。

（`_` 前缀框架目录被排除）。文档中「10 万」均为约数，精确值以 `PoolSize()` 为准。

## 10. 失败语义与降级

| 场景 | 行为 |
|---|---|
| `pool=curated` / docLoader=nil | 不启动锚定（profiles.status=idle），纯合成 —— 与现状一致 |
| 根目录缺失 / 索引空 | status=failed + logger.Warn，合成兜底；REST progress 如实披露 |
| 单卡解析失败 | 跳过 + Warn（parseFail 计数），不中断批量 |
| 池 < n（理论不发生：100,267 ≥ 100,000） | 只锚定前池大小名，Anchored 如实 < n |
| 锚定中月结/演化 | TickMonth 与 AnchorProfiles 都走 Backdrop.mu，天然串行；锚定前的演化值被覆盖（档案优先） |
| 服务器重启 | 城市本身不恢复（现状契约），重建房时重新锚定 |

## 11. 锁纪律与确定性

- **锁序不变**：`Manager.mu → WealthRoom.mu → Backdrop.mu`，无反向获取；
  anchorCityProfiles goroutine **只拿 Backdrop.mu**，绝不触碰 r.mu / m.mu（§92a）。
- 编排 goroutine 读 `r.docLoader / r.ResidentCount / r.seed`：均为 Start 后不变字段，
  Start 内（锁内）先把值拷贝进 goroutine 参数，**goroutine 不读 r.mu 保护的可变字段**。
- 广播回调锁外（room.go:9-12 既有纪律）。
- 确定性：rng2 独立流 → 同 seed 同路径集；锚定一次性热替换，不重放。
