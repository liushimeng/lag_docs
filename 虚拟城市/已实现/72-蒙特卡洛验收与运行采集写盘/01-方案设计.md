## 3. 策略代理（验收方案 §5.1 适配）

### 3.1 通用纪律（全部策略）

1. **确定性**：策略是 `(w *World, seat, month) → []Action` 的纯函数，**绝不调用 `w.Rand`**（否则移动引擎随机序列，破坏同种子复现；与批次 71 B10 护栏同一纪律）。
2. **动作面**：仅走既有 `w.ApplyAction`（与人类/Agent 同一入口、同一预算 `monthlyActionBudget=3`、同一校验），**不新建动作类型**。
3. **每月动作 ≤ 2**（预算 3 留 1 冗余给引擎自动动作路径）。
4. 动作失败（预算尽 / 现金不足 / 信用不足）→ 静默跳过，不重试不报错。

### 3.2 五个策略（archetype id 即 API 字符串，恒定）

| id | 行为定义 |
|----|---------|
| `safety_net_only` | **零动作**。仅靠自动月结（节俭档、失业保险、社保）生存 —— 基线对照锚。 |
| `minimum_effort` | 当 `cash > 6×月支出` 时，每月买国债 `0.2×(cash − 6×月支出)`（`buy_asset asset="bond"`）；否则不动。 |
| `balanced` | 盈余分配 40/30/30（验收方案 §3.7）：新钱（当月净结余 > 0 时）30% 买 bond、30% 买 stock，40% 留现金；不做存量再平衡（减少交易噪音）。 |
| `aggressive_leverage` | 仅 `CyclePhase == boom` 期行动：① 房产 < 4 且 `CreditScore ≥ 600` ⇒ `buy_house downpay_ratio=0.3`（贷款自动生成，即「贷款上限用满」的实现口径）；② 余钱 ≥ ¥10,000 ⇒ 全部买 stock。非繁荣期持有不动。 |
| `stress` | 行为同 `balanced` + **剧本覆盖**（§3.3）。 |

### 3.3 stress 剧本覆盖（确定性注入）

| 月 | 注入 | 实现口径 |
|----|------|---------|
| M25–M37 | 强制 `recession` | 每月 `SettleMonth` 后若下月落入窗口 ⇒ 直接写 `w.Market.CyclePhase = PhaseRecession; CycleMonthsLeft = 1`（引擎自身的相位转移 rand 照常消耗，写回覆盖 —— 同种子确定性保持） |
| M61–M73 | 强制 `depression` | 同上 |
| M26 | 全员失业冲击 | 每个存活座位 `p.UnemployedMonths = 2`（与 `MonthlyEvents` hazard 命中同字段同语义） |
| M62 | 全员健康冲击 | 每个存活座位固定 ¥50,000 医疗支出（经 `w.Pay(seat, SeatEntity, consumerPayTo, CatMedical, "压力测试医疗冲击")` 走 Ledger，不变量不受染）+ `Energy −5`（clamp −3）+ `HadIllnessYear = true` |

> 失业/健康不引入新 rand：固定月、固定金额、固定字段写回。

### 4.2 单局采集（`MCRunStats`）

每局 headless 驱动：`NewWorld(seed, cards)` → 12 座 `newPlayerFromCard` → `StartGame` → 循环 `策略动作 → SettleMonth → 采样`，至 M420 或 `Status == finished`。

采集项（内存，零落盘）：

- **逐月**：存活数、破产正式出局数（累计）、`World.Audits` 尾快照的 indicators（D2/D5/Gini）；
- **锚点月快照**（M1 / M97 / M120 / M360 / 终局）：每座净资产、FI、`Monthly.Net`（M1 用作 G1）、每座 top20 份额与 Gini（M60/M120/终局）；
- **排名对**：M1 与 M120 每座净资产数组（G10 Spearman 输入）；
- **门禁判定输入**：`minimum_effort` 局的 M120 FI 分布；`balanced` 局的 M360 FI 分布；`aggressive_leverage` 局的单局连锁破产峰值；

## 6. R-E1 / R-E2 红线（N4）

### 6.1 口径裁决：**市场级**品类年化（非居民级）

R-E1/E2 的语义是「**某投资品**模拟年化收益率持续偏高/偏低」⇒ 判定对象是**该品类的市场行情**，不是某个居民的已实现收益（那是 N3 居民级 `category_returns`，批次 73）。本批用市场级口径，零新增埋点。

### 6.2 品类年化计算（期初/期末价，年化复利）

| 品类 | 期初/期末量 | 年化公式 |
|------|-----------|---------|
| `stock_index` | `Market.StockIndex` | `(end/start)^(12/月数) − 1` |
| `gold` | `Market.GoldPrice` | 同上 |
| `house` | `DistrictIdx` 全区均值 | 同上 |
| `bond` | 月结 `BondRate`（新购票面）逐月均值 | 直接取均值（票面即年化） |

月数 = 本局已推进月数；月数 < 12 的局不产出该字段（数据不足）。计算函数零 rand、逐月缓存于 `CalibrationState.Current`。

### 6.3 红线判定（跨局均值）

- 常量：`redlineCategoryReturnMax = 0.30` / `redlineCategoryReturnMin = 0.03` / `categoryRunsWindow = 10`；
- 取 `CalibrationState.Runs` **最近 10 局完成运行**（`Strategy` 为空或非空的都计入 —— 品类行情与策略无关，但 MC 局与真实局混计时需 ≥10 局才触发）；
- 每品类算均值：> 30% ⇒ R-E1 触发（`actual = 该品类均值`，detail 列品类名与局数）；< 3% ⇒ R-E2 触发；
- 不足 10 局 ⇒ 不触发，detail 标注「样本不足（n=x/10）」；
- `EvaluateRedlines` 增第三入参 `runs []RunRecord`；红线数组由 5 条扩为 **7 条**（顺序 R-E1/R-E2 追加在尾部，前端按 id 渲染不受序影响）。
