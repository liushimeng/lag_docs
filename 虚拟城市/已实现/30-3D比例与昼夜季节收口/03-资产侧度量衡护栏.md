## 4. `--emit-json` / `--check-table` 用法

### 4.1 `--emit-json [path]` —— 实测 AABB 导出（世界单位）

```bash
python3 3d_script/verify_glb_aabb.py --emit-json /tmp/glb_dims.json   # 写文件
python3 3d_script/verify_glb_aabb.py --emit-json                      # 不带路径 = 打 stdout
```

- 键 = `<类别>/<名>`（无 `.glb` 后缀）；每键 5 个字段：
  `world` / `geo` / `minY` / `nodeScaleIssues` / `per_part`。
- `world` / `geo` 为**判据口径**（`per_part` 文件如 trash_can 取单件最大尺寸，
  与前端 `REAL_DIMS_M.trashCan` 单桶口径可直接对）；`per_part` 逐 mesh 节点给明细。
- **该 json 不入库**：`.gitignore` 已含 `3d_script/glb_measured_dims.json`；留档写本文档，别提交 json。

样例（节选）：

```json
{
  "nature/oak_tree": {
    "geo": [0.451402, 1.01, 0.47],
    "minY": 0.0,
    "nodeScaleIssues": [],
    "per_part": {"OakTree_Summer": {"geo": [0.451402, 1.01, 0.47], "minY": 0.0, "world": [0.451402, 1.01, 0.47]}},
    "world": [0.451402, 1.01, 0.47]
  },
  "road/trash_can": {
    "geo": [0.05, 0.1, 0.05],
    "minY": 0.0,
    "nodeScaleIssues": [],
    "per_part": {
      "TrashCan_Blue":  {"geo": [0.05, 0.1, 0.05], "minY": 0.0, "world": [0.05, 0.1, 0.05]},
      "TrashCan_Green": {"geo": [0.05, 0.1, 0.05], "minY": 0.0, "world": [0.05, 0.1, 0.05]}
    },
    "world": [0.05, 0.1, 0.05]
  },
  "ocean/cargo_ship": {
    "geo": [6.82, 1.42, 1.04],
    "minY": -0.14,
```

> 明细（每灯 5 个 primitive）。trash_can 是双节点（2 桶），per_part 才有"逐件"意义。

### 4.2 `--check-table <json>` —— 表值 vs 资产真值交叉校验

批次 29 方案 §3.7 想要的那一环：把任何尺寸表（含前端 `REAL_DIMS_M` 的 dump）丢进来，
逐边比对 ±5%，**不一致即非零退出**。

表格式：

```json
{
  "__unit__": "m",
  "nature/oak_tree": [4.50, 10.10, 4.70],
  "nature/oak_tree_winter.glb": {"world": [4.12, 9.55, 3.82]},
  "road/trash_can": {"x": 0.50, "y": 1.00, "z": 0.50},
  "civic/city_hall": [14.4, null, 8.4]
}
```

- `__unit__`：`"m"`（米制，比对前自动 ÷10）或 `"world"`（默认）。
- 值三种写法：`[x,y,z]` / `{"world":[x,y,z]}` / `{"x":..,"y":..,"z":..}`；某轴 `null` = 不比对。
- 键：`<类别>/<名>`（推荐）、唯一 basename（`cactus`）、可带/不带 `.glb`。
- 表项查无实测 / 同名歧义 / 偏差 >±5% ⇒ 打印 ✗ 并**非零退出**。

实测（正确表 → 退出码 0；错误表 → 退出码 1）：

```
· nature/oak_tree   Y 实测 1.0100 / 表值 1.2000  偏差 -15.83%  FAIL
✗ 表值比对 nature/oak_tree Y：实测 1.0100 表值 1.2000（偏差 -15.83%）
✗ 表项 nature/nope 查无实测（键应为 <类别>/<名> 或唯一 basename，可带 .glb）
```

## 5. `build_trash_can.py` 单位契约补齐（P0-3）

**改动性质：纯注释，零几何常量改动**（`BODY_R/BODY_H/LID_R/LID_H/DOME_SQUASH` 一行未动）。

1. **补单位契约块**（与 `build_cactus.py` 口径一致，四条硬约定写全）：
   - 米 → 世界单位 = ×0.1（1 世界单位 = 10 m）；
   - 唯一事实来源 = `cityScale.ts::METERS_PER_UNIT`（表值 `REAL_DIMS_M.trashCan` = ⌀0.50 m × 1.00 m）；
   - **尺寸必须烘焙进顶点**（`export_glb` 已统一 `bake_transforms()`；`make_*` 用 `obj.scale`
     表达尺寸、join 后须烘焙——这正是批次 29「20 m 巨型垃圾桶」的事故根因）；
   - **导出节点 scale 必须 identity**（消费端零旋转零 scale 直挂）。
2. **清掉错误旧注释**：原「几何（单位=米，**1u 世界 = 1m 模型**）」与旧半径/高度数字
   （r 0.035 / h 0.09 / 总高 0.11）是校正前残留，与契约（1u = 10 m）和现行常量表直接矛盾，
   已改写为「世界单位，以常量表为准」并注明旧值勿再引用。

**同批普查**：20 个 `build_*.py` 里**只有 2 个缺单位契约头**——`build_trash_can.py`（已补）
与 `build_oak_tree.py`（见下）。其余 18 个均有单位口径声明（`build_cactus/cargo_ship/
lighthouse/pine_tree/sailboat/snow_mountain` 为「⚠ 单位口径」标准块 + `U = 0.1` 行；
批次 19 的 civic/vehicle 系列为「世界单位：1 单位 = 10 m」段 + 目标包围盒行），
bake/identity 约定在各脚本导出调用点或 `__common__.export_glb` 文档里，本批未重复堆注释。
