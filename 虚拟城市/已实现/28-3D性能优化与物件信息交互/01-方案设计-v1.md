# 批次 28 · 3D 性能优化与全物件信息交互 — 方案设计 v1

> **批次**：28（2026-09-27）
> **触发**：用户反馈「进入虚拟城市主界面 WebGL 渲染很卡」+「所有 3D 物品/模型都要支持点击或悬停显示信息，一个都不能漏，后期要按信息裁剪模型」。
> **两条工作线**：A 性能优化（消灭卡顿）；B 物件信息交互（全物件 hover/click 简介）。
> **纯前端批次**：不动 `ServerGo/`、不动协议、不动 `game.state` 契约。

---

## 1. 背景与目标

批次 20 之后城区规模 32 区 + 批次 24–27 持续加场景内容，渲染负载早已超过批次 20 定下的红线
（draw call ≤ 1500 / mesh ≤ 3500）。批次 26 `02-实施记录.md` §4.2 已实测
「全场景 draw calls 约 1500~4930」并注明「建议单独立项评估」—— 本批次即该立项。

同时用户要求场景内**每一个** 3D 物件都能点/悬停看到简介信息。现状是全场景只有
`DistrictBlock`（城区地块）一个组件有 hover 卡片，其余 ~50 个场景组件（楼栋、街具、
市政设施、地标、车辆、行人、树木、水系、边缘景观……）全是不可交互的死几何体。

**目标**：

| # | 目标 | 验收阈值 |
|---|------|---------|
| G1 | 默认视角 draw call 显著下降 | ≤ **1500**（批次 20 红线；当前 ~4930） |
| G2 | 主线程 React 协调开销消除 | 场景树不再 4Hz 全量 reconcile；`?debug=1` 下帧率可感提升 |
| G3 | 全物件信息覆盖 | 场景内所有可渲染物件类型 100% 支持 hover 和 click 显示简介；无信息的**新建简介文案**（三语） |
| G4 | 零回归 | `tsc --noEmit` + `npm run build` 通过；昼夜/季节/雨雪/选区对焦等既有行为不变 |


## 4. 工作线 A：性能优化（逐项）

### A1（P0）消灭 4Hz 全树 re-render

1. `VirtualCityGamePage.tsx:195` 的 `setNow` 定时器**移出页面组件**：新建极小的
   `<TickerNow>`/独立 hook 承载（或改用 `cityTimeStore` 订阅），页面不再持有 250ms state。
   需要 `now` 的子 UI（倒计时/时间条）各自订阅，不牵动 `<VirtualCityCityMap>`。
2. `React.memo(VirtualCityCityMap)`，props 收敛为稳定引用（gameState 切片经 selector 取出，
   禁止内联对象/内联函数 props）。
3. `React.memo(DistrictBlock)`（props: def 常量、priceIndex、playerCount、selected），
   `React.memo(BuildingMesh)`、`React.memo` 街具类叶组件（props 均为稳定原语/常量）。
4. 验收：React DevTools/`?debug=1` 观察，静止状态下场景树 re-render 频率从 4Hz → 仅 WS state push。

### A2（P0）楼栋 draw call 收敛

1. `building_shapes.tsx` `BoxFaces` 六材质数组 → **2 group 版 box**（侧立面 1 组 + 顶/底 1 组）：
   重建/重排 BoxGeometry 索引组使侧面索引连续，`clearGroups()+addGroup×2`，材质数组长度 2。
   单 box DC 6 → 2，塔楼 3 box 由 18 DC → 6 DC。
2. 楼栋细节子件（ParapetRing / AcUnits / LiftRoom / PodiumRail / EntranceLobby /
   RooftopEquipment / BalconyLines / Shopfront / BillboardSign / SawtoothRoof…）继续走既有
   `mergeBoxes`（`building_shapes.tsx:255`）合并，目标**每栋 ≤ 6 mesh**。
3. 不跨楼合并（楼栋要保留逐栋 hover，见工作线 B）；不引入 LOD（见 §8 不做清单）。
4. 验收：`?debug=1` 读 `window.__cityRenderInfo.render.calls`，默认视角 ≤ 1500。

### A3（P0）阴影节流与 caster 裁剪

1. **阴影降频**：`EngineCanvas`/`DayNightCycle` 将 `renderer.shadowMap.autoUpdate = false`，
   由单个 `useFrame` 按 **15Hz**（每 4 帧一次）置 `needsUpdate = true`。太阳移动缓慢，15Hz 无感。
2. **caster 裁剪**：`TreesInstanced` 树冠/树枝 `castShadow=false`（保留树干）；
   车辆 GLB `castShadow` 仅 high 档保留；街具默认不投影。
3. 分档：low 档 `shadowMapSize` 1024 维持，树全不投影。
4. 验收：阴影 pass 几何量明显下降；日落长影仍可见（视觉抽查截图）。

### A4（P1）行人 / 小地图 / 材质 churn

1. `PedestrianV3`：`samplePath` 的 `segs[]` 改为 **useMemo 预计算**（路径不变则不重建）；
   动画/位移更新节流至 ~30Hz；`PEDESTRIAN_TOTAL_CAP` 按质量档取值（high 110 / low 60）。
2. `VirtualCityMinimap`：rAF 全量重绘 → **脏标记/10Hz 节流**（相机移动或玩家数据变化才重画）。
3. `textureCache.ts`：`useSharedPBR` 的 `matProps` 用 `useMemo` 按纹理实例稳定化；
   `withPBR` 避免每 render spread 新对象。
4. `useFrame` 合并非必须（行人已是薄回调）；若改动可控则把行人更新并入单驱动回调，否则维持（记入不做清单）。

### A5（P1）质量分档扩容 + 诊断

1. `QUALITY_PRESETS` 扩展字段：`pedestrianCap` / `treeShadows` / `anisotropy`（high 8 / low 4）/
   `weatherParticles`（已有 WeatherFX 内部档，改为读 preset）。
2. `?debug=1` 增加轻量 FPS HUD（近 1s 平均帧率 + draw call + triangle，DOM 浮层，不进 R3F 树）。
3. 实测口径：CDP 读 `window.__cityRenderInfo`，记录 N/E/W/S + 默认五视角 draw call 前后对比。

## 5. 工作线 B：全物件信息交互

### 5.1 架构

```
components/virtualCity/objectInfo/
├── catalog.ts            # 物件元数据注册表（唯一事实来源）
├── objectInfoStore.ts    # zustand：hovered/selected + 锚点世界坐标
├── useObjectInfoProps.ts # hook：返回 {onPointerOver,onPointerOut,onClick} 供组件展开
└── ObjectInfoOverlay.tsx # 单例悬浮卡（hover）+ 单例详情卡（click）
```

- **不给每个物件挂 drei `<Html>`**（32+ Html 是性能负担）——全场景只挂 **1 个** overlay，
  由 store 里的锚点世界坐标定位（`<Html position={anchor}>` 或 useFrame 投影定位）。
- hover：紧凑卡（名称 + 分类徽章 + 一句话简介）；click：详情卡（名称 + 完整简介 + 动态附加行
  如楼层/所属城区/运行状态），可钉住、ESC/×关闭。
- `useCursor('pointer')` 在 hover 时置手型（全仓首次引入）。
- **z 序契约沿用**：overlay `zIndexRange ≤ [30,0]`（不压 minimap z40 / error z50 / modal z200）。
- `DistrictBlock` 既有 hover 卡（含房价/租金/β）**保留**；本系统为地块补 click 详情卡即可，不重复造卡。

### 5.2 catalog 数据模型

```ts
export type ObjectCategory =
  | 'district' | 'building' | 'street-prop' | 'tree' | 'vehicle' | 'pedestrian'
  | 'civic' | 'landmark' | 'road' | 'water' | 'edge' | 'sky' | 'agent' | 'ground';

export interface ObjectInfoEntry {
  id: string;                    // 稳定 id，如 'building.tower' / 'prop.trash-can'
  category: ObjectCategory;
  icon: string;                  // emoji 徽章
  name: { 'zh-CN': string; en: string; ja: string };
  desc: { 'zh-CN': string; en: string; ja: string };   // 简介正文（新建文案）
}
```

- **i18n 决策**：简介文案直接内联三语入 `catalog.ts`，**不进** `i18n/Dict`——理由：
  (1) 数百条物件文案会撑爆 `virtualCityKeys.ts`/各 locale 的 1800 行上限；
  (2) catalog 是「场景物件注册表」（游戏数据，供后期按信息裁剪模型），与
  `VIRTUAL_CITY_DISTRICTS` 同性质，不是 UI 文案；(3) 语言切换走 `i18n` 的 `lang` 取值即可。
- **动态实例行**：hook 允许 `extra: {label, value}[]`（如 `{label:'楼层', value:'18'}`），
  由组件现场注入，不进 catalog。
- **覆盖保证**：catalog 增加自检单测——从场景组件清单（§5.4）导出的 id 列表必须
  100% 存在于 catalog，缺失即 fail（防「新物件忘了配简介」）。

### 5.3 接线方式

```tsx
const info = useObjectInfoProps('prop.trash-can', { anchorY: 0.6 });
return <group {...info} position={...}>…</group>;
```

- 所有 handler `e.stopPropagation()`，避免「点到楼里的是地皮」的穿透歧义
  （hit-test 优先级天然由 three 由近及远，stopPropagation 保住最外层获胜者）。
- **InstancedMesh**（树/路灯/信号灯/垃圾桶/边缘植被）：fiber 事件带 `instanceId`，
  handler 直接上报类型级简介 + `#instanceId` 动态行。
- **程序化楼栋**：`BuildingMesh` 接收稳定 id（`b-<districtId>-<idx>`，与 `buildingsFor()`
  的种子序一致）+ 动态行（所属城区、楼层、建筑类型名）。

1. **不做 LOD 动态切换**（批次 13/15 结论维持；80×80 世界实例化+DC 收敛已够）。
2. **不做跨楼/跨物件几何合并**（合并会破坏逐物件 hover 命中）。
3. **不做后端/协议改动**；不加 building 实体表——楼栋信息为前端程序化生成的展示层数据。
4. **不做粒子类（WeatherFX/Sparkles/水雾）的独立交互**（无实体语义）。
5. **不引入 post-processing / 新三方渲染库**。
6. **不动 `globals.css` 既有 @import 顺序**；不重构 `StreetPropsLayer` 布局算法。
7. **不做粒子级 LOD / 视锥剔除手动接管**（three 默认 frustumCulled 足够；WeatherFX 保持全绘）。
8. **不做 AgentToken 的深度交互改造**（只加 hover/click 简介，不改名牌体系）。
