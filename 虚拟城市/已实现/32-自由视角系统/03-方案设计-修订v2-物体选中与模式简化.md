## 2. 设计原则

1. **复用既有选中体系，不另造一套**。批次 28 已有 `objectInfo` 体系：
   `useObjectInfoProps(id, opts)` 把 `onPointerOver / onPointerOut / onClick` 绑到任意
   mesh 上，`onClick` 写 `useObjectInfoStore.setSelected(target)`，全城 30+ 物体已接线
   （建筑/街具/树/车/行人/道路/市政/地标/水系/城缘/地面/天空）。**选中 = objectInfo 的
   selected 状态**，无需为「选中」新建 store。
2. **碰撞体与渲染同源**。freeViewColliders 已给 353 栋建筑装配了 AABB，楼高随房价变化
   而更新。选中后的 orbit 半径 / 聚焦点直接从这份碰撞数据反查，保证「高亮圈」和
   「楼体投影」严丝合缝。
3. **引擎层仍然游戏无关**。`FreeViewControls` 不认识「城区」「楼宇」「objectInfo」，
   它只认识「聚焦点 `focus`（一个世界坐标 + 半径）」和「当前有无选中」两件事。
   「选中 → 聚焦点」的映射放在游戏侧薄适配层。

## 3. 需求 1 通用物体选中设计

### 3.1 选中语义（复用 objectInfo）

- **左键点击**任何物体 → `useObjectInfoProps.onClick` 已把该物体写入
  `useObjectInfoStore.selected`（含 catalog id + 命中世界坐标）。
- 再次左键点击**同一物体** → 我们需要「toggle」。objectInfo 的 `setSelected(target)`
  目前只有「设置」。本批给它加**幂等 toggle**：如果传入的 target 与当前 selected
  的 **catalog id 相同**（同一类物体），就清空 selected（取消选中）。
- 左键点击**空白处**（地面/天空）→ objectInfo 已把 `ground.city` / `sky.cloud` 接入，
  这会把它们选成「物体」。这与「选中物体」的直觉不符。本批：**地面与天空的
  `useObjectInfoProps` 改 `hover: false` + 禁用选中**（不再 setSelected），让左键点空白
  = 什么都不选中（只用于关闭选中）。`focusRef`（小地图点击聚焦）不受影响。

### 3.2 选中物体的通用检索

`FreeViewControls` 需要拿到「选中物体的世界坐标 + 半径」，才有东西可以环绕。来源：

| 来源 | 类型 | 说明 |
|------|------|------|
| 命中坐标 | `target.pos: [x,y,z]` | objectInfo 的 `ObjectInfoTarget.pos` = 命中点 + anchorY |
| 半径 | 检索 | 在 freeViewColliders 的 353 个建筑 AABB 里找「包含命中点的那个」⇒ 取其半宽/半深/顶面 y |

逻辑放在游戏侧薄适配层 `selectedTargetFor(pos)`：
1. 遍历 colliders，找 `minX<=x<=maxX && minZ<=z<=maxZ && y<=maxY` 的第一个盒；
2. 命中 ⇒ `focus = { x: 盒中心x, y: 盒中心y, z: 盒中心z, radius: max(半宽,半深) + 碰撞半径余量 }`；
3. 未命中（点中了树/路灯等非建筑物体，或点中楼顶/桥面）⇒ 退化成一个**合理默认半径**
   （`fallbackOrbitRadius`，按物体类别：地面/水系用 6，街具/树用 3），聚焦点 = 命中点本身。

### 3.3 选中特效设计（通用、全物体适用）

`ObjectInfoOverlay` 的详情卡**保留**（用户要看信息），但它只是 DOM 卡片。
「选中特效」必须是 **3D 空间内的效果**，且对**任何物体**（不仅是建筑）都成立。

#### 3.3.1 一个统一的 `<SelectionMarker>` 组件

挂在 `VirtualCityCityMap` 的 Canvas 内（不是某个物体组件内），订阅
`useObjectInfoStore.selected`，按 `target.pos` 定位：

| 图层 | 几何 | 效果 |
|------|------|------|
| 地面环 | `THREE.RingGeometry(0.85r, r, 48)`，X 轴 -90° 躺平 | 亮青 `#38bdf8`、透明 0.65、`AdditiveBlending` |
| 竖环 | 外接圆柱的 3/4 截面（顶点在 shader 内按 `theta ∈ [0, 3π/2]` 弧形扫掠） | 同上，作为「包裹物体」的立面指示 |
| 呼吸脉动 | `useFrame` 里 `scale = 1 + 0.05·sin(t·2.6)` + `opacity = 0.55 + 0.15·sin(t·2.6)` | 让「选中」一眼可辨 |
| 距地悬浮 | 环的 y 固定 `groundY + 0.06`（略浮于地面/水面） | 不被 z-fight |

> 设计为**通用**：不只服务建筑。r 从 §3.2 检索出来（建筑用盒半径，其它物体用 fallback），
> 环只是「一个半径 + 一个中心点」，与物体形状无关。这样**不需要**改任何物体组件。

#### 3.3.2 为什么不在被选中物体上「包一个半透明盒」

- 353 栋楼的合并 mesh（`DistrictBuildings` 按材质签名合并）是**多栋楼共享一个 mesh**，
  单独给某一栋加材质覆盖会破坏合并 ⇒ 每栋楼都得独立材质，draw call 退化。
- 非建筑物体（路灯/行人/云）形状各异，「包盒」观感差。
- 环 + 竖环是**通用几何**，不依赖物体本身。

| 落点 | 动作 |
|------|------|
| orbit 语义 | orbit 不再是「任意时刻的轨道相机」，而是**只有一个固定落点**的「归零点」。设 `FOCUS_TARGET: [0, 0, 0]`、`FOCUS_RADIUS: W*0.35=42`、`FOCUS_PHI: 0.85`、`FOCUS_THETA: π/4`（保持 [42,36,42] 落点）。按 orbit = 飞到并停在这个固定点；不再支持自由 orbit |

fly 仍是 N4 的载体：未选中物体时 WASD 沿视线移动（含俯仰分量），可任意位置、穿水平面。

## 5. 需求 5 fly 选中环绕设计

### 5.1 引入「选中聚焦」子状态

`FreeViewControls` 增加一个可空聚焦点（世界坐标 + 半径）：

```ts
focus: { x: number; y: number; z: number; radius: number } | null
```

来源 = 游戏侧 prop `selectedFocus`（§3.2 算好后传入）。每帧 fly 积分前先检查：

| `focus` 状态 | fly 行为（WASD 含义） |
|------------|---------------------|
| `null`（未选中） | 原 fly：W/S 沿视线前/后（含俯仰），A/D 沿视线左/右，`Space/E/Q` 垂直升降 |
| 非空（选中） | **轨道环绕**：`pos` 围绕 `focus` 旋转/缩放；W/S = 半径减小/增大（拉近/拉远）；A/D = theta ±；`Space/E/Q` 仍垂直升降（N5 允许任意位置）；朝向 `lookAt(focus)` |

### 5.2 环绕状态的相机朝向

环绕时 `quaternion = lookAt(pos, focus)`，与 orbit 一致。若用户想「一边环绕一边环视」，
可在环绕状态下用右键拖拽改朝向 —— 这会让相机的 lookAt 与 focus 偏离。为避免纠结：

- 环绕状态下**右键拖拽仍然可用**（改 yaw/pitch）；
- 但每帧环绕积分后，如果 `focus` 存在，最终 quaternion **强制 lookAt(focus)**，
  保证「环绕物体」这个语义不丢；
- 若用户想脱离环绕（取消 lookAt），左键点空白取消选中即可（§3.1）。

### 5.3 环绕的边界与碰撞

- 环绕 `radius` clamp 到 `[collisionRadius+0.5, maxDistance]`；
- 环绕后的 `pos` 仍走既有 `collide()`（建筑推出 + 地图边界 + 地面钳制），保证不会穿进楼；
- 环绕目标 `focus.y` 若落在建筑内，允许（相机会被推出到楼外，符合直觉）。

### 5.4 未选中 → 选中的平滑切换

当 `focus` 从 null 变成非空（或反过来）时，不硬切：直接把当前 `pos` 投影到
「以 focus 为中心、保持当前到 focus 距离」的球坐标上，下一帧开始环绕积分。
因为 fly 本身也是连续移动，这个投影是无跳变的（距离保持，仅约束方式变）。

### 5.5 选中状态下的速度 FOV

环绕时 `s.vel` 记录的是「位置变化率」（含切向 + 径向），自适应 FOV 仍适用
（切向速度大会让 FOV 张开，与「绕物体快速环绕」的体感一致）。
