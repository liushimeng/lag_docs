## 3. 总体方案

### 3.1 分层与职责

```

│   ├── cameraCollision.ts   新增：CameraBox + 球-AABB 推出 + 地图边界 + 地面钳制

│   ├── FreeViewControls.tsx 新增：三模式统一控制器 + 过渡状态机 + 快捷键 + 输入
│   ├── FreeViewHud.tsx      新增：DOM HUD（模式分段控件 / 键位帮助 / 碰撞指示）
│   ├── freeview.css         新增：HUD 样式（引擎层自持）
│   ├── CameraViewReporter.tsx 改：可选上报 yaw / fov（供小地图画视锥）
```

### 3.2 为什么替换而不是叠加

原 `orbit` 与 `walk` 是两套**互斥挂载**的控制器，切换靠重挂载（epoch）→ 无法做位姿插值（R11）。
自由飞行与轨道俯瞰共用「相机位姿」这一状态空间，本质上应该由**同一套积分器**驱动，
只在「输入 → 目标量」这一层分流。因此本批做**替换**：

- `WalkControls` 的能力（贴地、眼高、Shift 加速、文本编辑守卫、pitch ±83°）作为
  `FreeViewControls` 的 `walk` 模式保留，行为不回退；
- 删除 `WalkControls.tsx` 避免两套实现并存（§130 反模式）。

### 3.3 解锁策略

R12 要求「多数应用仅在建造/观察/暂停模式解锁全自由视角」。虚拟城市的定位声明是
「全 Agent 真实城市模拟器」，玩家全程处于**观察/调度**语义（无角色骨骼、无破坏操作），
故三模式**全程可用**，不设解锁门槛。若后续引入建造态，`FreeViewControls` 的
`allowedModes` prop 可直接收窄。

## 4. 三模式设计

### 4.1 公共骨架

单一 `FreeViewControls` 组件持有一份「相机目标量」状态，**每帧**按当前模式把它推进为
`camera.position` / `camera.quaternion` / `camera.fov`：

```
模式 ── 输入映射 ──→ 目标量（带阻尼） ──→ 积分 ──→ 碰撞/边界/地面钳制 ──→ camera
```

| 模式 | 内部状态 | 相机位置由谁决定 |
|------|---------|-----------------|
| `orbit` | `target: Vector3` + 球坐标 `(radius, phi, theta)` | `target + sphericalOffset(radius, phi, theta)` |
| `fly` | `pos` + `(yaw, pitch)` + 速度矢量 | 速度积分（自由六自由度） |
| `walk` | `pos` + `(yaw, pitch)`，y 恒 = `eyeHeight` | 水平速度积分，y 贴地 |

### 4.2 `orbit` — 轨道式俯瞰（默认）

| 输入 | 行为 | 目标量 |
|------|------|--------|
| 左键拖拽 | 绕目标公转 | `theta -= dx·k`、`phi -= dy·k`，`phi ∈ [0.05, 1.545]` |
| 右键拖拽 | **平面平移**（屏幕 X/Y 映射到相机右/上向量在水平面与 Y 上的投影） | `target +=` |
| 滚轮 | **缩放视距** | `radius *= exp(±0.12·step)`，clamp `[minDistance, maxDistance]` |
| `WASD`/方向键 | 平移聚焦点（沿视线水平前/右） | `target +=` |
| `E`/`Q` | 聚焦点升/降 | `target.y +=` |
| `Shift` | 平移加速 ×4 | — |

### 4.3 `fly` — 全自由六自由度

| 输入 | 行为 |
|------|------|
| **右键按住拖拽** | 控制**俯仰与水平旋转**（`yaw` 无界、`pitch ∈ [-1.553, 1.553]` ≈ ±89°，防翻转） |
| **WASD**/方向键 | 沿视线**前后** + **左右**平移（`W` 含俯仰分量 ⇒ 真六自由度） |
| **中键拖拽** | **视口平移**：在**垂直于视线的屏幕平面**内平移相机，朝向不变 |
| **滚轮** | 改 FOV（`[25, 80]`），不动位置 —— 远处建筑细节的「长焦检视」 |
| `Space`/`E` · `Q` | 垂直上升 / 下降（R9） |
| `Shift` | 加速 ×4 |
| `[` `]` | 档位 慢/常/快（×0.25 / ×1 / ×4） |

### 4.4 升降键位冲突裁决（R6/R9 vs R7）

规格一写「空格、Shift 分别控制垂直上升与下降」，规格二写「部分场景搭配 E/Q 键实现垂直升降」。
二者冲突（`Shift` 在通用 3D 规范里是加速键，本仓 `WalkControls` 亦如此）。
**裁决**：默认 `Space`/`E` 上升、`Q` 下降、`Shift` 保留为加速键（Web 端惯例优先），
并把升降键做成可配 prop（`verticalKeys`），需要规格一行为的调用方传
`verticalKeys={{ up: ['Space'], down: ['ShiftLeft','ShiftRight'] }}` 即可，无需改引擎。

### 4.5 限位表（R13）

| 项 | 缺省 | 虚拟城市传值 | 说明 |
|----|------|------------|------|
| `minDistance` / `maxDistance` | `2 / 100` | `W*0.06=7.2` / `W*1.5=180` | 7.2 单位 = 72 m，下限低于旧值 12 以支持贴脸看楼 |
| `minPolar` / `maxPolar` | `0.02 / 1.545` | 同缺省 | 0.02≈1.1°（近正上方），1.545≈88.5°（近水平，留 1.5° 余量防地平线穿帮） |
| `pitchLimit`（fly/walk） | `±1.553`（89°） | 同 | 防翻转 |
| `minY` / `maxY` | `0.1 / 200` | `u(2.5)=0.25` / `140` | 下限兼作地面/水面安全线 |
| 地图包围盒 | 由调用方给 | `x∈[-88,88] z∈[-88,155] y∈[0.25,140]` | 覆盖四缘带 ±80 与南海洋 z→150 |

### 4.6 输入卫生（R16 + R10 冲突规避）

| 关注点 | 实现 |
|--------|------|
| 右键默认菜单 | 控制器挂载期间对 `gl.domElement` 监听 `contextmenu` → `preventDefault()` |
| 页面失焦暂停 | `window.blur` → 清空按键集合 **且** 速度/角速度立即归零（避免切回页面瞬间漂移） |
| 文本编辑不劫持 | `isTextEditingTarget()`（沿用 `WalkControls.tsx:42-51` 实现，逻辑上提到 `cameraMath.ts`） |
| 修饰键 | `ctrl/meta/alt` 按下时全部按键忽略（不劫持浏览器快捷键） |
| 拖拽不误触选中 | 位移累计 > 4px 判定为拖拽 → 在 canvas **捕获阶段**吞掉紧随其后的那一次 `click`（解 R10） |
| 指针捕获 | `setPointerCapture` 保证拖出 canvas 不丢轨迹（沿用 `WalkControls.tsx:114`） |

## 5. 碰撞与边界（R3）

### 5.1 算法

**球 vs AABB 最近点推出**（保守、无抖动、天然处理角点）：

```
对每个 box（膨胀 r）：
  q = clamp(p, box.min, box.max)          // p 在 box 内的最近点
  d = p - q ; L = |d|
  若 L >= r → 不相交
  若 L > 1e-6 → p = q + d/L · r          // 侧面推出
  否则（球心在盒内）→ 沿最小穿透轴推出到面上
```

- 遍历 32 区 ×(8~14) 栋 ≈ **340 个 AABB**，每帧先做**平方距离早退**（球心到盒的 AABB 距离 > r
  即跳过），实际参与计算的通常 < 10 个 ⇒ 每帧成本可忽略（< 0.05 ms）。
- 无 `Raycaster`、无 BVH：静态数据 + 早退足够，且不产生 GC 压力（全程复用临时向量）。

### 5.2 碰撞体装配（`freeViewColliders.ts`）

```ts
// 模块级一次性装配（确定性，无 React）
CITY_COLLIDERS = VIRTUAL_CITY_DISTRICTS.flatMap(def =>
  buildingsFor(def).map(s => ({
    minX: def.x + s.x - s.w/2, maxX: def.x + s.x + s.w/2,
    minZ: def.z + s.z - s.d/2, maxZ: def.z + s.z + s.d/2,
    minY: 0,                        // 底贴地
    maxY: buildingTopY(def.id, prosperityOf(priceIndexOf(def.id)), s.factor),
  })))
```

- `buildingsFor` 是纯确定性函数 ⇒ 与 `DistrictBlock` 渲染出的位置**逐字节一致**。
- 楼高依赖 `price_index`（WS 推送变化）⇒ 碰撞体在 `useMemo([marketById])` 里重装配。
  装配成本 ~340 次对象字面量，可忽略。
- **不把道路/绿化/车辆纳入碰撞**：车辆与行人是动态贴图级小物件，相机穿行它们的观感优于
  「贴地横移时被路灯挡住」；道路用**地面高度钳制**处理即可（§5.3）。

### 5.3 地面钳制与「能不能钻到桥下」

- `minY` 钳制对**全模式**生效（`orbit` 也不例外 —— 否则拉近半径会插到地底）。
- 运河/港池水面 `y≈0.02`（`WaterPlane`），与城区地面同高，**不做水面差异化**：
  本世界无「桥下空间」（运河桥面为平铺 plane），统一钳制即可。
- `walk` 模式额外把 y 锁死为 `eyeHeight`，同时对地面高度取 `max(groundY, eyeHeight)`。

## 6. 阻尼（R4 / R14）

### 6.1 帧率无关指数阻尼

所有标量走 `THREE.MathUtils.damp(cur, target, lambda, dt)`（`= cur + (target-cur)·(1-e^{-λ·dt})`），
向量逐分量。**不用** `lerp(cur, target, 0.08)`（那会让手感随帧率漂移 —— 60 fps 与 144 fps
手感不一致，是 Web 3D 最常见的「抖动/黏滞」投诉来源）。

| 通道 | λ | 半衰期 | 主观 |
|------|---|-------|------|
| 转向（orbit theta/phi、fly yaw/pitch） | 18 | 39 ms | 跟手但无生硬 |
| 平移 / 飞行速度 | 12 | 58 ms | 稍有重量感 |
| 缩放（radius / fov） | 10 | 69 ms | 明显顺滑 |
| FOV 自适应 | 3 | 231 ms | 几乎察觉不到，只在持续加速中缓慢张开 |
| 过渡动画 | — | 固定 600 ms | `easeInOutCubic`，见 §8 |

### 6.2 速度积分（fly）

```
accel  = 目标速度 - 当前速度   （各分量 damp λ=12）
pos   += accel · dt
```
「目标速度」而非「直接改位置」⇒ 松手后有惯性滑行，配合 `blur` 归零不会漂。

## 7. 动态 FOV（R5）

```
targetFov = clamp(userFov + speedFactor · GAIN, FOV_MIN, FOV_MAX)
camera.fov = damp(camera.fov, targetFov, λ=3, dt)
```

- `speedFactor = clamp(‖v‖ / (base·BOOST), 0, 1)`，恒速巡航时 FOV 稳定，增减速时缓慢呼吸。
- **降眩晕的机理**：外周视觉的「运动感」正比于 `角速度/焦距`；速度↑而 FOV 不变时角速度不变，
  但屏幕像素的世界流速↑，两者失配产生眩晕。速度↑时**同步放宽 FOV**，像素流速被摊薄，
  失配减小。故取**正增益**而非「越快越窄」。
- 幅度克制：`GAIN = 10°`（45 → 55），且 λ=3 使其在 1 s 内只完成一半位移 ⇒ 不产生「呼吸泵浦感」。
- 用户滚轮改的是**基准** FOV（`userFov`），与自适应叠加而非互相覆盖。

## 8. 视角切换过渡状态机（R11）

```
        setMode(m') / 快捷键
idle ──────────────────────────────► transitioning
  ▲                                      │ 每帧插值，t/dur 计时
  └──────────────────────────────────────┘
```

### 8.1 三阶段

1. **Seed（新模式状态从当前相机位姿播种）**
   - `→ orbit`：`target = camPos + forwardHoriz · clamp(radius, min, max)`，`(r,φ,θ)` 由
     `camPos - target` 反解 ⇒ **切过去后视线方向不变**，只是绕到了目标后方。
   - `→ fly`：`(yaw,pitch)` 由当前相机朝向反解，`pos = camPos`，`v = 0`。
   - `→ walk`：同上，但 y 落到 `max(groundY, eyeHeight)`。
2. **Transition（600 ms）**：输入锁定；每帧
   `pos = poseLerp(from, to, t)`，`quat = slerp(fromQuat, toQuat, t)`，`fov = lerp(fromFov, toFov, t)`。
   - `poseLerp` 模式由 `transitionMode` 决定，缺省 `'auto'`：
     **两端都是「绕点」语义（↔`orbit`）→ 球面插值**（绕共同 pivot 公转，轨迹最短且不穿地）；
     **其余（涉及 `fly`/`walk`）→ 线性插值**（位置无公转语义，线性最可预期）。
3. **Settle**：`t ≥ 1` ⇒ 直接把新模式的内部状态置为 Seed 算出的值（此时相机已在该位姿）⇒ 无跳变。

### 8.2 为什么 Seed 而非「重置到默认位姿」

规格只要求「不跳变」。若切换时重置到 `CAMERA_START`，玩家每次按 `V` 都被甩回城市角落，
在 1200 m × 1200 m 的世界里是灾难性体验。Seed 保留玩家当前视线，切换只改变**约束方式**
（绕点 / 自由 / 贴地），这是主流 3D 工具（Maya / Unreal / Blender 导航模式）的做法。

### 8.3 快捷键（R11 / R15）

| 键 | 行为 |
|----|------|
| `V` | 在 `orbit → fly → walk → orbit` 循环 |
| `1` / `2` / `3` | 直达 俯瞰 / 自由 / 漫游 |
| `F` | 在「俯瞰 ↔ 自由」两态间快速往返（最常用） |
| `R` | 重置到 `initialTarget` / `initialPosition`（当前模式内） |
| `H` 或 `/` | 展开/收起键位帮助 |
| `[` / `]` | 速度档位 慢/常/快 |
| `Esc` | 收起帮助（不退出模式） |

全部走 `isTextEditingTarget()` + 修饰键守卫；`Esc` 与 `ObjectInfoOverlay` /
`ResidentProfileDrawer` 的既有 `Escape` 监听**并存不冲突**（各自只做自己的事）。
