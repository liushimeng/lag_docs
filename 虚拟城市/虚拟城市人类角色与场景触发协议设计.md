## 1. 问题诊断：为什么模拟器需要人类角色协议

### 1.1 三种可能的介入方式

| 介入方式 | 是否允许 | 原因 |
|---|---|---|
| 人类作为**居民**入座参与城市生活 | **禁止** | 人类决策会污染「全 Agent 涌现」这一核心命题；且与十万级居民 Agent 的统计口径不可比 |
| 人类作为**观察者**只读观看 | 允许 | 不改变系统状态，是研究、教学、演示的基础入口 |
| 人类作为**条件触发者**注入外部条件 | 允许（受限） | 这是预测运行的**自变量**——不注入条件，就无法做「如果……会怎样」的反事实研究 |

### 1.2 核心风险与本文档的闭合方式

| 风险 | 后果 | 闭合条款 |
|---|---|---|
| 人类入座 | 涌现结论失去可比性 | §2.2 硬约束：`virtual_city` 恒全 Agent，人类 join 一律 `35036` |
| 人类直接操纵居民 | 模拟退化为木偶戏 | §3.4 注入只改「世界条件」，不指定个体反应 |
| 无痕注入 | 预测报告不可复现、不可引用 | §3.5 审计流水 + 种子 + 基线快照三件套 |
| 滥用注入（刷屏、轰炸） | 系统过载 / 结果失真 | §3.6 速率限制与配额 |
| 注入等同「上帝视角」外挂 | 观察者获得不当信息优势 | §2.1 观察者也只看到与公开事件流一致的信息 |

## 2. 人类角色模型与权限矩阵

### 2.1 两种角色

| 角色 | 身份说明 | 权限 | 入口 | 限制 |
|---|---|---|---|---|
| **观察者（Observer）** | 只读观战者；不占座位、不进入 `Hub.rooms` | 查看 `game.state`、地图与城区、事件流、居民档案（公开字段）、指标看板、历史回放 | 房间列表「👁 观察」；路由 `/virtual-city/spectate/:roomId` | 不可发送任何输入帧（后端一律 `30011`）；不可查看未公开的居民私有字段 |
| **条件触发者（Condition Trigger / 场景操作员）** | 在观察权限之上，可向运行中的模拟注入场景条件 | 观察者的全部权限 + 调用场景目录 / 注入 / 注入记录三个接口 | 模拟房间页「场景推演台」面板（观察态即可见可操作） | 任意登录用户可用（与调研同权限口径）；受 §3.6 速率与配额约束；全部注入入审计流水 |

### 2.2 权限矩阵

| 能力 | 观察者 | 条件触发者 | 居民 Agent | 说明 |
|---|---|---|---|---|
| 连接观战 WS / 读 `game.state` | ✅ | ✅ | —（Agent 走内部通道） | 观战集合与参与集合互不相交 |
| 发送参与输入帧（`game.action` 等） | ❌ `30011` | ❌ `30011` | 虚拟城市无人类参与 | 人类入座在 HTTP 层即被拒（`35036`） |
| 发起调研问卷 | ✅ | ✅ | — | 既有能力，权限口径与注入一致 |
| 查询场景目录 | ✅ | ✅ | — | `GET /api/games/virtual_city/scenario_catalog` |
| 注入场景条件 | ❌ | ✅ | — | `POST /api/games/virtual_city/rooms/:id/scenario` |
| 查看注入记录 | ✅（公开事件流） | ✅（含自身 `actor`） | — | `GET /api/games/virtual_city/rooms/:id/scenarios` |
| 暂停 / 恢复模拟 | ❌ | ❌ | — | 仅服务端运维与房主策略控制 |
| 指定某居民的行为 / 修改其档案 | ❌ | ❌ | — | **绝对禁止**，即条件触发者也不可 |
| 修改规则参数（税率 / 利率基准） | ❌ | 仅可经 `policy_shock` 等场景**按协议**施加，且留痕 | — | 不走后台改参 |

### 2.3 硬约束（实现与验收共用）

1. **无人类座位**：创建 `virtual_city` 房间恒 `full_agent=true`，忽略客户端 `full_agent:false`；
   `JoinRoom` 在房间未命中全 Agent 集合时按 `game_kind=="virtual_city"` 兜底拒绝 `35036`。
2. **房间列表不提供「加入」**：大厅行只渲染「👁 观察」，行点击进入观战路由，不得触发 join。
3. **注入走 HTTP**：与调研一致，不新增 WS 输入帧；WS 侧人类输入拒绝规则保持不变（`30011`）。
4. **观察者与条件触发者同源可见**：注入结果通过公共事件流传回，不给人额外的私有数据通道。

## 3. 条件注入协议

### 3.1 接口契约

```
GET  /api/games/virtual_city/scenario_catalog
     → {code:0, data:{scenarios:[{kind, name, group, description,
          magnitudes:[1..5], default_magnitude, params:[...]}]}}

POST /api/games/virtual_city/rooms/:id/scenario
     body {kind, magnitude(1-5), duration_months?, target?, note?}
     → {code:0, data:{scenario:{id, kind, magnitude, applied_month, note},
          effects:[{metric, delta, text}]}}

GET  /api/games/virtual_city/rooms/:id/scenarios
     → {code:0, data:{scenarios:[最近 20 条注入记录]}}
```

错误码（backend-dev 按可用号段落位）：场景不存在 / 参数非法 / 房间未运行 / 本月注入超限。

### 3.2 可注入的内容

只允许注入《场景推演》§2 场景目录中的 `kind`，分组如下：

| 场景群 | `kind` | 作用对象 |
|---|---|---|
| 市场与经济 | `goods_price_shock` / `policy_shock` / `market_crash` | 商品篮子、税/利率/补贴参数、资产价格与杠杆 |
| 社会与舆情 | `survey_pulse` / `election_sentiment` | 问卷议题、媒体倾向、候选人议题设置 |
| 自然灾害 | `earthquake` / `tsunami` / `extreme_disaster` | 城区建筑、基础设施、人口与财政 |
| 未知灾难 | `meteorite` / `alien_invasion` | 全局信心、城市功能、制度应急 |

### 3.3 注入参数语义

| 字段 | 必填 | 语义 | 约束 |
|---|---|---|---|
| `kind` | 是 | 场景类型，决定传导模板 | 必须在目录内 |
| `magnitude` | 是 | 强度 **L1–L5**（见《场景推演》§3） | 1–5 整数；默认取目录 `default_magnitude` |
| `duration_months` | 否 | 条件作用月数；缺省取该场景默认持续期 | 1–24；持续期内按衰减曲线退坡 |
| `target` | 否 | 作用目标（城区 ID / 行业 / 商品类目 / 候选人） | 必须在白名单内；**不得为单个人** |
| `note` | 否 | 操作者备注（研究假设、实验编号） | ≤200 字，入审计流水 |

### 3.4 注入的边界（红线）

1. **只改条件，不改行为**：注入只能改写世界状态字段（价格、税率、损毁率、舆情倾向），
   不得向任何居民 Agent 的 prompt 注入指令或暗示，不得指定「某居民必须如何反应」。
2. **不可 targeting 个体**：`target` 只接受城区 / 行业 / 类目 / 候选人等聚合对象。
3. **不可改写规则本体**：注入是「事件」，不是「改配置」；税率结构、会计恒等式、结算函数不可被场景修改。
4. **不可逆性说明**：自然灾害类注入对存量资产（建筑、基础设施）造成的是**状态改写**，
   恢复依赖重建机制而非「撤销注入」；撤销操作只对纯流量型场景（如政策冲击）开放。

### 3.5 审计流水

每次注入落一条不可变记录：

| 字段 | 说明 |
|---|---|
| `scenario_id` | 注入唯一 ID（与事件流一一对应） |
| `actor` | 操作者 `user_id` + 角色（条件触发者） |
| `kind` / `magnitude` / `target` / `duration_months` | 注入参数原样 |
| `applied_month` | 生效的模拟月 |
| `baseline_snapshot_id` / `seed` | 该运行可复现的三件套之二（第三件是运行编号） |
| `effects[]` | 首月直接冲击的指标与增量 |
| `note` | 操作者备注 |
| `created_at` | 墙钟时间 |

> **可复现判据**：`baseline_snapshot_id + seed + scenario 记录` 三者齐备的预测报告才可对外引用。

### 3.6 速率限制与配额

| 约束 | 建议值 | 理由 |
|---|---|---|
| 单房间单模拟月注入次数 | ≤2 | 防止同月多场景叠加导致归因不可分 |
| 单房间同时生效场景数 | ≤3 | 保证传导链可解析；超限拒绝并提示先等待衰减 |
| 单用户单房间每日注入次数 | ≤20 | 防刷屏与算力滥用 |
| 同 `kind` 冷却期 | ≥3 模拟月 | 防止重复叠加同一冲击制造数值爆炸 |
| 全局并发注入 | 由后端信号量控制，超限排队 | 与其他 LLM 重任务共享算力预算 |

## 4. 人类触发场景与内生事件的边界

| 维度 | 内生事件 | 人类触发场景 |
|---|---|---|
| 来源 | 城市内部机制（市场周期、企业生灭、舆情扩散、行为偏差） | 条件触发者经协议注入 |
| 元数据 | `event_type` + 系统归因 | `scenario_id` + `kind/magnitude/target/duration/actor` |
| 是否留痕 | 事件流自然记录 | 事件流 + 审计流水（双份） |
| 传导机制 | 同一套子系统 | **同一套子系统**（不写死结果） |
| 可复现 | 由全局 seed 决定 | 由 seed + 注入记录共同决定 |
| 是否可叠加 | 可 | 可，但与内生事件共振时报告须标注「共振放大」 |

**判断规则**：一次状态变化若无法追溯到 `scenario_id`，即为内生事件；若可追溯，即为注入后果，
报告中必须同时给出「有注入」与「无注入同种子基线」两条轨迹的差值。

## 5. 居民 Agent 决策策略分层 T1–T4

> 这不是「给人类选的难度」，而是**居民 Agent 的决策能力分层**，用于校准覆盖率：
> 一座城市必须同时包含不同理性程度的居民，宏观结果才不会被单一策略抹平。

### 5.1 分层总表

| 档位 | 名称 | 决策算法 | 对应《总体设计》§10.2 原型 | 在城市中的角色 |
|---|---|---|---|---|
| **T1 低理性** | 随机决策 + 保守储蓄 | 60% 随机动作 + 40% 保底储蓄 | 谨慎赵阿姨的简化版 | 提供噪声底与尾部样本，防止模型过度理性 |
| **T2 规则型** | 规则驱动 + 基础资产配置 | 固定规则树：按所处空间节点类型执行预设动作 | 保守王姨 / 谨慎赵阿姨 | 城市主体人群，决定宏观中位数 |
| **T3 启发式** | 启发式 + 市场周期感知 + 行为偏差 | 启发式规则 + 读市场周期四阶段 + 注入 §7 偏差 | 激进小李 / 社交张哥 | 泡沫与踩踏的放大器，行为金融研究主力样本 |
| **T4 专家型** | 多目标优化 + 博弈 + 信息不对称利用 | 短视规划（3–5 步）+ 对手建模 + 内幕套利 | 学习陈博士 + 上述全部 | 市场的「聪明钱」，提供价格发现下限 |

### 5.2 各档行为规格（校准用）

**T1 低理性**
- 投资动作：60% 走「存钱/买债券理财」等保底选项，40% 随机选择（不读 EV 表）。
- 永不主动加杠杆；偏差事件触发后无抗偏差能力，直接照单全收。
- **校准价值**：提供「乱买也能活」的下界，用于检验破产率红线 R-E5 是否被噪声撑爆。

**T2 规则型**
- 预置一棵决策树：`if 现金>阈值 then 买入当前节点资产; elif 命中投资节点 then 按类型买入; else 存贷`。
- 能做最基础资产配置（股/房/债各占一块），但**不感知市场周期**（繁荣顶部也买、衰退底部也不敢抄）。
- 出价函数：固定锚定公允价值的 ±10%，不竞价。

**T3 启发式**
- 在 T2 基础上：①读市场周期阶段（《规则手册》§7），繁荣期加仓、衰退期减仓；
  ②拥有 §7 的行为偏差，会在高点追涨、低点割肉；③会参与 1–2 种拍卖。
- 出价函数：锚定公允价值 ±20%，并带情绪加价（连赢后过度自信加价 +15%）。
- **关键**：T3 是**唯一注入行为偏差的档位**，因此它是观测「偏差→价格扭曲」因果链的主样本。

**T4 专家型**
- 短视动态规划：以「3–5 步后 FI Index 最大」为目标函数，在约束（现金/信用/精力）下选动作。
- 对手建模：记录其他居民过去 10 步的买卖行为，推断其持仓与偏好。
- 信息不对称：掌握内幕信息时（v2.59 Stockpile 机制）会优先套利；不轻易暴露仓位。
- **校准价值**：T4 几乎没有可利用偏差，是检验「市场是否给理性者正确定价」的对照组。

### 5.3 分层投放比例

| 校准阶段 | 建议分层 | 理由 |
|---|---|---|
| α 机制闭合 | T2×3（少量 T1/T3 点缀） | 先保证流程与守恒，避免偏差噪声干扰定位 |
| β 参数校准 | 按 §6.1 原型比例投放（含 T1–T4 全谱） | 保证宏观指标在真实异质性下成立 |
| γ 规模与压力 | 全量池按画像自然分布 | 检验十万级异质 Agent 的收敛性 |

## 6. 结算引擎：职责与边界

> 结算引擎（原「Agent 银行家」）不是角色，而是**城市账本的执行者**：只结算、不预测、不建议、
> 不偏袒。

### 6.1 职责清单

| 阶段 | 引擎职责 | 触发时机 |
|------|---------|---------|
| 发薪 | 月结：发放月薪 + 全部被动收入，扣月支出 + 税 + 社保 + 利息 | 每模拟月 S4 |
| 账本结算 | 所有交易实时改三表，自动勾稽校验（《规则手册》§3） | 每笔交易后 |
| 拍卖清算 | 宣布起拍价、倒计时、落槌、赢家诅咒判定（v2.58 P0-04，超付 ≥15% 触发） | T2 交易窗口 |
| 市场事件播报 | 周期切换（复苏/繁荣/衰退/萧条）时播报利率与通胀变动 | 五年节点 / 季度结算 |
| 偏差事件呈现 | 按《行为金融》§2 阈值触发偏差事件，给出情境描述 | 触发条件命中时 |
| 破产判定 | 现金 < D5 且无可变现资产时，宣布破产与清算顺序 | S7 目标检查 |

### 6.2 播报文本模板（客观口径）

| 场景 | 模板 | 语气要求 |
|------|------|---------|
| 发薪 | 「【月结】X 月工资到账 ¥{salary}，被动收入 ¥{passive}。本月房贷 ¥{mortgage}、社保 ¥{si} 已扣除，现金余额 ¥{cash}。」 | 平稳、无情绪 |
| 周期播报 | 「【市场】进入{繁荣/衰退}阶段：基准利率 {rate}%，通胀预期 {cpi}%。」 | 客观、不评论 |
| 拍卖落槌 | 「【拍卖】{asset} 以 ¥{price} 落槌给 {resident}。{若超付≥15%：已触发赢家诅咒，下期该资产收益打折。}」 | 中立、提示性 |
| 偏差事件 | 「【情境】{偏差事件描述，见《行为金融》§5}——请做出你的决定。」 | 不替居民做选择 |
| 破产宣告 | 「【清算】现金流已断裂，按《规则手册》§12 进入清算：{资产处置清单}。该居民以{温饱/破产}结局结束。」 | 克制、不羞辱 |

### 6.3 边界（红线）

1. **不预测、不建议**：不回答「我现在该不该买房」，只做客观数据播报（复盘教练另见 §6.4）。
2. **不偏袒**：对所有居民使用完全同一套结算函数。
3. **话术固定模板**：所有播报可审计，不允许临场发挥诱导居民。
4. **结算可申诉**：任何一笔结算，可要求引擎展示「计算式」（哪几笔流水相加），透明可查。

### 6.4 复盘教练（与结算引擎分离）

教练只在**周期后复盘**或**居民主动提问**时出现，基于当前三表数据做分析（不给答案）。
v2.58 P1-12 的「AI 理财教练」即此角色；本文档只明确**教练 ≠ 结算引擎 ≠ 市场对手**三者职责分离。

## 7. 行为偏差注入矩阵与可观测性

> 偏差的学术定义与事件卡定义均见《行为金融》，此处只规定**注入哪些档位、产生什么可观测轨迹**——
> 目的是让研究者能从公开事件流中**识别**偏差正在发生，而不是让「人类利用 AI 赚差价」。

### 7.1 注入矩阵

| 偏差（《行为金融》§1） | 注入档位 | 可观测行为轨迹 | 对市场价格的影响 | 研究价值 |
|----------------------|---------|--------------|----------------|---------|
| **损失厌恶** | T3 激进小李 | 浮亏 >20% 时拒绝割肉，硬扛到腰斩 | 下跌时卖压延迟释放，尾部更深 | 观测「处置效应→流动性枯竭」 |
| **过度自信** | T3 / T4 | 连赢 3 次后下一笔加码 >净值 30% | 繁荣期换手率与杠杆同步抬升 | 观测「交易量—未来收益」负相关 |
| **羊群效应** | T3 社交张哥 + 同档 ≥2 个 | 一个 Agent 买入后同档跟风 | 局部价格自发放大 | 观测泡沫的微观起点 |
| **处置效应** | T2 规则型 | 只卖盈利资产、死扛亏损资产 | 供给曲线不对称 | 观测「赚跑输扛」的宏观代价 |
| **锚定效应** | T2 / T3 | 出价死守买入价附近，不随行就市 | 价格粘性上升 | 观测通胀预期的传导迟滞 |
| **沉没成本** | T3 经营企业者 | 持续给亏损企业注资 | 僵尸企业占比上升 | 观测「僵尸企业—生产率」关系 |

### 7.2 设计约束

1. **偏差必须可观测**：研究者能通过公开事件流（持仓公开、买卖播报）判断某居民正处于哪种偏差，
   否则无法做因果归因。
2. **偏差不能致命到必输**：只造成「次优」，不造成「自杀式错误」，否则会污染破产率红线。
3. **T4 不注入可利用偏差**：T4 的弱点是「过度理性导致不冒险」，作为理性对照组。
4. **归因闭环**：每次偏差事件触发后，事件流标注 `bias_type` 与 `tier`，供《校准框架》§4.4 的
   NEG-3 归因统计使用。

## 9. 场景注入与人类角色的校准指标

> 这些指标不进《校准框架》的主表，单独统计，用于治理与验收。

| 指标 | 定义 | 目标值 |
|------|------|--------|
| **注入审计完整率** | 含完整 `actor/kind/magnitude/applied_month/seed/snapshot` 的注入记录占比 | **100%** |
| **注入可复现率** | 同种子重跑后指标轨迹逐月一致的注入占比 | ≥99% |
| **注入归因可解析率** | 3 个月内能定位到具体传导链的注入后果占比 | ≥90% |
| **注入拒绝率** | 因配额/冷却/非法参数被拒的请求 ÷ 总请求 | 监控项（异常升高说明 UI 或额度设计有问题） |
| **观察者越权尝试拦截率** | 观察者发送输入帧被 `30011` 拒绝的次数 | 监控项（应为 100% 拒绝） |
| **人类入座拦截率** | `virtual_city` 人类 join 被 `35036` 拒绝 | **100%** |
| **注入面板可用性** | 从打开面板到完成一次注入的操作步数 | ≤4 步 |
| **单次注入响应时延** | 提交到首月效果回传的墙钟时间 | ≤2 秒（不含 LLM 排队） |
