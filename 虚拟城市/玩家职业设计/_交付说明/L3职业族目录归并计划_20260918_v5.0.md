## 1. 问题：同一个职业被拆成几十个目录

存量扫描发现，**同一个（行业 L1 → 细分 L2 → 职业名）**在历史上被按「L3 编号续号」反复新建目录，
而没有按职业名收敛，形成结构性冗余：

```
S-科学研究与技术服务/S03-检验检测与认证/
├── S0301-认证审核员/          ← 100 张卡
├── S0304-认证审核员/          ← 0 张（空壳）
├── S0307-认证审核员/          ← 0 张（空壳）
├── ... 共 49 个目录 ...
```

这不是「多份重复档案」，而是**同一职业族的档案被摊薄在 49 个编号壳子里**，导致：

- 单职业族的人口密度失真（仿真抽样时按目录/uid 取样会严重偏斜）
- 「文件名/目录」双层去重无法生效
- `10,030` 个目录里绝大多数是空壳或碎片

## 2. 归并规则

| 项 | 规则 |
|---|---|
| 分组键 | `(L1 行业, L2 细分, 职业名)` —— 职业名取目录名 `-` 之后的部分 |
| 保留项 | L3 码**字典序最小**的目录（如 `S0301-认证审核员`） |
| 卡片处理 | 其余目录下的卡片按**原 L4/L5 相对路径**整体搬迁进保留目录，<br>路径冲突时自动追加 `-dupN` 后缀 —— **一张卡都不删** |
| 卡内引用 | 同步把卡片 frontmatter 的 `industry_l3` 与正文职业族码替换为保留码 |
| 空壳清理 | 搬迁完成后，仅删除**确认为空**的旧 L3 目录树 |
| 回滚 | 全仓库 git 托管，`git checkout -- <path>` 可逐组回滚；执行前建议先确认工作区干净 |

## 4. 风险与对应措施

| 风险 | 等级 | 措施 |
|---|---|---|
| 搬迁过程中丢卡 | 高 | `shutil.move` 同分区 rename，原子性；逐目标落盘后**计数校验**：<br>执行前后全库卡片总数必须**恒等**（100,083 → 100,083） |
| 同名覆盖 | 中 | 目标已存在时自动 `-dupN` 避让，不覆盖任何既有文件 |
| 卡内 L3 码与路径不一致 | 中 | 搬迁后按组回写 `industry_l3`；执行后抽样 500 张校验路径 ↔ frontmatter 一致 |
| 正文职业族码误替换 | 中 | 只替换**该组自身出现过的旧 L3 码**，不做全局字符串替换 |
| 影响正在进行的其它治理批次 | 高 | 与本批次互斥执行；执行前确认无后台读写任务 |
