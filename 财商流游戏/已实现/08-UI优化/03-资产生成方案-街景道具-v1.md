## 2. 命名约定

### 2.1 城区/类别 `<id>` 取值

```
城区 id: finance | tech | industry | oldtown | commerce | residential | suburb | riverside
街道:    asphalt_main | asphalt_side | sidewalk_main | sidewalk_side | crosswalk | centerline
道具:    streetlamp | tree | vehicle | pedestrian | sign | rooftop
```

### 2.2 文件名格式

- 城区类：`{id}_{variant}.png`（facades），`{id}.png`（roofs，districts 已存在）。
- 街道类：`{name}.png`（name 即街道类型）。
- 道具类：`{variant}_{category}.png`（如 `oak_tree.png`、`sedan_vehicle.png`）。

> 设计动机：道具类用 `{variant}_{category}` 而非 `{category}_{variant}`，是因为
> `import.meta.glob` 会按字典序排序，前置 variant 在视觉列表/调试输出时更易扫读。

### 2.3 variant 字典（稳定 enum，不允许随意新增）

| 类别 | variant 取值 |
|------|------------|
| facade | `base` \| `mid` |
| streetlamp | `a` \| `b` \| `c` |
| tree | `oak` \| `pine` \| `palm` |
| vehicle | `sedan` \| `truck` \| `bus` \| `taxi` |
| pedestrian | `warm` \| `cool` |
| sign | `traffic` \| `info` |
| rooftop | `ac` \| `tank` \| `antenna` |

新增 variant 需同步更新：
1. `index.ts` 的字面量联合类型。
2. 本文档 §2.3 + 资产脚本 `*_VARIANTS` 列表。
3. 调用方 `StreetPropsLayer.tsx` / `BuildingMesh.tsx`。

### 4.4 占位图绘制逻辑

```python
def placeholder_solid(width: int, height: int, color: tuple[int, int, int], label: str = "") -> Path:
    img = Image.new("RGBA", (width, height), color + (255,))
    draw = ImageDraw.Draw(img)
    # 1px 白色描边
    draw.rectangle([(0, 0), (width - 1, height - 1)], outline=(255, 255, 255, 200), width=1)
    # 居中 label（如 "FB" = finance base）
    if label:
        try:
            font = ImageFont.truetype("DejaVuSans-Bold.ttf", min(width, height) // 8)
        except OSError:
            font = ImageFont.load_default()
        bbox = draw.textbbox((0, 0), label, font=font)
        x = (width - (bbox[2] - bbox[0])) // 2
        y = (height - (bbox[3] - bbox[1])) // 2
        draw.text((x, y), label, fill=(0, 0, 0, 255), font=font)
    out_path = OUTPUT_DIR / f"{label or 'placeholder'}.png"
    img.save(out_path)
    return out_path
```

### 5.4 脚本骨架（伪代码）

```python
def main():
    args = parse_args()
    api_dead = False
    consecutive_failures = 0
    tasks = build_task_list(args.only)  # [(category, key, desc, size, output_path)]
    results = []
    for idx, task in enumerate(tasks, 1):
        out_path = task.output_path
        if out_path.exists() and not args.force:
            results.append((task, "skip", out_path))
            continue
        if api_dead or args.placeholder:
            out_path = placeholder_for(task)
            results.append((task, "placeholder", out_path))
            continue
        try:
            gen_one(gen, task)  # 实际调 ArkImageGenerator + resize
            consecutive_failures = 0
            results.append((task, "api", out_path))
        except Exception as exc:
            consecutive_failures += 1
            if consecutive_failures >= 3:
                api_dead = True
            # 单张占位兜底
            out_path = placeholder_for(task)
            results.append((task, "placeholder", out_path))
    print_summary(results)
```

        prompt=PROP_TMPL.format(style=STYLE, desc=desc),

### 5.6 Ark API 调参

- **model**: `doubao-seedream-5-0-pro-260628`（与现有脚本一致）。
- **watermark**: `False`。
- **response_format**: `url`（高分辨率走 URL 下载 + 本地 resize）。
- **timeout**: 120s（与现有脚本一致）。
- **retry**: 单张失败重试 1 次（网络抖动），不递增。
- **consecutive_failures**: 连续 3 张失败判定 API 不可用，剩余全部转占位。

## 6. 配额策略与失败回退

### 6.1 配额假设

- 单次生成一张图约消耗 1 unit（豆包 model 计费略不同，本脚本不计算费用）。
- 首批 28 张占预算 ≤ 30 units；全量 64 张 ≤ 70 units。
- API 失败回退：自动 Pillow 占位（保证 CI 不崩）。

### 6.2 失败回退矩阵

| 失败类型 | 单图回退 | 全局回退 |
|---------|---------|---------|
| 网络超时 / 5xx | 单图占位 + 重试 1 次 | 连续 3 次失败 → 全局占位 |
| 4xx（请求非法）| 不重试，记日志后占位 | 不切换全局 |
| API 返回 base64 太大 | resize_image 自动降级 | 不切换 |
| 本地磁盘满 | 抛出异常，脚本中止 | — |

### 6.3 CI 兜底保证

- 即使全部 API 失败，所有 60+ PNG 仍以 Pillow 占位形式存在 → `npm run build` 通过。
- 前端 `import.meta.glob` + 空串降级链 → 即使文件是 0 字节占位，组件也不崩。

### 6.4 重新生成策略

- `--force` 强制重新生成所有资产（覆盖现有 PNG）。
- `rm <某张>.png` 删除后单跑 → 仅该张重新生成。
- `--only facades:finance` 仅生成指定子集。
