> 2026-09-19 用户需求响应。
> 需求原文：*「现在创建房间界面，背景是深蓝色，文字是黑色，导致显示看不清界面，

## 1. 结论摘要（TL;DR）

创建房间界面「深蓝底 + 黑字」**不是配色设计问题，而是一次 CSS 变量作用域泄漏事故**，
并连带牵出**一处波及全站的按钮样式污染**：

| # | 缺陷 | 实测对比度 | 根因一句话 |
|---|------|-----------|-----------|
| **D1** | 档位按钮（选中态）黑字压深蓝底 | **1.07:1** ❌ | `.wealth-tier-btn--active` 底色写 `var(--wealth-accent-strong)`，弹窗在 portal 内取不到该变量 → 底色透明 |
| **D2** | 底部「创建房间」主按钮同样黑字 | **1.02:1** ❌ | 同上，出处是 `wealth.css` 里**未加命名空间的全局** `.btn-primary` |
| **D3** | 所有 `.btn` 背景透明 / 无边框 / 触控高度失效 | — | `.btn` 的 `background/border/min-height` 三个值全是 `var(--wealth-*)` → 全部 undefined → `unset` |
| **D4** | 输入框、下拉、座位容器边框整条消失 | `border=0px/none` | `border: 1px solid var(--wealth-border)` → 整条声明作废 |
| **D5** | 表单标签 / 座位号 / 职业卡丢失文字层次 | — | `color: var(--wealth-text-dim)` → 回退为继承色 |
| **D6** | **全站污染**：辩论、象棋、狼人杀、大厅的 `.btn-primary` 全部变透明+黑字 | **1.02:1** ❌ | `wealth.css` 的全局 `.btn*` 在构建产物中**排在最后**，同级特异度直接胜出 |
| **D7** | `.minsky-moment-flash` 红屏闪烁从不触发 | — | CSS 写 `.minsky-moment-flash`，JSX 写 `wealth-minsky-moment-flash`（§130 复发） |
| **D8** | `wealth-p2.css`（504 行）**完全未生效** | — | `@import` 被放在 `wealth.css:1617`（文件末尾），位置非法被 Vite 丢弃，产物 0 命中 |

> **D6 是「大厅 `创建房间` 按钮看不清」的直接原因**——该按钮 `.btn.btn-primary.wealth-lobby__create`
> 位于 `.wealth-root` 之外，拿到的是 `wealth.css` 的全局规则，底色透明 + `#1a1305` 黑字。

## 2. 现状分析

### 2.1 事故链条

```
wealth.css:13   --wealth-* 十个设计令牌只挂在 .wealth-root 作用域
                        │
   ┌────────────────────┴────────────────────┐
   │                                          │
.wealth-root 内                            .wealth-root 之外
（WealthGamePage.tsx:183 唯一挂载点）        ├─ AppModal portal → document.body
   │                                        │   （建房/拍卖/议价/提前还款/终局 5 个弹窗）
   │ ✅ 变量可解析                           └─ WealthLobbyPage（className="lobby wealth-lobby"）
   │                                            大厅页与「创建房间」按钮
   │                                        │
   │                                        └─ ❌ var() 全部 undefined
   │                                              → 声明「计算期无效」→ 等价 unset
   │                                                 ├─ background  → transparent
   │                                                 ├─ border      → 0px/none
   │                                                 ├─ min-height  → auto
   │                                                 └─ color       → 继承（但选中态写的是
   │                                                                  字面量 #1a1305 → 黑字）
```

**关键证据**：`--wealth-*` 令牌在全仓库**只有一处定义**（`wealth.css:13`）：

```
$ grep -rn -- ":--wealth-accent-strong:\|--wealth-text:\|--wealth-panel-2:" ClientWeb/src/
ClientWeb/src/styles/wealth.css:15:  --wealth-accent-strong: #d4a017;
ClientWeb/src/styles/wealth.css:18:  --wealth-panel-2: #1c2431;
ClientWeb/src/styles/wealth.css:20:  --wealth-text: #e5e7eb;
```

共 **200 处** `var(--wealth-*)` 引用，全部依赖这唯一作用域。

### 2.2 为什么「文字是黑色」而不是回退成浅色

自定义属性未定义时，`var()` 无回退值 → 该声明**计算期无效**，等价 `unset`：

- 对**继承属性**（`color`）→ `unset` = `inherit` → 取父级 `--text`（浅色）；
- 对**非继承属性**（`background-color` / `border-*` / `min-height`）→ `unset` = 初始值 → 透明 / 无边框 / auto。

于是**恰好只有「选中态」会变黑**——因为它把文字色写成了**字面量**、把底色交给了变量：

```css
.wealth-tier-btn--active {
  background: var(--wealth-accent-strong);  /* → transparent（深蓝底透出来） */
  border-color: #f0d387;                    /* 字面量：金边仍在 */
  color: #1a1305;                           /* 字面量：近黑字 ← 看不清的真凶 */
  box-shadow: 0 0 0 2px rgba(212, 160, 23, 0.55);  /* 字面量：金色光晕仍在 */
}
```

> 即：用户在弹窗里看到的是**金色描边 + 金色光晕 + 近黑色文字悬在深蓝底上**——
> 控件「看得见轮廓、读不清文字」，与需求描述完全吻合。

### 2.3 D6 全站按钮污染（级联顺序证据）

`globals.css:94` 是 `@import './wealth.css';` 的**最后一行**（§2.1 约束 4 规定只追加不改序）。
构建产物中 `.btn-primary` 的出现顺序（`grep -o` 实测）：

```
.btn-primary{background:var(--accent);color:#fff}                       ← xiangqi.css:163
.btn-primary{background:var(--accent);color:#fff;font-weight:700;...}   ← ?（带光晕变体）
.btn-primary{background:#3b82f6;color:#fff}                             ← debate.css:924
.btn-primary{background:var(--wealth-accent-strong);border-color:#f0d387;color:#1a1305}  ← wealth.css:1153 ★最后一条
```

四条特异度均 `(0,1,0)` → **最后一条通吃全站**。
而 `wealth.css` 尾部这一整块 `.btn*` 规则（L1129–1180）**通篇没有 `.wealth-` 前缀**，
直接违反该文件自己在 L3 写下的命名空间约定：

> `命名空间：全部选择器前缀 .wealth-（杜绝与既有样式互染）`

## 3. 实测验证方法（可复现）

不依赖登录（CAPTCHA 无旁路，CLAUDE.md §21），而是**直接对真实构建产物 CSS 字节做计算样式审计**：

1. `npm run build` → 取 `ClientWeb/dist/assets/index-*.css`（311 KB，含全部级联）；
2. 用一份复刻 `AppModal`（`createPortal → document.body`）**真实 DOM 结构**的静态页
   `harness.html` 加载该 CSS——**刻意不复刻 `.wealth-root`**，即 portal 的真实处境；
3. Chrome CDP（`127.0.0.1:9222`，复用已运行的调试实例）注入脚本，
   对 **26 个控件选择器**逐一求 `getComputedStyle`，并沿祖先链做 alpha 合成求出**实际可见底色**，
   按 WCAG 相对亮度公式算对比度。

## 4. 解决方案（前端 CSS，4 处改动，全部落在 `wealth.css`）

### F1 — 设计令牌提升为全局作用域（修 D1–D5）

把 10 个 `--wealth-*` 令牌从 `.wealth-root` 移到 `:root`；`.wealth-root` **只保留布局属性**：

```css
/* 令牌挂 :root —— 前缀已自带命名空间（--wealth-*），全局无碰撞风险；
   AppModal 经 createPortal 渲染到 document.body，位于 .wealth-root 之外，
   令牌若仍挂在 .wealth-root，弹窗内 200 处 var(--wealth-*) 全部解析失败。 */
:root {
  --wealth-accent: #c9a227;
  --wealth-accent-strong: #d4a017;
  --wealth-bg: #10151d;
  --wealth-panel: #161d28;
  --wealth-panel-2: #1c2431;
  --wealth-border: #2c3644;
  --wealth-text: #e5e7eb;
  --wealth-text-dim: #b7bfcc;
  --wealth-pos: #4ade80;
  --wealth-neg: #f87171;
  --wealth-touch-target: 44px;
}
.wealth-root {
  display: flex; flex-direction: column; min-height: 0; height: 100%;
  color: var(--wealth-text); background: var(--wealth-bg);
}
```

> 为什么不给 AppModal 加 token class？——AppModal 是全站共享组件（狼人杀/辩论/模型后台等
> 均在用），改动其 API 的回归面远大于改一个 CSS 文件；令牌本就是 `--wealth-*` 命名空间，
> 提升作用域零语义副作用。

### F2 — 给全局 `.btn*` 块加回作用域（修 D6）

`wealth.css` L1128–1180 的 `.btn / .btn-primary / .btn-secondary / .btn-danger`
及各自 `:hover` / `:disabled` 变体，统一改为三个「财商流必须有效的上下文」：

```css
/* 财商流按钮需要生效的三处上下文：
   ① .wealth-root —— 对局页内；② .wealth-lobby —— 大厅页（含「创建房间」按钮）；
   ③ .app-modal   —— 5 个弹窗经 portal 渲染在 .wealth-root 之外。
   加作用域后不再以同级特异度压过 xiangqi/debate 的 .btn-primary（D6 全站污染的根治）。 */
.wealth-root .btn, .wealth-lobby .btn, .app-modal .btn { ... }
.wealth-root .btn-primary, .wealth-lobby .btn-primary, .app-modal .btn-primary { ... }
/* …其余变体同构 */
```

> **对既有页面的影响**：辩论 / 象棋的**页面级**按钮恢复各自 `debate.css:924` /
> `xiangqi.css:163` 的蓝底白字（修复）；各游戏**弹窗内**按钮维持现状视觉（本来就被
> wealth 规则覆盖，不构成回归）。

### F3 — disabled 去 `opacity` 反模式（修 D9，§26.2 #5）

```css
/* 原 opacity: 0.5 命中 §26.2 反模式 #5（污染选中态判定）。
   改为独立灰底 + cursor:not-allowed。 */
.wealth-root .btn:disabled, .wealth-lobby .btn:disabled, .app-modal .btn:disabled {
  background: #2a3240; border-color: #3a4655; color: #8b949e; cursor: not-allowed; opacity: 1;
}
```

同步覆盖 `.btn-danger:disabled`（原 `#4c1d95 + opacity:0.5`）。

### F4 — 死选择器归位（修 D7，§130）

`.minsky-moment-flash` → `.wealth-minsky-moment-flash`（L1028 与 L1576 两处），
与 `MinskyStatusBar.tsx:69` 的 JSX 类名对齐。

### F5 — 弹窗内原生控件可读性补强（防患于未然，§26「遍历所有控件」）

```css
/* 原生 <select> 下拉弹层：Chrome 会用控件自身计算色渲染 option 面板，
   暗底若不显式声明，部分平台回落系统浅色 → 浅底浅字。 */
.wealth-create-form__seatrow select option { background: #0f141c; color: var(--wealth-text); }
/* 原生控件暗色语义 + 滑杆主题色（原先沿用系统浅色 UI）。 */
.wealth-create-form { color-scheme: dark; }
.wealth-create-form__row input[type="range"] { accent-color: var(--wealth-accent-strong); }
/* placeholder 默认 UA 灰 #757575 在 #0f141c 上仅 ≈4.05:1，低于 §26.1 正文 4.5:1。 */
.wealth-create-form__row input::placeholder { color: #8b949e; }
```

### 4.1 明确不改的部分（边界）

- **后端零改动**：本轮不涉及 `ServerGo/`；
- **不动 `globals.css` 的 `@import` 顺序**（§2.1 约束 4）；
- **不动 `AppModal.tsx`**（共享组件，回归面大）；
- **`wealth-p2.css`（D8）本轮不接线**——修复它 = 让 504 行从未生效的 CSS 一次性生效，
  影响拍卖弹窗 / 市场徽章 / 操作栏，属**独立变更**且需整局对局验证，故列为后续项（见 §6）。
