## 6. 质量保证

### 6.1 零信息丢失判定（`verify_no_loss_v50.py`）

判定口径：把**工作区当前版本**与 **git HEAD 版本**逐卡比对 frontmatter 的 `(key, value)` 集合。

| 判定 | 规则 |
|---|---|
| A 无丢失 | HEAD 中非重复键的 `(key, value)` 必须 100% 出现在当前版本 |
| B 有依据 | HEAD 中重复键的保留值必须属于原取值集合（不可凭空编造） |
| C 无噪声 | 当前版本不得引入 HEAD 中不存在的新键 |

### 6.2 已定位并修复的缺陷：跨行标量截断

- **现象**：部分卡 `_enrich_v44.src_line` 在原文中是**跨两行的单引号标量**；
  去重首版只搬了第一行 → 引号未闭合 → YAML 解析失败。
- **根因**：回收逻辑按「单行」搬运，未识别 YAML 的**续行**。
- **修复**：① `dedup_fields_v50.py` 改为连同行续行整体搬迁；
  ② `repair_broken_v50.py` 对全库做「引号奇偶」预筛 + YAML 复检，
  破损卡一律**回 git HEAD 原文重跑修正后逻辑**，最差情况原样回退（保证 YAML 一定可用）。
- **信息安全**：修复数据源自 git HEAD 原版，不新增、不编造任何人物内容。
